# cproject —— 一份**纯 Loment 项目**，两个叶子单元用 C 拼法写

```
loment/examples/cproject/
    main.lomt       ← 宿主。**原生 Loment**：use、跨单元调用、类型转换、输出、退出码
    bitkit.lomt     ← 叶子。**C 拼法**（文件头 `choose write grammar c`）：位运算、CRC-32、varint
    numkit.lomt     ← 叶子。**C 拼法**：数论、排序网络、状态分类、控制流
```

跑出来是：

```
bits=533 nums=917 total=1450        （退出码 170 = 1450 & 255）
```

三个数都不是抄的：`533` / `917` 各自在 Python 里照 C 语义**另写一份**算出来
（与 `docs/186` §1 那条"要与独立算出的期望值对一次"同一个道理），`1450 = 533 + 917`。

```bash
# 没有 I/O 的时候，观测面是退出码；这份有输出，所以两种都看
python tools/loment.py ir loment/examples/cproject/main.lomt
```

## 为什么拆成"宿主原生 + 叶子 C 拼法"

不是风格选择，是**今天唯一能跑的拆法**。实测（本仓 HEAD，见 `docs/211`）：

| 想做的事 | C 拼法的单元能做到吗 |
|---|---|
| 被别的单元 `use` | **能**。前门发出来的就是 `pub fn` |
| 自己写 `use` 声明依赖 | **不能**。写进去的 `use` **静默消失**（对象、`skipped` 都不留痕） |
| 调用另一个单元的函数 | **不能**。报 `调用了本单元没有的函数`（Stage A 不跨单元），
`docs/186` §9 留的 `pub extern fn` 口子在 C 拼法里**没有写法** |
| 在两种整型之间转换 | **不能**。既无隐式转换也无 `(T)x`（`docs/186` §4 收了四种整型，
却没给任何一条缝） |

四条加起来：**C 拼法的单元只能是叶子**。所有依赖声明、跨单元调用、跨类型转换必须由
写原生 Loment 的那一层承担 —— 这份项目里就是 `main.lomt` 的 `bits()` / `nums()`。

⇒ "每个单元都用 C 拼法"（含入口）**今天做不到**；能做的形状就是这一份。

## 叶子是**真的 C 写法**，不是 Loment 加了注释

两份叶子的正文是 C：`unsigned int popcount(unsigned int x) { … }`、
`int gcd(int a, int b) { … }`。前门（`potato_from.front_door`）把它们翻成 Loment 的
`pub fn` 再进冻结核心 —— **不起 C 编译器、不链 `.o`**（`docs/188` §3）。

两份叶子各自**只有一种整型**（`bitkit` 全 `u32`、`numkit` 全 `i32`）。这不是我挑的：
上面第四条，混一种就编不过。

## 它同时是一组**语料**

写这份项目的过程就是在 C 前端上找缝 —— 找到的每一条都报了 issue，汇总在 `docs/211`。
两份叶子里的每一个函数都是**能跑出数**的：想复现某一条，把它的形状挪进来跑一遍即可。

改这份项目时注意：

* 叶子里的算术**压在整型不溢出以内**。C 的有符号溢出是 UB，拿它当语料比不出翻译器
  对不对（实测：`clang -O1` 与译文在那里没有可比性）—— `numkit` 的 `isqrt(40000)`
  就是为这个把上界压下来的。
* 叶子**不要**写 `use`、不要调别的单元、不要混整型 —— 都会以"静默消失"或
  "报在别处"收场（见 `docs/211`）。
