## 1. 为什么这一条是整个 T3 的重量所在

`docs/232` §4.4 把 T3 的判据写成一行：**去优化之后，结果与原生产物相同**。这一行是整个梯子上
唯一一条**正确性**判据 —— 其余每一格要么是"跑得出来"，要么是"更快"。

**"更快"不是正确性陈述。** 一个去优化写坏了的 T3，是一个**更快地给出错答案**的东西 ——
比 T0 更坏，因为 T0 至少答案是错的得看得见。所以：

> **没有 `docs/249` 这一篇，`docs/248` 那张 B 堆表一行都不许落地。**

上文 `docs/248` §4 已经说明："J2 拒的是拿不可预测换峰值，T3 交的是拿慢启动换峰值、而答案
仍然可核" —— **"可核"这三个字全部由这一篇承担**。

## 2. 要重建的是什么：T0 那个状态长什么样

**先把"回到哪儿"定义清楚，否则"重建"没有目标。**

* T0 / T2 是**栈槽机**（`docs/243` §3.2、与 `lomelf` 同型）：**每个 SSA 值一个槽**，
  实参走栈，聚合走隐藏结果指针。所以 T0 在任意一条指令边界上的状态 = **帧的值表 + 帧里的槽**。
* T3 打破的正是这个假设：一个值可能在**寄存器**里、可能被**折成了常量**、可能**根本不存在**
  （因为那条假设让它变得不必存在 —— `docs/248` §3.2 的 B1）。

**⇒ 去优化的定义（本篇的用法）**：在守卫失败的那条指令边界上，**把 T3 的帧翻译成 T0 会有的
那个帧**，然后**从那条指令起交给 T0 继续解释**。不是"退回去重跑"，是"接着跑，用另一种引擎"。

⚠ **接着跑 ≠ 重跑**。重跑看起来更省事（把整个函数重新解释一遍），但它会**丢掉副作用** ——
到守卫为止写出去的内存、发过的系统调用，重跑一次就发两遍。**这条要写成一条判据**
（§5.3）：那份夹具里必须**有**在守卫之前发生、且**只能发生一次**的副作用。

## 3. 值可能在哪儿：四档，以及每一档怎么重建

| 值在哪儿 | 重建 | 代价 |
|---|---|---|
| **还在栈槽里** | 什么都不用做 | 无 |
| **在寄存器里** | 元数据写下"它在 R 号 / 栈上第 k 格"；去优化时把寄存器**写回槽** | 一次写回 |
| **被折成常量**（B1） | **按常量重新物化**（`%x := C`） | 一条 `mov` |
| **算得出来的** | **重算**（重放那条指令）—— ⚠ **只许白名单里的纯式子** | 重放那几条指令 |
| **死了的** | **不物化** | 无 —— ⚠ 但"死了"必须**证明过** |

**白名单（可以重算的）**：`add` / `sub` / `mul` / `and` / `or` / `xor` / `shl` / `lshr` /
`ashr` / `trunc` / `zext` / `sext` / `ptrtoint` / `inttoptr` / `icmp` / `phi`（只在它两个
来源都已物化时）/ `getelementptr`。

**白名单之外**（`load` / `store` / `call` / 内联过的边界 / 内联汇编）**一律不许重放** ——
它们不是纯的。**不在白名单里的一律 spill before guard**（§4）。

**"死了的"这一档要格外小心**：它省的是物化，**赌的却是活跃性分析**。活跃性算错一次，
去优化读到的就是**没有写过的槽** —— 而那片内存通常是 0 或上一次的残留，于是错的表现
**不是一个崩，是一个看着合理的错数**。所以这一档的规则写死：

> **没有经过活跃性证明的值，一律物化。** "看着不会再用了"不是证明。

## 4. 那条硬不变式：**守卫之前，不可重物化的一律落槽**

整个设计只有一条不变式，但它是承重的：

> **在每一条守卫之前，所有"不可重物化"（§3 白名单之外、且没被证明已死）的值，
> 必须已经在栈槽里。**

理由是失败模式：漏掉一个，去优化就把**寄存器里的垃圾**或**上一条命的值**当成那个 SSA 值
继续解释 —— 而结果通常**是一个数**，不是一个错。**一个错的数比一个崩难得多**。

⇒ 这条不变式的判据（§5.2）不是"读代码相信"，而是**在去优化发生的那一刻把帧倒出来**，
逐值对 T0 的期待。

## 5. 判据

### 5.1 硬判据（`docs/232` §4.4 那一行）

一份**一次跑里假设就会被推翻**的夹具，原生产物与 T3 **stdout 字节 + 退出码逐字节相同**。

夹具的形状（B1 的最小形态，`docs/248` §3.2）：

```rust
fn f(x: u32) -> u32 { return x * 2; }

fn _start() -> u32 {
    let i: u32 = 0;
    let s: u32 = 0;
    while i < 1000 {          // 前 1000 次：实参一直是 7 ⇒ 剖面记下"一直是 7"
        s = f(7);
        i = i + 1;
    }
    s = f(9);                 // 第 1001 次：假设不成立 ⇒ 守卫必须响
    syscall4(1, 1, ...);      // 副作用：必须恰好发生**一次**（§2 末尾那条）
    syscall4(60, s as u64, 0, 0);
    return 0;
}
```

三条断言，各自钉一半：
1. **答案对**：退出码 / stdout 与原生逐字节同（这就是 `docs/232` §4.4 那一行）；
2. **确实去优化过**：这一趟的**去优化记录非空**（§6）—— 否则这份夹具压根没走到这条路上，
   判据是**空**的；
3. **副作用只发生一次**：§2 末尾那条。少了它，"退回去重跑"这种错实现**照样绿**。

⚠ **第 2 条是这一篇里最容易被跳过、也最必须的**：一条"跑了、对了"的判据，如果优化器
**根本没敢特化**（假设没成立、守卫没被编出来），它测的就不是去优化。所以"能说出**什么时候**"
不是装饰，它是这条判据**非空**的前提 —— 也是下面 §6 那件产物存在的唯一理由。

### 5.2 帧重建（§4 那条不变式）

去优化发生的那一刻，把重建出来的帧与**同一边界上 T0 的帧**逐值对上（同一份程序、同一个
输入、走到同一条指令）。**这是一个三方对照**（记忆里那条"验翻译链要三方"）：T0 / T3 去优化
后的帧 / **独立推出来的期望** —— 前两者相等不算证据（两边一起错时它照样绿）。

### 5.3 反例：**没有**假设被推翻的那一趟

同一份夹具，把最后那次 `f(9)` 去掉 ⇒ **一次去优化都不许发生**。
这条钉的是反面：一个"每条守卫都上去优化"的实现是**慢的**，而且说明它根本没在看剖面。

## 6. 记录去优化：与剖面**同形**的第三件产物

"必须能说出什么时候"落到实现上就是**一件产物**：一行一条记录，
**TAB 分隔、行末 LF、UTF-8、按 IR 解析顺序**，与 `docs/246` §4 同一套体例
（第三方可读是构造出来的，不是声称的）。

```
# lvm deopt v1
[deopts]
<fn>\t<block>\t<instr>\t<reason>\t<count>
```

* `reason` 是一个**短的、封闭的词表**（`guard:C` / `guard:type` 这种），不是自由文本 ——
  自由文本没法比字节，而这一档的纪律是"两个实现给同一个答案"。
* **它不进 Potato**，理由与剖面逐字相同（`docs/246` §3）：跑一次和跑两次的产物不能不一样。
* **关掉它不许改变行为**：不带这个开关 ⇒ 一个字节都不写，且 stdout / 退出码与开着时
  逐字节相同（`docs/246` 判据 D 的同一条）。

⚠ **它是**开发通道的事：VM 本身在发行版里调不到（`docs/231` §2），所以这一档不必新增闸；
**哪天 VM 放开，这一档要跟着重新想**（与 `docs/246` §6 同一个提醒）。

## 7. 我不主张

1. **不主张去优化是"退回去重跑"**。§2 末尾：那是**错的**（副作用会发两遍），不是"慢一点"。
2. **不主张这套元数据现在够用**。B1 是今天唯一需要它的东西（`docs/248` §3.2）；
   将来多一条假设，元数据就要多一档来源，**那时加**，别在这里预先设计。
3. **不主张"没有去优化记录"就等于"没去优化"**。记录是**开发通道**的产物，不带开关就没有 ——
   所以 §5.1 第 2 条断言的是**带着开关跑的那一趟**。
4. **不主张这一格与 T4 有任何关系**。VM 自己没有对象（`docs/232` §4.5.1），
   去优化重建的是**栈槽机的帧**，不是"对象图"。
