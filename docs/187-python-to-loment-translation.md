# 187 · Python 翻成 Loment（Stage A 的第二门）

> 承接 `docs/186`（C 那一门）。用户的顺序是「**先做 C 一门，跑通再加**」——
> C 已跑通并推送，这一门是"再加"的第一门。
>
> **一句话结论**：Python 这一门比 C 那门**难得多**，但难在**语义**上（三处），
> 不难在解析上 —— `ast` 白送一棵真语法树，而 C 那门的分词器与递归下降是自己写的。

## 1. 判据与 C 那门是同一条

用户定的那条：

> 判据是「翻译出来的 Loment 跑出的结果 == 用 clang 编那份 C 跑出的结果」

这一门把"用 clang 编那份 C"换成"用 CPython 跑那份 Python"：

```
Python ──CPython──> main() 的返回值 ──┐
                                      ├─> 比一比
Python ──potato_from──> Potato ──lomt_from --impl──> Loment ──> 退出码 ──┘
```

**比的是数，不是文本**（理由同 `docs/186` §1）。每一份语料还各自与一个**独立推出来的**
期望值对一次 —— 少了那一步，"翻译器与 CPython 一起错成同一副样子"会被当成通过。

判据落在 `tools/loment_pytrans_test.py`（3 条），语料在 `loment/pytrans/*.py`。

## 2. 三处**语义**差 —— 每一处错了都照样编得过

这是这一门与 C 那门最大的不同。C 那门只有一处（`int` vs `bool`）；这一门有三处，
而且**每一处错了都不报错，只是数不对**：

| | Python | Loment | 怎么办 | 语料 |
|---|---|---|---|---|
| **`and` / `or`** | 返回**操作数**（`1 and 2` 是 `2`） | `&&` / `\|\|` 出 `bool` | **只在条件位置收**；当值用就报错 | `unsupported.py` |
| **`//` 与 `%`** | **向下取整**（`-7 % 2 == 1`） | **向零截断**（实测 `-7 % 2 == -1`） | 发一对辅助函数 | `floordiv.py` |
| **作用域** | **函数级**（`if` 里赋的名，外面看得见） | `let` 是**块级** | 声明按需要**上提**到函数头 | `scope.py` |

### 2.1 `and` / `or` —— 一处**收得住**的差

```
if a and b:        # 条件位置 —— 只问真假，两边一致，**收**
    ...
x = a and b        # 值位置 —— Python 给的是**操作数**（可能是任何 int）
                   #            而 Loment 的 `&&` 只能给 bool。**报错，不猜。**
```

条件位置是**保义**的：`a and b` 同真 iff `(a != 0) && (b != 0)`，**短路也保住了**。
当值用则不然 —— 照翻成 `&&` 的话 `pick(1, 2)` 在 Python 里给 2、在 Loment 里给 1，
**两边都编得过**。这正是本仓反复要消灭的形状（`docs/167`）。

注意 **`not` 不受这条限制**：Python 的 `not` **永远**返回 bool，所以它在值位置也能翻
（`z = not a` -> `z = (a == 0) as i64`）。

### 2.2 `//` 与 `%` —— 发一对辅助函数

```
Python  -7 // 2 == -4    -7 % 2 == 1      （向下取整）
Loment  -7 /  2 == -3    -7 %  2 == -1    （向零截断，**探出来的**）
```

恒等式（`b != 0` 时成立）：

```
__py_mod(a, b)      = ((a % b) + b) % b          # 用 Loment 那套截断的 `%`
__py_floordiv(a, b) = (a - __py_mod(a, b)) / b
```

**只在用到时才发** —— 确定性，不留死代码（判据里有一条钉这个）。
`loment/pytrans/floordiv.py` 把四个符号组合都走一遍：只试 `-7 // 2` 的话，
那两条恒等式里的 `+ b` 与随后那次 `% b` 各自会漏掉一个符号组合。

判据还额外比一次**"照 Loment 原生语义直译会得到什么"**（62），与正确答案（56）
**必须不同** —— 不然那份语料只是在摆样子，辅助函数根本没被测到。

### 2.3 作用域 —— 最不起眼、最容易翻错的一处

Python 的名字是**函数级**的：

```python
if c:
    x = 10
else:
    x = 20
return x      # 合法 —— 而 Loment 的 `let` 是**块级**的
```

照直翻会得到 `if c { let x: i64 = 10; } else { let x: i64 = 20; } return x;` ——
**Loment 编不过**（块外没有 `x`）。

所以声明的位置按"这个名字**最外层**在哪一层被赋值"来定：

* 最外层就是函数体那一层 -> 就地 `let`（可读）；
* 更深的 -> **上提到函数头**，给个零初值。

上提那份的**类型也要真推**：`x = (a < b)` 上提的应该是 `bool`，照发 `let x: i64 = 0;`
既把类型改掉了，后面那句 `x = (a < b);` 也会编不过。

## 3. 一条被**判据抓出来**的 bug：`for` 循环变量的终值

`docs/186` 的判据抓出过"裸块"，这一门的判据抓出的是这个：

```
for i in range(3): …    # 循环结束后 i 是 2（最后一个取到的值）
```

第一版把它降级成

```
let i: i64 = 0;
while i < n { …; i = i + 1; }      # ← 循环结束后 i 是 3
```

两个都编得过，**只有数不一样**：`scope.py` 里 `return x + total + i` 因此多算 2
（直译给 42，Python 给 40）。判据当场红。

改成一个**计次变量推着走**：

```
let i: i64 = 0;
let __t1: i64 = <start>;
while __t1 < <stop> {
    i = __t1;              // 循环变量每一轮从这里取
    <body>
    __t1 = __t1 + 1;
}
```

最后一轮 `i` 取到 `stop-1` 之后 `__t` 才加一，而 `i` 不再被改 —— 与 Python 一致，
空区间时 `i` 一次都不被赋（那份零初值见 §4 ①）。

**这一条值得单独写下来**：它证明"比数不比文本"这条判据定的**对**。比文本的话，
第一版那份产物是一份看着完全合理的 Loment，谁也看不出它算错了 2。

**顺带一条与 C 那门相反的**：`for` 的目标**不用改名**。Python 的 `for` 写进当前函数
作用域（所以循环之后 `i` 还活着，上面那条才成立）；C 的 `for (int i = …)` 却是**新**
作用域，所以那边反而必须改名外提。同一个"for 降级"，两门的手法正好相反。

## 4. 语义选择（不是翻译，是决定）

1. **上提的声明、以及空区间的 `for` 变量，给零值。** Python 那时会 `NameError`，
   Loment 拿到 0。这是**行为差异**，不是等价翻译 —— 写下来是因为它改的是行为。
2. **`int` 映 `i64`**，与 `potato_from.PY_TYPES` 一致。Python 的 `int` 是任意精度、
   `i64` 有界 —— **溢出行为的差别没有处理**（溢出变成回绕）。
3. **局部变量的类型从它第一次赋值的右值推**（比较/布尔/`not` 出 `bool`，其余 `i64`）。
   Python 没有声明，所以必须有一条"谁来定"的规则；这条是可读且确定的。
4. **函数与模块的文档字符串转成 `///` / `//` 注释带走**，不是丢掉 —— 它们在 Loment 里
   有对应的位置，信息不丢。**散落**的字符串字面量（不是第一句）则**报错**。

## 5. 子集

| | |
|---|---|
| 模块级 | `NAME = <整数>`（全大写才算常量，与 `potato_from` 同一条判据）、`def` |
| 参数/返回 | **必须写类型注解**（`int` / `bool` / `None`）—— Python 不写就没有类型可用，而 Loment 必须有。猜一个宽度是把作者的意思改掉 |
| 语句 | 赋值、注解赋值、增量赋值、`if/elif/else`、`while`、`for i in range(…)`、`return`、`f(…)` |
| 表达式 | 整数、名字、调用、一元 `- + ~ not`、二元算术/位/比较、布尔 `and`/`or`（**仅条件位置**） |

**不收的一律报错**（`docs/167`）：`break` / `continue` / `lambda` / 推导式 / `try` /
`with` / 导入 / 元组解包 / 链式比较 / `**` / `/`（真除，出浮点）/ `str`·`list`·`dict` /
`for … else` / `while … else` / 装饰器 / 默认参数 / 嵌套函数 / 类。

**链式比较**单独说一句：`a < b < c` 在 Python 里中间的 `b` **只求值一次**，
照抄成 `(a < b) && (b < c)` 会求两次 —— `b` 是调用时结果就不一样。所以拒掉，
让人显式写成 `a < b and b < c`（那时中间那个是名字还是调用，他已经写清楚了）。

## 6. `lomt_from --impl` 这一侧的两处变化（`docs/186` 之后）

* **有正文时 ABI 那道闸门让开。** Python 对象的 `abi` 是 `"python"`（`docs/179` §2），
  默认那条路上会被闸门挡掉——那是对的，它不能发成 `extern fn`。但 `--impl` 是**定义**
  这个函数（实现由 `pytrans` 翻出来），`abi` 描述的那件事已经不成立了。
* **按 `language` 分派翻译器**（`c` -> `ctrans`，`python` -> `pytrans`，其余报错）。
* Python 那门还要**知道模块常量的名字**：正文里只有函数，常量在对象的 `consts` 里
  （`pub const` 由 `lomt_from` 自己发）。不给这张表的话函数体里一引用常量就报"没赋过值"。

## 8. 拿真语料试了一次：`multilang/02-python/policy.lomt` **整体翻不过去**

它是本仓自己那份多语言例子里的 Python 源。**整份**喂给 `pytrans` 会红，而且红得有道理：

```
[ERR] 子集外: 第 32 行: 模块级只收 `def` 与全大写常量，得到 `If`
```

—— 那是一份**脚本**（`if __name__ == "__main__":` + `open()` + `with`），不是一份库。
把 `__main__` 块去掉、再给 `level` 补上注解之后，它翻得很干净（连模块与函数的文档字符串
都当注释带过去了）：

```python
def level(frame: int) -> int:
    v = frame & 0xFFFF
    if v >= ALARM_LEVEL:
        return 2
    ...
```

```rust
pub const WARN_LEVEL: i64 = 500;

/// 帧 -> 0（正常）/ 1（警告）/ 2（告警）。取低 16 位读数。
pub fn level(frame: i64) -> i64 {
    let v: i64 = (frame & 65535);
    if (v >= ALARM_LEVEL) { return 2; }
    ...
}
```

**这条值得记下来的地方在于两门的分界**：

* **C 那门**的语料（`loment/ctrans/*.c`）是**为翻译写的 C** —— 干净、无 IO；
* **Python 那门**面对的常态是**脚本**，而脚本里 `__main__` / IO / 无注解到处都是。
  `loment/examples/multilang/02-python/policy.lomt` 正是那种形状。

所以"Python 能不能翻"这个问题的答案不是"能/不能"，而是**"翻的是函数，不是脚本"**。
脚本那一层（`__main__`、`open`、`with`、`print`）是 `docs/173` §2 那条**运行期腿**的活儿
（起进程读 stdout），不是翻译的活儿 —— 这两条腿将来在同一个文件上会同时出现。

## 9. 下一步

* **Java 那一门**：`docs/179` §7 记着它已经有一份成员级解析（`_java_members`），
  但没有表达式级。它的语义差大概是"整型宽度 + `>>` 是有符号的 + 字符串"，
  与 C/Python 又不同 —— **先探再写**，别照抄。
* **跨单元调用**：Stage A 只翻一个单元。
* **Python 侧的 `break` / `continue`**：Loment 没有，要它们得先有对应的降级方式
  （C 那门记的是"用 did 标志改写"）。
* **`int` 的宽度**（§4 ②）：`i64` 与任意精度之间的差别没处理。
