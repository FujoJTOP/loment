# 246 · LVM 第二格（T1）：**反馈剖面**

> 状态: **规范**（2026-10-15）· 上游: `docs/232`（总纲 §4.4 的 T1 行 / §2.3 的 J 账）·
> `docs/243`（T0，已落地）· `docs/229`（基座：V8 的 Ignition → Sparkplug/TurboFan 怎么用剖面）
> 判据: `tools/lvm_profile_test.py`；孪生那一半在 `tools/lvm_twin_test.py`
> 一句话: **T0 是"走一遍"，T1 是"记住走的时候发生了什么"** —— 而记什么，由**这份 IR 是静态类型**
> 这一点决定，不能照抄 V8 的清单。

---

## 1. 先说清楚：照抄 V8 的"类型反馈"在这里是**空的**

`docs/232` §4.4 把 T1 写成"反馈向量（类型 / 分支 / 调用点剖面）"，对应物是 V8 的
feedback vectors。**第一项在这里不成立，而且这一点必须写在最前面**：

* V8 吃的是 JavaScript —— **没有类型**。所以"Ignition 看见这个加法两边是 Smi"是**新信息**，
  TurboFan 靠它把 `add` 编成整数加法。那是 V8 反馈向量**最重要**的用途。
* LVM 吃的是 **LLVM IR 子集**：`add i32 %a, %b` 里 `i32` 是**写在指令里**的。
  同一个加法在每一次执行里**只能**是 i32。类型反馈在这里不是"新信息"，是**把已知的东西再抄一遍**。

⇒ **T1 不记"每个站点观察到的类型"**。记了也换不来任何东西，而且会让人以为这一档做完了
V8 那一档的事。这条不是取舍，是**这份 IR 的性质决定的**。

（那 V8 的其余用途呢？**分支方向**与**调用点**是有的 —— 见 §2。）

## 2. 那么记什么：三样**静态读不出来**的东西

| 记什么 | 静态为什么不给 | 谁将来会用它 |
|---|---|---|
| **块的执行次数** | 一个块跑 0 次、1 次还是 10⁶ 次，IR 里没写。它同时是"热不热"和"这段值不值得编" | T2（按热布局）、T3（按热挑优化对象） |
| **`br` / `switch` 每条边走过的次数** | 条件的两支在静态下一样可疑 | T2（分支布局）、T3（把常走的那支做成主路径、把 `switch` 变成表） |
| **每个调用点被调的是谁、各多少次** | T0 只认直接调用，所以"被调是谁"静态可知 —— 但**"是不是同一个"**不可知。同时记调用点**执行了多少次**，那是内联的门槛 | T2（小函数的热调用点内联） |

**不记的**（写明，免得以后被当成漏了）：类型（§1）、值域、时间、内存行为、GC 行为。
时间是**机器**的属性不是程序的属性（`docs/226` 那条"绝对数不跨小时比较"同理）；值域的
记账面在 `docs/210` 的 `gc_ladder` 那一族，不在这一档。

## 3. 剖面**不进 Potato**（这是一条决定，不是懒）

Potato 是**单元形态对象**：它回答"这个单元**是**什么"。剖面回答"它**跑起来的时候**发生过什么"。

把后者塞进前者会有两个直接后果：

1. **同一份源会产出两份不同的对象** —— 跑一次和跑两次的 Potato 不一样。而这一仓对 Potato 的
   核心纪律是**两个实现逐字节相同**、以及**同一份输入给同一份输出**。剖面带进去就把它破了。
2. **它就再也不能"关掉"了**。`choose` 那一族的所有开关都建立在"产物里**没有**这一维"之上；
   一个"跑过就有了"的字段没法这样证明。

⇒ 剖面是**另一件产物**：一个**文本**文件，和 IR 摆在一起。`docs/232` §4.4 那句"剖面**进产物**"
在这里读作"**它是一件产物**"，不是"加进 Potato"。

## 4. 形状：行文本，排序，可第三方读

```
# lvm profile v1
# 站点标识 = (函数名, 块标签, 块内指令下标)；块以 (函数名, 块标签) 标识
[blocks]
<fn>\t<block>\t<count>
[edges]
<fn>\t<block>\t<instr>\t<edge>\t<count>
[calls]
<fn>\t<block>\t<instr>\t<callee>\t<count>
```

* **文本、TAB 分隔、行末 LF、UTF-8**。第三方可读**是构造出来的**：它就是一张表，
  不需要任何 LVM 内部结构就能读（判据里那个读它的解析器是**另写的一个小东西**，不复用 VM 的代码）。
* **三个段各自按标识排序**，数字是十进制。⇒ 同一份程序 + 同样输入 ⇒ **逐字节相同**。
  这条不是美观：T2/T3 要拿它当输入，输入不确定就无法复现（`docs/226` 的规矩）。
* **`edge` 是这一条边的编号**（`br` 条件分支：0 = 真、1 = 假；`switch`：按 case 出现次序，
  然后是 default）。没走过的**不写** —— 文件里出现的每一行都意味着"走过 ≥ 1 次"。

## 5. 判据（`tools/lvm_profile_test.py`）

| # | 判据 | 证伪方式 |
|---|---|---|
| **A** | **确定性** | 同一份程序跑两遍，两份剖面**逐字节相同** |
| **B** | **第三方可读** | 用**另写的一个小解析器**读它，断言内容与**手推的期望值**相同（不是拿 VM 自己再读一遍） |
| **C** | **计数是真的** | 一个分支/循环次数**已知**的夹具：块的次数、两支各几次、调用点几次，逐条对上 |
| **D** | **关掉就什么都不做** | 不带开关 ⇒ **不写文件**；而且 stdout 字节 + 退出码与**开着时逐字节相同**（记录**不许**改变被记录的行为） |
| **E** | **孪生** | 参考与自举镜像产出的剖面**逐字节相同**（在 `lvm_twin_test` 里）—— 这一条把 VM 的孪生从"行为同"升成"这一份新产物也逐字节同" |

**E 值得单独说一句**：`docs/243` §5 讲过 VM 的孪生只能比行为（两边跑的是同一份 IR，中间产物
没有可比性）。**剖面是第一个由 VM 自己产出、两边可以直接逐字节比的东西** —— 于是自举那条
"两个实现对同一条输入给同一个答案"的纪律，在这一档上第一次够得着了。

## 6. 开关：**不是** `choose`

`choose` 那一族的纪律是"**写进产物**、每维一次、≤300 行"。剖面**不进产物**（§3），
所以它不是一维 `choose`，是**命令行上的一个选项**（`--profile-out PATH`）。

⚠ 但它仍然是**开发通道**的事：LVM 本身在发行版里调不到（`docs/231` §2），所以这一档不必新增闸。
**哪天 VM 放开，这一档要跟着重新想** —— 记在这里，别到时候以为它天然是安全的。

## 7. 我不主张

1. **不主张这是 V8 那套**。§1 说了：最重要的一项（类型反馈）在这里是空的，因为这份 IR 不是 JS。
2. **不主张它现在有用**。它**只是被记下来了** —— 用它的那一刻是 T2/T3，而"用了之后确实更快"
   是**那两格**的判据，不是这一格的。
3. **不主张剖面的形状已定稿**。它今天够 T2 用；T3 若要别的量，**加段**（版本号 +1），不偷偷塞进现有段。
4. **不主张它便宜**。每一档加一次记账就是慢一点；T1 的判据里**没有**性能要求（性能账在 `docs/226`，
   而那要等 T2/T3 才有得比）。
