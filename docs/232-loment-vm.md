# 232 · Loment VM（LVM）：总纲

> 状态: **总纲**（2026-10-11）· 上游: `docs/229`（基座与研究）· `docs/231`（渠道与 `vm` 维）
> 一句话: **LVM 不是"写程序的帮手"，也不是"跑得更快的路"。它是第二条跑法 ——
> 让程序能被随时收编、换页，而且在收进来之前先验一次。**

本文是 LVM 的**入口**：读完这一篇就知道它是什么、为什么、怎么做、做到哪了、
以及**哪一句话能被证伪**。深的东西在两篇上游里，本文只做指针，不抄它们。

---

## 0. 一句话

> 今天 Loment 的程序是一条**单行道**：源码 → 一次编成原生可执行文件 → 跑。
> 路上没有第二个岔口，也没有"到了再决定"的地方。
>
> **LVM 就是在路上开的第二个岔口**：产物也可以交给一个**执行体**，
> 由它按需收编、按需换页 —— 而收编之前，它**读产物里已经印好的东西**来决定收不收。

---

## 1. 说清它是什么（以及不是什么）

### 1.1 一个类比就够

| | 今天（原生静态产物） | 有了 LVM |
|---|---|---|
| 像什么 | 一本**装订好的书** | 一个**活页夹** |
| 加一块东西 | 重印整本（重链全程序） | 抽换一页 |
| 收别人写的一块 | **做不到** | 能，但**收之前先判** |
| 那"判"的依据 | —— | **页面上本来就印着**（端口表 / 能力域 / 有没有运行期 / 回收组成） |

**它是"带批注的活页夹"。** 活页夹别人也有（JVM、Wasm、.NET 都算），
差别在最后那格：**批注不是运行期猜出来的，是编译期就印在产物里的。**

### 1.2 它**不是**什么（三条要被打破的误读）

这三条每一条都有人会顺口这么说，而**每一条都不成立**：

| 误读 | 为什么错 | 出处 |
|---|---|---|
| **"跑得更快的路"** | 反了。原生路已经比 C `-O2` 慢 10.7×（数组基准 342ms vs 32ms），**VM 是在那之上再慢一层**。要快走的是逃生舱，不是 VM | `docs/212` §1 · `docs/229` §1 |
| **"一次编写到处跑"** | 这条本仓早已判给**编译期**（同一份 IR → ELF / PE / 裸机对象）。而且它经不起自己的判据：若真为可移植，判据该是"新增一个目标不用写后端"—— 可今天也只有两个目标 | `docs/205` §2 |
| **"帮人更快地写程序"** | 那是**另一批东西**的活：六门表层语法（用 Python/Rust/Java 的拼法写）、`loment fmt`、LSP、`comefor` 方言、agent 指南。**LVM 一个都不沾**，它在程序写完之后才登场 | `docs/179` / `docs/188` / `docs/197` |

**这三条要写在最前面**，因为对外说错这三条，LVM 就变成一个"什么都想干、什么都不精"的东西 ——
而它真正的位置（运行期收编 + 加载期验收）反而没人做。

## 2. 它为什么在这门语言里**可能**是新的

### 2.1 两处空白

| # | 是什么 | 最接近的前史 | 为什么可能还是新的 |
|---|---|---|---|
| **①** | **执行模型进产物** —— 产物声明"我是给 VM 的还是原生的"，第三方**不读源码**可核 | **Android ART**：唯一"一份 dex、三种执行模型共存、且有项目级开关"的系统 | ART 把选择放在**系统属性与服务**里，**不写进 dex/oat**。别人把执行模型当**构建配置**，这里当**语义声明** |
| **②** | **内部缺席**是一等可验收主张 —— "这个产物里没有运行期 / 没有分配器" | **Wasm 的空 import 段**（最近）；**.NET CAS 的 `RequestRefuse`**（唯一明确尝试，**结局是被弃**） | Wasm 管的是"不依赖外部实现"，是**接口的语法属性**；CAS 被弃的理由是"要你**穷举**不想要的" ⇒ 打在穷举上，不打在"我里面没有"上 |

⚠ **一条必须分开的边界**（否则 ② 会被读成补课）：**外部**缺席（"我不导入 X"）
在 `docs/218` §5 里**已经自判为补课**（撞 WASI / 组件模型）。本文只主张**内部**缺席。

> **分界线一句话**：**"我不要 X" 是穷举、靠不住；"我里面没有 X" 是可数的、靠得住** ——
> 后者不要求任何人写全一张单子。

### 2.2 前史：没有一块砖是新的

证据随产物走 + 宿主加载期裁决 = **PCC（Necula 1996）**；"证不了就拒"的加载期验证器 =
**eBPF / JVM / NaCl**；一份输入多执行模型 + 项目级开关 = **ART**；
分层执行 / 反馈向量 / 去优化 = **V8**；框架化的语言实现 = **Truffle**。
**"可验证的缺席"这个说法检索不到标准学术用法**（用了 `verifiable absence` / `proof of absence` /
`absence property` / `negative capability declaration` 四组词）。**没检索到 ≠ 没有。**

### 2.3 与 J1 / J2 的账（这一节不能跳）

`docs/204`/`docs/205` 里有两条**明确不抄**的裁决，LVM 正面撞上它们，账要结清：

* **J2（JIT：运行时画像）"明确不抄"** —— 基座决定（§3）**直接推翻它**。
  能成立的前提只有一条：J2 当年拒的是"**运行期画像换峰值、代价是预热期与不可预测**"，
  而 `choose vm` 是**显式 opt-in** 的一维，**默认档一行不受影响**
  ⇒ 冲突面从"整个语言"缩到"选了 `vm` 的那一档"。
  ⚠ 但**发育梯 T1–T3 每一档都要重打这一仗**（它们就是运行时画像）；**T0 不要**。
* **J1（字节码 + VM 解耦）"换形式抄"** —— 它给字节码 + VM 记的代价是
  "**多了一层永远存在**"。**那正是当初拒它的实质理由**。`choose` 把它变成
  "多了一层，**但你可以不要**"—— 而"要不要"**写进产物**（§4.1）。
  这是唯一能正面顶回 J1 的东西，**它不是新机制，是既有的 `choose` 用在新的一维上**。

## 3. 基座（用户 2026-10-11 定）：**V8 与 GraalVM**

**自研**（不直接建在它们之上），但它们定**零件清单**与**框架形态**。

| | **V8** | **GraalVM / Truffle** |
|---|---|---|
| 贡献哪一极 | **工程实现** | **架构形态** |
| 分层执行 | **Ignition**（字节码解释器）→ **Sparkplug**（基线）→ **Maglev** → **TurboFan**（优化 JIT） | 自优化 AST 解释器；**JIT 不是写出来的，是从解释器经部分求值派生出来的** |
| 运行期剖面 | **反馈向量**（类型 / 分支 / 调用点） | 由 `@Specialization` 节点自带 |
| 回退 | **去优化**（bailout） | 部分求值的**守卫**失败 |
| 内存 | **Orinoco**：分代 + 并发/并行标记，**精确** | 宿主的；Native Image 侧是 AOT 的堆 |
| 启动 | **快照** + 惰性编译 | **Native Image**：closed-world AOT、无解释器、带 PGO |
| 语言无关能力 | —— | **Instrument API**：调试器 / 剖面 / 覆盖率，任何 Truffle 语言白拿 |

**为什么不是硬接**（形状本来就对上了）：
Loment 发的是**文本 LLVM 子集 IR**，而 GraalVM 有 **Sulong**（把 LLVM bitcode 跑在 Truffle 上）
⇒ 两边是**同一种东西**；而 `lomelf` 本来就是"每个 SSA 值一个栈槽"的**栈机**
（`tools/lomelf.py:19`）⇒ **V8 的 Ignition 是同一件事的成熟版**，
两者差的是**分层与去优化**，不是形状。

⚠ **甲 / 乙两条读法**（本文建议**甲**，但该由用户拍）：
**甲 = 架构参照系**（自己实现，清单照 V8、形态照 Truffle）；
**乙 = 直接建在之上**（做成 Truffle 语言 / 走 Sulong 那条路）。
**乙能拿到性能与工具链，拿不到独特性** —— Native Image 的 closed-world 与
Loment 要的"可核的缺席/组成"**方向相反**。详见 `docs/229` §1.5.4。

## 4. 设计

### 4.1 字节码**不发明新的** —— 它就是现有那份 IR 的序列化

这是整个设计里最省的一条。今天的后端有三条（Rust 转译 / clang / `lomelf`），
而 `lomelf` 已经证明：那份 IR 子集有**一个完整的栈槽执行模型**
（每个 SSA 值一个槽、实参走栈、聚合走隐藏结果指针）。**VM 缺的只有"执行"这一步。**

⇒ **LVM = 同一份 IR 的第四个读者。** 零新前端、零新 IR、零新类型系统；
规范的"指令集"就是 `lomelf` **已经支持的那个子集**，逐条对得上。

### 4.2 `choose` 的第五维：`vm` / `no_vm`

形状照抄既有四维（`mode` / `gc` / `runtime` / `port`），**默认 `no_vm`**：

| 情形 | 结果 |
|---|---|
| 不写 | `no_vm`（默认，与今天的行为一致） |
| `choose vm`（**开发通道**） | 通过；进 Potato；**今天产物与 `no_vm` 逐字节相同**（引擎还没写，见 §4.6） |
| `choose vm`（**发行版**） | **编译错误**，点名 + 给修法（§4.3） |
| 同一维写两次 / 取值拼错 | 报错（与其余四维同一条纪律） |

**取值只说"有没有"**，不说"是哪一档"（照 `runtime` 维的纪律）：档位会随年份长
（§4.4 那张梯子），钉进值名里就等于把今天的内容钉成这一维的身份。

**与 `runtime` 正交但今天同向**：VM 今天要用运行期，所以 `choose vm` + `choose no_runtime`
会被 `docs/227` 那条**既有的**检查接住（"声明了 `no_runtime` 但它会让产物带上运行期"）——
**不新写冲突，复用既有规则**。将来 VM 做到不拖运行期，这一对该放开。

### 4.3 渠道闸：**发行版里非法，只有 dev 能用**（用户 2026-10-11 定）

> 「不要在发行版 Loment 里被调用，所有调用 VM 的都是非法的，只能 dev 可以被调用，
> 直到第一个可使用的 LVM 诞生。」

**为什么这是一条闸而不是一句提醒**：`choose vm` 若在发行版里编得过，它就是
**一句用户写得出、却什么也拿不到的承诺** —— 而**承诺落空比拒绝更坏**。

**怎么实现的**（`docs/231` §2）：渠道是**一个常量、一行**，放在自举侧
`loment/selfhost/checker.lomt` 里；`loment_dist.py` 打包时**只替换那一行**，
用翻转后的树重算**发行版种子**，由它建包里的每一个工具。
⇒ **"包里除那一行之外与仓库逐字节相同"是一条可判据的话**（判据见 §7 F）。
参考实现侧那份是 `tools/loment_channel.py`（恒为 dev —— 它不进包）。

### 4.4 发育梯 T0–T4（照 V8 的分层）

**每格要能被证伪，不许写"做一个 JIT"。**

| 档 | LVM 要做到的 | V8 / GraalVM 的对应物 | 判据（可证伪） |
|---|---|---|---|
| **T0** | 字节码 + **直接解释** | Ignition | 与原生产物 **stdout + rc 逐字节相同** |
| **T1** | **反馈向量**（类型/分支/调用点剖面） | V8 feedback vectors | 剖面**进产物**且第三方可读；关掉剖面 ⇒ 产物逐字节不变 |
| **T2** | **基线编译**（去解释开销，不做优化） | Sparkplug | 同一程序 T2 显著快于 T0，**语义逐字节相同** |
| **T3** | **优化编译 + 去优化** | TurboFan / Graal | 去优化后**结果与原生产物相同**（T3 唯一的硬判据） |
| **T4** | 分代 / 并发回收 | Orinoco | ⚠ `docs/210` §2.4 今天明写"不做分代"（写屏障无处可放）⇒ **不是本档顺手能做的** |

**0.1.6 落在 T0**，而且 **T0 不欠 J2 任何账**（§2.3）。

### 4.5 与 `runtime` / `gc` / `port` 的关系

* **`runtime`**：VM 要运行期 ⇒ §4.2 那条既有冲突接住它。
* **`gc`**：`gc_ladder` 今天把每个 `alloc` 站点在**编译期**分到四层 —— 那是"**没有运行期实体**"
  的别扭处。VM 档下这张梯子的含义要**重划**（可能整层交给运行期），本文不预设。
* **`port`**：端口表是**外部**缺席，按 §2.1 的边界**不在本文主张内**，但它与"内部缺席"是
  同一套记账手法。

### 4.6 它今天**不提供**任何东西（诚实账）

`choose vm` 编得过（dev 通道）、进 Potato、每维一次 —— **但产物与 `no_vm` 逐字节相同**。
**今天那个箱子是空的。** 这与 `docs/175` §3.6 末尾"`runtime` 维只声明不提供"是**同一种欠法**，
由 `docs/227` 补齐过。**记在这里，别假装它是兑现的。**

## 5. 它在大项目里扮演什么角色

### 5.1 先泼冷水

大项目最常见的两个诉求 —— **编译快**、**跑得快** —— **LVM 都不解决**：
前者是**编译器内部**的问题（符号查找线性扫、成本超线性：130→253→435 个函数是
4.6s→12.8s→34.1s），正确解是**给那几处查找加索引**；后者 §1.2 已说，VM 更慢。

### 5.2 但"大"在这门语言里已经量出三处痛点，**只有第一处 VM 能治**

| 大项目暴露的问题 | 出处 | LVM 能治吗 |
|---|---|---|
| **发射符号是平的** ⇒ 100 个模块的函数名必须**手工全局唯一**（`m007_f3`），两个模块各写一个 `f0` 会被拒 | `loment/examples/megaproject/README.md` §1 · issue #221 | **能，而且只有它能** —— 每个模块一个命名空间，**加载期解析** |
| 模块级常量不能用（同名局部被静默忽略 / 参数与常量同名被误报重复） | 同上 §2 · issue #216 / #217 | 不能（那是**缺陷**，不是架构） |
| 编译超线性 | `docs/225` §3.3 | 不能（编译器内部索引问题） |

**第一处最要紧**：它是"**一份静态链接**"这个模型本身的后果 —— 大项目最典型的可扩展性问题，
被语言结构**直接顶到用户脸上**。仓库里已经有一条超大型项目判据在跑
（`loment/examples/megaproject/`：**100 模块 × 10 函数 = 1000 个函数**，另有 Java 语法的
300 模块一份），所以这不是推测，是**量出来的**。

### 5.3 三个角色（按"原生静态路上**做不到**"排）

1. **动态收编**（插件 / 扩展 / 规则）。原生产物加一个模块要**重链整个程序**；
   VM 加载一个字节码单元即可。
2. **热更新 / 增量**。改一个模块不重链全程序。
3. **跑不可信代码**（AI 生成的、第三方的扩展）。
   ⇒ **这一条才是本仓的独有东西第一次有用武之地**：静态链接时"端口表 / 能力域 / 缺席 /
   `gc_ladder`"是**审计**（事后看），到了**运行期加载**，它们变成**闸**（事前判）。

### 5.4 0.1.7 / 0.1.8 是它的**使用者**

路线图上对象系统（0.1.7）与内存管理系统（0.1.8）排在 LVM 之后，不是巧合 ——
那两样都是**动态图**上的东西，要的正是"有一个运行期实体"。

## 6. 对外能写的那一句（可证伪）

**不要**写"帮助更快地写程序"之类 —— 那是**证伪不了的形容词**，编辑器、插件、AI 助手
都能这么说，说了等于没说（而本仓对外立身的规矩是"每条主张都要有一条能打死它的判据"）。

**能写的是这一句**：

> **加一个扩展模块，不需要重链整个程序；而且加载之前就能判它碰不碰得到不该碰的东西。**

这句话**能被证伪**（做不到就是做不到），而且**只有这条路能给**。

## 7. 判据（每条可证伪）

| # | 判据 | 证伪方式 | 状态 |
|---|---|---|---|
| **A** | 执行模型进产物 | 产物里读得出是 VM 还是原生，且**第三方不读源码**可核 | ✅ 已落（Potato v13 的 `vm` 字段） |
| **B** | §4.1 的反例（**决定新颖面成不成立**） | 找到一个把执行模型作**产物内可核字段**的系统 ⇒ 这一处死 | ⏳ 检索不到，但**没查干净** |
| **C** | §2.1② 的反例 | 找到能给**自身内部**"无某组件"加载期可核声明的系统 ⇒ ② 死。**Wasm 已试过，给不出** | ⏳ 同上 |
| **D** | **发行版拒 / dev 收** | 发行版驱动器跑 `choose vm` ⇒ **rc ≠ 0 且点名**；dev 驱动器 ⇒ rc = 0。**两端都测**（只测"拒"的话，一个"什么都拒"的驱动器也能绿） | ✅ **已跑通**（`tools/loment_channel_test.py` 5/5） |
| **E** | 默认档**逐字节不变** | 现有语料（不写 `choose vm`）⇒ 产物一字不动 | ✅ `loment_potato_emit_test` 逐字节孪生 |
| **F** | **可重算的定点相等** | 发行版种子 = f(仓树, channel=release) 可重算；且与 dev 种子**长度相同**、差异**只在渠道常量被读到的那些处**（`CHANNEL_READ_SITES` 处，今天 **2**） | ✅ 判据已写（同上） |

> **⚠ 口径改了一处（2026-10-12，`docs/232` §1.1）**：原文写的是"只差**一个字节**"。
> LibL 的 `use libl` 也挂到同一条渠道闸上（用户 2026-10-12：「LibL 仍然在仓库中，
> 和 LVM 一样发行再锁」），而它的闸在**名字解析**处（`driver.lomt`），于是常量被
> **读两处** ⇒ 两个种子差 **2** 个字符（长度仍相同）。
> 判据 `test_release_seed_differs_only_in_the_channel_constant` 因此改成钉**处数**
> （`CHANNEL_READ_SITES = 2`）：以后多一处读取点就红，逼改的人先想清楚。
> **没有**加一个函数把读取点合并回一个 —— 实测往自举单元加函数会让那版顶破 60s 护栏

### 8.1 落地时踩到的三处（都写进了 `docs/231` §2.2）

1. **渠道常量做成独立模块 ⇒ 引出一个与渠道无关的红**（空单元的 IR 收尾两个实现不一致）。
   ⇒ 改回**一行常量**。
2. **`常量 == 字面量` 踩 issue #224**（`tools/lomentc.py` 把 `bool` 期望类型渗进整数运算）
   ⇒ 两个实现差**恰好 1 字节**。**根因在参考实现**，不在这里顺手修；绕过 = **先落到局部变量再比**。
3. **自举侧加一个函数 ≈ +4.7s**，而 60s 护栏本来就只剩 ~1% 余量（实测 59.33s）。
   同条件 A/B：纯净树 58.52s（过）/ 加函数版 **62.9s（红）** / 改局部变量 58.03s（过）。
   ⇒ **这一维不许在自举侧新加函数**；放宽护栏是**放松门禁**，不行。
4. **漏了一处登记处，而它报的是「对的码、错的话」。**
   自举侧那张核心维词表**有第二份手抄**：`loment/selfhost/switches.lomt` 的 `sw_is_core`
   （装载器用来把 `choose X` 分成"核心维"还是"开关"）。漏了 `vm` 之后，`choose vm`
   被当成**开关**查表 ⇒ 报 **E022「未定义的开关」**。
   **而 `loment_rule_parity` 抓不到** —— 它只比**码集**，三条 `vm` 负例两边都报 22，判绿。
   抓出它的是**正向**用例（"dev 驱动器必须**收** `choose vm`"）
   ⇒ **加一维要动的登记处是三处**（`CORE_DIMS` 那族 / `chk_core_dim` / `sw_is_core`），
   而**负例表钉不住"不该拒的别拒"**。
