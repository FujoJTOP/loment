# 204 · 四种语言的优点收集（C / Rust / Java / Python）

> 状态: **收集，不是判据**（2026-09-23）· 用途: 设计取舍的**输入**
> 一句话: 每条优点都写成 **机制 → 得到什么 → 代价** 三段 —— **缺了机制，那条优点抄不走；
> 缺了代价，那条优点是个陷阱。**

## 0. 为什么非要三段式

形容词不可搬运。"Rust 安全" 搬不走 —— 安全是**结果**，不是**手段**；
"Rust 用借用检查换来无 GC 的内存安全" 才搬得动，因为你至少知道要付出什么。
反过来，只抄手段不看代价同样会撞墙：把"穷尽 match"抄进一个每两周加一个变体的领域，
就是把"编译错误"变成"天天编译错误"。

所以下面每条都是这三格。**这不是该语言的优点全集**，是"我看到的、能说清机制的那些"。

---

## 1. C

| 优点 | 机制 | 得到什么 | 代价 |
|---|---|---|---|
| **薄抽象机** | 语言定义离机器很近：没有隐藏的分配、没有隐式控制流、没有边界检查 | 你写的东西 ≈ CPU 干的事 —— 性能与内存布局**可以推理**（这是它至今是系统层默认的原因） | 一切安全归你；**UB** 让编译器的假设能反噬你写的每一行 |
| **C ABI 是通用货币** | 调用约定、结构体布局是平台的事实标准 | "能被 C 调"就等于"能被一切调" —— 别的语言绑的第一个东西就是它 | 你的类型系统必须在 C 的表示上做功（`extern fn` 那条路）；C 的表示成了**所有语言的公共底层**，包括你不喜欢的那些 |
| **编译器的可达性** | 语言小到可以被搬到任何目标上 | 从 8 位机到超算都有 C 编译器 —— **不用求人**就能上新平台 | 语言本身不给现代设施，全在库与约定里；于是每个平台长出了自己的方言 |
| **小到能完整掌握** | K&R 两百多页；规范（C11）可通读 | 一个团队可以**共同持有**整套语义，不需要"某个人懂那个角落" | 生态里遍地是各家扩展（`__attribute__`、编译器 flag）—— "C" 实际不是一个语言 |
| **显式内存与指针** | 没有 GC、没有隐式拷贝、没有异常 | 你能**造**运行时、分配器、内核；本表其它三个语言都站在它上面 | 手写内存就是手写 bug；ASan/valgrind 从可选变成必需 |
| **"不作主张"的谦虚** | 不强制范式（不强制 OO / 函数式 / 安全） | 它活成了**底座**（ABI、可移植汇编器的位置） | 没有主张就没有护栏：读别人的 C 之前得先重建作者的心智模型 |

## 2. Rust

| 优点 | 机制 | 得到什么 | 代价 |
|---|---|---|---|
| **所有权 + 借用检查** | move 语义 + "**别名 XOR 可变**"在编译期判；NLL 把借用期收窄到实际使用范围 | **无 GC** 的前提下把 use-after-free / 数据竞争变成编译错误 | 图状与自引用数据要绕（`Rc`/`RefCell`/索引表/`unsafe`）；曲线陡，且**错误信息本身就是学习成本** |
| **`Result` + `?`** | 错误是**值**、写在类型里；`?` 只做早退 | 没有隐式控制流，错误路径可见**且被强制处理** | 签名要写错误类型；跨层错误要 `From` 转换，样板会堆在一个地方 |
| **穷尽 match** | 模式匹配 + 穷尽性检查 | "忘了处理一个分支"是**编译错误**，不是线上事故 | 加一个枚举变体是破坏性改动 —— 这是对的，但要认 |
| **trait + 单态化** | 静态派发、零成本抽象 | 抽象**不付**运行时代价；`impl Trait` / 关联类型表达力强 | 单态化 → 代码膨胀 + 编译变慢；想省就用 `dyn`，那是另一种代价，而**选哪条要人来定** |
| **`unsafe` 是词法边界** | 危险操作必须显式写出来 | 信任边界可 grep、可计数、可审计 —— 一个工程可以规定"`unsafe` 只许出现在这三个文件" | 它只是"编译器不再检查"，正确性论证仍然要人做（**边界可见 ≠ 边界正确**） |
| **Cargo 与统一工具链** | 构建 / 测试 / 文档 / 格式 / 发布**一套命令** | 生态没有"构建系统多样性税"；**doc-test 让文档里的例子被编译**（文档没法静默腐烂） | 单中心生态的风险；离线与 vendoring 的现实摩擦 |
| **卫生宏** | `macro_rules!` + proc-macro（编译期代码生成） | `serde` 那类"零样板"库才有可能；语法糖可以由**库**提供而不是由语言委员会提供 | 编译时间与诊断质量；宏的调试体验差，报错指向生成物 |

## 3. Java

| 优点 | 机制 | 得到什么 | 代价 |
|---|---|---|---|
| **字节码 + 规范化 VM** | 语言编译到中间表示，**VM 与语言解耦** | "一次编写到处运行"；而且**别的语言能用同一个 VM**（Kotlin/Scala/Clojure 全沾了这个光） | 多了一层永远存在；启动与内存有底噪；能干什么受 VM 暴露面限制 |
| **JIT（运行时画像）** | 收集真实调用点，再决定内联 / 去虚拟化 / 布局 | 长跑服务**越跑越快**；静态编译器看不到的信息它看得到 | 预热期；性能不再是静态可预测的量；AOT 场景吃亏 |
| **成熟的 GC** | 分代 + 并发收集器，几十年调参，且**可换收集器** | 内存管理不是程序员的问题；"该用哪个收集器"变成了一个**部署变量** | 停顿与占用成为运维指标；"什么时候回收"不可控 |
| **名义类型 + 显式接口** | 名字即契约，编译期检查 | 重构、IDE、工具链能靠类型**可靠**地做事（这是它工具生态强的一半原因） | 样板；表达力不足的部分要用设计模式补 |
| **向后兼容当最高纪律** | 二十多年不破坏旧代码；规范（JLS）成文 | 十年前的代码今天还能编 —— **"稳定"本身是一个可交付的优点** | 包袱永久留存；新特性得塞进旧模型，或另开语法 |
| **内存模型（JMM）首次被规范** | 并发语义跨平台成文 | 并发推理可以脱离具体 CPU | 难；多数人用不到，但**认知成本人人要付** |
| **（有争议）受检异常** | 编译器强制处理某些错误 | 错误**必须**被看见 —— 意图是好的 | 语法噪声、在 lambda 里难用、最后被包成运行时异常 —— 所以抄它的**意图**（不可忽略的错误）比抄它的形式更有价值 |

## 4. Python

| 优点 | 机制 | 得到什么 | 代价 |
|---|---|---|---|
| **可读性当第一目标** | 缩进即语法；一种显然的写法（PEP 8 / `import this`） | **读**代码的成本被当成设计指标 → 交接、评审、多年后回读都便宜 | 表达力受限（没有多行 lambda，块不引入作用域）；以及格式之争永无宁日 |
| **REPL 与交互式** | 解释执行；`python -i`；notebook | 反馈环最短 —— 探索、数据分析、教学没有对手 | 性能与"能上生产的边界"要靠别的手段去划 |
| **动态类型 / duck typing** | 名字在运行时解析；接口靠约定 | 写得快，原型与脚本无敌 | 错误推迟到运行时；大工程要靠类型注解 + mypy **补回来** |
| **内建数据结构与切片** | `dict`/`list`/`set`/`tuple` + `a[1:-1]`、`a[::2]`、推导式 | 日常数据处理的最短路径 —— 这是它赢下科学计算的一半原因 | 切片语义曾经是性能陷阱（因此 numpy 反过来定义了另一套） |
| **一切皆对象 + 内省** | `getattr`/`dir`/元类/装饰器 | **框架**成为可能（Django、pytest 的魔法全在这层）；装饰器把"包裹"写成了**语法** | 魔法难静态分析；"读了源码也没用"的时刻真实存在 |
| **生成器 / 迭代器协议** | `yield`；`for x in …` 统一协议 | 惰性序列是**语言级**的，不用库 | 惰性让调试变难（栈不完整），也让副作用时机不明显 |
| **`with` 与上下文管理器** | 词法作用域结束即释放 | 资源清理不用 `try/finally` 样板 | 依赖约定（`__enter__`/`__exit__`），且**没有任何东西强制你写它** |
| **标准库 + 生态广度** | "batteries included" + PyPI | 九成的事不用离开这门语言 —— numpy/pandas/torch 是它今天真正的护城河 | 生态质量参差；打包与部署（venv/conda/uv）长期多头 |

## 5. 对照组：同一个目标，相反的路

这一节比上面四张表更值得读 —— **语言设计上真正的分歧，是"同一个目标选了哪条路"**，
而不是"谁的特性多"。选了某条路，就同时选了它的代价。

| 目标 | 各路怎么解 | 选它等于选了 |
|---|---|---|
| **可移植性** | C：抽象机很薄 + 编译器遍地；Java：在语言与机器之间**插一层 VM** | 选 C 省掉那一层，但要自己适配每台机器；选 VM 省掉适配，但那层**永远在** |
| **成本在哪一刻付** | C：**不保证**（可能在你用户那里，UB）；Rust：写的时候（编译期）；Java/Python：跑的时候（运行期） | 这一条决定了团队要什么样的人，以及"交付前的信心"从哪来 |
| **"这段代码碰不到什么"由谁回答** | C：没人，靠约定；Java：VM 沙箱 / 反射清单（部分）；Rust：所有权类型；Python：没人 | 想让这件事**可被机械回答**，就得把"能碰什么"放进类型或形式对象里 |
| **依赖与模块** | C：预处理器 + 链接器（**名字即接口**）；Java：包 + 类加载器 + 坐标；Python：模块搜索路径 + 索引；Rust：crate + 一个中心工具 | 选"名字即接口"最轻但最脆；选"坐标 + 中心"最可复现但引入中心 |
| **版本演进** | Java：向后兼容优先；Python：付了 2→3 的代价；Rust：**edition**（语言层面允许多版本共存）；C：不变即特性 | 兼容性不是免费的：要么留在旧模型里，要么让两套并存 |
| **可预测性 vs 峰值性能** | C：全静态、可预测；Java：JIT 换峰值、牺牲预热期的可预测 | 实时/系统层要前者，长期服务要后者 |

## 6. 我不主张（诚实清单）

1. **这是判断，不是实测。** 它**不能**当判据用，也不能引用它去证明任何事 ——
   本仓的规矩是"每句话都有一条判据"，而这一篇**没有**，它只是收集。
2. **不主张某个语言更优秀。** 每条优点都绑着它的使用场景与代价；离开场景比较优劣
   就是上面 §0 说的那个错误。
3. **不主张 Loment 该照抄任何一条。** 取舍要逐条论证（`docs/175` §6 是那个论证的入口）。
4. **不主张这是完备的。** 它是"我看到的、能说清机制的优点"。任何一个语言都有
   我写不出来的优点，以及我懒得列的优点。

## 7. 与 Loment 的关系（简短，不越界）

这份是**输入**，不是结论。三个已有的落点，只当例子说明"同一个优点在不同项目里
未必该抄"：

- **Rust 的第 1 条（借用检查）**问的是"这段内存谁在用"；
  Loment 的能力域问的是"**这次访问在不在声明的域里**"（`docs/146`）。
  两者都能在编译期拒掉一类东西，但**它们拒的不是同一类**，所以不能互相替代。
- **Java 的第 1 条（把可移植性交给 VM）**与 Loment 相反：Loment 把可移植性放在
  **编译期**（同一份 IR 出 ELF / PE / 裸机对象），代价是它必须自己写后端
  （`docs/167`、C19/C20/C24 那几条主张）。
- **Java 的第 5 条（向后兼容当纪律）**对应 Loment 的**冻结面**（`docs/158`）：
  冻结不是"不改"，是"改要付四条代价"。

**每条优点要不要抄、以什么代价抄，得各自论证** —— `docs/175` §6 那张表是入口。
