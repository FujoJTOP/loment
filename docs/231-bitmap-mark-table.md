# 231 · 标记表换成位图（B3）：那张表不再吃掉 arena 的一半

> 状态: **已落地**（2026-10-11）· 上游: `docs/230` §4 的 **B3**、`docs/228` §1、`docs/210` §2
> 一句话: 收集器的标记表以前是**每 8 字节一个 `i32`** —— 于是一个 1 MiB 的 arena 要带
> **512 KiB 的 `.bss`**。换成位图后是 **16 KiB**（1/64），而**口径一个字节没动**。

行号按 2026-10-11 本检出（`tools/lomentc.py`，`docs/230` 落地之后）。

---

## 0. 这一步在还什么

`docs/230` 把 `hosted` + `gc_auto` 接上了宿主那块 1 MiB 的 arena，代价写在它的 §4 里：
**表是"每 8 字节一个 `i32`"，也就是 arena 的一半**。1 MiB 的 arena ⇒ **512 KiB 的 `.bss`**。

这不是"浪费一点内存"：它是 **B2（多段 / 无上限增长）的前置** —— 只要表的代价与 arena 成
**1/2**，把 arena 放大 10 倍就是放大 10 倍的常驻表，那条路走不下去。位图把它压到 **1/64**。

而且这张表本来就该是位图：**它存的是一个 bit 的信息**（"这块标过没有"），却占了 32 个。

---

## 1. 换的是什么：三件位运算，加一处清法

**口径不变**（这一条是整件事的前提）：位号仍是「块头偏移 `>> 3`」—— 每 8 字节一位。
于是

```
位号   = 块头偏移 >> 3
字节下标 = 位号 >> 3          （= 块头偏移 >> 6）
掩码    = 1 << (位号 & 7)
```

四处站点各换一次（`docs/228` §1 那张表里的"标记表"那一行）：

| 处 | 以前 | 现在 |
|---|---|---|
| `__loment_markp` 标记并回答"是不是第一次" | `load i32` / `icmp eq …, 1` / `store i32 1` | `load i8` → **按位与**判 → **按位或**写回 |
| `__loment_collect` 清标记那一趟 | `store i32 0` | `store i8 0` |
| 传播那一趟的"标过没有" | `icmp eq …, 1` | 按位与 |
| 清扫那一趟的"标过没有" | `icmp eq …, 1` | 按位与 |

**清标记那趟为什么可以直接把整个字节写 0**：一个字节盖 8 个位号 = **64 字节的 arena**，
而最小的块是 16 字节 —— 所以**最多 4 个块共用一个字节**。清那一趟走的是**块**（从偏移 8 起、
按块长前进），于是"顺手清掉邻居的位"是安全的：**清标记整趟跑在任何标记之前**，邻居那一格
待会儿走到时也会被清（而且它那时还没被标上）。**每一条标记都会被清**这条也没丢 ——
每一条标记都属于某个块，而那一趟**走遍所有块**。

**写标记必须是"读-改-写"**（`or` 回写），不能整字节写 1 —— 理由同上：一个字节住着好几个块。

## 2. 这一步**第一次**动了 `sealed` 的产物

前面三步（`docs/228`/`230`）都挂在 `choose port hosted` 上，所以 `sealed` 一个字节没变 ——
那是我们一直拿在手上的护栏（自举种子逐字符一致 + 那 9 份孪生目标）。

**B3 无法挂在任何闸门上**：标记表是**两个端口共用**的同一段收集器文本（`_IR_GC_SHARED`），
而位图对两边都严格更好。所以 `sealed` 的 `gc_auto` 产物**这次变了**。

代价与替代：那条"逐字节不变"的护栏换成**运行时判据** —— 而它们本来就在，且这次全都过了：

- `loment_elf_test` 那四条 GC 运行时判据（块纪元 / 空闲链表复用 / **auto 在 64 KiB 里收下
  1.4 MB 的请求** / **alpha 的自适应分得开 44 KB 的活集**）；
- **新加的一条**（§3 的 B3-3）：静态档自己跑一次收集，守着活数据。

其中 alpha 那一条最值钱：**它的自适应触发要读 `__loment_livebytes()`**，而那正是按位判的一处
—— 换句话说，"分得开 44 KB 与 44 KB 以下"这件事**依赖位图算得对**，不是"能跑就算过"。

---

## 3. 判据（每一条都能证伪）

| # | 主张 | 判据 |
|---|---|---|
| **B3-1** | 表的代价与 arena 是 **1/64** | 两档的表声明必须是 `arena / 64 x i8`，且 `arena / 8 x i32` 那个旧形状**不许再出现**。判的是**关系**，不是某个数 |
| **B3-2** | 口径没变 | 位号仍是「块头偏移 `>> 3`」；位运算三件（`>>3` 取字节 / `&7` 取掩码 / 按位与判）都在 |
| **B3-3** | **静态 64 KiB 上收得回来，且活数据原样** | 一份只求 **64 KiB** 的程序累计要 **200 KB**（收不回来必然 OOM），同时守着一块只被栈指着的 1000 字节 —— 跑完必须返回 9（`loment_hosted_test`） |
| **B3-4** | 两个端口仍然只是 arena 那三件事不同 | `_IR_GC_SHARED` 与 `_IR_GC_SHARED_HOSTED` 去掉 arena 行后**逐字相同**（`docs/230` 那条，跟着位图一起更新） |
| **B3-5** | 孪生 | 两个实现逐字节一致（`test_m82_hosted_arena_is_byte_identical` 两份源 + 那 9 份 sealed 目标） |
| **B3-6** | 既有行为不退化 | `loment_elf_test` 四条 GC 运行时判据全绿 —— 尤其 auto 收下 1.4 MB、alpha 分得开 44 KB |

**B3-3 是骨架**：B3-1/B3-2 量的都是**文本形态**，而"位运算写对了"与"收集器在这块 arena 上
真的收得对"是两件事 —— 位号与掩码错一位，症状是**静默地少收或多收**，只有跑起来读回数据
才抓得到。B3-6 那一对（auto/alpha 的量级判据）是它的加强版。

## 4. 代价与没做的

- **自举种子重生成**（`codegen.lomt` 里三处字面量跟着换：收集器本体、hosted 那一份、
  alpha 的触发）⇒ 一条 `[生成物]` 提交。三处都是**脚本从 `lomentc` 的常量换出来的**，不手抄。
- **`sealed` 的 `gc_auto` 产物字节变了**（§2）。这是这一步唯一"往外扩"的代价，写在这里不藏着。
- **仍然没做**（`docs/230` §4 那张表，B1/B3 划掉）：
  * **B2 多段 / 无上限增长** —— 表便宜了，但偏移仍是 `i32`、arena 仍是**一段**；多段要
    `(段, 偏移)` 或裸指针 = 重写分配器与收集器。**B3 只是把它前面的那块石头搬开**。
  * **B4 arena 大小可调** —— 仍是编译期常量。
  * **B5 `sealed` 向 OS 要页** —— 破 `sealed` 的定义，没有需求就不做。
  * **B6/B7** —— `docs/219` 的账 / arena 的归还。
