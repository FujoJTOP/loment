# 215 · 重算回收：把「垃圾」的定义从"不可达"改成"不值得留"

> 状态: **研究提案 / 待裁决**（2026-10-09）· 上游: `docs/210`（四层梯）、`docs/213`（回收极限）、`docs/214`（绝对极限）
> 一句话: **取消 GC 的第一不变量** —— 对**可证纯、可证确定、重算有界**的块，允许在**仍然可达**时回收；
> 真正再被用到时**重算**。于是"垃圾"的定义从「不可达」变成「**保留比重算贵**」。

## 0. 它违反的那条不变量

所有 GC —— 追踪、引用计数、区域、所有权 —— 都建立在**同一条**不变量上：

> **可达的东西不许回收。**

本文取消它。而**取消它等于取消"垃圾"这个概念本身**：垃圾不再由**可达性**定义，而由**经济性**定义。

> **一个块是垃圾 ⟺ 保留它的代价 > 重算它的代价。**

这不是"更好的收集器"。**这是把"收集器"换成"经济人"。**

## 1. 前史先行

### 1.1 这个机制在**三个更窄的层面**已经存在

| 层面 | 已有人在做的 | 出处 |
|---|---|---|
| **寄存器层** | `rematerialization`：重算一个值，而不 spill 它 | **GCC `early-remat.c`**、GCC Summit 2004《Register Rematerialization in GCC》；以及一批把它推广到内存分配的专利（US20080098371A1） |
| **tensor 层** | 静态内存规划：编译期决定 buffer 的分配与释放 | **MLIR `StaticMemoryPlannerAnalysis`**（bufferization，2025）；XLA / PyTorch Inductor 的 memory planning；`idealloc`（DATE 2026） |
| **最坏资源界** | 把资源界**写成类型** | **Hofmann & Jost 2003（AARA）**、**RAML / Resource-Aware ML**（Lichtman & Hoffmann, FSCD 2017；"Arrays and References in RAML"）、《Type-based amortized resource analysis with integers and arrays》(JFP 2015)、Type-Guided Worst-Case Input Generation (2018) |
| **纯度判定** | 判定"这个函数没有副作用" | purity analysis（VUB 博士论文 2016）；**IncPy**（动态纯度检测，Guo）；GCC `pragma Pure_Function` |
| **理论骨架** ⚠ | 把它形式化成**石子游戏**、并给出**最优调度的硬度**与**空间下界** | **Gilbert–Lengauer–Tarjan 1980 / Lingas 1980**（黑石子游戏最优调度 **PSPACE-完全**）；**Nordström**《New Wine into Old Wineskins: A Survey of Some Pebbling Classics》；**Hong & Kung 1981**（红蓝石子游戏）；**arXiv 2410.22237 / IPL 2026**（**带部分计算**的石子游戏） |
| **理论天花板** ⚠ | 重算能把空间压到多低 | **Bennett 1989《Time/Space Trade-Offs for Reversible Computation》**（空间压到 **O(log S)**，付时间）；**quant-ph/9703009**《Reversible Simulation of Irreversible Computation by Pebble Games》；《Reversible Space Equals Deterministic Space》 |
| **筛选策略的最优** ⚠ | "该留哪一块"在**离线**下有最优算法 | **Belady 1966**（离线最优置换，MIN）；learning-augmented paging 与竞争比下界（arXiv 2410.01760 / 2606.01342） |
| **编译器早已在玩** | 表达式 DAG 的寄存器分配按石子游戏做，**空间最优** | **Sethi & Ullman 1970** |
| **近亲（要划清）** | 自调整计算（增量重算）/ 记忆化（正向）/ 内容寻址构建（离线重算 vs 取缓存）/ 检查点回滚（重算指令烘进二进制） | **Acar**《A Cost Semantics for Self-Adjusting Computation》；**Michie 1968**《Memo functions》；Nix / Bazel 的 cache-and-recompute；**ACR: Amnesic Checkpointing and Recovery（HPCA 2020）**；《Recomputation Enabled Efficient Checkpointing》(arXiv 1710.04685) |

⚠ **而收集器这一层有一条更近的**：**Bacon & Rajan 的 "Pure" 同步环收集**（`Bacon03Pure`）用**因果依赖**（causal dependence）而不只是可达性来判断环 —— 也就是说，**"可达"不是唯一可用的信号**这件事，他们已经开过头。

> **⇒ 没有人把"重算代替驻留"做到通用堆上。** 这就是本文那一格。**窄得可以一句话说完，而且必须说完。**

### 1.2 与 `docs/210` §6.4 的关系（这一条必须写清）

`docs/210` §6.4 关掉的是「**用可逆计算省擦除的税**」—— 而它关得对：`free` 不擦任何东西，税挂在复用上。
**本文用的是同一个工具（Bennett 的重算），指向另一条轴：驻留**（`docs/213` §2.3）。

> **擦除那条轴被关过；驻留这条轴没有。** 本文不是重开 `§6.4`。

### 1.3 为什么**只有 Loment 能做**

前提是**纯度 + 确定性**，而：

* **确定性是 Loment 的立身之本**（`docs/140` 的差异点）；别的语言没有这个**可证的全局性质**；
* 而且**第一刀已经现成**：Potato **v7 的 `boundary` 计数**（`docs/205` R5）—— 一个函数**边界操作为 0**，就是"无 I/O、无 syscall"。

## 2. 机制

### 2.1 判定：**可重算性**

一个函数 `f` 可重算，当且仅当四条**同时**成立：

1. **`boundary(f) = 0`** —— 无 `extern fn` 调用、无 `syscall4`、无裸 `ptr` 变换（**v7 已经在数**）；
2. **`f` 确定** —— Loment 的核性质；
3. **`f` 的重算成本有界** —— AARA 式的一个界（§1.1 那一栏）；
4. **`f` 的依赖闭包**里的函数**也都可重算**（否则重算会碰到边界）。

### 2.2 动作

对**由可重算函数产生的块**：

| 步 | 做什么 |
|---|---|
| 编译期 | **允许提前回收**该块 —— **即使它仍然可达** |
| 产物 | 记一张 `recompute` 表：哪些块走这条路、重算的**界**是多少 |
| 运行期 | 解引用一个"已按重算回收"的块 ⇒ **重算**它 |
| 回退 | 重算**超过预算** ⇒ **退回为保留**（不是崩，不是 UB） |

### 2.3 产物里的**第五个数**

`gc_ladder`（v10）加一格 `recompute`，并且：

$$ l_0 + l_1 + l_2 + l_3 + \text{recompute} = N_{sites} $$

**与 v10 那条自洽规则同形**，于是"这个产物有多少内存走的是重算而不是保留"**不读源码可判**。

---

### 2.4 理论骨架：这不是一个新机制，是一个**石子游戏**

把 §2 形式化之后，它落进一个**有四十年定理**的模型里。这一节是本文**唯一有定理的地方**。

**模型**：程序的值图是一张 DAG。**保留一个块 = 在节点上放一颗黑石子**；**回收 = 拿走**；**重算 = 沿路径重新导出**。
于是本机制就是：

> **带重算的黑石子游戏**（black pebbling *with* recomputation）。

四条已知道理直接从那里搬过来：

| # | 定理 | 对本机制意味着 |
|---|---|---|
| 1 | **最优调度是 PSPACE-完全的**（Gilbert–Lengauer–Tarjan 1980；Lingas 1980） | **启发式不是偷懒，是必然。** 要把 §3.1 从"不可判定"升级成这句话 —— 后者讲的是**问题本身**的硬度 |
| 2 | **Bennett 1989**：可逆模拟能把空间压到 **O(log S)**，代价是时间 | **机制有一个已知的天花板，而且很高。** §4 的"arena 缩小"应该接在这条曲线上，而不是停在"缩小" |
| 3 | **Sethi & Ullman 1970**：表达式 DAG 的寄存器分配按石子游戏做，**空间最优** | **编译器早就在玩这个游戏** —— 这是"该由编译器做"的最硬先例 |
| 4 | **Belady 1966**：*该留哪一块* 在**离线**下有最优算法 | ⚠ **编译器有离线视野，运行期收集器没有** —— 这是"这件事该由编译器做、不该由运行期做"的**定理级论据**。我原来完全没写这一条 |

**并且**：红蓝石子游戏（Hong & Kung 1981）给了**内存层级的代价模型**；而 **arXiv 2410.22237（IPL 2026）的"带部分计算的石子游戏"** 与本机制**几乎同形** —— 说明这条路**有人在走**。

**要划清的近亲**（别把它们说成本机制）：

* **自调整计算**（Acar）：改的是**增量重算**，不选择"留不留"；
* **记忆化**（Michie 1968）：**正向**（重算换保留）；本机制**反向**；
* **内容寻址构建**（Nix / Bazel）：与 Belady 那一支同族，而且**工程上已大规模跑通** —— 这是最有利的一栏；
* **检查点 / 回滚**（HPCA 2020；arXiv 1710.04685，它把重算指令烘进二进制）：**几乎同形**，但目标是**容错**不是空间；
* **部分求值 / 超编译**（Futamura）：把计算**搬到编译期**，与本机制**互补**。

> ⚠ **诚实附记**：检索中发现 **`wilcompute/W33-Theory` 有一个提交叫 "Add reversible checkpoint GC and recompute economics model"** —— **有人在做几乎同名的事**。它不是同行评审产物，但**不能假设这条线是空的**。

## 3. 先把不可能性写死（四条）

### 3.1 "该不该重算"是 **PSPACE-完全的**（不是"不可判定"）
它取决于图的结构与未来的使用序列 —— 而这个优化问题**本身**是 PSPACE-完全的（§2.4 #1）。
⇒ **只能预算式/启发式，不可能最优** —— 但这句话现在是**定理**，不是我的判断。
（"判活不可判定"那条在 `docs/213` §2.2；这里是**更强、更准**的一刀：它讲的是**调度问题**的硬度。）

### 3.2 它**不能与 `L3` 共存**
`L3` 的**存在性**依赖于"可达 = 活"。重算回收把"可达但已死"变成"可达但**可重算**"—— 那是**另一个概念**。
⇒ **梯子变成三个数**（`L0`/`L1`/`L2`）+ `recompute`；`L3` 要么在，要么不在。

### 3.3 最坏代价可**超线性**
重算一个依赖链，代价可以是链长的函数。⇒ **必须有预算**，否则这是一个 **DoS 面**（攻击者构造一条长链，让每次解引用都重算一遍）。

### 3.4 **零收益区是存在的**（最容易骗自己的一条）
同样一次计算，**纯函数重算 ≥ 读一遍内存**。所以重算**永远不会比读便宜**。

⇒ **它只在「驻留节能 > 重算能耗」时划算** —— 这是一个**可测的阈值，不是普适的胜利**。
> 把它写成"重算更快"就是骗人。它换的是**空间与驻留能耗**，付的是**时间**。

## 4. 它换来了什么

| 得到 | 依据 |
|---|---|
| **arena 缩小**（保留集 → **不可重算集**） | 本文 §2 |
| **驻留能耗下降** | `docs/213` §2.3：`E_retain ∝ 存活字节 × 刷新功率` |
| **零观察**（只要重算路径不扫堆）⇒ 量子侧可用 | `docs/213` §4.2（**带条件**） |
| **一个新的物理含义**：arena 的必要内容 = **程序的"不可重算状态"** | 即：**输入 + 副作用留下的东西**；一切能由输入重新导出的，都不必留 |

**但上限不是"缩小"，是一条已知的曲线。** Bennett 1989（§2.4 #2）说的是：可逆模拟能把空间压到 **O(log S)**，代价是时间。
⇒ **机制的目标函数不是一个数，是一条 `空间 × 时间` 的曲线**，而**那条曲线的下端已经被证明在那儿了**。

> 换句话说：**"arena 能缩到多小"这件事有答案，而且答案不在本文手里，在 1989 年那篇论文里。** 本文只是说：Loment 有把它**变成语言规则**的前提（确定性 + `boundary` 计数）。

## 5. 代价（逐条）

| 代价 | 说明 |
|---|---|
| **时间换空间** | 最坏情况下**更慢**（§3.4 的零收益区） |
| **编译器更重** | 要纯度判定 + 有界判定 + 依赖闭包 |
| **与 `L3` 二选一** | §3.2：这是**排他**的，不是叠加的 |
| **DoS 面** | §3.3：必须有预算，而预算会**削弱**收益 |
| **纯度判定的假阴性** | `boundary = 0` 是必要不充分（§6.4 是它的判据） |

## 6. 判据（每条可证伪；一条都还没跑）

### 6.1 一对程序（**这一条是全部的重量**）
**同一份源码**：一块**由纯函数产生**、且**仍然可达**的块（例如挂在一个一直活着的槽上）。
* 开重算：**在更小的 arena 里跑完**；
* 关重算：**耗尽**。
> **形状与 `docs/210` §5 那几对同构** —— 一对只差一行的程序，行为不同。**若两边都跑得完 ⇒ 重算没有发生；若两边都耗尽 ⇒ 重算做不到。这一条直接判本机制的生死。**

### 6.2 自洽（§2.3）
五数之和 == `total_sites`；**两份校验器各自独立判得**（v10 的 `MUTATORS_V10` 同形）。

### 6.3 **零收益区必须被判出来**（§3.4）
构造一个"重算明显更贵"的程序 ⇒ 编译器**必须不选**重算。
> **选了 ⇒ 那是 bug**，而且是会被线上感知的那种（变慢）。

### 6.4 纯度假阴性（§1.3、§5）
`boundary(f) = 0` 但 `f` **不确定**（例如读到未初始化的东西）⇒ **必须不判为可重算**。
> 判成可重算 ⇒ 重算出来的值与原来的不同 ⇒ **静默改语义**，是最坏的失败形状。

### 6.5 **对标离线最优，报竞争比**（§2.4 #4 —— 这条是新的，也是最有分量的一条）
机制的行为**必须**与**离线最优（Belady MIN）**对照，报 **竞争比**，而不是只说"省了"。

> **理由**：编译器**有**离线视野（它看得见整个程序），而运行期收集器**没有**。这既是本机制的技术优势，**也是它的必要义务** ——
> **做不到"明显优于在线策略"，这个机制就没有存在理由**（那运行期自己就做了）。

⇒ 判据：在一个**已知离线最优解**的合成程序族上，本机制的 `recompute` 决策与最优的比值**必须**有一个**上界**，且该上界**进产物**。

## 8. 我不主张

1. **不主张这机制是新的。** §1.1 三栏都有先行工作，**收集器层那条最近的也已被占**；新颖面只有"**通用堆 + 纯度证明 + 产物里的第五个数**"。
1b. **不主张"把它形式化成石子游戏"是新的** —— §2.4 的四条定理都是别人的；**本文做的是搬运**（把已知模型搬到 Loment 的产物上）。
1c. **不主张这条线是空的** —— 检索里有 `wilcompute/W33-Theory` 的同名提交（§2.4 附记）、有"带部分计算的石子游戏"（IPL 2026）、有把重算指令烘进二进制的检查点工作。
1d. **不主张那条上限能拿到** —— Bennett 的 O(log S) 是**可逆模拟**的界；要它落在本机制上，得先证 Loment 的纯度判定能覆盖那个模拟所需的全部结构。**这一步本文没做。**
2. **不主张它更快。** §3.4：它**永远不比重算便宜**，换的是空间与驻留。
3. **不主张它普遍适用。** §3.2 与 `L3` **排他**；§3.3 有 DoS 面；§3.4 有零收益区。
4. **不主张任何数已经量过。** §6 一条都没跑。
5. **不主张本文改任何判据、碰 `lom/`、或改 `docs/210`/`213`/`214`。**
6. **不主张本文经过独立复核。** 与作者同源（`docs/203` 体例）。
