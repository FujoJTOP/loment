# 180 · std 核：约定、模块、以及 hosted 层为什么还没开

> 状态: **核部分已实现**（2026-09-17）· 目录: `loment/lib/`
> 判据: `loment_std_test`（2/2，27 项与 Python 逐字节一致）· 定题: `docs/175` §6 第 3 条
> 一句话: **先把"成体系"理解成约定 + 判据，再谈往里放什么。**

## 1. "成体系"不是文件数量

`loment/lib/` 原先三个文件（`json` 619 行 / `sha256` 172 行 / `proc` 150 行），都是有分量的
东西。它们不"成体系"的地方在**三处**，一处比一处隐蔽：

1. **没有一条判据在问"这些函数算得对不对"。** `loment_lib_test` 测的是**库系统**
   （身份/去重/物化/多版本共存），`loment_json_test` 测 json 一个模块。
   库里最容易被"看起来有"蒙混过去的就是这个：签名在、检查过、编得出，而**算错了**。
2. **模块之间没有分层。** `sha256` 直接调 `load32`/`store32`，而那两个函数在
   `loment/examples/bytes.lomt` —— 它**谁也不 `use`**。它能编过，只是因为消费者
   （`lompkg`）碰巧把 `bytes` 拉进了同一个单元。**单独一份检查不过。**（见 §4）
3. **同一件事写了好几遍。** 十六进制输出在 `json.lomt`（`j_hexdig`/`j_hex4`）与
   `sha256.lomt`（`hex_dig`）各有一份；字节比较 `json.lomt` 自己写了一遍。

所以这一轮做的是：**补上第 1 条的判据、按第 2 条分层、按第 3 条抽公共件。**

## 2. 这一轮加了什么

| 模块 | 内容 | 为什么它该在 |
|---|---|---|
| `loment/lib/mem.lomt` | 字节级 `copy`/`move`/`fill`/`zero`/`eq`/`find`/`find_ne` + 小端 16/32 位读写 | 语言内建只给单字节 `load8`/`store8`；"一段字节"的操作原先在每个用到的地方各写一遍 |
| `loment/lib/num.lomt` | 十进制/十六进制的写出与解析（`dec`/`hex` 双向 + 各配一个"读了几位"） | 输出一个数、读一个数是每个程序都要做的事；十六进制输出原先写了三遍 |
| `loment/lib/sha256.lomt`（改） | 改为 `use mem`，用 `mem_load32`/`mem_store32` | 让它**自足** —— 原先靠别人给符号（§4） |

`json` / `proc` 未动（它们已经在正确的层上）。

## 3. 约定（写下来才算"体系"）

这三个是既有三个模块**本来就在遵守**的，只是从没写下来过 —— 不写下来，新加的模块就会
各走一套：

1. **输出写进调用方的缓冲，返回写出的字节数。**
   **没有返回 `str` 的函数** —— 语言没有字符串常量、也没有分配器，"在这里造一个串返回"
   这条路根本不存在（`docs/143`）。所以形状一律是 `fn f(out: ptr, cap_or_nothing) -> u32`，
   调用方拿返回值切。`num_to_dec` / `num_to_hex` / `json_str_into` / `hex_dig` 都是这个形状。
2. **输入是 `(ptr, 长度)`，不假设 NUL 结尾。** 长度由调用方给。字符串一旦越过接口边界，
   长度就必须跟着走（`str` 类型自己带长度；裸 `ptr` 不带）。
3. **"找不到/没有"用 `i64` 返回 -1，不用 `u32` 的哨兵值。** `u32` 上表达不了"比 0 还小"，
   而 `0xFFFFFFFF` 是个**合法数据**——拿它当哨兵就是把"没找到"和"找到了一个很大的数"
   混成一个。`mem_find` / `mem_find_ne` / `num_hex_val` 都用 `i64`。

**分组:** `lib/` 放**自足**的模块（只依赖别的 `lib/` 模块或语言内建），不放会依赖
`examples/` 或 `tools/` 的东西 —— `examples/` 是示例、`tools/` 是工具，都不是库。
§4 那个 bug 就是这条被违反的结果。

## 4. 撞出来的两件事（都不是计划里的，是写这一轮时露出来的）

### 4.1 `sha256.lomt` 单独一份**检查不过**

它调 `load32`/`store32`，而这两个函数定义在 `loment/examples/bytes.lomt`，它**谁也不 use**。
Loment 把 `use` 进来的文件拼成一个**平单元**，所以只要消费者那一侧碰巧带了 `bytes`，
符号就"有"了 —— `lompkg` 的依赖闭包恰好是 `bytes, json, sha256`。

**这不是"能跑就行"**: 它是**单元全局名字空间**（`docs/158` §2 那条"发射符号是平的"）
给的一种假象 —— 一个模块的**依赖**可以是调用方带来的。真相是它不自足，
而**没有任何判据在问"每个 lib 模块自己能不能过检查"**。

修法：`mem.lomt` 提供 `mem_load16/32`、`mem_store16/32`（与 `bytes.lomt` 的
`load16/32`、`store16/32` **同语义，连写法都一样**：乘加而不是位移，两份要能逐位对上），
`sha256.lomt` 改 `use mem`。判据补在 `loment_std_test::test_std_modules_are_checkable`
（**不依赖 clang，永远跑**）。

### 4.2 混宽整数比较**产出非法 IR** —— `docs/158` §4 的 B1

`mem_find` 原来写 `load8(hay, i) == needle`：`load8` 的 Loment 类型是 `u32`、`needle` 是
`u8`，于是这是**混宽比较**。两边都不对：

- 参考实现只把**左边**提升到 i32，右边留 `i8`，产出 `icmp eq i32 %t1, %t2`（`%t2` 是 i8）
  —— **非法 IR**，clang 当场拒。症状是 `loment_pkg_test` 三个用例全红。
- 自举那边把左边**截到窄的**再比。对 `load8` 恰好等价，对一般 `u32 == u8` 是**错码**
  （`300 == 44 as u8` 会被判真）。而且在 `load8(…) == x` 这个形状上两边**不一致** ——
  `loment_cli_test` 的自举/参考对照红 2 字节就是它。

**"两边一致地错"最危险**: 语料里从来没有混宽比较，所以 54/54 逐字节一致一直绿，
绿得让人以为它是对的。

**本轮只绕开，没修编译器**：`mem.lomt` 里显式 `let want: u32 = needle as u32;`，两边都变宽。
修编译器要走 `docs/158` §5 的四条，是一次独立的语言面改动（`docs/158` §4 的 B1 记了最小复现）。

## 5. hosted 层为什么还没开

`docs/175` §6 第 3 条要两件事：**std 核收口**（这一轮做了）与 **hosted 层先只做"够跑通一条
判据"**。第二件**没做**，而且不是没时间 —— 它卡在一处**跨线决定**上：

hosted 层的实质是"**哪些 L0 原语在 std 模式下可用**"。那要 `lom/*.lom` 里的原语带上
`freestanding` / `hosted` 标记，而 `lom/*.lom` 是**跨线冻结契约**（`CLAUDE.md` 第 1 条），
改它要单独提交并知会 compat 线。**标记语法尚未定**（`docs/176` §6 的 B0）——
**不替对方猜**，这是 `docs/175` §7.1 与 `docs/176` §6.1 都记着的那条。

所以本文档的边界是：**`loment/lib/` 里全是能在两种模式下都编的代码**（它们只用语言内建
与彼此）。一旦某个模块开始问"现在是不是 std"，那就得等 B0。

## 6. 下一步（本文档不做）

1. **合并 `examples/bytes.lomt` 与 `lib/mem.lomt` 的那一份重复。** 现在
   `load16/32`、`store16/32` 有两份实现（一份在 `examples/`，一份是 `mem_*`），
   语义相同、写法相同，但**两份就是两份**。合并要动 `loment/examples/`（进 p8 的
   逐字节语料），所以单独做。
2. **把 `json.lomt` / `sha256.lomt` 里剩下的手写循环换成 `mem` 的调用。** 这一轮只把
   `sha256` 的 32 位访问换掉了；`json` 的字节比较与十六进制输出还在自己写。
3. **`docs/158` §4 的 B1**（混宽比较）—— 修它，然后本文件 §4.2 的绕法就可以去掉。
4. **模块按功能分组。** 现在 `lib/` 是平铺的 5 个文件；等到十几个再谈目录，
   **现在分层是过度设计**。
