> 状态: **盘点 / 议程**（2026-10-10）· 上游: `docs/210`（四层梯）、`docs/213`/`214`/`215`（极限三部曲）、

> 一句话: **把"Loment 的运行期"与"Java 的运行期"放上同一张桌子之前，先得承认它们不是同一类东西**；

## 0. 口径纠正：它们不是同一类东西

拿"Loment 的 GC 比 G1 差多少"当问题是**问错了题**。两边根本不是一类对象：

| | **Loment 的运行期** | **Java 的运行期** |
|---|---|---|
| 是什么 | 两段 **IR 文本**：`_IR_RUNTIME` 1473 B（`lomentc.py:56`）+ `_IR_HEAP` 5354 B（`:133`）；带上收集器则 + `_IR_GC` 5425 B 或 `_IR_GC_ALPHA` 6633 B（`:4563`/`:4564`） | 一个**产品**：加载器 + 分层 JIT + 剖面采集 + safepoint + 分代并发 GC + 类元数据 + 线程 |
| 存在条件 | **按需**：发射出来的文本里没有 `@__loment_alloc` 就整段掉出去（闸门 `:6312` `"@__loment_" in text_all`、`:6331` `_needs_heap`、`:6337` `gc_auto or gc_alpha`） | 永远在；jar 里**没有一栏**能说"我不要 GC" |
| 堆 | 产物里一个 **64 KiB 的 `.bss` 全局**（`@__loment_heap`，`:276`），**从不向 OS 要页** | 由 VM 向 OS 要 |
| libc | **从不链**（M31，`_IR_RUNTIME` 头注 `:57`） | 就是 C 运行时 |
| 线程 / 信号 | **没有** —— 所以"并发标记""safepoint"这一类连门都没有（`docs/210` §2.4） | 全是 |
| 收集 | **标记-清扫、不搬移**；根**精确**（`@__loment_roots` 存**槽地址**），**块内保守**（`alloc` 无类型） | 分代 + 并发 + 可换 |

⇒ **Loment 的运行期是"编译期组装、产物里可判"的**；**Java 的是单体服务**。
这条差别就是 `docs/210` §3 的全部内容，也是本文一切判断的前提。

> **性能那一格要诚实**：数组循环实测 **342 ms**（C `-O2` 32 ms、**Java 231 ms** —— 比 JVM 慢 1.5×、
> 比 C `-O2` 慢 10.7×），`docs/212` §1。**那不是这条线的轴**，但它是这条线**不能拿性能说事**的原因。

## 1. 前史先行（这一节不许跳）

照 `docs/207` 的教训：**先点名，再说话**。本盘点**没有新机制** —— 它是一份**议程**，而下面每一格都有人先到过。

| 本文用到的 | 谁写过 | 写到哪儿 |
|---|---|---|
| 擦除下限 / 可逆计算 / **"回收 = 反向的子计算"（摘要里就点了栈）** | Landauer 1961 / Bennett 1973 / **Baker, IWMM '92, LNCS 637 pp. 507–524** | **整条"回收 × 物理"轴**；`docs/207` 是它的**重发现**（见该篇头注的自报） |
| 有界内存 + 正垃圾熵率 ⇒ 不可能无限继续 | Wu（Zenodo `10.5281/zenodo.20252480`, 2026-05） | 速率的界 |
| 精确判活**不可判定**（机器验证） | folklore；`emberian/dregg` 的 `dead_undecidable`（Lean） | `docs/213` §2.2 / `docs/214` §2.1 的最强依据 |
| 编译期放掉分配：逃逸分析 / 区域推断 / Perceus 引用计数 | Go & Swift 的逃逸分析、**Tofte–Talpin**、**Koka Perceus**、MLKit | `docs/210` §1 一张表已点全 |
| **"仿射类型 + 生命周期 ⇒ 自动 uncomputation"** | **Qurts**（PACMPL `10.1145/3704842`） | ⚠ **直接压住 `docs/213` §4.3**（`L1` 是它的经典影子） |
| 线性/仿射类型规避无克隆 | 量子 λ 演算、Proto-Quipper、Guppy | **教科书**，不是发现 |
| **"声明依赖、宿主必须满足"** | ⚠ **WebAssembly 的 import/export + capability host functions** | ⚠ **`docs/214` §1 那 38 篇里没有它** —— 它是**工程系统**，不是 PL 论文。见 §4.① |
| **把编译期决定印给人看** | ⚠ **Go：`go build -gcflags=-m`**（逃逸分析逐行打印） | ⚠ 同上，不在那 38 篇里。见 §4.③ |
| 编译器后端端到端验证 | CompCert 一系（`docs/214` §1.1 #19） | 「证到哪一层」 |

**所以本盘点的新颖面**：**它不是提案，是"把已发生的事和没做的事分清楚"**。
`docs/214` §1 已经做过这个动作（38 篇，结论"没有一块砖是新的"），本文把它的范围从**机制**扩到**工程系统**
（Wasm / Go 那两条），并提出**三处仍然空白的可研究项**（§4）。**"没检索到 ≠ 没有"** —— 这三处同样如此。

## 3. 未做的（三类，性质**完全不同**）

### 3.1 被**理由**挡着的 —— 不是懒

| 没做 | 挡它的理由（明写） |
|---|---|
| **分代** | 结构体/枚举字段**还装不了指针** ⇒ "老→新"这件写屏障唯一要管的事几乎不存在，加卡表**买不到什么**（`docs/210` §2.4） |
| **搬移 / 压实** | 块内**保守扫**（`alloc` 无类型）⇒ 不知道块里哪个字是指针；保守与搬动**耦合**，只能二选一 |
| **并发 / 增量 / 亚毫秒** | 后端**单线程、无信号** —— 没有并发可言（ZGC / Shenandoah / Go 那一类**连门都没有**） |
| **弱引用 / 终结器** | 语言面没有对应构造 |
| **大对象区 / TLAB / region** | 没有线程，也没有页管理层 |

### 3.2 做得了、但没做

* **L2 的四条边界** —— 根因是"**token 流上认不出作用域**"，真解法是**作用域解析**（`docs/210` §7）。
* L2 只认 `while`/`for` 的**体**；`if` 的体、**函数体本身**都没做（后者与 L1 是同一件事的两个做法）。
* **收集器从没在真实语料上量过** —— `docs/210` §2.4 的所有数字都来自判据里的玩具程序。
* **证明面只有 17.4%（4/23）**，而且**样本太小**：`loment/lib` + `loment/selfhost`（编译器本体在内）
  **一共只有 4 个 `alloc` 站点** —— 它们走 `sys_alloc` / `brk`，不走语言的 `alloc`。
  **不是证明面窄，是被量的东西太少**（`docs/210` §7）。
* `debug` 档下 **L0 / L2 未核**。

### 3.3 白拿的（唯一不付设计代价的一格）

**自举编译器的符号查找是线性扫**（`chk_lookup_slot` / `find_fn`）⇒ 单元越大越贵，实测**超线性**
（130 → 253 → 435 个函数：4.6s → 12.8s → 34.1s）。**今天那条 60s 护栏只剩 ~1% 余量**
（2026-10-10 单独跑实测 **59.33s**，`loment_p8_test::test_m86_selfhost_perf_budget`）。
**加索引**是这条线上唯一"不付设计代价"的改进 —— `docs/210` §7 自己点过名。

## 4. 需要研究的：**三处仍然空白**

每处按同一格式：**是什么 / 最近的前史 / 为什么可能是新的 / 怎么证伪**。

### ① 运行期作为**声明式契约**，而不是"链接进来的东西"

* **是什么**：产物**声明**它需要哪些运行期服务，而**链接器/装载器必须核对**这件事 —— 包括"必须为空"。
  `docs/224` 的 `runtime` 维是这一步的第一格（`no_runtime` 现在是**强制**的），`port` 维（main 上的第四维）
  是第二格（"这个产物通不通着世界"）。
* **最近的前史**：⚠ **WebAssembly 的 import section + capability host functions** —— Wasm **也**
  "声明依赖、宿主必须满足"。**`docs/214` §1 那 38 篇里没有它**（全是 PL/GC 论文；这是工程系统）。
* **为什么可能还是新的**：Wasm 的 import 语义是"**必须被满足**"，**不是"必须不存在"**。
  `no_runtime` 那一半（可证伪的**缺席**）在 Wasm 里**没有对应物**；`gc_ladder` 那种"**组成**"也没有。
* **怎么证伪**：拿一个 Wasm 工具链，问它能不能给出一份"**这个模块里没有 GC/分配组件**"的**可验证声明**。
  给得出 ⇒ 这一处不是新的。

### ② 证明面的**可复现测量** —— 一个数

* **是什么**：在**真实**代码库上，"有多大比例的 `alloc` 能被静态证出收集器"。
* **最近的前史**：**没有人出版过这个数**（可查：Go/Swift 的逃逸分析有**实现**，但**没有一份跨语料的比例测量**）。
* **为什么可能还是新的**：它是**测量**不是机制 —— 而按本仓自己的规矩（`docs/214` §5），**测量本身可以是贡献**。
  它把整个论点（"GC 可以不必要"）变成**一个可证伪的数字**。
* **怎么证伪**：`docs/214` §6.4 与 `docs/213` §6.2 都是它 —— 两篇都写着"**今天就能测**"，**没人跑过**。
  跑出来若是"真实代码 < 5%"，那这条线就是**一个玩具**。

### ③ `κ` 的**可操作诊断** —— 把"为什么证不出来"做成能读的东西

* **是什么**：编译器不只**拒**，还说出**为什么**给不出界、以及**最小的界**是什么
  （"这一行的界给不出来，因为 `x` 经 `y` 流到了 `z`"）。
* **最近的前史**：⚠ **Go `-m`**（逃逸分析逐行打印）。**不在那 38 篇里**。
* **为什么可能还是新的**：Go 那份是**调试输出** —— 不稳定、不进产物、不能当契约。
  做成**稳定的、可复现的、进产物的契约**（错误码 + 修法 + 最小界建议）**没有对应物**。
* **为什么它正对要害**：`docs/214` §5 假设 2 的代价那一格写着"用户要写界与作用域；**曲线陡**"，
  而 §7 **证明**了"自动改写"不可能 ⇒ **剩下的全部价值都在这条诊断上**。
* **怎么证伪**：拿一个被 L0/L1/L2 拒掉、语义上其实可证的函数，看诊断能不能给出**用户照着改就过**的建议。
  给不出 ⇒ 这一处只有形式没有内容。

## 6. 我不主张

1. **不主张这份盘点完备。** 它只覆盖我读过的那些文档与今天摸过的代码；`docs/214` §1 那 38 篇之外
   一定还有我漏掉的先行工作。
2. **不主张 §4 那三处"没人做过"。** 它们的措辞一律是**"没检索到"**。`docs/207` 那次教训（重发现 Baker 1992）
   就是这么来的 —— **动笔之前先按那三组词检索**（`"thermodynamics of garbage collection"`、
   `"reversible garbage collection"`、`garbage collection "rate distortion"`）。
3. **不主张 Loment 的运行期"更安全"。** 它买到的是**可判**（组成可读、缺席可验），不是安全。
4. **不主张性能会追上。** 342 ms vs Java 231 ms 是**今天的**数，且 `docs/212` 的逃生舱三件里
   第一件（LLVM）**还没接**。
5. **不主张这套议程该排在前面。** 排序是用户的事；本文只把**代价**与**证伪方式**写清。
