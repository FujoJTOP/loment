## M97 · 设计决策有据可查 ✅

每个关键决策都有文档编号与理由（docs/140 §10 决策记录 + 各层规范）：

| 决策 | 结论 | 依据 |
|---|---|---|
| 为什么不发明语法 | 取 Rust 严格子集 | 零语料问题；docs/140 §4 |
| 为什么 L0 先行 | 同一接口 N 语言重写 = N+1 问题 | docs/140 §2–3（cfg7/.fuc/FUJR 三处不一致实证） |

| 为什么形式对象强制导出 | 没有强制就没有"同一份对象" | docs/147 §3 |

## M98 · 与 Rust/C/Zig 的对比矩阵 ✅

| 维度 | Rust | C | Zig | Loment |
|---|---|---|---|---|
| 内存安全 | 所有权+生命周期 | 无 | 部分（可选检查） | 移动/借用最小子集，无生命周期 |
| 能力域（语言级） | 无 | 无 | 无 | `capability` + `guard` + 编译期边界 |
| 形式对象导出 | 无 | 无 | 无 | 每编译单元强制导出（Potato v1） |
| 裸机目标 | 有 | 有 | 有 | LLVM IR → freestanding ELF（M32） |
| 与既有代码互操作 | FFI | ABI | C ABI | 转译到 Rust + C ABI 边界 |
| 包管理 | Cargo | 无官方 | 内置 | `lompkg`（本地路径 + 锁） |
| 工具链成熟度 | 高 | 高 | 中 | **低**（自举未完成，无编辑器插件） |
| 标准/生态 | 大 | 大 | 小 | **极小**（本仓库自用） |

诚实结论：Loment 在成熟度上远不及三者；它唯一的结构性差异是**形式对象与能力域进入语言契约**
（对比表里前两行的"无"），其余都是"够用即止"的子集实现。

## M99 · 端到端可复现实验包 ✅

`tools/loment_release.py --check`：在任意机器上重算 98 个工件的 sha256 并比对；
配合 `ci.py --static-only`（9 项门禁）与 `loment_manual --check`，构成一条
"检出 → 一条命令 → 全绿"的复现路径。

复现命令（第三方）：

```
python tools/ci.py --static-only        # 9/9
python tools/loment_release.py --check  # 98/98
python tools/loment_manual.py --check   # 25/25
python tools/loment_p7_test.py          # 8/8（需 QEMU + 已构建内核）
```
