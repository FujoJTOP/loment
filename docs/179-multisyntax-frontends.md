# 179 · 多语法前端：外源语法 → L1

> 状态: **已实现**（2026-09-17）· 工具: `tools/lomt_from.py`（新）+ `tools/potato_from.py`（既有）
> 判据: `loment_multisyntax_test`（11/11，含三条端到端 + 三条语法识别）· 定题: `docs/175` §5 / §6 第 4 条
> 一句话: **一条链把外源源码变成 L1 单元，链上跑通并有判据 —— C 与 Rust 两条都跑通了。**

## 1. 这条链长什么样

```
   任意源语法            表示层              冻结核心的输入        冻结核心
   ──────────           ──────              ──────────────        ────────
   x.c / x.rs  ──potato_from──>  Potato  ──lomt_from──>  x.lomt  ──lomentc──>  ELF
   （既有）                    形式对象      （本文档新增）  （L1）
```

`potato_from` 早就会做前半段（Python / C / Rust → 形式对象，`docs/147` 波 C 的测量臂）。
**缺的是后半段** —— 从形式对象发出 L1 源码。本文档补的就是它。

### 1.1 语言怎么定：后缀优先，内容兜底

`docs/175` §5 那句的关键词是"**非 Loment 源语法的 `.lomt` 文件**" —— 后缀说的是"这是
Loment 的源文件"，而那种文件里装的东西可以是别的语法。所以判语言分两层（`potato_from.resolve_lang`）：

| 层 | 规则 | 为什么这个顺序 |
|---|---|---|
| ① 后缀 | `.c`/`.h` → C，`.rs` → Rust，`.py` → Python | **显式比猜的可靠** —— 一个 `.c` 文件不用去猜 |
| ② 内容 | 后缀不在表里（`.lomt` 就在这一档）时按**特征**判 | 这是那条特性的落地处 |

内容判据**按"谁最专有"排**：`module <名字>` / `capability`·`guard`·`excluded` → Loment；
`def`·`class`·`import` → Python；`fn` → Rust；`#include` 之类预处理 → C；都不到才看
**函数定义的形状**（那一步是启发式，所以放最后）。

**两条边界，都是刻意留的**：

- **认不出就报"请用 `--lang` 指明"，不猜。** 猜错比认不出更坏 —— 一份被猜成 C 的 Loment
  会被转出一堆错的 `extern` 声明。
- **整行写完的 C 只认类型关键字开头那一种**（`int add(int a, int b) { … }`，不是
  `fn f() { … }`）。判据是"开头是不是 C 的类型关键字" —— Loment 从 `fn`/`struct`/`const`
  开头，都不在那张表里，所以两种语言不会在这里撞车。这条有反例判据钉着。

**为什么走表示层而不是直接源到源**：`docs/140` §9 的分工是"语法属于源语言，表示属于
Potato"。两段各自的输出都**可被独立检查**：前半段的产物过 `potato.py`，后半段的产物过
`lomentc.check`。直接写一个 C→Loment 的转译器会把这两道检查合并成一道，也会让"再加一个
源语言"变成再写一个完整转译器；现在加一个语言 = 加一个 `potato_from` 的解析器 + 复用
后半段。

## 2. 只出**接口**，不出带体的实现 —— 以及为什么这不是权宜之计

**Potato 的 schema 里没有函数体。** 表示层记的是"有什么"（结构 / 能力 / 契约 / 布局），
不是"怎么算"（`docs/142` §1、`docs/147`、`docs/178`）。所以这一版的前端产出的是
**声明单元**：类型、常量、能力、函数签名。

函数一律发 `pub extern fn`：

- 它在语义上**就是对的** —— 一份"我把那个模块的接口抄过来了"的文件，本来就是对
  外部符号的 FFI 声明（`docs/173` §2）。
- 它**真的能用**：生成的单元可以直接 `use`，配上外面编好的目标文件就能跑。
  判据里的两条端到端就是这么做的。

**这一版不做的事**（写下来是为了让边界清楚，不是为了少干活）：

- **不带体**。要做到"用 Rust 语法写整个 Loment 程序"，得让表示层携带实现 ——
  那是 Potato 的一次**结构性**扩展（不是加一个字段），本文档不动它。
- **不做名称修饰还原**。C++ 的重载/名字修饰、Rust 的泛型单实例化都不在表示层里；
  库对外暴露的那一面照例是 `extern "C"`（`docs/173` §5 对 C++ 已记同一条）。

## 3. 两条闸门，缺一不可

从"对象里有个函数"到"产物里有条 `pub extern fn`"，中间要过两道：

| 闸门 | 在哪里 | 卡什么 | 不过怎么办 |
|---|---|---|---|
| **签名** | `lomt_from._ffi_ok` | 只收标量与 `ptr` —— 与编译器的 `lomentc._extern_ty_ok` **同一条线**（`docs/173` §3） | 跳过 + 报出 |
| **ABI** | `lomt_from` 读对象里的 `abi` | 只有 `"c"` 能发成 `extern fn` | 跳过 + 报出 |

**ABI 这道闸门是这一次动手才长出来的**，起因是一个真错编风险：

- 原先 `potato_from._RS_FN` 要求 `fn` 紧跟修饰符，于是 `extern "C" fn` 里夹着的
  `extern "C"` 让它**匹配不上** —— 恰恰是**真有 C ABI 的那些函数被整个漏掉**；
- 同时普通 `pub fn` 会被转写出来，如果照发 `extern fn`，就是**拿 Rust ABI 当 C ABI 调**。

所以 ABI 判断放在**源语言那一侧**（只有它知道 `extern "C"` 有没有写），记进对象，
由 `lomt_from` 决定能不能发。

### 3.1 `abi` 是**可选**字段，所以不动契约版本

`abi` 加在函数的条目上（不是顶层），取值 `c` / `rust` / `python`。校验规则：
**省略合法；给了就必须是已知值**。

- **可选**是刻意的：`docs/178` §1 那条教训是"**必填**字段才逼着升版本"。这一个字段不值得
  动契约版本，而且不认识它的消费者**忽略它就是对的**（它们本来也不判 ABI）。
- 但**给了就必须认得**：拼错一个 ABI 名一路静默到链接期，正是这套工具链反复要消灭的东西。

**跨线影响**：`potato.py` 是内核线消费的那一层的校验器，而这是一次**附加**改动 ——
老对象（没有 `abi`）仍然合法，老消费者（不读 `abi`）仍然正确。所以与 `docs/178` 的 v2
升版**不同**，这一次**不需要** compat 线做任何事。

## 4. 少发一个函数是安全的，但**不许沉默**

跳过的函数**不进产物**。这在这里是**安全**的：

- Loment 没有重载，名字是精确的 —— 调用点会得到"未声明的函数"（E002），
  而**不会**静默绑到别的函数上；
- 所以"宁缺勿错"成立。

但**必须报出来**：`lomt_from` 把每条跳过项连原因写到 stderr，`--out` 模式下还在成功行里
带上条数。理由与 `lomelf`、自举驱动一贯的那条一样（`docs/167`）：**静默**才是敌人，
不是"拒绝"。

### 5.1 顺带修掉的一处"报告里静默"

`potato_from._blank()` 一直少一个 `guards` 键，而 v1 要求它是非负整数 ——
于是 **`potato_from` 发出的每一份对象都是非法 v1**。

这件事**一直看得见**（它写在自己的 `validate_errors` 里），但**没有任何测试读那份报告**。
`test_transcribed_objects_are_valid` 就是补的那一格。教训与 `docs/176` §7.3 同源：
一个事实出现在报告里、却没有判据盯着，仍然是静默 —— 只是换了个地方静默。

## 6. 实测：拿一份真的 C 装 `.lomt` 跑一遍

2026-09-17 让一个子 agent 写了一份 C（阶乘 / 辗转相除 / FNV-1a / utoa / popcount，
无 `#include`、无 libc），存成 `.lomt` 后缀，跑整条链。**跑通了**（退出码 230 = Python
独立算的结果），但路上撞出四个坑 —— 全记在这里，因为它们**都不是假想的**，是那份真源码
按出来的。

那份 C 现在**蒸馏成了 `loment_multisyntax_test.C_IN_LOMT` 那份内联夹具**，由
`test_c_in_lomt_end_to_end` 每次跑（刻意保留了下面四坑里的三个形状：Allman `{`、
`unsigned` 单独写、单引号字符字面量）。**不另存一份 demo 目录** —— 那种"当时跑过一次"
的东西没有判据盯着，会烂掉，而判据里这份每次都在跑。

### 6.1 `clang` 会把 `.lomt` 当 linker 输入，**rc=0 且什么都不产出**

C 工具链按**后缀**认语言。把 `mymod.lomt` 喂给 clang，它警告
`'linker' input unused` 然后**退出码 0、不产出目标文件**。你得显式 `-x c`。

**这是本次最阴的一个**: 没有报错、没有非零退出码，只有你去找产物时才发现是空的。
判据里因此在 clang 那一步**先查 `obj.stat().st_size > 0`**，并在注释里点名 `-x c`。

### 6.2 `unsigned` 单独写没有映射 —— 5 个函数丢了 4 个

C 的 `unsigned` 就是 `unsigned int`（标准这么定，不是缩写习惯），而 `C_TYPES` 里只有
`unsigned int`。于是 `unsigned lom_gcd(...)` 的**返回类型"无映射"**被跳过。
补了 `unsigned` / `signed` / `char`（`char` 的符号性在 C 里是实现定义的，x86-64 Linux 上是 i8）。

### 6.3 工具把**转写那一步的报告扔了**

`lomt_from` 只打印 `lomt_from` 自己跳过的项，把 `potato_from` 的 `Report.skipped` 丢了。
于是 6.2 那 4 个被丢的函数**一条 `[skip]` 都没有** —— 看起来像"它只认出 1 个函数"。

**同一类病第二次犯了**（`docs/180` §4.1 是第一次）：事实被记下来了，只是**没有送到人眼前**。
现在两步的跳过项都报。

### 6.4 `char *` 参数过不了 FFI 第 1 阶段那道闸门

`char *` 在类型表里映成 `str`（"指针 + 长度"），而 FFI 第 1 阶段只收标量与 `ptr`
（`docs/173` §3：`str` 不是 C 字符串）。所以**任何收 `char *` 的 C 函数都用不了** ——
`lom_utoa` 就是这样被挡下的（判据要求它**必须被报出来**）。

**这不是 bug，是两条决定的交点**：`char * → str` 那个映射是为 `const char *` 入参定的，
对**出参缓冲**就不合适。现在的绕法是让调用方把缓冲声明成 `unsigned char *`（映成 `ptr`）。
要不要把 `char *` 改成映 `ptr`，是个**表示层的取舍**，不在本文档里单方面定。

### 6.5 顺带的：`loment diag` 原先会让人去改一份**语法正确**的 C

那份 C 第 63 行有个 `'0'` 字符字面量，Loment 词法没有它 —— 于是报的是
`63:25: 非法字符 "'"`，而 `loment diag` 照 E019 的通用建议说"按消息给的行:列**改那一行**"。
照做会把一份好 C 改坏。

现在多一层判断：**有错就闻一下内容**，是 C/Rust/Python 就直说"这个文件不是 Loment 语法"
并给出该走哪条命令。**触发条件是"有错"而不是某条特定消息** —— 第一版只认
`期望 module`，而这份 C 的词法错**先于**解析发生，提示根本不出现（判据因此测的是行为，
不是那条消息）。

**这条提示只在仓库侧，是刻意的。** 编译器本身发的仍然是
`1:1: 期望 module（文件必须以 module 开头），得到 'int'` —— 那句是**真的**，不该改；
而"该走多语法前端"这条建议在这里成立、在**发行包里不成立**（包内没有 `potato_from`，
更不该有 Python）。所以提示放在 `loment diag`（dev-only 工具）里，**不放进核心的诊断**：
核心只该说它自己知道的事。

## 7. 下一步（本文档不做）

1. **带体**：表示层携带实现 —— 这是 Potato 的结构性扩展，做完才谈得上"用 Rust 语法写
   整个 Loment 程序"。
2. **加语言**：现在是"一个语言 = 一个 `potato_from` 解析器 + 复用后半段"。
   Go / Zig / Java 都够了（`docs/173` 的 FFI 那 10 个语言是**链接**面，与这里的前端面不同）。
3. **前端 → 前端**：`docs/175` §5 那句"**或其他 loment 文件**"暗示的可能是更宽的东西
   （比如把 L1 的某个子集重新表达）。**现在不猜**，等有人真要它。
