# 179 · 多语法前端：外源语法 → L1

> 状态: **已实现**（2026-09-17）· 工具: `tools/lomt_from.py`（新）+ `tools/potato_from.py`（既有）
> 判据: `loment_multisyntax_test`（**55/55**：C / Rust / Go / Java / Python **每种十条** + 五条跨语法）
> 定题: `docs/175` §5 / §6 第 4 条
> 一句话: **一条链把外源源码变成 L1 单元 —— 五种语法各十条判据，其中链接型的那几种真编真链真跑。**

## 1. 这条链长什么样

```
   任意源语法            表示层              冻结核心的输入        冻结核心
   ──────────           ──────              ──────────────        ────────
   x.c/.rs/.go  ──potato_from──>  Potato  ──lomt_from──>  x.lomt  ──lomentc──>  ELF
   x.java/.py
   （既有）                    形式对象      （本文档新增）  （L1）
```

`potato_from` 早就会做前半段（Python / C / Rust → 形式对象，`docs/147` 波 C 的测量臂）。
**缺的是后半段** —— 从形式对象发出 L1 源码。本文档补的就是它。

### 1.1 语言怎么定：后缀优先，内容兜底

`docs/175` §5 那句的关键词是"**非 Loment 源语法的 `.lomt` 文件**" —— 后缀说的是"这是
Loment 的源文件"，而那种文件里装的东西可以是别的语法。所以判语言分两层（`potato_from.resolve_lang`）：

| 层 | 规则 | 为什么这个顺序 |
|---|---|---|
| ① 后缀 | `.c`/`.h` → C，`.rs` → Rust，`.go` → Go，`.java` → Java，`.py` → Python | **显式比猜的可靠** —— 一个 `.c` 文件不用去猜 |
| ② 内容 | 后缀不在表里（`.lomt` 就在这一档）时按**特征**判 | 这是那条特性的落地处 |

内容判据**按"谁最专有"排**：`module <名字>` / `capability`·`guard`·`excluded` → Loment；
`def`·`class:`·`import` → Python；`fn` → Rust；`func`·`package main` → Go；
`class {`·`package …;` → Java；`#include` 之类预处理 → C；都不到才看
**函数定义的形状**与**结构体字段的写法**（那两步是启发式，所以放最后）。

**有几组关键字是两种语言共有的**（`class`、`package`、`import`），判据得靠**结尾字符**
或**有没有分号**分开 —— 细节与踩过的坑在 §7.2。**认错的后果是"用错语言的解析器去解"，
而它不会报错**。

**两条边界，都是刻意留的**：

- **认不出就报"请用 `--lang` 指明"，不猜。** 猜错比认不出更坏 —— 一份被猜成 C 的 Loment
  会被转出一堆错的 `extern` 声明。
- **整行写完的 C 只认类型关键字开头那一种**（`int add(int a, int b) { … }`，不是
  `fn f() { … }`）。判据是"开头是不是 C 的类型关键字" —— Loment 从 `fn`/`struct`/`const`
  开头，都不在那张表里，所以两种语言不会在这里撞车。这条有反例判据钉着。

**为什么走表示层而不是直接源到源**：`docs/140` §9 的分工是"语法属于源语言，表示属于
Potato"。两段各自的输出都**可被独立检查**：前半段的产物过 `potato.py`，后半段的产物过
`lomentc.check`。直接写一个 C→Loment 的转译器会把这两道检查合并成一道，也会让"再加一个
源语言"变成再写一个完整转译器；现在加一个语言 = 加一个 `potato_from` 的解析器 + 复用
后半段。

## 2. 只出**接口**，不出带体的实现 —— 以及为什么这不是权宜之计

**Potato 的 schema 里没有函数体。** 表示层记的是"有什么"（结构 / 能力 / 契约 / 布局），
不是"怎么算"（`docs/142` §1、`docs/147`、`docs/178`）。所以这一版的前端产出的是
**声明单元**：类型、常量、能力、函数签名。

函数一律发 `pub extern fn`：

- 它在语义上**就是对的** —— 一份"我把那个模块的接口抄过来了"的文件，本来就是对
  外部符号的 FFI 声明（`docs/173` §2）。
- 它**真的能用**：生成的单元可以直接 `use`，配上外面编好的目标文件就能跑。
  判据里的端到端就是这么做的。

**这一版不做的事**（写下来是为了让边界清楚，不是为了少干活）：

- **不带体**。要做到"用 Rust 语法写整个 Loment 程序"，得让表示层携带实现 ——
  那是 Potato 的一次**结构性**扩展（不是加一个字段），本文档不动它。
- **不做名称修饰还原**。C++ 的重载/名字修饰、Rust 的泛型单实例化都不在表示层里；
  库对外暴露的那一面照例是 `extern "C"`（`docs/173` §5 对 C++ 已记同一条）。

## 3. 两条闸门，缺一不可

从"对象里有个函数"到"产物里有条 `pub extern fn`"，中间要过两道：

| 闸门 | 在哪里 | 卡什么 | 不过怎么办 |
|---|---|---|---|
| **签名** | `lomt_from._ffi_ok` | 只收标量与 `ptr` —— 与编译器的 `lomentc._extern_ty_ok` **同一条线**（`docs/173` §3） | 跳过 + 报出 |
| **ABI** | `lomt_from` 读对象里的 `abi` | 只有 `"c"` 能发成 `extern fn` | 跳过 + 报出 |

**ABI 这道闸门是这一次动手才长出来的**，起因是一个真错编风险：

- 原先 `potato_from._RS_FN` 要求 `fn` 紧跟修饰符，于是 `extern "C" fn` 里夹着的
  `extern "C"` 让它**匹配不上** —— 恰恰是**真有 C ABI 的那些函数被整个漏掉**；
- 同时普通 `pub fn` 会被转写出来，如果照发 `extern fn`，就是**拿 Rust ABI 当 C ABI 调**。

所以 ABI 判断放在**源语言那一侧**（只有它知道 `extern "C"` 有没有写），记进对象，
由 `lomt_from` 决定能不能发。

### 3.1 `abi` 是**可选**字段，所以不动契约版本

`abi` 加在函数的条目上（不是顶层），取值 `c` / `rust` / `python` / `go` / `java`。校验规则：
**省略合法；给了就必须是已知值**。

- **可选**是刻意的：`docs/178` §1 那条教训是"**必填**字段才逼着升版本"。这一个字段不值得
  动契约版本，而且不认识它的消费者**忽略它就是对的**（它们本来也不判 ABI）。
- 但**给了就必须认得**：拼错一个 ABI 名一路静默到链接期，正是这套工具链反复要消灭的东西。

**跨线影响**：`potato.py` 是内核线消费的那一层的校验器，而这是一次**附加**改动 ——
老对象（没有 `abi`）仍然合法，老消费者（不读 `abi`）仍然正确。所以与 `docs/178` 的 v2
升版**不同**，这一次**不需要** compat 线做任何事。

## 4. 少发一个函数是安全的，但**不许沉默**

跳过的函数**不进产物**。这在这里是**安全**的：

- Loment 没有重载，名字是精确的 —— 调用点会得到"未声明的函数"（E002），
  而**不会**静默绑到别的函数上；
- 所以"宁缺勿错"成立。

但**必须报出来**：`lomt_from` 把每条跳过项连原因写到 stderr，`--out` 模式下还在成功行里
带上条数。理由与 `lomelf`、自举驱动一贯的那条一样（`docs/167`）：**静默**才是敌人，
不是"拒绝"。

## 5. 判据：五种语法 × 十条，表驱动

`loment_multisyntax_test` 的规模**本身**有一条判据钉着（少一种语言、少一条判据就红）——
规模是有人明确要过的，就该有东西看着它。

每种语法各有这十条（**同一个函数对每种语言各跑一遍**，因为"每种语言都该同样能过"）：

| # | 判据 | 钉住什么 |
|---|---|---|
| 1 | `_1_types` | 类型映射：标量/指针/字符串 → 我们声明的 Potato 类型 |
| 2 | `_2_aggregate` | 结构体/类 → `types`，字段逐个对 |
| 3 | `_3_signatures` | 形参名、形参类型、返回类型 |
| 4 | `_4_abi` | ABI 归类（`c` 还是那一族自己的约定）—— **整套东西的安全阀** |
| 5 | `_5_skips_reported` | 发不出来的**必须被报出来**（名字 + 原因）。看的是**整条流水线**的跳过项（转写那一步 + 发射那一步），只看后者会让"前一步丢的"看起来像没丢 |
| 6 | `_6_order` | 声明顺序不被重排 |
| 7 | `_7_checkable` | 发出的 L1 过 `lomentc.check` |
| 8 | `_8_detected` | 一份 `.lomt` 装着这门语法 → 认出来 |
| 9 | `_9_deterministic` | 同一份输入 → 同一串字节 |
| 10 | `_10_leg` | §7.1 那三档：链接型真跑 / Go 比名单 / 运行型钉住"一条都不发" |

另有**十条**跨语法的：规模、**关键字撞车**（§7.2）、`abi` 值必须在 schema 里、
诊断提示别误导、发不出来的对象要报错退出、§8 的**语料库**，以及 §8.2 那三条
**"这个具体形态不许再消失"**的夹具（字段级跳过出声、三种声明形态、数组字段不毁对象）。
5×10 + 10 = **60**。

### 5.1 顺带修掉的一处"报告里静默"

`potato_from._blank()` 一直少一个 `guards` 键，而 v1 要求它是非负整数 ——
于是 **`potato_from` 发出的每一份对象都是非法 v1**。

这件事**一直看得见**（它写在自己的 `validate_errors` 里），但**没有任何测试读那份报告**。
`test_transcribed_objects_are_valid` 就是补的那一格。教训与 `docs/176` §7.3 同源：
一个事实出现在报告里、却没有判据盯着，仍然是静默 —— 只是换了个地方静默。

## 6. 实测：拿一份真的 C 装 `.lomt` 跑一遍

2026-09-17 让一个子 agent 写了一份 C（阶乘 / 辗转相除 / FNV-1a / utoa / popcount，
无 `#include`、无 libc），存成 `.lomt` 后缀，跑整条链。**跑通了**（退出码 230 = Python
独立算的结果），但路上撞出四个坑 —— 全记在这里，因为它们**都不是假想的**，是那份真源码
按出来的。

那份 C 现在**蒸馏成了 `loment_multisyntax_test.C_IN_LOMT` 那份内联夹具**，由
`test_c_in_lomt_end_to_end` 每次跑（刻意保留了下面四坑里的三个形状：Allman `{`、
`unsigned` 单独写、单引号字符字面量）。**不另存一份 demo 目录** —— 那种"当时跑过一次"
的东西没有判据盯着，会烂掉，而判据里这份每次都在跑。

### 6.1 `clang` 会把 `.lomt` 当 linker 输入，**rc=0 且什么都不产出**

C 工具链按**后缀**认语言。把 `mymod.lomt` 喂给 clang，它警告
`'linker' input unused` 然后**退出码 0、不产出目标文件**。你得显式 `-x c`。

**这是本次最阴的一个**: 没有报错、没有非零退出码，只有你去找产物时才发现是空的。
判据里因此在 clang 那一步**先查 `obj.stat().st_size > 0`**，并在注释里点名 `-x c`。

### 6.2 `unsigned` 单独写没有映射 —— 5 个函数丢了 4 个

C 的 `unsigned` 就是 `unsigned int`（标准这么定，不是缩写习惯），而 `C_TYPES` 里只有
`unsigned int`。于是 `unsigned lom_gcd(...)` 的**返回类型"无映射"**被跳过。
补了 `unsigned` / `signed` / `char`（`char` 的符号性在 C 里是实现定义的，x86-64 Linux 上是 i8）。

### 6.3 工具把**转写那一步的报告扔了**

`lomt_from` 只打印 `lomt_from` 自己跳过的项，把 `potato_from` 的 `Report.skipped` 丢了。
于是 6.2 那 4 个被丢的函数**一条 `[skip]` 都没有** —— 看起来像"它只认出 1 个函数"。

**同一类病第二次犯了**（`docs/180` §4.1 是第一次）：事实被记下来了，只是**没有送到人眼前**。
现在两步的跳过项都报。

### 6.4 `char *` 参数过不了 FFI 第 1 阶段那道闸门

`char *` 在类型表里映成 `str`（"指针 + 长度"），而 FFI 第 1 阶段只收标量与 `ptr`
（`docs/173` §3：`str` 不是 C 字符串）。所以**任何收 `char *` 的 C 函数都用不了** ——
`lom_utoa` 就是这样被挡下的（判据要求它**必须被报出来**）。

**这不是 bug，是两条决定的交点**：`char * → str` 那个映射是为 `const char *` 入参定的，
对**出参缓冲**就不合适。现在的绕法是让调用方把缓冲声明成 `unsigned char *`（映成 `ptr`）。
要不要把 `char *` 改成映 `ptr`，是个**表示层的取舍**，不在本文档里单方面定。

### 6.5 顺带的：`loment diag` 原先会让人去改一份**语法正确**的 C

那份 C 第 63 行有个 `'0'` 字符字面量，Loment 词法没有它 —— 于是报的是
`63:25: 非法字符 "'"`，而 `loment diag` 照 E019 的通用建议说"按消息给的行:列**改那一行**"。
照做会把一份好 C 改坏。

现在多一层判断：**有错就闻一下内容**，是 C/Rust/Python 就直说"这个文件不是 Loment 语法"
并给出该走哪条命令。**触发条件是"有错"而不是某条特定消息** —— 第一版只认
`期望 module`，而这份 C 的词法错**先于**解析发生，提示根本不出现（判据因此测的是行为，
不是那条消息）。

**这条提示只在仓库侧，是刻意的。** 编译器本身发的仍然是
`1:1: 期望 module（文件必须以 module 开头），得到 'int'` —— 那句是**真的**，不该改；
而"该走多语法前端"这条建议在这里成立、在**发行包里不成立**（包内没有 `potato_from`，
更不该有 Python）。所以提示放在 `loment diag`（dev-only 工具）里，**不放进核心的诊断**：
核心只该说它自己知道的事。

## 7. 五种语法：Go 与 Java 是这一轮加的

原来只有 C / Rust / Python。加 Go 与 Java 之后到五种，判据也从 7 条长到 **55 条
（每种十条）**。加语言本身很快 —— **慢的是它逼出来的那些"原来如此"**，全记在这里。

### 7.1 "腿"分三档，不是两档

原先按"能不能链接"二分（链接型 / 运行型），加 Go 之后**不够用了**：

| 档 | 谁 | 判据第 10 条测什么 |
|---|---|---|
| `link` | C / Rust | 真编目标文件 → 生成接口单元 → L1 调用 → 链 → **跑出 42** |
| `c-abi-subset` | **Go** | **只有 `//export` 过的**才发得出来 —— 钉住"哪些进产物、哪些不进" |
| `runtime` | Java / Python | **一条都不许**发成 `extern fn`（要调它们走进程桥，`docs/173` §4） |

Go 落在中间那一档：**普通 `func` 是 Go 自己的调用约定**（照 C ABI 调就是错编），
而 `//export` 过的**就是** C ABI。所以"Go 能不能当 FFI 声明"这个问题**没有整门语言的答案**，
只有逐个函数的答案 —— 判据因此比的不是"有没有 extern fn"，而是**发出来的名单对不对**。

（Go 那一档没做真链：C ABI 的 Go 目标文件要 `-buildmode=c-archive`，还得有目标平台的 C
交叉工具链。它跑得通那条在 `loment_ffi_test` 的**进程桥**里 —— 那是另一条腿。）

### 7.2 三个"关键字撞车"，都是**静默**的

| 撞的 | 结果 | 分开的判据 |
|---|---|---|
| `class`（Python 与 Java 都有） | 一份 Java 被判成 **python** | Python 的类以 `:` 结尾、Java 的以 `{` 结尾 |
| `package`（Go 与 Java 都有） | 一份 Java 被判成 **go**（实测撞到） | Go 是 `package main`、Java 是 `package a.b;` |
| `import`（Java 与 Python 都有） | —— | Java **不认**裸 `import` 当判据（它太泛），只认 `package …;` 与 `class … {` |

**这三个都不会报错，只会认错** —— 而认错的后果是"用错语言的解析器去解"，抽出来的东西
看着像那么回事。所以 §5 的判据里专门有一条 `test_sniffing_separates_languages_that_share_keywords`
逐组钉住。

### 7.3 两种语言里"声明被静默吞掉"的地方

| 位置 | 症状 | 根因 |
|---|---|---|
| Java `public native int j_native(int a);` | **整个方法消失** | 判成员顺序写成了"以 `;` 结尾 = 字段"，而抽象/接口/native 方法**也以 `;` 结尾** —— 它们掉进字段那一支然后被丢。而丢掉的恰好是**唯一那类与外部实现对接的方法** |
| C `struct P { int a; int b; };` | 只抽到**第一个**字段 | 字段正则锚了行首，一行写完的结构体整行只匹配一次 |
| Rust `pub struct Pt { pub x: i32 }` | 字段**全没** | 没剥 `pub`，于是 `IDENT_RE.match("pub x")` 失败，整个字段被跳过 |
| `loment_diag.foreign_note` | Go/Java 的提示**不出现** | 里面**硬编码了** `("c","rust","python")` —— 加语言时必然漏。现在从 `potato_from.LANGS` 推导 |

四条是同一类病：**一份"支持哪些"的清单被抄了第二遍**（关键字表、成员分类顺序、字段正则、
语言元组）。凡是抄第二遍的，加第五种语言时就会漏 —— 而漏法是**静默**的。

## 8. 语料库：15 个**别人写的**整项目

夹具是**照着我写的规则写的** —— 它撞不出"我没想到的写法"。§6 那份 C 之所以值钱，就是
因为它是照着 C 的习惯写的，而不是照着我的正则写的。

所以这一轮的最后一件事是：让三个**独立的** agent 分别用 **Python / Rust / Java** 语法
各写 **5 个完整项目**（共 15 个），放在

```
loment/examples/multisyntax/<语法>/<NN-名字>/<名字>.lomt
```

文件后缀是 `.lomt` —— 也就是**走内容兜底那条路**，后缀一点忙都帮不上（§1.1）。

**这份语料只在开发树里，不进发布清单**：它要靠 `tools/`（前端 + 判据）才能跑，而
`tools/` 本来就不随包发（`loment_publish.py` 的清单里没有它）。发布清单那条判据因此
一行都不用改 —— `loment/examples/` 的 glob 是**非递归**的，子目录天然是惰性的。
装好工具链的人看不到它，看得见它的人手上有全部工具。

`test_multisyntax_corpus_projects_all_check` 把这 15 个接成一条判据，钉四件事：
**目录名就是它声称的语法**（`detect_lang` 要认对）、对象合法、**产物非空**、过
`lomentc.check`。"产物非空"那条不能省 —— 前三件事在一份"什么都没抽出来"的对象上
**也全都成立**。

### 8.1 它撞出六个"静默丢东西"的口子

**先说清哪几个是语料撞到的、哪几个不是** —— 这三份报告的价值不一样：

| # | 症状 | 根因 | 怎么撞到的 |
|---|---|---|---|
| 1 | `scale: float` / `names: list` 字段**消失**，`[OK]` 那行一个字都不提 | 字段级跳过只进 `Report.field_notes`，而 `lomt_from` **只打印** `skipped`。五个前端**都**在调 `skip_field`，所以这是全体 | **探针** |
| 2 | `LOW = -5` / `MAX: int = 8` / `SHIFT = 1 << 4` **三个常量全没**，汇总行只报"跳过 1 条"（那条是函数） | 常量只收 `ast.Assign` + **裸 `Constant`**：`-5` 是 `UnaryOp`、`MAX: int = 8` 是 `AnnAssign`（**最 Pythonic 的写法**）、`1 << 4` 是 `BinOp` | **探针** |
| 3 | 5 个文件共 **14 个 `pub const` 全没**，一条 `[skip]` 都没有 | `from_rust` 只有 struct/enum/fn **三条循环**，常量那一条**根本不存在** | 语料 |
| 4 | `int[]` / `[u64; 8]` **当结构体字段**，整份对象被判**非法**，`[ERR]` 退出 | 校验器里**有两遍**查同一批字段：前一遍用 `_type_ok`（认复合类型），后一遍用**裸字符串相等**（`fd["type"] not in declared`）。后一遍只可能误报，且它的 `declared` **还不含 enums** | **探针**（Java 与 Rust 各自独立撞到） |
| 5 | `public void set_base(int v)` 报"返回类型 `'void'` 无映射" | `JAVA_TYPES` 里**没有 `void`** —— 而 C 那边一直映的是 `"()"`。**提示本身是错的**：`void` 完全表示得了 | 语料 |
| 6 | `import java.util.List;` 让整份文件被判成 **python**，然后**甩出一坨 traceback** | Python 的 `import` 判据排在 Java 前面，而它匹配了 `import java.util.List;`。`ast.parse` 随后在 `package a.b;` 上抛 `SyntaxError` | **探针** |

**只有 3 和 5 是语料撞到的。** 另外四条是三个 agent 在**写完项目之后**用 `python -c`
探针试出来的 —— 它们写那 15 个项目时**回避了**这些写法（"数组字段会让整份对象非法，
那就改用 `*mut u64`"；"import 会让文件被判成 python，那就不写 import"）。

这件事本身比那六条更值得记：**语料的价值取决于写它的人当时知不知道哪里会塌**。
它们撞出 #3/#5 是因为那两处**没法回避**（Rust 项目必然有 `pub const`；Java 必然有
setter）；能回避的都被绕过去了。所以下面两件事都要做：

1. **把回避掉的写法放回语料**（§8.2）—— 否则这份语料只是"另一套夹具"，
   而它凭什么比夹具强，就在"不受控"这三个字上；
2. **给那四处各加一条夹具判据** —— 语料测"能不能过"，夹具测"**这个具体形态**
   会不会又塌"。两者不是一回事，缺一个就有一半的口子没人看着。

第 4 条最值得说：**同一件事被写了两遍判据**，而两遍各自漂移 —— 一遍学会了复合类型，
另一遍没有。这正是 §7.3 那条"同一份清单抄第二遍"的变体，只不过抄的是**判据**。
修法是**删掉后一遍**（它只可能是前一遍的子集）：不是补一个特例让它俩一致，
那样下次还会漂。

第 6 条暴露了第二层：**认错语言之后抛的是裸 traceback**。识别错了不丢人，
认错还甩一坨 Python 内部栈才丢人 —— 现在是一条干净的
`[ERR] 按 python 解析失败: 第 1 行 invalid syntax` 加一句"这份源码不像是 python"。

### 8.2 回避掉的写法放回语料

| 文件 | 放回了什么 | 对应 |
|---|---|---|
| `python/02-fixedpoint` | `FX_FRAC_BITS: int = 16`（带注解）、`FX_MIN_RAW = -(1 << 31)`（负号 + 移位）、`FX_QUARTER_ULP = 1 << 14`（纯字面量表达式） | #2 |
| `rust/03-bitmap` | 新增 `pub struct WordTable { n: u32, w: [u64; 8] }` —— **字段**是定长数组 | #4 |
| `java/02-frames` | 补一行 `import java.util.List;` | #6 |

都是这些语言里最平常的写法。#1（字段级跳过不出声）没进语料 —— 它测的是**工具的
输出**，而语料只测"能不能过"；它在 `test_field_level_drops_are_reported_too` 里，
走的是 `lomt_from.main` 的输出。

### 8.3 修完之后的数

15 个项目全部**认对 / 合法 / 非空 / 过检**，零例外：

| 语法 | 项目 | 常量 | 枚举 | 类型 | 函数 |
|---|---|---|---|---|---|
| Python | 5 | 39 | 0 | 17 | 51 |
| Rust | 5 | 14 | 6 | 13 | 48 |
| Java | 5 | 54 | 6 | 17 | 56 |

常量那三格是这次修出来的：同口径下 Python 是 **36 → 39**（丢 3 个）、Rust 是
**0 → 14**（14 个全丢）。Rust 那个 0 是这条链上最干净的一个证据：**整类声明
一条循环都没写**，而报告上一个字都不提。

## 9. 下一步（本文档不做）

1. **带体**：表示层携带实现 —— 这是 Potato 的结构性扩展，做完才谈得上"用 Rust 语法写
   整个 Loment 程序"。
2. **加语言**：现在是"一个语言 = 一个 `potato_from` 解析器 + 复用后半段"。
   Go / Zig / Java 都够了（`docs/173` 的 FFI 那 10 个语言是**链接**面，与这里的前端面不同）。
3. **前端 → 前端**：`docs/175` §5 那句"**或其他 loment 文件**"暗示的可能是更宽的东西
   （比如把 L1 的某个子集重新表达）。**现在不猜**，等有人真要它。
4. **语料库自己长大**：现在是 3 种语法 × 5 个项目。加语言时**照着 §8.1 那张表看一遍**
   —— 那六条都是「这份东西在别的语言里很平常、而我这里没有对应」。加一门语言时
   最先要问的就是这个问题。
5. **类与类之间的前向引用**（Java 里 A 引用后声明的 B）：现在不通，会**出声**地少映射。
   修它要预扫一遍类型名，而预扫会把"整类被丢掉"的名字也放进去 —— 见 `from_java` 里
   那段注释说的两难。真要修就先解决"被丢掉的类型"这件事。
