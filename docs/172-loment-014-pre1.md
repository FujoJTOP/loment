> 版本 `0.1.4-pre1` · 显示名 `Loment 0.1.4 Pre1` · 对外 tag `v0.1.4-pre1`
> 上一版 `0.1.4-alpha2.3`（tag `v0.1.4-alpha2.3`）
> 唯一真源：`tools/loment_release.py` 的 `RELEASE` / `RELEASE_NAME`（自举镜像在 `loment/tools/lomrel.lomt`）
> 上游：`docs/143`（语言规范 §2.3）· `docs/158`（冻结面）· `docs/169`（CLI §3b）· `docs/162`（发行包 §2b）

## 0. 一句话

**这一版把语言的两个面交给使用者**：源码叫什么后缀、`loment` 还能有哪些命令，都不再由
Loment 官方说了算。alpha 系列到此为止 —— pre 之后语言面不再改。

## 1. 两个开口

### 1.1 后缀不再属于语言

原先"L1 源必须是 `.lomt`"是**装载器写死的**。现在：

- **只有 `.lom` 是特殊的** —— 它是 L0 接口契约，`use "x.lom"` 走 L0 复用那条路。**别的任何
  后缀都是 L1 源**，`.lomt` 只是习惯。
- 名字形式 `use <名字>` 找哪个后缀，由**项目根**（或工具链旁边）的 `loment.conf` 定：

  ```
  // <项目根>/loment.conf —— 与 lompi.conf / pkg.lomp 同一种形状
  module conf

  pub fn source_ext() -> str { return ".foo"; }
  ```

- **只管名字形式**：路径形式 `use "area.foo"` 自己带后缀，配置管不着。
- **默认始终兜底**：配了 `.foo`，候选顺序是 `.foo` 再 `.lomt` —— 仓库自带模块与随包 store
  全是 `.lomt`，少了这一步，换个后缀等于把标准库弄丢。
- **读不出来就当没配**（没文件 / 没这个标签 / 值不以 `.` 开头 / 值里带转义）。

规范在 `docs/143` §2.3（可判定的判定表）；**为什么"两个实现必须同源"**记在 `docs/158` §5。

### 1.2 自定义 `loment` 命令

像 `git`：`loment foo ...` 先看 `PATH` 上有没有 `loment-foo`，有就**原样转发**（`shift` 掉名字、
后面的参数一个不动、退出码原样带出）；没有才交回官方 CLI。**官方命令优先**，所以
`loment-version` 顶不掉 `loment version`；**没有注册表** —— 约定就是文件名。

细节与三条设计取舍在 `docs/169` §3b。

## 2. 顺带修掉的三处（都在装载器）

都与上面那条"两个实现必须同源"同源，都是**静默错编**那一类：

1. **名字形式的搜索层**（E018）：原先只认**仓库相对**的四个根，所以装在用户机器上
   （没有仓库）时 `use std` 一个都找不到。现在是三层：① `<项目根>/deps/<名字>/` ② 工具链自带
   `<工具目录>/../share/lompi/store/<名字>/<版本>/` ③ 内置四根。**只有第 ③ 层要求唯一** ——
   前两层是搜索路径（像 `PYTHONPATH`），先命中先用。
2. **路径形式的基准**：参考实现是「仓根 → 导入文件所在目录」，自举镜只按 CWD。仓库内自测
   看不出（CWD == 仓根），换成 `deps/<包>/` 就分叉（`deps/std/std.lomt` 里的 `use "mem.lomt"`
   会去找 `<CWD>/mem.lomt`）。现在两边同序。
3. **单文件 `use` 条数**：自举镜的暂存区按 8 条布局，**第 9 条起静默丢掉**，而参考实现无上限 ——
   同一份源码两个实现给出**不同的单元**。现在两边都是 **300**，超过报 **E020**。

`loment.conf` 的读法本身也走过一次同样的弯路：参考实现最初用完整 parser 读它（于是要求
`module` 头），自举镜用词法器扫标签（`lompi` 读 `lompi.conf` 的做法，不要求）。改成**两边都
走词法器**，并把转义值在两边一起拒掉 —— 那是唯一还会分叉的口子。追这条的记录在 `docs/158` §5。

## 3. 兼容性（相对 `0.1.4-alpha2.3`）

- **既有 `.lomt` 程序零改动**：默认后缀没变，`use` 的两种写法照旧。仓库自己的语料
  54/54 仍**逐字节一致**（参考实现 ↔ 自举驱动）。
- **新增能力是纯增量**：不写 `loment.conf` 就还是 `.lomt`；不往 `PATH` 放 `loment-*`
  就还是那 38 条官方命令。
- **诊断码 E020 是新增的**（E001–E020）—— 码只增不改，按码匹配的 CI 不受影响。
- **自举种子变了**：`loment/build/selfhost_driver.ll` —— 装载器改了，IR 跟着变。
  从种子起头重建工具链的人要换新种子。
- **发行包/源码包文件名随版本变**：`loment-0.1.4-pre1-*`（见 `docs/162`）。

## 4. 判据

```bash
python tools/lomentc_test.py     # 106/106 (含 loment.conf 的三条: 生效/坏配置退回/兜底)
python tools/loment_p8_test.py   # 16/16: 语料 54/54 逐字节 + 定点 + 驱动闸门
python tools/loment_cli_test.py  # 32/32 (含自定义命令的两条)
python tools/ci.py --static-only
```

驱动闸门里新增的两条**是这一版的要害**：一个真配了 `.foo` 的工程（名字形式 + 包内路径形式）
跑**自举驱动**与跑**参考实现**，要求 IR **逐字节一致**；另加一条"配坏的后缀两边都当没配"。
只对一边测等于只测了一半 —— 自举镜多试一个后缀、参考实现少试一个，都是"装得少一点"的
静默错误。

## 5. 不主张

- **`.lomt` 之外的语料没有进那 54 个**：仓库自己的语料仍全是 `.lomt`，自定义后缀只有那两条
  闸门用例在盯。
- **自定义命令是"启动器行为"，不是语言行为**：`loment` 之外的入口（比如直接调
  `loment-cli`）看不见 `loment-*`。
- **后缀仍然不能改变 `.lom` 的语义**：L0 与 L1 的分流按**后缀名**判，不按内容。
- 其余见 `docs/160 §2` 的不主张清单（未外部审计、aarch64 未执行、驱动器无 parser…）。
