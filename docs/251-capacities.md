# 251 · 编译器的固定容量：把它变成一个数

> 状态: **已落地**（2026-10-16）· 上游: `FujoJTOP/loment#345`、`#343`、`#370`
> 一句话: `#345` 说"能定这个案的是一个数 —— 编译器有多少个固定容量、几个越界时说得上话"；
> 这一篇把那个数**算出来**，并让它**不会漂**。

---

## 0. 为什么这件事值得单独做

`#345` 把三件事摆在一起，环就闭合了：

1. 头条承诺是"一份程序可以被证明**不带运行期**"（`no_runtime` 是默认档，会把运行期拖进来的
   构造在编译期就点名拒）；
2. 编译器自己就是这样一份程序 —— 一个 freestanding 产物；
3. 于是编译器**不能用运行期**，于是**没有一个真堆**，于是它自己在 `brk` 上写了 19 处
   `sys_alloc`，而且**大部分状态仍然住在定长缓冲里** —— 缓冲越界时**没有恢复点**，
   进程直接死，用户什么也看不到（`#343` 那一族）。

`#345` 自己把话收得很紧：**它不是**"给编译器加个 GC"，也不是"（a）–（d）哪一条是对的"。
它要的是那个数 —— 而那个数**哪里都没记**。这一篇给它。

---

## 1. 口径（机械的，不靠记性）

`tools/loment_caps.py` 扫 `loment/selfhost/` 与 `loment/tools/` 两棵树（**排除**生成的
数据文件 `surface_data.lomt` / `win_shim_data.lomt` —— 它们的常量是表项，不是"编译器自己
有多少内存"），对每个 `const NAME: u32 = <数字>` 判两件事：

| 判什么 | 怎么判（写在代码里，不是这里） |
|---|---|
| **它是不是容量** | 它得**被当上界或尺寸**用过：出现在一条**序关系**比较里（`>` `>=` `<` `<=`，`==`/`!=` 不算 —— 那是码值），**或者**被乘在别的东西上／本身就是一次分配的长度 |
| **越界时说不说话** | 那处守卫**往后 8 行**里有没有一句说得出话的东西：`fail(`、`sym_pub(`、`err_`、或带 `E0`／`太大`／`非法`／`超`／`越界` 的字面量 |

**这份盘点是算出来的，所以它不会漂**：改一个容量、加一条检查，下一轮的行数就变。判据
`loment_caps_test` 把两个数与**那份沉默名单**逐名钉住（名单本身也是从工具输出生成的，
不手抄 —— 手抄的清单第一次改代码就漂，而这份的全部价值就是它不漂）。

**说清楚它的噪声**：口径是"上界**或**尺寸"，所以会有几处**码值区间**混进来
（`K_INT_MAX = 8`、`TY_K_NAMED = 2` 那类：它们以区间上界的样子出现，其实是编码）。
反过来，正因为"尺寸"那一路也在口径里，`SLOT`（只做步长、从没被比较过）才进得来。
**数的是同一个口径下的东西**；要拿它比大小，就比同一口径下的两次。

---

## 2. 数（2026-10-16，`tools/loment_caps.py`）

```
容量 226 处；有话 56，沉默 170
```

**沉默的那 170 处里最出名的几个**（都是真的会写穿的）：

| 处 | 值 | 说明 |
|---|---|---|
| `loment/selfhost/driver.lomt:34` | `SLOT = 524288` | 每层源文件槽 —— **2026-10-11 那次段错误就是它**（`codegen.lomt` 长到 262858 时只越界 714） |
| `codegen.lomt:35` | `CG_MAXFN = 4600` | 函数表 |
| `codegen.lomt:36` | `CG_MAXENUM = 320` | 枚举表 |
| `driver.lomt:703` | `DIR_CAP = 1024` | 目录项 |
| `driver.lomt:810` | `SUBP_CAP = 1472` | 子路径 |
| `driver.lomt:1239` | `EXT_CAP = 256` | 扩展名 |
| `interp.lomt:38` | `TOK_CAP = 600` | 解释器词法缓冲 |

**对照的那一半**：`UNIT_CAP`、`TOKS_CAP`（`driver.lomt`）、`TB_SLOT_MAX`（`lomelf.lomt`）
是"有话"的 —— 它们越界时会打印一句 `fujoc-s: 单元太大: …` 然后退出。同一面墙，
**有的分支会说话、有的不会**，`#345` 说的就是这个形状。

⇒ `#345` 的 (a) ——"给每一处固定容量配一条明确的失败路径"—— 的**工作量就是那 170 处**
（其中 144 个不同的名字；同一个名字可能在几处用到）。它不是"顺手补几条"，是一个可数的清单。

---

## 3. 这不是"（a）就是答案"

`#345` 把 (a) 定为**地板**而不是策略 —— 它只是让墙开口说话，**不抬高天花板**（编译器仍要
~4 MiB 才能编一个 190 KiB 的单元）。这一篇只交付那个数，不替 `#345` 选 (a)–(d)。
选的时候，这一篇给出的两个数是分母。

---

## 4. 判据

| 判什么 | 怎么判 | 状态 |
|---|---|---|
| **两个数不漂** | 容量条数 = **226**、"沉默"条数 = **170**；任一处变（新加一个容量、加一条检查）就红 | `loment_caps_test::test_the_two_numbers_are_pinned` ✅ |
| **名单不漂** | 沉默的那 **144** 个名字**逐名**钉住：多出任何一个 ⇒"它越界时不报错，只会写穿"；少任何一个 ⇒"名单比代码旧" | `::test_the_silent_list_cannot_drift` ✅ |
| **口径是机械的** | 同一棵树扫两遍结果相同；每一行的文件都落在那两棵树里、且不是被排除的生成数据文件 | `::test_the_scan_is_confined_and_deterministic` ✅ |

**可证伪**（2026-10-16 实测）：把口径里"会说话"那一组清空（等价于所有失败路径都没了），
前两条当场变红 —— 所以它们不是空判据。
