# 110 · W36 — 论文三立项：Potato（土豆）——FujoOS 的平台语言

> 状态: **立项（命名确认 2025-06）** · 定位: 第三篇论文的对象语言
> 一句话: **Potato 是一门像 .NET 一样的平台语言（语言 + 运行时 + 基类库 + 编译器），
> 目标 = 加快 FujoOS 系统开发**——第一门"为 FujoOS 而生"的语言。
> 与论文一（FUAI 安全信封）/ 论文二（FUFORALL 兼容论）并列，构成三论文序列。

## 1. 定位（.NET 对标）

| .NET 概念 | Potato 对应 | 说明 |
|---|---|---|
| C# / F# 等语言 | **Potato**（一等语言） | 语法/语义由 FujoOS 定义，不为任何外部生态妥协 |
| IL（中间语言） | **Potato IR** | 编译器输出目标，可 JIT/携载 |
| CLR（公共语言运行时） | **Potato Runtime** | 运行在 FujoOS 上的运行时（内存/异常/线程/互操作） |
| FCL/BCL（基类库） | **Potato Base Lib** | 为 FujoOS 服务/设备建模的系统库 |
| Roslyn（编译器） | **Potato 编译器** | 自托管路线候选（参考 m128/m140 tcc 自举链） |

## 2. 动机（为什么是第三篇）

- FujoOS 现有系统代码**全部使用外部语言**（内核 Rust no_std · 样本 C · 散件工厂 C 子集 ·
  工具链脚本）——系统自身的"语言生态"是空的。
- 兼容层（论文二）声明了"只翻译有等价语义的对象"；Potato 提供**最早的原生语义**：
  一切 FujoOS 服务对 Potato 是一等公民，不再经外部 ABI 折衷。
- 加快系统开发：内核组件/驱动/工具链/散件工厂统一到一门语言，减少语言上下文切换；
  语言特性为 FujoOS 域设计（能力/域、帧协议、无中断环境抽象等）。

## 3. 与现有资产的接口（先例链）

| 资产 | 关系 |
|---|---|
| 散件工厂（docs/106） | Potato 最早的**前端替代**候选：header-only C 子集 → Potato 编译目标（tcc 链可复用） |
| fujocc（LLVM/clang, `x86_64-unknown-fujo`） | 早期后端的过渡宿主（Potato → IR → fujocc 目标） |
| 内核 Rust 链 | 内核本体不动；Potato 初版 = 用户态/工具链语言 |
| .run / FUJR | Potato 程序的原生打包/装载格式 |
| 论文二 BOX-BRIDGE | Potato 供应商（LEGO 路径）：散件工厂语义转录 + Potato = 原生组装的一等公民 |

## 4. 论文三结构预览（证据先行，与论文一/二同款纪律）

1. **最小实现**：Potato 编译器前端（语言子集）→ Potato IR → 后端（fujocc/自产 tcc）；
2. **运行时**：Potato Runtime 在 FujoOS 上（内存模型/异常 → 域映射）；
3. **测量**：与 C/Rust 同任务的开发效率/代码量对照（B 类任务）；
4. **自举**：Potato 编译器自编译（参考 B-1 tcc 自举链的成败经验）；
5. **论文主句候选**：*一个为单系统操作系统而生的平台语言；它的规格即系统的接口公理*。
