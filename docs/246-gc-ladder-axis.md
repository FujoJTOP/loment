# 246 · 梯子挂错了轴：GC 的策略该按"**知道了什么**"分，不该按"**证明了多强**"分

> 状态: **研究稿 + 第一刀已落地**（2026-10-15）。起点是一次测量（`tools/loment_gc_surface.py`），
> 不是一次设计：**63 份语料、23 个 `alloc` 站点 → L0=3 · L1=1 · L2=0 · L3=19**（证明面 17.4%），
> 而 **L2 在整个语料里一次都没开过**。
> 本文问的**不是**"怎么把证明写宽一点"（那是 `docs/210` §2 那条线 —— 它已经把规则从
> `load8/store8` 放宽到跨函数 deref-only 了一次，证明面没怎么动），
> 而是 **这四层为什么会长成"三层寄生在一个收集器上"**，以及**该挂到哪根轴上**。
> 结论先行：**轴错了**。today 的梯子按"**证明有多强**"排（`不外逃` 是总闸，不满足就整格落 L3），
> 而机制们关心的从来不是同一件事 —— **尺寸、寿命、访问形状是三条独立的事实**。
> 挂到"**知道了什么**"这根轴上，三层才真的有事可干。§5 是本文附带落地的第一刀，§6 是它的靶子。

## 0. 一句话

> **今天不是"四个策略挑一个"，是"一个收集器 + 17% 的折扣"** ——
> 而且那 17% 还得**先接受收集器**才拿得到：三层静态证明只存在于 `gc_auto_alpha` **档内部**。

## 1. 量出来的现状

`tools/loment_gc_surface.py`（`docs/210` §7 的那把尺子）在今天的树上：

| | L0 | L1 | L2 | L3 | total | 证明面 |
|---|---|---|---|---|---|---|
| 63 份（examples + lib + selfhost，跳过 2 份已表态的） | 3 | 1 | **0** | **19** | 23 | **4/23 = 17.4%** |

逐站点读那些 L3 的"为什么"（19 个），最扎眼的是**同一段代码重复 3 次**：

```rust
fn write_dec(fd: u64, v: u32) {
    let buf: ptr = alloc(12);              // 字面量尺寸、从不外逃、原地理用
    ...
    syscall4(1, fd, buf as u64, n as u64); // ← 唯一的"罪证"
}
```

`loment/examples/all_loment.lomt:32`、`native_match_full.lomt:43`、`tour.lomt:55` —— 这三个站点
**一字不差**，都因为"把指针 `as u64` 交给 `write(2)`"而落 L3 ✗。同一句 cast 在
`loment/examples/bootprobe.lomt:11`（390 字节的缓冲，先交给 `uname(63)` 再交给 `write(1)`）
那儿是**另一种形状**，死因相同 —— 于是"因为一次 cast 落 L3"的站点一共是 **4** 个。

**反面也在这份语料里**：`loment/examples/selfcheck.lomt:26` 的 `alloc(8)` 同样 `as u64` 交出去，
但收它的是 **`seccomp(317)`** —— 白名单（§5.3）**正确地拒了**它。这一格是后面那张表**真的在干活**
的证据：它没有把"cast 进系统调用"一把放宽，而是**按号**放。

其余 15 个分成三类（同样是读代码读出来的，不是统计）：

* **形状**（2 个）：`store8(alloc(1), 0, t as u8)`（分配**没绑到名字**）、
  `let p: ptr = int_to_ptr(ptr_to_int(alloc(8)))`（结果被**恒等往返**包了一层）——
  两条都与"这块活多久"无关，纯粹是**候选形状**太窄；
* **交给用户函数 / 动态尺寸**（最大的簇，`lumtui_demo.lomt` 的 7 个）：
  尺寸是调用表达式或名字（`alloc(lumtui_arena_bytes())`、`alloc(cap)`、`alloc(W * H * 4)`），
  指针随后交给 `build(d)` / `dump(fb, w, h)`；
* **真外逃**（1 个）：`loment/selfhost/ir_builtin.lomt:8` 的 `return alloc(n)` ——
  **这一个确实该是 L3 的活**。

### 1.1 产物层不是病灶（先排除掉）

拿一份**全是 L0 站点**的程序试（`choose gc_auto_alpha`）：`@__loment_heap`、`__loment_alloc`、
`markp`、`collect`、`minor`、写屏障 —— **一个都不发** ✓。堆那一整套是**按需要**发的
（`_heap_needed` 预扫描，`tools/lomentc.py:7983`），不是按档位发的 ✓。

唯一残留是"**有根没堆**"：根表跟 `gc_any` 走（`tools/lomentc.py:8196`），
于是全静态的 alpha 单元仍会发一张根表和它的 push/pop。这笔账 `docs/210` §7 已记着，
与本文的结论无关（它是"多发了几十行 IR"，不是"策略少"）。

## 2. 三条病灶

**① 三层静态证明寄生在 alpha 档里。** `tools/lomentc.py:6156`：

```python
if m.chooses.get("gc") != "gc_auto_alpha":
    continue
```

L0/L1/L2 的分析**只在这一档跑**。默认档 `gc_manual` 一条都不跑（`docs/210` §2.1 的表自己
写着 L0 = `—`），而 alpha 档里它们也只捞到 17%。也就是说：**"提升到栈"和"背一个收集器"
是同一条 `choose` 决定的** —— 你要前者，必须连 arena + 精确根 + 收集器 + 写屏障一起收下。
这是"堆叠在 L3"最硬的那一面：不是 L3 收得多，是**上面三层寄生在 L3 的档位里**。

**② L3 里只有一种机制。** mark-sweep（+ 自适应触发 + 分代）。所谓"自适应"调的是
**什么时候收**（阈值跟活集走、空间触发），不是**用什么收**。`docs/175` §3.4 那句
"算法策略池"在 L3 内部一次都没兑现 —— L3 是一个策略，只是它的**参数**在动。

**③ 门是"语法形状"，不是"寿命"。** 三层共享 `_ptr_only_uses`（`docs/210` §2.2/§2.5）：
名字的每一处出现，要么是声明、要么是 `load8`/`store8`/`atomic_add`（或经全局不动点证成
"透明被调"的函数）的**整个第一个实参**。它否掉的是 **token 位置** ——
一次 `as u64`、没绑名字、多传了一个实参、`free` 过 —— 而不是"这块活多久"。
**17% 是形状的代价，不是结构的必然**：4/19 就死在一次 cast 上。

## 3. 要写死的不可能

> **没有一种"token 流上的语法谓词"能同时做到"可靠"与"关于寿命精确"。**

寿命（这块活到哪一行）与规模（一圈循环要几块）**都不是 token 位置的函数** ——
别名、动态尺寸、调用返回的指针、系统调用会不会留存 —— 这些在 token 序列上不可见。
于是任何语法判据只有两条路：**拒**（落 L3）或**错**（不安全）。**没有第三种。**

**推论（本文最硬的一句）**：**"证明面 17%" 不是语料太刁，是判据的表示带来的上界。**
表示不变，把规则写宽只会走上"错"的那条路 —— 这正是 §5 里那一刀必须**带一个语言级断言**
才敢落的原因。

## 4. 可拿掉的假设

**(i) "策略由档位关键字决定"。** 拿掉它 = 让机制成为**站点的属性**，档位只声明"证明不了的
怎么办"（而不是"能不能证明"）。**代价明写**：`gc_manual` 有一条硬承诺
（`docs/175` §3.4 五条之一）—— "**一行都不动，不许改变任何现有程序**"，
而 L0 把对象从堆挪到栈会**改变产物字节**。所以这一条要么给个新档位，要么改那条承诺，
**不能偷偷做**。

**(ii) "分析必须长在 token 流上"。** 现状的理由写在代码里（`_l0_promotable` 的 docstring）：
自举侧**没有 AST**，而 AST 走法有两个自举侧补不平的洞（`for x in …` 的 `x`、
`match P::V(x)` 里的名字**不在表达式位置** —— AST 递归看不见它们 ⇒ 两边会数出不同的格子）。
拿掉它等价于：**让两份实现共享一个 IR/字节码级的表示**。那条线**已经在手里**——
**LVM**（`docs/243`）。所以 (ii) 不是一个"要不要"的问题，是**依赖顺序**：LVM 先，更强的分析后。

## 5. 挂到"知道了什么"这根轴上（第一刀）

### 5.1 表：事实 × 机制

今天一层是"一票否决"（不外逃是总闸，否则整格落 L3）✗。而机制们要的**不是同一条事实**：

| 知道什么 | 该买什么机制 | 今天为什么买不到 |
|---|---|---|
| **尺寸是常量** | 静态区域 / 预留着落（**即使指针外逃**） | "不外逃"是总闸 ⇒ 外逃就被判死 |
| **寿命可数**（最后一次用处） | 栈 / 作用域末尾归还（今天的 L0/L1） | ✓ 有，但被形状刷掉一大堆 |
| **访问只经 8 字节字** | 精确槽（今天的块内精确 `docs/210` §2.9） | ✓ 有，同一条形状门 |
| **都不知道** | 收集器（今天的 L3） | ✓ 有 |

于是"让 L0–L2 有事可干"**不是把规则写宽**，而是**把总闸拆成三条门**：
哪条事实成立，就买那条事实能买到的机制。

### 5.2 第一刀（**参考侧实现过，未落地**）：**"不外逃"该按参数位，不该按"首参"**

三层的证明走的是跨函数 deref-only 那一套（`docs/210` §2.2 末）：一个函数的**首参**
在它体内只当"安全被调的整个第一个实参"透过 ⇒ 调它等于调内建 ⇒ 把指针传给它的**首参**
不算外逃。**这条规则把"不逃"挂在了"第一个参数"上，而不是挂在"这个参数本身有没有外流"上** ——
于是 `fn wr(fd: u64, p: ptr, n: u32)` 这种把指针放在**第二位**的辅助函数（`lumtui_demo` 里
整整一族）一句都用不上，尽管 `p` 在体内同样只被 `store8`/`load8` 透过。

改法：把摘要从"这个函数安不安全"细化成"**这个函数的第 k 个参数是不是只被解引用透过**"，
调用点按**实参所在的位**查。`docs/210` §7 自己把"**首参之外**的实参"列为真缺口 ——
这一刀就是把那个缺口关上。**它不需要任何新假设**（与原来那条规则是同一个证明，
只是不再把结论钉死在 k=0）。

**但它没有落地，而理由是量出来的**：参考侧实现完之后，语料上的证明面 **4/23 → 4/23，一个都没动**
（§6 第一节）。而它要两份实现一起改（自举侧的安全表得带上"位置掩码"），那是它自己的一次改动 ——
拿一笔实测为零、成本不为零的改动去挤这一版，不划算。**空结果记在这儿，刀留着**：
等真有一份"调用点在参数位上传指针"的语料（`lumtui_demo` 的 `wr(fd, p, n)` 那类就是），
它才付得起自举侧那一半。

### 5.3 第二刀（**本文附带落地**；要先做一条语言级断言）：把"不外逃"再拆成"**不外逃到会留住它的地方**"

今天 `buf as u64` 交给 `write(2)` 同样被判死 —— 而那一次 cast 之后指针进了**系统调用**。
改法：**系统调用的实参是"借"** —— 按**系统调用号**白名单（那些"调用期间拷完/写完就走、
不留存用户指针"的）。

**这是一条语言级断言，不是一次放宽**：它的内容是"这些 syscall 不把用户指针存进内核
数据结构"，因此它

* 写在 LANG 侧、**可审**（白名单是一张表，读得出来）；
* **可以缩**（拿不准的一个都不放进去）；
* **错了就是内存不安全**（栈上的缓冲被留存 ⇒ 悬垂）—— 所以它必须**窄**，
  而且必须和 `standard/LLS.md` 的开关一起看（它是"Loment 知道内核的什么"这一类的第一条）。

买到的：`write`/`read` 那一类站点从 L3 进 **L1**（最后一次用处之后还掉，尺寸都不必是常量）。

顺带两处**形状**放宽（与寿命无关，纯属候选形状太窄）：`store8(alloc(n), …)`（分配没绑名字）、
`ptr_to_int` 与 `int_to_ptr` 的**恒等往返**。

## 6. 可测靶子（每一格都当场能复核）

1. **证明面**：同一把尺子（`tools/loment_gc_surface.py`）**4/23 → ?**
   **第一刀落地后的实测（2026-10-15）：4/23 → 4/23，一个都没动。**
   这条空结果**本身是一格情报**：语料里的外逃**不是参数位的问题** ——
   `lumtui_demo` 那一簇的外逃发生在**被调函数体内**（`fn wr(fd, p, n) { return syscall4(1, fd, p as u64, …) }`
   里那句 cast），而不是"调用点把指针放在了第几位" ✗。
   所以第一刀**单独**什么也买不到，它是第二刀的**前提**：只有"位"这件事对了，
   放开 `wr` 体内那句 cast（第二刀）之后，"把指针传给它第二参"才接得住。
   **顺序不能反**，而这条实测就是它的证据 —— 反过来说：既然第一刀不进，第二刀就**得自己站住**，
   它站住了（下面那一格）。

   **第二刀落地后的实测（2026-10-15）：4/23 → 8/23 = 34.8%**（L0 3→7 · L3 19→15）——
   **本文落地的只有这一刀**（第一刀未落地，见 §5.2）——
   动的正是那 4 个 `buf as u64` 站点（`all_loment` / **`bootprobe`** / `native_match_full` / `tour`）。
   **这 4 个名字是量出来的，不是读代码读出来的**：把 `_SYSCALL_BORROWS` 置空重跑同一把尺子、
   逐文件对差分，得到的就是这四个。原先我按 §1 的读码结果写成了 `selfcheck` —— **错的**：
   它那个站点交给的是 `seccomp(317)`，白名单拒了它，改动前后都是 L3（也对，见 §1 末）。
   第二刀自己就把这 4 个站点全买下来了。两刀合起来才是完整形态的规则（第一刀管"调用点把指针
   放在第几位"，第二刀管"交出去的那个动作算不算逃"），而**今天语料上能作数的是第二刀**。`lumtui_demo` 那 7 个**没动** ——
   它的外逃在被调函数里还有别的形状（把参数存进结构、或交给不在白名单里的东西），
   那是第三刀（候选形状：`store8(alloc(n), …)` 没绑名字、`ptr_to_int`/`int_to_ptr` 恒等往返）。
2. **L2 从 0 起**：今天语料里**没有**"循环体内分配、指针不出体"的程序 ——
   那既是一条待补的语料，也是一条判据（否则 L2 是不是空转，没人知道）。
3. **判据**（已落地）：`lomentc_test::test_syscall_borrow_rule` —— 三份**只差一行**的源，
   **三个方向都钉**：表内（`write`=1）⇒ 提升 · **表外（`sendto`=44）⇒ 不提升**（这一格是"表本身"
   的守卫：谁把 44 加进白名单，判据立刻红）· 号**不是字面量** ⇒ 不提升。**已验可证伪**
   （把规则关掉 ⇒ 那一格变 `{}` 而红）。两实现逐字节（`loment_p8_test`）；以及**行为**那一格 ——
   把 `write_dec` 那份当成语料编成 alpha，跑出来的输出必须与今天一字不差
   （借是"不多不少"的：它只该让回收更早，不该改行为）。
4. **反证**：把白名单里的号换成一个"会留存"的号（例如 `io_uring_register` 那一类），
   判据必须红 —— 否则这一刀测不出它想测的东西。
