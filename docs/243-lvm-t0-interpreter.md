# 243 · LVM 第一格（T0）：**那份 IR 的第四个读者**

> 状态: **规范**（2026-10-13）· 上游: `docs/232`（总纲 §4.1 / §4.4 / §7 H）· `docs/231`（渠道 + `vm` 维）
> 一句话: **字节码不发明新的** —— 就是 `lomelf` 已经吃的那份 IR；VM 只是它的**第四个读者**，
> 缺的只有"**执行**"这一步。判据是 **`choose vm` 的程序与原生产物 stdout + rc 逐字节相同**。

---

## 0. 一句话展开

今天那份 IR 有三个读者（clang / `lomelf` / Rust 转译）。T0 加第四个：
一个**解释器**，吃同样的文本 IR，**当场跑**，不落任何机器码。

⇒ 它**不引入新的中间表示**、不引入新前端、不引入新类型系统。
规范的"指令集"就是 `lomelf` 自述支持的那一份，**逐条对得上**。

---

## 1. 它吃什么（子集 = `lomelf` 已经支持的那一份）

| | 内容 | 出处 |
|---|---|---|
| **类型** | `i1`/`i8`/`i16`/`i32`/`i64`/`ptr`、结构体 `{…}`、数组 `[N x T]` | `tools/lomelf.py` 头注 |
| **指令** | `alloca` / `load` / `store` / `getelementptr` / `extractvalue` / `insertvalue`；算术 / 位运算 / 比较 / 转型；`br` / `switch` / `phi`；**直接** `call`（≤6 实参）；内联汇编 `syscall`；`atomicrmw add`；`ret` / `unreachable` | 同上 |
| **明确没有** | 浮点、`bitcast`、`select`、间接调用、闭包、聚合返回值、变参、结构体动态下标 GEP | 同上（那条"没有"清单**就是**这一格的边界，别再划一遍） |

**边界不自己划**：`lomelf` 那条"没有"清单**就是**这一格的边界 —— 它变了这一格跟着变。
判据（§4）在语料上钉的正是"两边支持面相同"。

---

## 2. 它**不做**什么（整段跳过，不是"还没做"）

`lomelf` 里有一大批东西是**降级时才需要**的，解释器一个都不要：

| 跳过的 | 为什么 |
|---|---|
| 全部 x86 编码（`rex`…`sext_to64`）与 `Asm` 类 | 不产机器码 |
| 标签→偏移回填（`Asm.finalize` 的 fixups） | 直接按**标签名**跳表 |
| **`plan_frame`（SSA→栈槽）** 与所有 `put`/`get` 落字节 | 值是宿主值，不进内存 |
| 重定位、外来目标文件、归档 | 纯解释不产目标文件 |
| ELF / PE 写出（`build_elf` / `build_pe` / `PeEmitter`…） | 同上 |
| 收编面（`emit_conscript` 的 C ABI 薄壳） | 没有 C ABI 要接 |

⚠ **但有一批"降级期语义"必须留着** —— 它们是**语言语义**，不是代码生成细节：
`get` 的零扩展、`get_signed` 的符号扩展、各指令的按宽度截断与回写、以及 **phi 的两趟模型**
（`lomelf` 的 `_emit_phis_then` 用两趟正是因为一趟会自我覆盖）。

---

## 3. 解释器的形状（一句话：先成表，再走一遍）

1. **解析成表**（不边扫边解释）。`lomelf` 的 `parse_ll` 本来就产出 `Instr`/`Block`/`Func`/`Global`
   这套表 —— 复用它的**解析**（`parse_type` / `size_of` / `field_offset` / `parse_operand` /
   `result_type` / `parse_phi` 等），只把"发射"换成"求值"。
   **边扫边解释等于把这套重写一遍**，而且 `phi`/`br` 的目标是标签名、必须有完整表。
2. **值**：一个 `dict[str, Value]`，SSA 名 → 宿主值。内存是一块**字节数组**，
   地址 = 下标 —— 全局常量按固定地址放进去，`alloca` 占帧槽，`alloc` 走 bump。
3. **内存与指针**：`load`/`store`/`gep` 按 `size_of`/`field_offset` 算偏移。
   全局字符串常量（`c"\4D\36…"`）按八进制转义解成字节。
4. **调用**：直接调用按名字查表；`asm sideeffect "syscall"` 是**唯一**的对外通道 ——
   解释器实现一小张系统调用表（`write`/`exit`/…），返回值放 `rax` 对应的槽。
5. **入口**：`_start` 就是入口；`exit` 走系统调用表结束。
   ⚠ `lomelf` 的桩在**退出码恒 0**，那与本格无关 —— 本格比的是**程序自己**的 stdout 与 rc。

## 4. 判据（照 `tools/loment_elf_test.py` 的体例）

| # | 判据 | 证伪方式 |
|---|---|---|
| **A** | **产物等价** | 同一份程序，`lomelf` 原生产物与 VM 各跑一遍 ⇒ **stdout 字节 + 退出码相同**。不看时间、不看中间表示 |
| **B** | **支持面相同** | 语料里每一份若 VM 说"不支持"，则 `lomelf` 也必须发不出来（反之亦然）—— 用一张**棘轮**表钉，只许变短 |
| **C** | **默认档不变** | 不写 `choose vm` 的语料 ⇒ 产物**逐字节不变**（本格**不碰** `no_vm` 那条路） |
| **D** | **渠道** | 本格只在 **dev 通道**可用 —— 由既有的渠道闸管着（`docs/231` §2），不新增机制 |
| **E** | **孪生**（两个实现） | 同一份 `.ll` 喂 `tools/lvm.py`（参考）与 `loment/tools/lvm.lomt`（自举镜像，走种子自举链编成 ELF）⇒ **stdout 字节 + 退出码相同**。⚠ 只证"两边一致"，不证"对"——"对"是判据 A 的活 |

**这一节的规矩**（照 `docs/210` §5）：每条要么有一个**反例**，要么有一对**程序**。
只钉"某个形容词成立"的不算。

## 5. 这一格**不含**什么

* **不含字节码格式**。"就是那份 IR" —— 紧凑编码是**后面**的事（`docs/229` §5 假设 1 的代价那一格）。
* **自举镜像已落**（本格的第二次提交）：`loment/tools/lvm.lomt`，判据 `tools/lvm_twin_test.py`
  （判据 E）。⚠ 与语言面**不同**：`docs/158` §5 那条"两个实现同一次提交"管的是
  lexer/parser/checker/codegen，不是新工具 —— 所以它没有跟第一笔一起进；但**孪生纪律照旧**，
  且这一格的比法与 `lomelf` 那一对**不同的地方**是：那边比产出的 ELF **逐字节**，
  这边比**跑出来的行为**（stdout 字节 + 退出码）。原因很直白 —— 两边跑的是同一份 IR，
  中间产物没有可比性。
* **不含性能**。T0 是解释器，只会更慢（`docs/232` §1.2）。
* **不含 JIT / 反馈向量 / 去优化**（T1–T3）。
* **不含 `extern` / FFI**：T0 只走系统调用表那一条对外通道。

### 5.1 自举镜像的形状（与参考实现**不必**逐行同）

参考实现是 Python（有字典、有 `bytes` 对象、随便分配）；自举侧没有那些东西。所以两边的
**结构**不一样，只有**行为**必须一样。自举侧的三条：

* **解析成表，再走一遍**（不边扫边解释）：名字 / 类型 / 文本全存**输入文本里的 span**（子串不拷贝），
  指令的**种类在解析期算好**。`br` 的目标标签在第二趟里解析成**块号** —— 分支是热路径，
  不能每条都线性找块。
* **聚合暂存按 SSA 名缓存**。SSA 里一个名字只被一条指令写，所以同名的多次执行（循环的每一轮）
  可以把同一格**反复覆写**；每次分配就会变成"每轮吃一格帧" —— 实测 `tour` 在第 1023 轮把 32 KiB
  的帧吃光。`undef`/`null` 聚合更省：VM 地址 `[0, GLOBAL_BASE)` **永不分配**，它恒为 0，
  直接当只读的零页用。
* **有步数上限**（`STEP_CAP`）。不是性能护栏，是"**不许挂死**" —— 解释器进了死循环要能自己回来，
  而且要说清卡在哪个函数的哪条指令。T0 没有性能判据，所以这条只当安全网。

### 5.2 自举镜像**抓到**的两件事（记在 issue #316）

镜像要走 clang 链接，而 clang 是这条链上**第一个会验 IR 的**下游（`lomelf` 是宽松的，照收）——
于是两种"发出来的 IR 本身不合法"当场现形：

1. **两边都有**：一个二元算子的两个操作数位宽不同时，**不做提升**，发出来的
   `shl/icmp/sub i64 %a, %b` 里 `%b` 是 i32 —— LLVM 要求两者同类型，clang 直接拒。
   `u64 <op> u32` 是很常见的写法（u64 计数器对 u32 长度、u64 值移 u32 位）。
2. **只有自举侧**：`a && b != c` 这个形状里，`!=` 的结果类型自举发 **i64**，参考发 **i1**。
   这就违反了 `docs/158` §5 的孪生纪律。

`lvm.lomt` 里用显式 `as u64` 与"用 u32 记符号"绕开了，注释里指回 #316。**没有在本文档里顺手改编译器**：
那是另一条线，且要两个实现一起动。

### 5.3 写 `.lomt` 会连撞的语义硬约束（自举子集）

* `const` 的初值只吃**字面量**（`4 * 1024 * 1024` 解析不过）；
* **没有 `break`** —— 早退只能靠标志位或 `return`；
* `x as u64 << 32` 会被读成泛型实参 —— 要写 `((x as u64) << 32)`；
* **没有模块级 `let`** —— 可变状态一律落在 arena 头那 256 字节的**格区**里（照 `lomelf.lomt` 的做法）。

## 6. 我不主张

1. **不主张这一格"能跑大程序"**。目标是**一小批会终止的 `_start` 程序**与原生产物**逐字节同**。
2. **不主张它是字节码**。它就是那份 IR；叫它"字节码"是**目标**不是现状。
3. **不主张快**。反了 —— 那是 T1–T3 的事，而且要先过 J2 那一仗（`docs/232` §2.3）。
4. **不主张模板化的判据**（`docs/208` 体例：与作者同源，未经独立复核）。
5. **不主张自举镜像"与参考实现逐行同"**。它俩**结构不同**（§5.1），只有行为被钉住。
6. **不主张它现在能被 clang 以外的后端编**。§5.2 那两条是**编译器**的毛病，镜像只是绕开。
