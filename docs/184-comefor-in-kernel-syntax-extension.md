## 1. 它长什么样

> ⚠️ **一处按你的原话写不了、我改了一处字符**：你写的是 `comefor let '词语' to { … }` 与
> `byuse '<名字>' done`。**Loment 没有单引号字面量**（`SKILL.md` §280：字符串是 `"..."`，
> 转义 `\n \t \" \\`；`lomc.py:60` 的 `_PUNCT` 里也没有 `'`）—— 照写是**词法错**
> （"非法字符 `'`"）。所以两处都用**既有的双引号字符串**：
> `comefor let "reg" to { … }` / `byuse "reg" done`。
> 不为它加一种字符串形式：那是加一个**语言级**的字面量（词法器 + 两个实现 + token 记录），
> 而这里要的只是"一个名字"。名字用现成的字符串，**这一档零个词法改动**。

```rust
module k

// 定义。体是**一段 Loment 程序**，内核在编译期跑它。
comefor let "reg" to {
    // 它吃 token、吐 token（§3 说清拿到什么）
    ...
}

// 从这里到 `byuse`，`reg` 是这个新语法
reg LEDS: 0x4000 {
    bit ON  = 0;
    bit OFF = 1;
}

fn _start() {
    poke(LEDS, ON);
}

byuse "reg" done
```

**`byuse` 终止的是"这个词在哪儿有效"，不是那个 `{}`** —— `to { … }` 的括号早就配平了。
所以这套块**不能嵌套、跨整个文件有序依赖**（`docs/183` §8.4 记过这条代价）。

> ✅ **已钉死（S4.1 实施前，2026-09-18）**：`byuse` 后面跟 `comefor` 里那个名字。你的原文是
> `byuse language done`，而"语言名"只在 `comefor let <语言名>` 那一格出现。**取"跟 `comefor`
> 里那个名字"**；不填语言名时（纯 Loment 语法），**那个词自己当名字**（`byuse "reg" done`）。
> 理由：不这样，"不填语言名"那一档就没有名字可终止。
> 判完要几个 token：`byuse` + 字符串字面量 + `done` —— **3 个**（不填语言名那一档同样 3 个，
> 因为名字就是那个字符串）。

## 2. 为什么是 token 层（不是语义宏）

上一轮讨论里我说过"内核内可以在**检查之后**展开，于是知道类型"。**那句话经核实不成立**——
不是内/外的区别，是**两个实现必须一致**这条约束决定的：

| | 参考实现 | 自举 |
|---|---|---|
| token | ✅ | ✅ |
| AST | ✅ | ⚠️ **有，但没接进管线** |

`loment/selfhost/parser.lomt` 是 M80 的成品（"Loment 版 parser，产出规范 AST dump"，
有与 Python 版逐字符对照的判据）—— 但**没有任何东西 `use parser`**：driver 和 checker
都在 **token 流**上工作。

⇒ **两边共处的层只有 token。** 展开只能在那儿发生 ⇒ **它是语法宏，不是语义宏**。

**要拿语义宏，得先做一件独立的事：把 `parser.lomt` 接进编译管线。** 那会动到 checker 与
codegen 的形态，`docs/158` §5 那条逐字节一致要重来一遍。**本文件不覆盖它**，记在 §7。

## 3. 核心件：**两个解释器**

这是内核税的具体形态，也是这份设计里**唯一的新大件**。

| | 参考实现 | 自举 |
|---|---|---|
| 语言 | Python | **Loment** |
| 走什么 | `Parser` 已产出的 AST | **token 流**（它没有接上的 AST） |
| 位置 | 新件 | 新件 |

**仓里今天没有任何解释器** —— 一个都没有。`driver.lomt` 是**发射** IR，不解释；
`tools/lomc.py` 编 `.lom`，不解释。所以这是**从零写两个**。

**它有多自举**：自举侧那个是**用 Loment 写的 Loment 解释器**，由自举编译器编译，在编译期
跑用户写的 Loment。**Loment 编 Loment 跑 Loment。**

**而它是安全的**：工具链自己**不用 `comefor`**（现在还不存在），所以**种子的编译不经过
解释器** —— 解释器有 bug 只会让用宏的程序编错，**不污染种子**。没有循环。

**一致性判据因此升级**（`docs/158` §5 那条的第三次加码）：

> **两个解释器跑同一段宏体，得到同一结果。**

### 3.1 宏体拿到什么、交回什么

用户选了"自己解析"，所以契约是**最窄也最强的那一种**：

- **拿到**：一个 token 游标（能看 kind / 文本跨度 / 行列），起点是方言词**之后**的第一个 token；
- **交回**：追加到**输出 token 流**（不是返回字符串 —— 见 §4 的位置）；
- **吃多少**：**`fn main() -> u64` 的返回值 = 吃掉的源 token 数**（从游标起点算起，不含
  方言词本身）。

> ✅ **已钉死（S4.1 实施前，2026-09-18）**：选"宏体显式报数"，理由是 §3.1 自己写的那条
> ——**显式更可审计**。而且它落在**既有形状**上：`fn main() -> u64` 本来就返回一个值，
> 在语料里那个值是"结果"，在宏体里那个值是"吃了几个" —— 同一个形状，两种解释。
> 选"按游标停在哪收"则要求解释器额外暴露游标。
>
> （`ct_run` 的签名**确实**还是变了 —— 但不是为这条，是为 §7 墙 ①b 那个堆：
> `ct_run(src, n, out) -> u32` 变成 `ct_run(src, n, out, heap) -> u32`。
> 本条的决定**没有**为它付任何账。）

**展开规则**（内核侧，一句话）：

    形如 `<方言词> <tok…> <tok…>` 处
    吃掉的 = 源 token 里 `[词后第 1 个, 词后第 1 + N 个)`
    换上的 = 宏体吐出的流

内核**不检查**吃掉的区间是不是"配平的块" —— 那是宏体的责任（同 §4 的位置）。
一个吃少了的宏体会把剩下的 token 留给 parser，报出来的错指在方言区里 —— 可接受。

### 3.2 宏体拿到的内建（S4.1 就落地，S4.2 才关进域）

§5 那张表里的"**读 token**"与"**吐 token**"两格，落到四个内建。**全走宿主内存**
（`alloc` 出来的那块，与 `bytes.lomt` 的 `load8`/`store32` 同一空间）：

    ct_n() -> u64                              // 游标起还有多少 token
    ct_tok(i: u64, buf: ptr) -> u64            // 源 token(游标起第 i 个) 的字段 -> buf；越界 -> 0
    ct_out(buf: ptr) -> u64                    // buf -> 输出流（文本/位置都照 buf）
    ct_syn(k: u64, txt: ptr, ln: u64, line: u64, col: u64) -> u64   // 合成一个 token

**记录形状（20 字节，与自举侧 token 记录**逐字段同序**，这不是巧合）**：

    +0 kind(u32)  +4 off(u32)  +8 len(u32)  +12 line(u32)  +16 col(u32)

**`off`/`len` 圈的是源里的**原始片段**，不是 `val`。** 两者不等：字符串字面量
`"hello"` 的 `len` 是 **7**（含引号），而它的值是 5 个字节。宏体要的是**前者** —— 照抄进
输出流时"文本 + 位置"都得是原来那一份。`lomc.Tok` 因此补了 `off`/`len` 两个字段
（`lomc.lex` 填），自举侧本来就是这个形状。

**`ct_out` 的 kind 与位置怎么取**（这一条要钉死，否则两边会各取一套）：

* `kind` **取 buf 的**（宏体可以改它 —— 那是"把标识符变成关键字"的用法）；
* `off`/`len` **取 buf 的**，而**文本按这个跨度在源里查回来**；
* `line`/`col` **取源里那个 token 的** —— 跨度定了，位置就定了。
  宏体想自己定位置就用 `ct_syn`。

跨度查不到任何源 token（宏体自己编的）-> **报错**，不是静默用 buf 里的行列。
`ct_tok` 会填 `line`/`col` 是为了让宏体**读得到**位置（§5 那张表的"kind / 跨度 / 行列"），
不是让 `ct_out` 拿它当准。

**为什么是四个而不是两个**：§5 那两格说的是**能力**（读 token / 吐 token），不是内建个数。
`ct_out` 的文本指**源**（照抄，位置因此免费正确 —— §4 那条"构造出来的位置"就是这么来的），
`ct_syn` 的文本指**宏体自己的宿主堆**（要造新词时用）。**两类吐法不能合并**：合并就得让内核
猜一个 `off` 是源里的还是堆里的，而那个猜测在越界时是**静默错**，不是报错。

**帮手放库里**（§3.1 尾）：`loment/lib/cttok.lomt` 给 `tok_kind(buf)` / `tok_is(buf, "fn")` 这类
小函数。内核只出上面四个。

**"每个宏作者都要写一个 token 解析器"不该由内核解决** —— Loment 出一个**消费 token 的
辅助库**（`loment/lib/` 里的一个 `.lomt`）。**帮手放库里，不放内核里**，与本仓一贯做法一致
（`docs/168`）。

## 4. 位置：为什么"所见即所写"在内核内是**结构保证**

用户选了"编辑器显示你写的那份"。在 token 层展开，这一条是**免费**的：

- 宏体吐出的 token，`line`/`col` **由宏体填**，而它填的是**原文件的位置**（它手里的游标就在那儿）；
- 所以**不需要行映射表** —— 位置是**构造出来的**，不是事后对齐的；
- 报错、跳转、补全全指回用户写的那一行。

**代价如实记**：这条是**宏体的责任**，不是内核保证的。一个乱填位置的宏体会让报错指到别处，
而**内核看不出**。这要写进文档，并且是"完整宏系统"必然带的东西。

## 5. 编译期求值：**必须有一个域**（这一节替 B settle）

**为什么必须有**："跑"如果不加限制，宏体能 `syscall4(60, 0)` 把编译器杀掉，或者读任意文件。
**编译期执行任意代码 = 编译器变成一个运行任意代码的东西。**

**形状**：**能力域就是那个形状**（`capability` + `guard`，Loment 唯一的原创语义层）。
但要说清它今天管什么：**索引区间** —— `guard cap(slot)` 判 `slot` 在不在 `[lo, hi]`，
越界 trap。`SKILL.md` 自己写着"**`guard` 只约束索引落在域内，不是授权**"。

⇒ **要拿它管"这段能不能 syscall / 能不能开文件"，是给能力域加一个维度，不是白捡现成的。**
这是本设计里**唯一一处要求扩展既有语义**的地方，要单独记账。

**建议的域**（`comefor` 体自动落在里面）：

| 在域里 | 不在域里 |
|---|---|
| 算术 / 比较 / 控制流 / 函数调用 | `syscall4` / `syscall6` |
| `alloc` / `free`（**宿主**内存） | `inb` / `outb` / `atomic_add` |
| `str_*`（`str_len` / `str_byte` / …） | 打开文件 / 起进程 |
| **新的：读 token**（kind / 跨度 / 行列） | `load8` / `store8` **对程序内存** |
| **新的：吐 token**（追加到输出流） | |

**报错通道已经有了**：E004 / E005 就是域违规，不用新造码。

**域里那两条"新的"是本设计唯一的新内建** —— 它们也是宏体的全部能力。

### 5.1 实测：这个域**不需要扩展既有语义**（本节 §5 高估了）

S4.1 落地后回头看，上面那句"**唯一一处要求扩展既有语义的地方**"**是错的** ——
域**已经在了**，而且是**靠"没有"实现的**：

两个解释器都只实现**一张固定的内建表**（`alloc` `free` `load8` `store8` `load32`
`store32` `str_len` `str_byte` `str_ptr`，加上 §3.2 那四个 `ct_*`）。表外的东西**调不到**：

* `syscall4` / `syscall6` —— 不在表里 ⇒ `nobuiltin`（**两边同一个种类名**）；
* 开文件 / 起进程 —— 同上，语言里压根没有这些内建；
* `inb` / `outb` / `atomic_add` —— 同上；
* `load8` / `store8` **对程序内存** —— 解释器里这两个**只落在宏体自己的 arena 上**
  （`ar`），碰不到被编译程序的内存；
* 跑飞 —— `LIMIT` 报 `spin`、递归报 `depth`，两个实现同值。

**所以 §5 那张"建议的域"表不是要新建的东西，它就是内建表本身。** 原来把它读成
"要给 capability/guard 加一个维度"，是因为**默认了宏体跑在一个真编译器里**（那样
`syscall` 才是可达的）。跑在**解释器**里，可达集就是内建表 —— 而 `docs/184` §0 第六条
（"宏体执行 = 解释"）是**先**定的。**两条决定合起来把 §5 的账消掉了。**

**S4.2 因此缩成两件事**（判据 + 文档），不是一条语义扩展：

1. 判据钉住"表外的东西调不到"且**两边种类名一致**（`syscall4` 写在宏体里 → 两边都 `ERR nobuiltin`）；
2. 把这张表**写进用户文档**（`SKILL.md` §2.3 已写），因为对宏体作者来说
   "我能用什么"就是这张表，没有别的说法。

**这不改变 §7 的记账**：能力域那条"既有语义要被扩展"的担忧消失了，但"内核内"的其余
代价（两个实现必须一致、位置是宏体的责任、读者税）一条都没消失。

## 7. 墙与代价（如实记）

**① 两个解释器，而且必须一致。** §3。这是最大的一件，一次性。

**①b 自举侧：解释器的堆与编译器的堆**撞**。**（S4.1 实施前实测到的，原设计没料到。）

自举 driver 的缓冲走 `sys_alloc`（brk），**不用**语言自带那 64 KiB bump 堆 ——
`driver.lomt:1188` 的注释写明理由：`emit_module` 一次就要 49152B，与别的叠起来会越过
65536，而越界的边界检查在无 libc 环境下是 `@__loment_abort`（SIGILL，看起来像"编译器崩了"）。

问题是 `interp.lomt` 里被解释的程序用的**正是**那个 64 KiB 堆（`alloc` 内建），而它自己的
静态缓冲已经占了 43472B。于是：**driver 要跑宏体，就得让 49152B 的 codegen 与 interp 的堆
在同一进程里共存 —— 两边加起来 92624B > 65536。**
⇒ 不解决，自举侧的 `comefor` 一跑到 codegen 就崩。

**三条出路**（S4.1 自举侧开工前要先选）：

1. **给解释器一个外部堆** —— `ct_run` 加一个堆指针入参，被解释程序的 `alloc` 改成在这块上
   bump。**参考侧同步改**（`Interp` 的 `HEAP` 变成入参）。代价：动 S4.0 那两块（约 900 行
   Loment + 350 行 Python）与 `ct_run` 的签名。
2. **把 64 KiB 改大** —— 数**六处**：`lomentc.py:129`（Rust 运行时）、`:4037`/`:4048`/`:4603`
   （IR 发射）、`lomentc_test.py:916-917`（断言 `[65536 x i8]` 字面量）、
   `loment_p8_test.py:1251`/`:1271`（内存预算模型）、`codegen.lomt:1677`（自举发射）。
   **动的是两个实现共有的语言运行时** —— 即 `docs/158` §5 那条逐字节面，种子/ELF/PE 尺寸全跟着变。
3. **串行 + 收尾释放** —— **做不到**：`alloc` 是 bump，没有 reset，而 interp 的静态缓冲是
   **常驻**的，不会消失。

> ✅ **已定：走 1**（2026-09-18）。理由**不是"改得少"** —— 2 改的是六处但每处都机械，

>

这是**结构性扩展**。方言的定义体要进 Potato（否则产物不自解释），所以**要升 v4**。

**⑦ 方言对读者是永久税**（`docs/183` §8 记过）：读者群 ≈ 作者群的场合合适，公开库/教学

## 8. 不做什么（边界）

- **不做语义宏** —— §2。那要先把 `parser.lomt` 接进管线，是**另一件事**，不混进这一轮。
- **不做"外部语言名"那一档**（`comefor let c '…' to { … }`）。用户 2026-09-17 定的是
  **"不填语言名"**那一格。填了语言名的那种 ≈ S1（`docs/183` §8）加用户起名，**并进 S1 设计**，
  不进本文件。
- **内核不提供 token 解析的辅助** —— 帮手放 `loment/lib/`。
- **不引入新错误码** —— 域违规走既有的 E004/E005。

### S4.1 自举侧落地时撞到的四处（都记着，别重犯）

1. **形参上限 10 槽是硬墙，而越过去不是报错、是生成错代码。** `cf_run` 第一版写了
   **12 个形参**，症状是**驱动编自己时 SIGILL（exit 132）、编方言源时段错误**。
   同一个原因连着塌了四条判据（`m83_selfcompiles_itself` / `m85_..._corpus` /
   `m82_coverage_report` / `m85_codegen_arg_arity_is_loud`），**看起来像四件不同的事**。
   改法：不变的实参先摆进语境块，函数只剩 `(cf, d)`。
2. **`switches.lomt` 的 `copy_tok` 是"原地压缩"用的** —— 它读写的是**同一块**
   （`store32(toks, o*20+q*4, load32(toks, j*20+q*4))`）。拿它做**跨数组**拷贝，源那一侧
   会从**目标数组**里读 —— 而展开的目标是一块刚拿到的未初始化内存，于是抄出来**全是 0**、
   且末条不是 `eof`，症状是 driver 在"扫到 eof 为止"那个循环里**跑飞**（段错误）。
   `comefor.lomt` 因此自带 `cf_copy`。
3. **方言词的跨度**：定义处那个名字是**字符串字面量**（`"def"`，含引号），使用处是
   **标识符**（`def`）。注册时存整段的话两边**永远对不上** —— 定义被抹掉了、使用却
   从不生效，看起来像"整个 `comefor` 没接线"。存 `off+1 / len-2`（掐掉引号）。
   参考侧比的是**文本**（`t.val`），所以那边天然没有这个问题。
4. **`interp` 与 `switches` 都定义了 `block_end`** —— 一直相安无事，因为**没有任何东西同时
   `use` 两者**。`comefor` 一 `use` 就撞上了。另外 `driver` 想直接 `use interp` 也会撞
   `codegen`/`checker` 的 `skip_type`/`find_fn`/`op_code`/`E_ARITY`。**平 ABI 是这个仓
   的既有代价**，这次是它第一次真的收账：`interp` 的内部名加了 `ct_` 前缀，`comefor` 转出
   `cf_heap_bytes()` / `cf_err_name()` 两个口给 driver，driver 不 `use interp`。

**为什么这四条值得单列**：它们**没有一条**是"逻辑写错了"。是**这个仓的形状**（平 ABI、
10 槽、原地压缩的助手、两种"名字"的表示）与一个天真直译的镜像之间对不上。
第 1、2 条尤其：**症状离原因很远**（SIGILL / 段错误 指向的是别的地方），
只有把 driver 当黑盒逐段打探针才找得到。**镜像的代价在这里，不在行数上。**

### S4.1 自举侧要做什么（已做完，留作记录）

1. **`loment/selfhost/comefor.lomt`（新件）** —— token 层展开器，逐条镜像
   `tools/loment_comefor.py` 的 `_Expander`：认形状、注册方言词、跑体、替换区间。
   **自举侧比参考侧少一件事**：体**不用解析成 AST** —— 它本来就是一段 token，
   自举的 interp 直接在 token 上跑。参考侧要 `Parser` 是因为它只会走 AST。
2. **`interp.lomt` 加一个"从 token 起跑"的入口** —— `ct_run` 现在先 `lex_cap` 再
   `find_main`；宏体是**文件 token 表里的一段**，已经有 token 了。要么加
   `ct_run_toks(src, toks, nt, base, out, heap)`，要么让 `ct_run` 收 `(toks, base)`。
3. **四个 `ct_*` 内建** —— 落在 interp 的内建分派里（自举侧是 `span_is(src, off, ln, "…")`
   那串 `if`），语境（游标 / 输出流 / 源 token 表）走 `st`。
4. **driver 接线** —— `apply_switches` 之后调 `comefor`，并**把那两百来行守卫删掉**。
   堆：driver 用 `sys_alloc(CT_HEAP_BYTES)` 给解释器（墙 ①b 已清）。
5. **判据** —— 把 `loment/comefor/def_dialect.lomt` 加进 `loment_p8_test` 的语料，

**为什么不等价于"参考侧那份照抄一遍"**：第 2 条是参考侧**没有**的活（参考侧把体当文件解析），

（`ST_BYTES`）动一发牵 `args_for(st)` 那条"实参栈紧挨状态块"的约定。**它不是抄，是镜像。**
上面那四条实测撞到的，就是"镜像"与"照抄"之间的差。
