## 0. 决定（用户 2026-09-17 逐条定）

| 维度 | 决定 | 一句话理由 |
|---|---|---|
| **落点** | **内核内**（不是内核外的工具） | 用户："由我付（内核税）—— 我不是资本家，我是开源主义者" |
| **编辑器所见** | **你写的那几份**（不是展开后的） | 所见即所写；补全/跳转/报错都指着它 |
| **展开时机** | **token 层**（**不做**语义宏） | 见 §2：自举的 parser **没接进编译管线**，两边共处的只有 token |
| **宏体执行** | **解释**（内核跑它） | 用户："跑" |
| **宏体拿到什么** | **自己解析 token**（不是内核给结构化实参） | 用户："i，你都做了，那就做到底" |
| **范围** | 完整宏系统 | 用户 2026-09-17 定 |

**为什么这些是一条链而不是六个独立选择**：选了内核内 ⇒ 要两个实现一致 ⇒ 自举只有 token 可用
⇒ 展开只能在 token 层 ⇒ 宏体只能拿到 token ⇒ 它只能自己解析。**往下每一步都是被上面那步逼出来的。**

## 1. 它长什么样

```rust
module k

// 定义。体是**一段 Loment 程序**，内核在编译期跑它。
comefor let 'reg' to {
    // 它吃 token、吐 token（§3 说清拿到什么）
    ...
}

// 从这里到 `byuse`，`reg` 是这个新语法
reg LEDS: 0x4000 {
    bit ON  = 0;
    bit OFF = 1;
}

fn _start() {
    poke(LEDS, ON);
}

byuse 'reg' done
```

**`byuse` 终止的是"这个词在哪儿有效"，不是那个 `{}`** —— `to { … }` 的括号早就配平了。
所以这套块**不能嵌套、跨整个文件有序依赖**（`docs/183` §8.4 记过这条代价）。

> ⚠️ **一处我按 X 写、你不同意就说**：`byuse` 后面跟哪个名字。你的原文是
> `byuse language done`，而"语言名"只在 `comefor let <语言名>` 那一格出现。
> **我按"跟 `comefor` 里那个名字"写**；不填语言名时（纯 Loment 语法），**那个词自己当名字**
> （`byuse 'reg' done`）。理由：不这样，"不填语言名"那一档就没有名字可终止。
> 这条要在实施前钉死，因为它决定解析器要几个 token 才能判完。

## 2. 为什么是 token 层（不是语义宏）

上一轮讨论里我说过"内核内可以在**检查之后**展开，于是知道类型"。**那句话经核实不成立**——
不是内/外的区别，是**两个实现必须一致**这条约束决定的：

| | 参考实现 | 自举 |
|---|---|---|
| token | ✅ | ✅ |
| AST | ✅ | ⚠️ **有，但没接进管线** |

`loment/selfhost/parser.lomt` 是 M80 的成品（"Loment 版 parser，产出规范 AST dump"，
有与 Python 版逐字符对照的判据）—— 但**没有任何东西 `use parser`**：driver 和 checker
都在 **token 流**上工作。

⇒ **两边共处的层只有 token。** 展开只能在那儿发生 ⇒ **它是语法宏，不是语义宏**。

**要拿语义宏，得先做一件独立的事：把 `parser.lomt` 接进编译管线。** 那会动到 checker 与
codegen 的形态，`docs/158` §5 那条逐字节一致要重来一遍。**本文件不覆盖它**，记在 §7。

## 3. 核心件：**两个解释器**

这是内核税的具体形态，也是这份设计里**唯一的新大件**。

| | 参考实现 | 自举 |
|---|---|---|
| 语言 | Python | **Loment** |
| 走什么 | `Parser` 已产出的 AST | **token 流**（它没有接上的 AST） |
| 位置 | 新件 | 新件 |

**仓里今天没有任何解释器** —— 一个都没有。`driver.lomt` 是**发射** IR，不解释；
`tools/lomc.py` 编 `.lom`，不解释。所以这是**从零写两个**。

**它有多自举**：自举侧那个是**用 Loment 写的 Loment 解释器**，由自举编译器编译，在编译期
跑用户写的 Loment。**Loment 编 Loment 跑 Loment。**

**而它是安全的**：工具链自己**不用 `comefor`**（现在还不存在），所以**种子的编译不经过
解释器** —— 解释器有 bug 只会让用宏的程序编错，**不污染种子**。没有循环。

**一致性判据因此升级**（`docs/158` §5 那条的第三次加码）：

> **两个解释器跑同一段宏体，得到同一结果。**

### 3.1 宏体拿到什么、交回什么

用户选了"自己解析"，所以契约是**最窄也最强的那一种**：

- **拿到**：一个 token 游标（能看 kind / 文本跨度 / 行列），起点是 `comefor` 里那个词**之后**的第一个 token；
- **交回**：追加到**输出 token 流**（不是返回字符串 —— 见 §4 的位置）；
- **吃多少**：**宏体自己决定**。它不报"我吃到哪"，内核靠它**吐出的流**判断 ——
  这条要定清：**要么宏体显式说"我吃到第 N 个"**（显式更可审计），**要么**内核按"游标停在哪"
  收（更省事但要求解释器暴露游标）。

> ⚠️ **我不在这里替你定**，因为它是解释器接口的形状，而定它要先看 §5 的域能给什么。
> 实施 S4.1 时第一件事就是把它定死。

**"每个宏作者都要写一个 token 解析器"不该由内核解决** —— Loment 出一个**消费 token 的
辅助库**（`loment/lib/` 里的一个 `.lomt`）。**帮手放库里，不放内核里**，与本仓一贯做法一致
（`docs/168`）。

## 4. 位置：为什么"所见即所写"在内核内是**结构保证**

用户选了"编辑器显示你写的那份"。在 token 层展开，这一条是**免费**的：

- 宏体吐出的 token，`line`/`col` **由宏体填**，而它填的是**原文件的位置**（它手里的游标就在那儿）；
- 所以**不需要行映射表** —— 位置是**构造出来的**，不是事后对齐的；
- 报错、跳转、补全全指回用户写的那一行。

**代价如实记**：这条是**宏体的责任**，不是内核保证的。一个乱填位置的宏体会让报错指到别处，
而**内核看不出**。这要写进文档，并且是"完整宏系统"必然带的东西。

## 5. 编译期求值：**必须有一个域**（这一节替 B settle）

**为什么必须有**："跑"如果不加限制，宏体能 `syscall4(60, 0)` 把编译器杀掉，或者读任意文件。
**编译期执行任意代码 = 编译器变成一个运行任意代码的东西。**

**形状**：**能力域就是那个形状**（`capability` + `guard`，Loment 唯一的原创语义层）。
但要说清它今天管什么：**索引区间** —— `guard cap(slot)` 判 `slot` 在不在 `[lo, hi]`，
越界 trap。`SKILL.md` 自己写着"**`guard` 只约束索引落在域内，不是授权**"。

⇒ **要拿它管"这段能不能 syscall / 能不能开文件"，是给能力域加一个维度，不是白捡现成的。**
这是本设计里**唯一一处要求扩展既有语义**的地方，要单独记账。

**建议的域**（`comefor` 体自动落在里面）：

| 在域里 | 不在域里 |
|---|---|
| 算术 / 比较 / 控制流 / 函数调用 | `syscall4` / `syscall6` |
| `alloc` / `free`（**宿主**内存） | `inb` / `outb` / `atomic_add` |
| `str_*`（`str_len` / `str_byte` / …） | 打开文件 / 起进程 |
| **新的：读 token**（kind / 跨度 / 行列） | `load8` / `store8` **对程序内存** |
| **新的：吐 token**（追加到输出流） | |

**报错通道已经有了**：E004 / E005 就是域违规，不用新造码。

**域里那两条"新的"是本设计唯一的新内建** —— 它们也是宏体的全部能力。

## 7. 墙与代价（如实记）

**① 两个解释器，而且必须一致。** §3。这是最大的一件，一次性。

**② Potato 没有 `body`。** `docs/183:22`：v0/v1/v2 顶层字段里没有 `body`，`docs/179:70` 明说
这是**结构性扩展**。方言的定义体要进 Potato（否则产物不自解释），所以**要升 v4**。
（C1 建的 v3 是加 `switches` —— 那是加字段；`body` 不是。）

**③ 能力域要加一个维度。** §5。**唯一一处要求扩展既有语义的地方。**

**④ 它是"一族语言"从可选变成内建。** 外部方案至少能说"内核不知道方言存在"；内核内把
机制本身变成语言的一部分。**这是用户明确选择付的账**（"由我付"）。

**⑤ 内核税的具体形状**：从此每次改语言，都要带着这个机制活着，都要保证两个解释器一致。
Loment 现在还在高频改（`lomentc.py` 两天九次），**这个阶段的税最贵** —— 而用户已决定付。

**⑥ 位置是宏体的责任，不是内核保证的。** §4。内核看不出一个乱填位置的宏体。

**⑦ 方言对读者是永久税**（`docs/183` §8 记过）：读者群 ≈ 作者群的场合合适，公开库/教学
材料不合适。**这条不因为改内核内而消失。**

## 8. 不做什么（边界）

- **不做语义宏** —— §2。那要先把 `parser.lomt` 接进管线，是**另一件事**，不混进这一轮。
- **不做"外部语言名"那一档**（`comefor let c '…' to { … }`）。用户 2026-09-17 定的是
  **"不填语言名"**那一格。填了语言名的那种 ≈ S1（`docs/183` §8）加用户起名，**并进 S1 设计**，
  不进本文件。
- **内核不提供 token 解析的辅助** —— 帮手放 `loment/lib/`。
- **不引入新错误码** —— 域违规走既有的 E004/E005。
