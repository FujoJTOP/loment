# 216 · GC Alpha v2 设计定稿

> 状态: **设计定稿**（2026-10-09）· 上游: `docs/210`（四层梯）、`docs/213`（回收极限）、`docs/214`（绝对极限）、`docs/215`（重算回收）
> 一句话: **v1 的三条判断一条都不动**；v2 加**一个细分**（`recompute ⊆ l3`）、**一个可选档**（`gc_strict`）、**两条自洽规则**、**一条离线最优义务**。
> **所有新增都在产物里可判，且默认档逐字节不变。**

## 0. v2 是什么、不是什么

**是**：`gc_auto_alpha` 的一次**加法**。三档（`gc_manual`/`gc_auto`/`gc_auto_alpha`）语义不动，`L0/L1/L2/L3` 四条判据**一条都不改**。

**不是**：不是新算法，不是第五层梯，不是把 `L3` 拿掉。

---

## 1. 设计判断（逐条：决定 / 理由 / 代价 / 判据）

### D1 · `recompute` 是 **`l3` 的细分**，不是第五层

**决定**：`recompute` 数的是"**可达但按重算回收**"的站点，因此 `recompute ⊆ l3`。

**理由**：`docs/215` 的机制**只作用于"本来会被保留"的那一类** —— 也就是 `L0/L1/L2` 都没接住、落到 `L3` 的站点。它不改梯子的**分派**，只改 `L3` **怎么处理**。所以它是细分，不是新层。

**代价**：`l3` 这一格从此**不是一个数，是两个**（保留 / 重算）。

**判据**：`recompute <= l3`（两条自洽规则之一，见 D4）。

---

### D2 · `recompute` 与 `L3` **共存** —— ⚠ **本稿推翻 `docs/215` §3.2**

**`docs/215` §3.2 原文**：「它**不能与 `L3` 共存**…… ⇒ **梯子变成三个数**（`L0`/`L1`/`L2`）+ `recompute`；`L3` 要么在，要么不在。」

**本稿的决定：那条假设拿掉。** 理由：

1. **冲突是概念上的，不是操作上的。** `L3` 处理**不可达**；`recompute` 处理**可达但可重算**。两件事**互不覆盖**。
2. **原先的"排他"论证依赖的是一条可修的假设**：一个被重算回收的块，对追踪器来说是一个**悬垂指针**。但"**洞**"是**可表示**的 —— 块头上多一位"当前处于重算态"，追踪器**到洞就停**，不把它当根、不当边。
3. ⇒ 代价是**收集器要认洞**（一个位 + 传播时一跳判断），不是**两者取一**。

**这与 `docs/210` §2.3 那次改形是同一个动作**：原稿要手写 `epoch`，实现时把那条假设拿掉了，于是更好。**这里是第二次。**

**代价**：收集器的四趟遍历各多一条"洞"判断；根表不动；**`L3` 的判据全部保留**。

**判据**：一对程序（§3 判据 A），一个走 `L3`、一个走 `recompute`，**同一个产物里两者都非零** ⇒ 共存成立。

---

### D3 · `gc_strict`：**gc 维的第四档**

**决定**：新增 `choose gc_strict` = 「**`gc_auto_alpha` + `l3 > 0` 即编译期拒**」。

**理由**：`docs/214` §3 的 `L*` 是唯一能给出**别人给不了的断言**的形态 ——

> **"这个产物里没有内存管理组件"，且不读源码可判。**

但 `docs/214` §2.1 说 `L*` 让语言**在内存维度不完备**。⇒ **这绝不能是默认行为**，只能是**自愿**的一档。于是它落成一个 `choose` 值，而不是语言的性质。

**代价（明写）**：
* **它不是"更强的 alpha"，是"更弱的接受面"** —— 会拒掉本来能编的程序；
* 拒的范围**大于必须拒的范围**（`docs/213` §2.2 不完备性）；
* `docs/205` §3.4 那条「`no_std` + `gc_auto` 拒」的形状要**照抄**到 `gc_strict` 与 `no_std` 的组合上（先划窄）。

**判据**：一个 `gc_strict` 能编过的单元，产物里 **`@__loment_alloc` 一次都不出现**。
> ⚠ **这一条不是新机制**：`docs/210` §4.5 已经记着，全 `L0` 的产物里**连分配器都不剩**。`gc_strict` 做的是把"**恰好全 L0**"变成"**要求全 L0**"。

---

### D4 · 产物：**Potato v11**，加两个字段 + **两条**自洽

**决定**：`gc_ladder` 从 v10 的五个数变成**六个数**：

```
gc_ladder = { l0, l1, l2, l3, recompute, total_sites }
```

**两条约束**（都要由**两份校验器各自独立判得**，v10 的 `MUTATORS_V10` 同形）：

| # | 规则 | 它挡住什么 |
|---|---|---|
| 1 | `l0 + l1 + l2 + l3 == total_sites` | v10 原有；**一个字不改** |
| 2 | `recompute <= l3` | 挡住"顺手把重算报成第五层" |

**向后兼容**：`recompute = 0` ⇒ 退化成 v10 语义。**默认档（不加任何 `choose`）产物逐字节不变。**

**理由**：这是全项目的形状（`docs/147` 台阶累积 + `docs/205` R5 自洽）。

---

### D5 · **离线最优义务**：竞争比要报

**决定**：`recompute` 的决策**必须**与**离线最优（Belady MIN）**对照，报**竞争比上界**。

**理由**（`docs/215` §2.4 #4，也是 v2 唯一的技术优势论据）：

> **编译器有离线视野，运行期收集器没有。**
> ⇒ 做不到"明显优于在线策略"，这个机制**就没有存在理由** —— 那运行期自己就做了。

**代价**：要造**已知离线最优解**的合成程序族（`docs/215` §6.5）。**这一条是 v2 里最贵、也最容易被跳过的一条。**

**判据**：在那个程序族上，比值有**上界**且**可复现**。

**分阶段（诚实）**：**竞争比先做成判据，不先做成产物字段** —— 一个数要在算得出来之后才能进产物。字段等 v12。

---

### D6 · **默认档一行不动**（承重，不可协商）

不加 `choose` 的语料 ⇒ 产物**逐字节不变**。由 `loment_potato_emit_test` 的逐字节孪生守着（`docs/175` §3.4 那五条之一）。

---

## 2. 产物形状（Potato v11）

```
gc_ladder = {
  l0, l1, l2, l3,          # 四层梯的份额（v10 起）
  recompute,               # l3 中按重算回收的那一部分（v11）
  total_sites              # 该单元的 alloc 站点数
}
```

**v11 是一次升版**，所以 `v11` 的**必填面 = v10 的必填面 + `recompute`**（台阶累积）。
落点：`tools/potato.py` 的 `TOP_KEYS_V11` / `GC_LADDER_KEYS`；`tools/lomentc.py` 的 `_count_gc_ladder`；自举侧 `loment/selfhost/{codegen,potato}.lomt` **同一次改完**（`docs/158` §5 那四条）。

## 3. 判据（每条可证伪；进 `ci.py`，且不在基线里）

| # | 判据 | 证伪方式 |
|---|---|---|
| **A** | **共存**（D2） | 一对程序：一个走 `L3`（不可达）、一个走 `recompute`（可达但可重算）；**同一个产物里 `l3` 与 `recompute` 都非零**。若二者**不能同时非零** ⇒ D2 死，退回 `docs/215` §3.2 |
| **B** | **重算真的发生**（D1） | 一对**只差一行**的程序：一块由纯函数产生、**仍然可达**。开 `recompute` ⇒ **在更小 arena 里跑完**；关 ⇒ **耗尽**。两边都跑完 ⇒ 没发生；两边都耗尽 ⇒ 做不到 |
| **C** | **两条自洽**（D4） | 两份校验器各自独立判 `Σ 四数 == total_sites` **与** `recompute <= l3`；`MUTATORS_V11` 各配一条反例 |
| **D** | **`gc_strict` 的产物没有内存管理组件**（D3） | 一个 `gc_strict` 能编过的单元 ⇒ `@__loment_alloc` **零出现**；**并且**：一个 `l3 > 0` 的程序 ⇒ **必须被拒**（带诊断码与修法） |
| **E** | **零收益区被判出来**（`docs/215` §3.4） | 一个"重算明显更贵"的程序 ⇒ 编译器**必须不选** `recompute`。**选了 ⇒ bug** |
| **F** | **纯度假阴性**（`docs/215` §6.4） | `boundary(f) = 0` 但 `f` 不确定 ⇒ **必须不判为可重算**（判错 = 静默改语义，最坏的失败形状） |
| **G** | **默认不变**（D6） | 现有语料（不含新 `choose`）⇒ 产物**逐字节不变** |
| **H** | **两个实现一致** | 上面每一条的**静态那一半**，参考实现与自举侧**逐字节相同**（`docs/210` §5 第七行的同形判据） |
| **I** | **离线最优义务**（D5） | 已知离线最优解的程序族上，比值**有上界且可复现** |

**这一节的规矩**：**每一条都要有一对程序或一个反例**。只钉"和"的判据不算（`docs/210` §5 那条：`{0,0,0,4}` 与 `{1,1,1,1}` 都让和成立）。

## 4. v2 **不**做什么（连同理由，一次性列出）

| 不做 | 理由 |
|---|---|
| **搬移 / 压实** | 块内保守扫 ⇒ 不知道块里哪个字是指针（`docs/210` §2.4）。量子侧还多一条：无克隆 ⇒ 必然（`docs/213` §4.1） |
| **分代** | 写屏障唯一要管的事（老→新）在本后端几乎不存在：指针只存局部/形参槽（`docs/210` §2.4） |
| **并发 / 增量** | 后端**单线程、无信号**（`docs/210` §2.4）；且它撞 `B0`（`docs/202` §3） |
| **块内精确** | `alloc(N)` **无类型**（`docs/210` §4.2） |
| **弱引用 / 终结器** | 语言面没有对应构造 |
| **自动改写程序**（把"拒"做成"不是拒"） | `docs/214` §7：**三者必付其一**，这条被证明不可能 |
| **跨运行期的持久堆** | 没有 `B0` 之外的入口，且不在 0.1.5 的账上 |
| **竞争比进产物** | 先做成判据（D5），字段等 v12 |
| **动 `L0`/`L1`/`L2` 的任何一条判据** | v2 是加法 |

## 5. 与 v1 的差异（逐条可核对）

| | v1（今天） | v2 |
|---|---|---|
| 梯子 | `L0/L1/L2/L3` | **不动** |
| `gc` 档 | `gc_manual`/`gc_auto`/`gc_auto_alpha` | + **`gc_strict`** |
| `l3` 的含义 | 残差 | **残差，且其中一部分可被重算回收** |
| 产物 | v10，五个数，**一条**自洽 | **v11，六个数，两条**自洽 |
| 离线最优 | 无 | **一条义务**（判据，非字段） |
| 默认档 | 逐字节不变 | **逐字节不变**（不可协商） |

## 6. 我不主张

1. **不主张 v2 会提高 `κ`。** `recompute` **不改变 `κ = (l0+l1+l2)/N`** —— 它改的是 `l3` 的**内部处理**。`κ` 仍由 `docs/213` §3 定义。
2. **不主张 D2（共存）已经论证完整。** 它的论证依赖"洞可表示"，**那个表示还没写**（判据 A 是它的第一道检验）。
3. **不主张 `gc_strict` 有人需要。** 它是**一个可选的能力**（`docs/214` §3），不是需求。**没人需要它就没人用。**
4. **不主张 `recompute` 更快。** `docs/215` §3.4：它**永远不比重读便宜**，换的是空间与驻留。
5. **不主张任何数已经量过。** §3 一条都还没跑。
6. **不主张本文改 `lom/`、改 `L0`/`L1`/`L2` 判据、或动默认档。**
7. **不主张本文经过独立复核。** 与作者同源（`docs/203` 体例）。
