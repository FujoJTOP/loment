## 2. 按"移除它会破坏什么"分五类 —— 每一类的去路都不同

### A. 判据（Python 86，`tools/` 的大头）—— **必须搬进 Loment**

`ci.py` / `loment_*_test.py` / `lomc_test.py` / `potato_test.py` …

**这是最大的一块，也是唯一一块"没有替代品就动不了"的。** 判据是给别的改动兜底的；
先拆它等于把安全带解了再开车。

**模板已经有了**（`docs/159` §4b）：同一份源码喂**两个实现**、比 stdout **逐字节相同**
—— `lomfmt` / `lomdoc` / `lompkg` / `lomc` / `lomrel` / `lomstatus` 全是这么落的。
判据的迁移照这个来：**Loment 版判据 + 与 Python 版逐字节相同**，直到 Python 版可以拆。

### B. 参考实现（`tools/lomentc.py` / `lomc.py` / `lomelf.py` …）—— **排在 A 之后**

它是"两个实现逐字节一致"（`docs/158` §5）里的**对照面**。

⇒ **移除它 = 那条开发期纪律没有对照物了。** 那**是对的**（自举完成时本来就只有一个
实现），但**时机**必须排在 A 之后：判据先搬进 Loment，再拆参考实现。
**顺序反了的话，回车键前一刻没有任何东西能告诉你搬对了没有。**

### C. `loment/build/` 里那些 Rust / C / LLVM IR（53 个）—— **要用户点头**

**它们不是手写的，是生成物。** 谁生成的决定了去路：

* `.rs` / `.c` / `.py` —— **`lomc` 的后端**（`tools/lomc.py:546/571/613` 与它的 Loment
  孪生 `loment/tools/lomc.lomt`）。**那正是 `lomc` 存在的理由**：L0 契约要交付成
  Rust / C / Python，给 FujoOS 那一侧用（`lom/fuai.lom` → `fuai.h` / `fuai.rs` /
  `spec.json`）。
  **⇒ "移除全部 rust/py/c"与"L0 契约要交付成 rust/c"是同一件事的两面。**
  这条**不能自己定**：要么下游改吃 `.lom`，要么这一条指令对 `lom/build/` 不适用。
* `.ll` —— IR 种子/中间物。`genesis` 落地之后编译用户程序**不需要**它，但它是**链条起点**
  （`docs/159` §3）。属于 F 那一类。

### D. `kernel/` `sdk/`（Rust 8 + C 4）—— **要用户点头**

它们是**从 FujoOS 拿来的只读对照物**（`CLAUDE.md` 第 1 条、`loment_publish.COUNTERPARTS`）。
`lom_audit` / `fuai_contract_check` / `lomc_test` 靠它们做**逐字段对账**。

**⇒ 移除等于"L0 契约在本仓没有对照面"** —— 而 `CLAUDE.md` 明写"少了它们判据会**崩**，
不是静默红"。

这条是**跨线**的，不是语言线自己能定的。

### E. `editors/vscode/src/*.js`（2）—— **要用户点头**

VS Code 扩展**只能**是 JS/TS，没有别的选择。移除 = 放弃编辑器支持
（而 `editors/` 是 `docs/157` 花过力气的地方）。

### F. 启动脚本（`.ps1` 2 + `.sh` 2 + `.ld` 1 + `.ll` 13）—— **链条起点的鸡生蛋**

`loment/bootstrap.sh` / `scripts/lomc.ps1` 是**自举链的第一步**。在"从零重建"这个场景里
总得有一个东西先跑起来 —— `genesis` 把这一步压缩到了一小段，但**压不到零**。

`docs/159` 的"仍待做"里记着 **PE64 / 去 WSL / 构建路径去 Python** —— 属于这一格。

### 3.0 S0 的决定（用户 2026-09-18）—— **两条都定了**

#### C：`lomc` 的 rust / c / py 交付后端 —— **交付物豁免，但不再提交**

用户原话选的是这一条。落地形状：

* `loment/build/` 里那些 `.rs` / `.c` / `.py`，以及 `lom/build/` 的 `fuai.h` / `fuai.rs` /
  `fuai.py` —— **从索引里移除、进 `.gitignore`**。仓库里不再有它们的字节。
* **`lomc` 照旧能生成它们**（能力不动）。判据从"提交的那份逐字节一致"改成
  **"生成出来 == 上一层输入"** —— 即"从 `lom/fuai.lom` 生成出来的那份，与生成器说的一致"，
  而不再与一份**存在仓库里的副本**比。
* **代价（写在这里，别到 FujoOS 侧才发现）**：那边原先直接吃**提交好的**文件，
  改完要在自己的构建里**先跑一次 `lomc`**。这是一条跨线的施工顺序，不是这一侧能单方面改完的。

> **为什么这条最贴"自举"的本意**：那 53 个文件**不是代码，是产物**。产物留在仓库里，
> 读的人分不清"这是别人写给我的 C"还是"这是我自己生成的 C" —— 而后者恰恰是自举的证据。
> 移出索引之后，"仓库里只有 Loment"这句话**字面上成立**，而能力一点没少。

**⚠ 实测出来的耦合 —— 做 S3 之前必须先看这一条**（2026-09-18 数完 `git ls-files` 之后查的）：
那 49 个文件里有几个**不只是"交付产物"，它们被本仓的工具在运行时加载**，
所以"移出索引"**不是删文件那么轻**：

| 谁 | 怎么用 | 移出索引之后 |
|---|---|---|
| `tools/fuic.py:28` | `spec_from_file_location(…, "lom/build/fuc.py")` | **import 期就崩** —— 打包器起不来 |
| `tools/fujopack.py:26` | 同上，`lom/build/fujr.py` | **同上** |
| `lom_audit.py:38-50` | 一张 `(.lom, 目标, 产物路径)` 对账表 | 报"缺失"（`lom_audit` 本就是本机固有红项，但这条会变成**新的**红因，混在里面） |
| `loment_lomc_test.py:204-210` | `--check` 拿**提交的那份**当对账目标 | **对账没有对象了** |

**⇒ S3 的真形状不是"删 49 个文件"，而是"把'产物与源头一致'那条不变式换个说法"**：

    旧：提交的那份副本 == 生成器此刻会生成的
    新：生成是**确定的**（同样输入两次出同样字节）+ 漂移**检得出来**

后半句已经有一半了 —— `loment_lomc_test` 的漂移检出那一半用的是**临时副本**
（`loment/build/lomc_bad_tmp`），不依赖索引 ✓。要改的是前半句。

上面两个**运行时加载器**另有一条交代 —— **已定 (a)**（现场按需生成），理由是**那条依赖本来就在**：

* 先看两条候选：**(a)** 文件不在就现场调 `lomc` 生成；
  **(b)** 文件不在就报一句清楚的话、让构建顺序**显式**。
* **选 (a) 的关键一条**：`lom_audit` 明令「打包器必须引用生成模块、**不能退回手写**」
  （`lom_audit.py:206`）—— 也就是说**打包器拿布局的唯一合法来源就是那个生成物**。
  于是"按需生成"不是**引入**了一条依赖，是把**本来就有的**那条依赖**实现出来**。
* (b) 另有一处说不通：S3 之后「文件不在」是**仓库的默认状态**（新克隆就是这样），
  而**对默认状态报错是错的** —— 那不是异常，是常态。
* 代价记一笔：`fuic.py` / `fujopack.py` 从此要么调生成器（S2 之前 `lomc.py`、
  之后 `lomc.lomt`），要么在文件已在时直接加载。**能省的只做一次**：文件在就不调。

**顺带一条好消息**：`loment/build/fuai_syscalls.lomt` 那种**生成物是 Loment 源码**
（`lom_audit.py:324`），所以它**不在**这一格里 —— 它照旧提交。按扩展名一刀切会把它误伤。

#### D：`kernel/` + `sdk/` —— **保留**

它们不是本仓的代码，是 **L0 契约对面那一侧的只读对照物**（`CLAUDE.md` 第 1 条、
`loment_publish.COUNTERPARTS`）。保留的理由是**判据的对照面**：`lom_audit` /
`fuai_contract_check` / `lomc_test` 靠它们做逐字段对账，而 `CLAUDE.md` 明写"少了它们
判据会**崩**，不是静默红"。

这条豁免不是"网开一面"，是把那句指令的**适用范围**说准。

### ⚠ 但在排格子之前，先问一句：**这件工具活得过 S2 吗？**

把 53 件"参考实现"摊开看，它们不是一类 —— **有的工具的全部用途就是"把两个实现比一比"**
（`loment_probe` 头注自己写着"**门禁里不跑, 是定位工具不是检查项**"、`loment_ir_diff`、
`loment_rule_parity` …）。参考实现一拆，**它们就没有意义了** —— 给它们写 Loment 孪生
是白写 ✗。

| 类 | 特征 | 怎么办 |
|---|---|---|
| **活得下去** | 干的是真活（`loment_eol` 查行尾、`loment_src` 打源码包、`lomfmt`/`lomdoc`…） | **写孪生**（S1 的正题）|
| **随 S2 消失** | 它的输出就是"参考 vs 自举"的对照（`loment_probe` / `loment_ir_diff` / `loment_rule_parity`） | **不写孪生**，跟着参考实现一起拆 |
| **换人** | 要 Loment 没有的能力（`loment_filetype` 写 HKCU；`loment_sign` 走 Authenticode/openssl） | 留给安装器/外部工具，或明确留在 Python 那一侧 |

⇒ **53 这个数不是要给 53 件写孪生**：先把每一件归到上表的一类，再谈工作量。
（这条是 2026-09-18 排第二格时想清楚的 —— 差点给 `loment_probe` 写一个没有意义的孪生。）

**三种判据形态要先分清**（不然 44 格会各写各的）：

* **工具型**（判据在测一个 `tools/` 里的工具）→ Loment 版就是那个工具的孪生，
  比 stdout 天然成立（`lomstatus` / `lomrel` 就是这么落的）。**这一型优先做**：
  不新增 Python（孪生是 Loment ✓），而且 S2 拆参考实现时正好把那件 Python 收走。
* **检查型**（判据自己就是一段检查逻辑，没有对应工具）→ 得**先把它抽成一个程序**
  （Python ✓），再写孪生。注意这一步会**让 Python 多一个文件**（`86 → 87`）——
  是为了让"两条实现逐字节比"成立，不是为了永久留着；
* **对**外部神谕**的**（CPython / clang / javac / dotnet / go 当对照物 —— `docs/188`
  §7.1 那六门的判据全是，`loment_json_test` 也是）→ **神谕不能被搬走，也不该搬**。
  Loment 版是**驱动器**：走进程桥（`loment/lib/proc.lomt`）去调那个外部工具，
  比 stdout。这一型的"逐字节相同"比的是**驱动器自己的报告**，神谕那一侧照旧。

**从哪一格开始**（按"不碰 git / 进程 / 编译器"排序，最便宜的先做）：

#### 第 1 格踩到的两处（后面 43 格都会再撞，先写下来）

1. **入口是 `fn _start()`，不是 `fn main()`。** 写成 `main` 时 lld 找不到入口、把入口留成 0
   —— 现象是**一跑就段错误、一个字都不输出**（不是链接失败，也不是编译错，所以最难猜）。
   照抄同行的写法（`lomstatus.lomt` / `loment_ffi_test` 的腿 2 都是 `_start`）就不会错。
2. **别照抄 `loment_status_test` 的比较器**：那个 `_norm` 把反斜杠归成斜杠，前提是"输出里的
   反斜杠只会来自路径"。而 `loment_eol` 的报告里**有一个字面的 `\n`**
   （`写仓库内工件要用 newline='\n'` 那一句）—— 归一之后**判据自己造出一个假差异**，
   红的是比较器、两边真输出逐字节相同。**这一格的 `_norm` 因此刻意什么都不做**，
   并把这个"为什么不做"写在函数头上。
3. 另外两处小的：`const` 只收整数字面量（命令串不能做 `const`，得内联）；
   语言只有 `load8`/`store8`，32 位读写要自己拼（`ld32`/`st32`）。
   两者陷阱清单里都写着，我各踩了一次 —— **写之前先读 §6 那一节**。

#### 第 2 格（`loment_syscalls`）踩到的一处

**别绕开自己的 `open_ro` 助手去直接 openat 字面量指针。** 驱动里 `argv_at` 是先
`open_ro(str_ptr("/proc/self/cmdline"), str_len(...), scr)` —— 它把路径**拷进 scratch 补
NUL** 再 openat。我图省事写成 `syscall4(257, AT_FDCWD, str_ptr("…"), 0)`，结果 openat
失败、`argc = 0`，两条配对判据一起红，而**报出来的话是"需要 --emit 或 --check"** ——
指的完全不是真正的原因（这正是本仓反复讲的"错要指在错的地方"，我自己造了一次）。
**照抄同行的调用姿势比自己拼参数便宜。**

#### 第 3 格（`loment_editors_test` 第 1 条）: **检查型**怎么落

这一格没有对应工具（检查逻辑就写在判据里），所以按 §3 的"检查型"走 —— 但**不必**
先把检查抽成一个 Python 程序（我原先在表里是那么写的，**错了**）：判据那一侧可以
**直接调那条检查函数**（`contextlib.redirect_stdout` 捕获它打印的那一行），拿它当参考。
**Python 一个文件都不用多**。

另一件要划清楚：Python 那一侧**成功是一行 stdout、失败是 `assert` 抛异常** ——
异常没有 stdout 可比。所以这一格**只比成功那一趟**，失败那一档两边各写各的语气
（孪生自己说缺哪些词并退 1）。这与第 1 格的 `--fix` 是同一种边界：**该划出去的划出去，
并写明白**。

**一处自查没抓住、判据会抓住的**：我把 `"syn keyword loment"` 的长度写成了 20（真的
是 18），编译照样过、跑起来也"像是绿的" —— 抓住它的是那条**独立清点**（孪生报的两个数
必须等于判据自己从 vim 文件里数出来的）。**"两边相同"型判据必须配一条独立期望值**，
这是本仓反复讲的那条。

#### 第 4 格（`lom_spec_emit`）：**动工了又撤回**，把查清的东西留在这儿

写了一半发现它是**这批里最大的一格**（三种块 + 一个 JSON 转义器 + 输出顺序与文件顺序
不同），当时那份已经出现占位函数与死表 —— 那不是能落进本仓的东西，所以**撤掉**，不硬凑。
下次按下面这几条重开：

1. **输出顺序 ≠ 文件顺序。** 文件里是 `meta -> param -> enum`；JSON 是
   `$schema/title/version/authority` → **layers** → **primitives**（来自 enum）→ formats →
   gates → deployment_params。**一趟流式发不出来**，必须"先收表、再按 JSON 顺序发"。
2. **判据只走 `--check`。** 写盘那一趟会把 `LinuxFUAI/spec/spec.json` **建出来** ——
   那是**伪造对岸的对照物**（`CLAUDE.md` 第 1 条明令不许）。所以判据不碰写盘那趟。
3. **它的 stdout 里有绝对路径**（`{t}` 打的是 `Path`），两边平台不同 —— 判据要么成文地
   收敛成仓库相对路径再比，要么只比**写出的 JSON 字节**（那份里没有路径，是干净的）。
4. 格式细节（照 `json.dumps(..., ensure_ascii=False)`）：分隔符 `", "` / `": "`；键一律
   双引号而 `deployment_params` 的数值是**裸的**；缺的键写 `null`；组内最后一项后不加
   逗号、`primitives` 段结尾**总是** `],`、param 里每个键**都**带逗号（`note` 最后不带）；
   结尾一个换行。

#### 第 5 格（`potato_assert`）：**"比写出的字节"抓到的是参考实现的宿主依赖**

这一格 157 行，比前四格厚（要 JSON 解析 + 目录枚举），踩到五处：

1. **别靠传递依赖，把 `use` 写全。** 孪生要 `load16`（在 `loment/lib/bytes.lomt`）。我
   只写了 `use json`，而 `json.lomt` 自己 `use bytes` —— 平名字空间下**检查器照样放行**
   （名字从依赖里可见）。但那是**隐式**的：探针程序里同样一段代码就报
   "调用未定义的函数 load16（跨模块调用需要 pub）"。**用谁就写谁的 `use`。**
2. **后缀要当后缀比。** `is_potato` 我一开始写成"名字长度 == 12 且整名等于
   `.potato.json`" —— 把后缀字面量的长度当成了整名长度。语料里 `ahci.potato.json` 有
   16 个字节，于是**一个文件都收不到**，报的是"没有形式对象"（离真正的原因很远）。
   抓它的是那份最小探针（单独打印 `getdents64` 回来的原始记录），不是编译错误。
3. **自举侧一张形参表只有 10 槽。** `row_add` 我写了 12 个形参：参考实现照编不误，
   **种子上 11 个以上就 `panic(10)`** —— 退出码 132、**一个字都不输出**（比"报错指错地方"
   更狠的一档: 连话都不说）。判据第 4 条（自举链）抓到的。改法是把 12 个标量换成
   **一个 10 个字描述符的指针**（形参降到 3 个）。上限本身 `SKILL.md` 早有
   （"形参最多 10 个"），**没写的是失败形态** —— 已补进那一行。
4. **"比写出的字节"不是形式主义: 它抓到参考实现随宿主换行。** `potato_assert.py` 的
   `write_text(want, encoding="utf-8")` **没给 `newline="\n"`**（另外两个生成器
   `loment_syscalls.py` / `lom_spec_emit.py` 一直都有）—— Windows 上产物是 CRLF、
   Linux 上 LF，也就是**同一个形式对象集的产物随宿主变**，与 §3.0 S3 的判据
   （"生成是确定的"）直接冲突。`--check` 看不见它（`read_text()` 的通用换行会把 CRLF
   折回 LF，同机自洽）；只有把两边写出的字节摆在一起才现形。**已在参考实现那一侧修掉**
   （改的是参考实现, 不是孪生 —— 孪生那侧本来就是 LF）。
5. **`--check` 的两条消息里带一个路径，那是平台不是工具。** `Path.relative_to` 给的是
   **本机**分隔符（Windows `\` / WSL `/`）—— 同一份 Python 换个平台换个分隔符。判据只在
   这两条消息上折成 `/`，并且**先把归一的合法性钉死**：`--print` 的内容里一个反斜杠都
   没有（那条断言就在同一格里），所以替换只可能碰到路径分隔符。

另外两件是**这一格实现了、别格可以直接抄**的：

* **JSON 用 `loment/lib/json.lomt`，不要手搓扫描器。** 它是给 LSP 写的，`json_get` /
  `json_str_into` / `json_as_u32` 正好够（`loment_json_test` 已经钉过它）。
  它**没搬的部分**是 `potato.validate()` —— 那是对**形式对象自身**的校验（`potato.py`
  的另一件事），在合法语料上一个字都不输出，判据比不出差别；这一档孪生不复制，写在头注里。
* **目录枚举照抄 `lomrel.lomt` 的 `scan_dir`**（`getdents64` 记录: `d_reclen` @16、
  `d_name` @19、按字节插入排序）。

#### 第 6 格（`loment_extblock_test` 第 1–4 条）：**输入用文件交，别用字面量**

这一格检的是"外部代码块正文的字节保真 + 消歧"，纯词法，没有外部进程。三处值得记：

1. **被检的那段正文，正好是"字符串字面量装不下"的那段**（它带 `"` / `\` / `\0` / 非
   ASCII）—— 所以**孪生不能把它写成 Loment 字面量**（那正是 `docs/185` 要证明的事）。
   做法不是硬编码，是**判据把八个输入文件写出来, 孪生按固定文件名读进去**: 文件名成为
   两个实现之间的接口, 输入同一份。
2. **判据那一侧的期望值用 `lomc.lex`（参考词法器）算, 孪生用自举侧
   `loment/selfhost/lexer.lomt`** —— 于是这一格顺带成了"两个词法器在外部代码块上给出
   同一个答案"的判据。自举侧词法器**能当普通库用**（`use lexer` + `pub fn lex`），
   token 是 20 字节记录（kind/off/len/line/col）。
3. **"字节保真"的操作定义要写对**：不是"与某个 Python 字符串相等"（那会把"两个实现
   都把转义解成同一个错"当成通过），而是 **raw token 的 `(off, len)` 正好被 `{` 与 `}`
   夹住**（`src[off-1] == '{'` 且 `src[off+len] == '}'`）—— 判据的两侧都这么断言。

**没搬的一档**：`test_body_round_trips_into_potato`（正文进 Potato v5 并过校验器）——
那要自举侧的 potato 通路（§4 那根轴），本格不碰，写在孪生头注里。

#### 第 7 格（`loment_json_test`）：**搬到 Loment 侧反而更短** —— 探针那一层没了

这一格是 §2 点名的第三种形态（**对外部神谕的**）的第一格：对照物是 **CPython 的 `json`**，
神谕不搬，Loment 侧出观察、判据那侧用神谕出期望，比 stdout。三处值得记：

1. **参考实现那侧要"生成一份探针源 -> 编出来跑", 而 Loment 侧不需要那一层。**
   原因很直接: Python 调不了 Loment 的库, 只能把被测逻辑写成一份 `.lomt` 再编;
   而 **Loment 程序自己就能 `use json`** —— 于是这一格从"三件套"缩成"一个程序"。
   ⇒ **丙/丁里凡是"编一个探针来测某个库"的判据, 搬到 Loment 侧都会变短。**
2. **观察要覆盖库的**两条路**, 不然另一条会悄悄漂。** `json.lomt` 取字符串有两条路:
   `json_str_into`（解码, 含 `\uXXXX` 与代理对）与 `json_raw_off/len`（原文区间）。
   只测其中一条, 另一条坏了照样绿。所以规则写成: **str 取解码后的、num 取原文区间**、
   obj/arr 空串。
   *例外*: `true` / `false` / `null` **没有原文区间**（`j_parse_lit` 建节点时给的是
   `(0,0)`）—— 它们的拼法由 JSON 规范定死, 这两种观察合起来正好把这条**也钉住了**。
3. **`return;` 不合法**（`return <expr>;` 必须有值, `SKILL.md` §3 那张表里写着）——
   我照着"提前返回"的习惯写了一次, 报的是 `期望表达式，得到 ';'`。改成 `if/else` 即可。

#### 第 8 格（`loment_std_test`）：**同一句话的第二次兑现**

与第 7 格同形（对外部神谕、探针那一层没了），只多一条**新的坑**：

**`_start` 不能 `return`。** 参考那侧的探针写成 `fn _start() { … }` 收尾不带返回
（它末尾直接 `syscall4(60, …)`）；我照第 5/6/7 格的形状写成 `fn _start() -> u32`
却收尾 `return 0` —— **段错误、一个字都不输出**。原因是 `_start` 是 ELF 入口，
栈上压的是 **argc/argv**, 不是返回地址, `ret` 就跳进垃圾里。同一个坑的另一半
（写成 `main` → lld 把入口留成 0）§第 1 格已经记过；这次是**同一件事的第三种写法**。
已补进 `SKILL.md` §3 那张表（原先只写了"freestanding 入口"）。

#### 第 9 格（`lomc_test`）：**被测对象是另一件 Loment 程序** —— 判据当场抓到一处真缺陷

这一格与前面几格都不同: 被测的不是一个库、不是一件工具, 而是**另一件 Loment 程序**
（`loment/tools/lomc.lomt`, L0 编译器的 Loment 版）。于是判据只能走它的**命令面**
（`--print json` + 退出码 + stderr 上的诊断), 判据那侧也得按同一套"看产物"的规则算期望
—— 不能复用上面那些进程内摸 `mod.records` 的检查, 否则比的是两种不同的断言。

四处值得记：

1. **`proc_sh` 的命令只能是编译期字面量。** 它收的是 `str`, 而语言里**没有 ptr -> str
   的构造**（内建只有 `str_len/eq/concat/byte/ptr`）。所以命令行里的路径只能是**相对
   字面量** —— 判据把工作目录设成一个**每次一份**的临时目录, 里面放好 `./lomc`（被测
   二进制）与各个输入。并发跑门禁的两个进程各在自己的目录里, 不会互相跑对方的东西
   （`_T` 那条纪律的同一个理由）。
2. **退出码要紧挨着被量的那句话取。** 我先写的是 `cmd …; echo; echo -n "|rc=$?"` ——
   中间那句裸 `echo` 把 `$?` **冲成 0**, 于是 15 条命令的退出码**全是 0**; 正例凑巧期望
   0 才没露馅, 负例（期望非 0）**全红**。改成 `r=$?; …` 先存再回显。
   （`lomeol.lomt` 里那条尾巴没有中间那句 echo, 所以没踩到。）
3. **判据当场抓到一处真缺陷**：`lomc.lomt` 原先**放行**重复的 meta 键 —— 参考实现
   （`tools/lomc.py` 的 `parse_meta_body`）是拒的。已在同一笔改动里补上（`meta 键重复`,
   按"同一层"判: 用 `MK_OPEN`/`MK_CLOSE` 深度计数把嵌套块的键排除掉 —— 池**不去重**,
   所以同名键在池里有两份、只能比字节）。顺手补了顶层 `meta 块重复`（空 `meta { }`
   也是 0 条, 所以另开一格 `C_HASMETA` 记"见过", 不能拿 `C_TOPMETA` 兼）。
   补完之后 `loment_lomc_test`（孪生 vs 参考, 逐字节）**仍然全绿** —— 没有回归。
4. **措辞的差别要按类别收。** `lomc.lomt` 的诊断比参考**简**（重复枚举值: 参考
   `E.b 与 .a 同值 1（枚举值必须唯一）`, Loment 版 `枚举值重复`）。所以判据按**类别**
   断言（"重复值" 收 `重复` 或 `同值` 两种说法), 不照抄某一边的句子 —— 那不把措辞
   变成判据, 也不假装两边一样。

#### 第 10 格（`loment_comefor_test`）：**又抓到两处真差距，还顺带顶破了种子的上限**

同第 9 格的形状（驱一件自举侧的 Loment 程序），四处值得记：

1. **`byuse` 收一个没定义过的名字，原先静默通过**（退出码 0）。根因: 驱动只看
   `has_comefor`, 而它只认 `comefor` —— 于是**只有 `byuse` 的文件整趟展开都不跑**,
   "收的不是任何在用的方言"那条守卫**根本走不到**。改法: `has_comefor` 也认 `byuse`
   （名字没改，语义是"这一份要不要过展开器"）。
2. **体里的 `use` 没被拒**：参考侧在 `_body_module` 里拒, 自举侧会一路走到后面, 报成
   "名字导入找不到或有歧义"那种**指不到点子**的错。改法: 定义那一支里扫体 token 的
   标识符 `use`（`cf_is` 已限定 `kind == 0`, 与参考的 `_is_ident` 同义），返回新错码
   `10`，由 `comefor_fail` 说出来。
3. **测"体里不许 `use`"，得先让那句 `use` 有东西可解析。** 我第一版用内建的
   `use bytes`: 导入解析**在展开之前**跑, 而临时目录里到不了内建根 —— 于是它先报
   "名字导入找不到或有歧义", 真正要测的守卫**根本轮不到**（判据红了才发现测的不是那件事）。
   改成在输入目录里放 `deps/myhelper/myhelper.lomt` ✓, 让那句 `use` 能解析, 守卫才轮到。
4. **这一动顶破了种子的上限** —— 见下。

#### 顺带: **自举种子长过了 lomelf 的 2 MiB 输入缓冲**（上限抬到 4 MiB）

给 comefor 补那两处守卫（外加驱动里一条新错码）之后, 种子从 2095775 B 长到 **2098535 B**,
而 `lomelf` 的输入上限是 **2097152 B** —— **超出 1383 B**。这不是猜的:
上一轮刚落的 `loment_genesis_test::test_seed_fits_lomelf_input_buffer`（记余量的那条）
当场红, 并且 `bootstrap.sh` 的第 1/4 步**响亮地**报出 `lomelf: 输入 .ll 超过 2 MiB 上限`
（`docs/192` 补的那条守卫 ✓ —— 不是静默截断成一个启动就崩的二进制）。

⇒ 照 `docs/192` 记的那条待办办: **把 lomelf 的布局整体抬高**（输入 / 代码 / 输出各给
4 MiB, 表区与全局数据不动, `ARENA` 13.6 MB → 19.9 MB）。改完三件都绿:
`loment_seed_test` 4/4、`loment_genesis_test` 3/3（含上面那两条）、`bootstrap.sh` 全链。
**这条上限就是种子的上限** —— 余量只有 1.4 KB 时谁都可能顶破, 抬到 4 MiB 才算留了余地。

**没搬的一条**: `no_comefor_is_identity`（展开器不改无 comefor 文件的 token 流）——
那是**词法层**的判据（要 `use comefor` 的 token 级 API + 逐 token 比对），本格只走命令面；
同 `domain_is_the_builtin_table` 一条。写在孪生头注里。

#### 第 11 格（`loment_err_test`）：**同一份源的两个后端产物，渲染要一致**

同第 9/10 格的形状（驱一件 Loment 程序），三处值得记：

1. **报错器把整张卡写到 `stderr`。** `proc_sh` 只收 **stdout** —— 我第一版七条命令都没带
   `2>&1`，于是"载荷"永远是空的，**7 项全红**（而手工在 shell 里跑时我用的是 `> f 2>&1`，

   ⇒ **驱一个外部程序时，先确认它往哪个 fd 写**，再决定命令尾巴带不带 `2>&1`。
2. **两侧跑的是同一个源的两个后端产物**：Python 那侧跑 `lomenterr` 的 **PE**（Windows 原生，

   插入符、编号修法、汇总行），**一条都不碰路径** —— 所以两侧的诊断即使写着各自的平台路径，
   报告仍逐字节相同。这一格因此顺带是"两个后端渲染一致"的判据。
3. **诊断由判据写出来，不是拿参考编译器的 `--diag-out`。** 参考一拆那条路就没了，而且
   两个实现必须**看同一份输入**。
   ⚠ **这一格暴露了 S2 的一个待办**：`loment_err_test` 现存那 20 来条**夹具全来自

   是"如果夹具改由判据自己写"的样子；其余那些要么照这个样子改，要么随 S2 一起走。

#### 第 12 格（`loment_cli_test`）：**驱动器型里最难的一格，四处都得记**

被测的还是**另一件 Loment 程序**（`lomcli.lomt`，Python 那侧跑 PE、孪生那侧跑 ELF），
但它比第 9/10/11 格都难 —— 那一件的命令面有 39 条、每条的断言形状都不一样：

1. ⚠ **`alloc` 只有 64 KiB，而且不回收**（`SKILL.md` 的 `alloc(n)` 那一行写着）。
   孪生一开始是"一条命令一次 `proc_sh`"—— 而 `proc_sh` 每条 `alloc(PROC_WS)` = **4 KiB**，
   40 来条就是 **160 KiB**。症状最先不是崩，是**前面几条断言读到被踩坏的缓冲**
   （`hash` / `cat` 两条假红），再往后才是 `Illegal instruction`（panic，rc 132）。
   **修法**：判据写一个 `run_all.sh`（夹具, 与第 13 格的 `cases.txt` 同路数），每条命令
   前后打 `@@名字 退出码` 标记，孪生**一次** `proc_sh` 拿全部输出、再按标记切段。
   ⇒ 凡是"要跑十几条外部命令"的格子，先按 4 KiB × 条数 算一遍堆。
2. **抓到一条死判据**：`test_every_catalog_command_is_actually_dispatchable` 断言的是
   **中文** `未知命令`，而 CLI 的文案早就改成纯 ASCII 了（它自己的判据
   `test_every_command_outputs_pure_ascii` 就是那么要求的）—— 于是那条**永远为真**，
   目录里真列一条敲不动的命令它也不会红。判据与孪生**两边一起**改成 `unknown command`。
3. **`doctor` / `where` 是按 `argv[0]` 那个目录找工具的**，不是按 cwd。所以
   "红的那棵树"必须用**它自己的**那份二进制去跑 —— 拿另一棵树的二进制，体检会读到
   错的组件表（实测：`p_red` 里一个桩都没有，却报 all green）。孪生那侧的
   `cd ../p_red && ./bin/loment-cli doctor` 是自然对的。
4. **两侧不能共用一棵可变的夹具树**：`new hello` 会往 `newdir/` 里落一个文件，
   先跑的那侧一落，后跑的那侧的 `new` 就变成"已存在"（实测踩到）。现在两侧各一棵。

**断言必须与平台无关**，否则两侧报告不可能逐字节相同：绝对路径一处都不比
（`example nope` 的报错里带着它、`examples`/`env` 打的是从 `argv[0]` 推出来的目录），
只比退出码 / 相对路径回显 / 行号 / 计数 / 子串。期望值（sha256、字节数、行数、错误码表）
由判据拿 **CPython 当神谕**算出来写成夹具。

**其余还没搬的（同类，都不便宜）**：`loment_src`（要 git + 比写出的包字节）、
`loment_audit`、`loment_manual`（要加载每个示例）。

#### 第 14 格（`loment_lib_test`）：**先把孪生从 1 条命令扩到 2 条，再对拍**

丁类的最后一件，也是这一轮里唯一**要先扩工具、再搬判据**的一格：`lomlib.lomt` 原先只做
`id`（一次递归哈希），而判据要的是**整棵实例图**。`tree` 就是那个视图：去重后的实例树、
每条边 `-> 名字 版本 [身份前 8 位]`、重复实例的 `（同一实例, 已见）`、`[OK] n 个实例`、
多版本那条 `[NOTE] 同名多实例`。

六处值得记（**五处是踩到的内存/顺序坑，一处是真缺陷**）：

1. ⚠ **`alloc` 是 64 KiB 的 bump 堆，而本程序把 256 KiB 的静态区全 brk 出来了。**
   打印路上用 `alloc` 的后果很怪：**输出全对**、进程在**函数返回时**才死
   （ELF 上 rc=132 SIGILL、PE 上 0xC0000005）。改成 M_TMP 里的静态暂存就好了。
   （与第 12 格同一条纪律的两副面孔：那边是"调用次数 × 4 KiB 顶穿堆"，这边是"堆与静态区
   不相干，但 `alloc` 自己也不够用"。）
2. **`S_INFO + 224` 是 `sha_final` 的 64 字节摘要格**，它跨过 S_INFO 的尾巴伸进 `S_EDG`
   头 32 字节 —— 所以 S_INFO 里**没有**真空闲。版本一开始放在 `+200`，正好被那份摘要盖掉，
   版本永远是空的。版本/边数因此挪到每层尾巴（`S_VER`/`S_VL`/`S_LEC`）。
3. **边数那个共用标量格会被子层踩掉**：`ident_of` 打完这一层还要回来读它，读到的却是
   最后一个叶子层的 0（症状：边一条都不打）。现在 `collect_edges` 之后往本层存一份。
4. **`M_SEEN` 一开始摆在 `M_CB`（196928）= argv 缓冲的头上**，而 `dirp` 就指着里面那一段：
   第一次 `seen_add` 就把命令行的头 64 字节盖掉 —— 身份随即全错、版本读不到。
   两张新表改从 201024 起（argv 缓冲之后）。
5. **顺序**：Python 的 `_tree_lines` 是"打一条边、**立刻**展开它、再打下一条"（交错），
   不是"先把边列全再逐条展开"。第一版按后者写，输出整段错位。
6. ✅ **抓到一处真缺陷**：边扫描的门槛写成 `e > s + 5`，于是 `use b` 这种**单字符依赖名**
   （整行正好 5 个字符）**被静默丢掉** —— 环、菱形、多版本这些夹具用的都是两字符以上的
   名字，所以从没暴露。新加的环夹具（`a` use `b`）当场抓住。改成 `e > s + 4`。

**没搬的**（都写在孪生文件头）：`cap`（要一份能力声明扫描 + 去重闭包）、
`check`（要按 token 判"引用了一个有多个来源的名字"）、`materialize`（要按 token 改写源码）。

#### 第 15 格（`potato_test`）：**丙类最后一件，也是"判决要对齐"最严的一格**

`lompotato.lomt` 是一份**独立的 Potato 校验器**（只吃 JSON，不 import 编译器 —— M47 那条
纪律照旧），对着 `potato.py` 的 `validate` 跑：判据把 **98 份对象**（48 合法 / 50 非法）
喂给两边，比的是 **stdout 逐字节相同 + 退出码相同** —— 也就是**接受/拒绝**与**错误条数**
两样都对上（不是只对上"收/拒"）。

它比前面几格都长（约 1500 行），八处值得记 —— **前六处都是"这一格独有的坑"**：

1. ⚠ **两个哨兵不一样**：`json_first_child` / `json_sibling` 的链尾是 **`0`**，而 `json_get`
   缺键是 **`FAIL`**（4294967295）。写成 `while c != FAIL` 就是**死循环**（第一版在空对象上
   转不出来）。本文件把它们统一裹成 `FAIL`，免得每条循环都要记是哪一种。
2. **`const` 只吃整数<u>字面量</u>**，不接受算式 —— `const TB_TP: u32 = M_TB + 0 * TA;` 是语法错
   （`期望 number（整数）`）。表基址只好写死，算式留在注释里。
3. **void 函数不能写 `return;`**；把它们改成 `-> u32` 之后**必须在末尾补 `return 0;`** ——
   掉了就是"函数末尾掉下去"，**在返回时才崩**（与第 14 格那个 `alloc` 坑同一个症状）。
4. **枚举变体是裸字符串**（要用"值就是标识符"的那个帮手），不是带 `name` 字段的对象；
   拿错帮手 → 每个变体一条假错。
5. **解码缓冲不能拿"正在比对的那一块"**：`find_trait_methods` 一开始把候选 trait 名解进
   `M_SB`，而 `tn` 就指着 `M_SB` —— 名字当场被盖掉，合法对象被判非法。trait 名另给一块。
6. **"缺字段"只许报一次**：`chk_v1`（版本必填那五行）报过了，`chk_generics` 那几个就不能
   再报一次 —— 否则错误条数多 1，判据红。同理**泛型参数的个数要数全**（重复的那个也算，
   Python 那边是 `list(ps)` 的长度），漏数会让 `instances` 的"args 数量不符"漏报。
7. **名字表容量**：自举的 `selfhost_codegen` 有 **121 个函数** —— 64 条的表当场溢出、
   每多一个报一条错（40 / 57 条假错）。抬到 256。输入缓冲同理（那些对象已到 44 KB）。
8. ✅ 这一格**没抓到 Python 侧的缺陷**（前几格各抓了一条），但它把"判决 + 条数"两样都
   钉死了 —— 比只比"收/拒"严一档：漏实现一条规则、或多报一条，都会红。

**没搬的**：`potato.py` 的文案（每条错误里插了 Python 值的 `repr()`，Loment 侧复现不了）
—— 文案那半留在 `MUTATORS` 表里（每条反例钉一个错误片段）。

#### 第 16 格（`loment_ctrans_test` 的前端那一半）：**§4.1 那根轴的第一块**

`lompotc.lomt` 是 **C 源 -> Potato 对象** 的 Loment 版（对着 `potato_from.from_c` 移植，
不是对着 `ctrans` —— 判据走的是 `from_c -> lomt_from` 这条链）。判据加了两条：**27 份 C
（五份语料 + 22 份自带小输入）产出的对象逐字节相同**；孪生另走种子自举链编译且 IR 相同。

**它比前面几格难**：上游那四条扫描是**正则**（`_C_STRUCT` / `_C_FIELD` / `_C_ENUM` /
`_C_FN`），Loment 没有正则 —— 手写的扫描器要逐条对齐语义，含 `_C_FN` 里那两处**惰性量词**
（"`group1` 短、`\s+` 紧跟"⇒ 掐掉尾部空白后最后一个标识符就是名字；"`\s*` 在 `[;{]` 前"
⇒ `)` 之后可以跨换行）。

八处值得记 —— 前五处是**语言/工具面**的坑，后三处是**这一格独有的**：

1. **`const` 只吃整数<u>字面量</u>** —— 表基址只好写死（与第 15 格同一条；这已经是第二次撞）。
2. **void 函数不能写 `return;`**；改成 `-> u32` 之后**末尾必须补 `return`** —— 掉了就是
   "函数末尾掉下去"，**在返回时才崩**（第 14/15 格也是同一个症状，第三次撞）。
3. **字符串字面量不能跨行拼接**：`"...` + 换行 + `"..."` 是语法错（`期望 )`）。整串写一行。
4. **本语言没有 `continue`** —— 抹 `#` 指令那段循环要改成 if/else 结构。
5. **`M_CNST` 开小了（100 条 × 72B = 7200，只给了 4096），写越界过了 brk → 段错误**；
   而且"源长度"那个标量还存进了与它重叠的槽。两个 bug 叠在一起，症状是"四份崩、一份空"。
6. **"算出来了却没存"**：参数类型文本我只把 `*` 写进了缓冲，普通 token 没写 ⇒ `to == 0`
   ⇒ 每条参数判定都失败 ⇒ **每一份都输出 0 个函数**。纯文本比对让这种半成品立刻现形。
7. **共享暂存的槽要想清楚谁在什么时候踩谁**：`last_tok` 起初把名字起点写进 `M_R+0`
   （`R_NO`）—— 正好把刚扫出来的**函数名**盖掉，输出的名字成了 `"b) "`。
8. **⚠ 这是"一根轴"，不是"一格"**：`lomt_from`（Potato -> Loment 源）、
   `from_class_lang` 的 **C# 那一半**、`from_python` / `from_rust` / `from_go`、
   以及 `trans_core`（语法树那条路）**都还没有 Loment 版**。`lompotc.lomt` 的文件头写着
   同样的边界。

**C++ 同一天跟着进来了**（`lompotc --cpp`）—— 上游两门本来就是**同一个引擎**
（`_from_c(..., grammar, types)`），差异只有类型表那一张。但它一次就撞出**两个**坑：

9. **哨兵值撞上车长度**：我用 `2` 表示"命中但这一门不映"（C++ 的 `char` / `char *` /
   `const char *`）—— 而 **`i8` / `u8` 的长度就是 2**。于是**凡是映到两个字符的类型**
   （`char`、`signed char`、`unsigned char`）全被判成"无映射"，函数整条消失。
   症状极具误导性：`unsigned int`（→`u32`，3 字符）过，`unsigned char`（→`u8`，2 字符）不过。
   ⇒ **哨兵要用不可能与真实返回值重合的值**（改成 `FAIL`）。
10. **`M_CAP - 2048` 当 argv 缓冲 —— 那正好压在 `M_SC` 上**：读一次 cmdline 就把"源长度"
    与"模式"盖掉。C 那一侧一直没露出来（argv 短、名字短），C++ 一上来（多一个 `--cpp`、
    临时目录里的名字又长）就现形：unit 名多出 4 个下划线、或者干脆"打不开源文件"。
    ⇒ **缓冲区不能靠"从末尾倒着算"来摆** —— 末尾那个常量改一次它就压到别的东西上。

**Java 同一天跟着进来了**（`lompotc --java`）—— 上游 `_from_class_lang` 是
"函数住在 `class X { … }` 里"这一族的共用引擎（Java / C#），**与 C 那套完全不是一批扫描器**：
类体要按花括号**配平切成员**（深度 0 上遇 `;` 或一段完整的 `{…}` 收一个），
类型走另一张表（`char` 是 **16 位无符号** ⇒ `u16`；装箱类型与 `float`/`double` 显式无映射），
而且**字符串字面量先换成 `""`、抹注释在后**（那一层**会改长度**，所以走 `M_SRC2 → M_BODY` 两级）。
判据：`loment/jtrans/` 三份语料 + 51 份自带小输入（**54 份**）产出的对象逐字节相同。

四处值得记：

11. ⚠ **`_JAVA_METHOD` 的参数表我要的是"起止"，一开始存成了"长度"**。症状极有误导性：
    带参的函数**整条消失**、无参的 `entry()` 却好好的 —— 因为 `a > b` 时那段遍历
    一次都不跑，`jparams_ok` **空转返回 1**（"没有参数要判"）。⇒ 校准一个下标口径时，
    先拿**空输入**试一遍：空输入走的那条路会把口径错误伪装成"通过"。
12. ⚠ **`body_line` 数的是"字符行号"，而缓冲是字节**。上游 `_body_at(src, off, raw)` 的
    `off` 是 Python 字符串的**字符**下标、数的却是**原文**的换行 —— 而 `jtrans/*.java`
    的注释里全是中文（UTF-8 一个字符 3 字节）。第一版按字节下标数，`Bits.java` 上少了 2 行
    （正好是那份注释里两个多字节字符的差）。⇒ 自己加的两个帮手：`chars_n`（数**字符**）
    与 `line_at_chars`（数**字符**下标之前的换行）。
13. ⚠ 上面那条**不能拿"抹过注释的 body"去数**：`blank_noise` 是**逐字节**把注释写成空格的
    —— 一个中文字被写成 3 个空格，于是**字符数凭空多 2**（`chars_n(body, ms)` 直接爆到
    19 行）。要在**没抹过的那份**（`M_SRC2`）上数。**"等长"是对字节说的，不是对字符说的。**
14. ✅ **顺带修了 C 那边的同一处**：`emit_one_fn` 的 `body_line` 原先也是按字节下标数的
    （`line_of(src, ms + lead)`）。C 语料这次全绿并不说明它对 —— 只是那五份里多字节字符
    没正好压在换行边界上。改成字符口径之后 C/C++ 那 37 份**仍然全绿**（反而更贴上游）。

**C# 也进了同一份孪生**（`lompotc --csharp`）—— 上游 `from_csharp` 与 `from_java`
**共用** `_from_class_lang`（`docs/188` §7.1 的"一份解析器 + 方言表"），所以这一门不是
"再写一个引擎"，而是**把那四张正则与一张类型表变成参数**（把 `mode` 串下去）。
三处不同的地方：声明形状多收 `struct`（且修饰词是**一整张反复的表**，连 `public` 都在
里面，与 Java 那个"可选 `public` + 反复的 final/abstract"不同形）、常量是 `const`
（**隐含 static**，没有 `static final` 那一截）、成员修饰词表多 `internal`/`sealed`/
`partial`/`async` 那十六个；类型表里 **`byte` 是两门唯一没落在同一格上的**
（C# 无符号 ⇒ `u8`，Java 有符号 ⇒ `i8`）。判据 34 份（三份语料 + 31 份自带小输入）。

15. ⚠ **"两门共用"的那张表最容易悄悄串味**：我把 `final` 留在**共用**的修饰词扫描里，
    于是 `static final int K = 5;` 在 **C#** 下被吃成"修饰词 `static final` + 字段 `K`"
    —— 而上游 `_CS_MODS` 根本没有 `final`，那一行是"无映射、丢掉"。C# 那一格的自带小输入
    （`cs_static_final_is_not_const`）当场抓住。⇒ 抽共用表时，**"哪些词只在某一门里"要逐条
    对一遍**，别默认"多认一个无害"：多认一个就是**把一门的东西按另一门解释**。
16. **`String` / `boolean` 是 Java 那张表里的**：共用尾巴不挡的话，C# 的 `String x;`
    会被判成 `str`（上游是"无映射"）。同一条纪律的另一半 —— **共用的部分要能"这一门不算"**。

**Go 也进了同一份孪生**（`lompotc --go`，第三条支路）—— 上游 `from_go` 与 C/C++/Java/C#
**都不是一批扫描器**：类型写在**名字后面**、条件不带括号、没有 `while`；它仍是**轻量解析
那一派**（三条正则），所以能照抄。判据 32 份（一份语料 + 31 份自带小输入）。

17. ⚠ **"攒着的名字 + 这一段自己的名字"要一起发**：分组形参那一步对应的是
    `for n in pending + [pn]`，第一版只发了 `pending` —— 于是**最常见的 `func f(n int)`
    一个形参都不发**（语料里每个函数都中）。`a, b int` 那种反而正常，因为那时 pending
    里有东西。**"只错最常见写法"的 bug 靠自带小输入兜不住**（那里若只写分组写法就漏了）
    —— 要靠真语料，两边都得有。
18. ⚠ `struct` 的体**不是**配平出来的：`(.∗?)^[ \t]*\}` 到**第一个以 `}` 起头的行**为止。
    第一版按"配平"写，`type P struct { x int }`（一行写完）会匹配上 —— 而上游**不匹配**
    （`^` 要求行首），整个 struct 该丢。⇒ 转正则时**连"它匹配不上什么"也要照抄**。

**Rust 也进了同一份孪生**（`lompotc --rust`，第三条支路）—— 与 C 那套、类体那套都不是
一批扫描器：类型写在名字**后面**、结构体字段按**逗号**切、常量要**真算值**。判据 76 份
（`kernel/src/*.rs` 六份真核代码 + 70 份自带小输入），而且这一格**连跳过项
（`S <类别> <名字>`）与字段损失（`F <宿主> <字段>`）一起比** —— 上游那个 `Report`
的信息量在这儿，不比就等于放着"静默丢掉"没人管。

19. ⚠ **`int(t, 0)` 是一整套规矩，不是"读个十进制"**：十进制**不许有前导零**
    （`010` 是错，Python 的 base 0 就这样）、认 `0x`/`0b`/`0o`、符号写在前缀**之前**、
    后缀（`u32`/`usize`/`i128`…）**只剥一次**。第一版按"去掉下划线再 `int()`"写，
    `010` 会当 10 收下 —— 而上游是"跳过并出声"。
20. ⚠ **`known` 进场的时机要分开传**：上游那一圈是 struct 先、enum 后，所以
    "struct 的字段引用一个 enum"在 struct 圈里**查不到**（字段被丢 + 出声），
    而常量/函数那两圈排在枚举之后、看得到枚举名。第一版把两圈一次做完再解字段
    ⇒ `enum E { A } struct S { e: E }` 多出一个字段来。⇒ 同一张 `known`，**不同用途
    要按上游的时机分别组装**（这里是一个 `withenums` 参数）。
21. ⚠ **字段损失要在"这个 struct 整块不发"时也出声**：第一版把笔记放在
    "有字段才走"的那一支里 ⇒ 全字段无映射的 struct 只报"整块丢"，丢的是哪几个字段
    一个字都没有。上游那两件事是**分开记的**（`skip` 与 `skip_field`）。

#### 第 17 格（`loment_multisyntax_test` 的**发射那一半**）：`Potato -> L1 接口单元`

`lomtfrom.lomt` 对着 `tools/lomt_from.py::emit_lomt(doc)`（**默认那条路**，`impl=False`）
移植：把形式对象发成一份 `.lomt` —— 头部三行 + `module` + 能力域 + 常量 + 结构体 + 枚举 +
`pub extern fn` + `excluded`。**这一格与第 16 格是一对**：`lompotc` 是"源 -> 对象"，
本格是"对象 -> 源码"，合起来才是判据走的那条 `from_c -> emit_lomt` 整条路。

判据：113 份对象（仓库里**已提交**的 43 份 `loment/build/*.potato.json` + 五门语料经
`potato_from` 转出来的 13 份 + 57 份自带的），比 **stdout 逐字节 + 退出码 + 跳过项的名字**。

四处值得记：

19. ⚠ **枚举变体是裸字符串**（`{"variants": ["A", "B"]}`），不是带 `name` 字段的对象 ——
    按对象那套读，**每个变体报一条假错**（整份对象被拒）。第 15 格（`lompotato`）
    已经在同一处栽过一次，这次又栽 —— **同一份 schema 的同一个坑，换个工具照样踩**。
20. ⚠ **`_ty("")` 也是错**（`not isinstance(t, str) or not t` 里的 `not t`）：
    我的 `sval` 对空串返回长度 0、不是 `FAIL`，于是"空类型"被当成合法值发了出去。
    ⇒ 把"取到了但为空"与"没取到"分开判 —— 与第 15 格那条"两个哨兵不一样"是同一类。

    `None`/`""`/`0`/`False` 都落到 `"()"`（**合法**），而 `True`/数组/对象是"真值"

**没搬的**：`--impl`（带正文的函数交给 `ctrans`/`pytrans` 翻成真实现）要的是**整条语法树
那条路**（`trans_core` + 六门方言），那是另一根轴；`--lang`（先转写再发射）与 `--out`

#### 第 18 格（`trans_core`）：**语法树 -> Loment 源码**

四门（C / C++ / Java / C#）共用一份扫描器 + 一个递归下降 + 一个发射器，差异是**一张方言表
加几个开关**（`safe_suffix`、两个 `coerce_*`、`int_default`）—— 孪生照搬这个形状，
一个 `if <语言>` 都不写。判据：141 份源，**stdout 逐字节 + 退出码**（成功/子集外/解析不过
三种退出码，所以"没实现"与"你写错了"仍然分得开）。

五处值得记（前两处是**又一次**同一类坑）：

23. ⚠ **暂存格被嵌套的同名构造盖掉**。`if` 的 `then`/`else` 的 (start, count) 我先写进
    `st+400/404`，等整个 `if` 解析完再取 —— 而 `else if` 里那个内层 `if` **用的是同一批格子**，
    于是外层的 `then` 拿到的是内层的语句。**`if / else if` 链上必现**，语料里到处是它。
    上游那半边是局部变量（`then = self.block_or_stmt()`），天然没这个问题 ——
    **"照抄结构"照抄不到"上游靠什么活着"**。修法：一拿到就抄进局部。
24. ⚠ **`guard` / `as` 是 Loment 保留字**。拿它们当变量名，报的是"期望 ident（能力名）"
    （指不到点子上）。第 1 格那条"`const` 初始化器只吃整数字面量"的同一族：**写 Loment
    得像查着关键字表写**，编译器的报错在这类错上帮不了你。
25. **行有三种，不是一种**：函数头**不缩进**、收尾的 `}` **不缩进**，而 `}` / `} else {`
    **要缩进**（上游是 `lines.append(head + " {")` 对 `self.out("}", depth)`）。
    另加一条隐形的：`gap()` 判断"上一行是不是空/以 `{` 收尾"里的**以 `{` 收尾**是一个
    要显式传的标志 —— 漏标 `} else {` 的话，`else` 块里第一个控制流前面会多一个空行。
26. **名字池与"拿谁当基准比"必须同一个池子**。`--keep` / `--const` 的名字住在 `M_SCR`
    高处（因为查名字两边都拿 `M_SCR` 比）；外部函数表不一样 —— 它的键来自调用点，
    两边各是各的池子，靠 `same_n` 的两个指针参数比。混了就是静默查不到。
27. **`--extern` 收进来的条目占着函数表 `1..n`，而解析起点把游标抹成 0** ——
    第一个真函数把它们整个盖掉（症状：外部函数的返回类型**静默失效**，调用点按本单元的
    看法走）。这类"两处各自初始化同一个游标"的错，只在**同时用**那两条路时才露头。

**没搬的**：`--tokens` / `--pre` / `--ast` 是孪生自己的调试开关（不是上游接口），
判据不碰它们 —— 它们的作用是把"读错了"和"发错了"分开。

#### 第 19 格（`from_python`）：**坐在 `ast` 上的那一门**

**先纠正一句自己写过的话**：这一格原先记的是"要 Loment 侧先有一个 Python 解析器"。
**探过之后不成立** —— 上游 `from_python` 只读 `tree.body` 那一层（模块级的 `def` /
`class` / `NAME = <整数>`），**函数体一个字符都不解析**（`ast.get_source_segment` 就是
按位置切原文）。所以真正要的是**一台按缩进的顶层扫描器 + 一台很小的整数折叠器**，
不是把 Python 的语法搬一遍。这与第 5 格那条"一处语义差是探出来的、不是推出来的"同源：
**"要付多大的工"同样得探，不能推。**

四处值得记：

28. **`fc == 0` 不能当"还没有代码字符"的哨兵** —— 行首那个位置**就是 0**，于是第一个
    字符写下 `fc = 0` 之后，下一个字符又把它改掉，`fc` 一路漂到行尾。症状是 `ind` 变成 1，
    顶层那一支（判 `ind == 0`）**整支进不去，一条函数都发不出来**。同一个形状在第 18 格
    的"暂存格被嵌套构造盖掉"上出过一次：**哨兵值必须与合法值不相交**。
29. **循环步子要在子扫描之前存下来**。`py_block` / 类体那两个子循环都会重扫，
    把 `PY_NEXT` 推到最后看的那一行上；主循环直接拿它当步子就会**整段整段地跳过**
    （症状：三个函数只发得出两个，跨过去的那个一声不响）。三处同一个坑。
30. **"跳过"与"静默"是两件事**，而这一门最容易撞上后者：`A = 1; B = 2`（一行多条语句）
    上游按 `;` 切、两边都收，这里不做 —— **不做可以，但必须出声**（报 `S const A`）。
    单开一条判据钉着"出声"这一半，因为**判的是有没有声音，不是有没有收**。
31. **口径别混**：`py_ws(start, end)` 是 (起点, 终点)、`py_type_id(off, len)` 是
    (起点, **长度**)。四个调用点全按后者写错了一次，症状是**每条注解都"无映射"**
    （于是函数、字段、常量整片消失）。修法是把口径写进签名旁边，不靠记性。

**没搬的**：一行多条语句（见上，**出声地**不做）。

#### 第 20 格（`pytrans`）：**换行 + 缩进**那一门，机器要重写

第 19 格搬的是"源 -> Potato 对象"那一半（`lompotc --python`），这一格搬的是
**"语法树 -> Loment 源码"**那一半（`lomtrans --lang python`）。两者都对着 Python，
**但机器完全不同**：第 19 格读的是源码的顶层结构（不需要表达式语法），这一格要
**真的把语句与表达式解析出来**，而且 C/C++/Java/C# 共用的那台词法器与递归下降
（花括号 + 分号）**一点都不适用** —— 另写了一台会造 INDENT/DEDENT 的词法器与一台
吃缩进的递归下降。发射那一层也另写（规则不同：`bool -> int` 不转只报错、
`and`/`or` 是 **n 元**的、`for` 不改名外提）。

五处值得记（前两条是**同一族**：一个"值"到底是起点还是末端）：

32. ⚠ **`->` 漏在双字符运算符表里**。`def f(a: int) -> int:` 被切成 `-` 和 `>` 两个
    记号，于是**每条签名都读不出来**、一条函数都发不出去。症状与"表少一个词"完全不像
    （表现是"整个模块空"），只有把词法器单独对一遍才看得出来。
33. ⚠ **`app()` 返回的是"新的末端"，不是起点**。给文档字符串那一行拼 `"/// " + 内容`
    时拿返回值当起点去 `trimr`，于是空行裁不掉（`/// ` 带尾空格出去，上游是 `///`）。
    第 19 格那条"`py_sw` 跳过空白却不写回游标"是**同一族**：**这类函数的返回值到底是
    什么，用之前先看签名那一行**。
34. ⚠ **弹缩进时要先判"要不要弹"，再看"栈空没空"**。反过来的话，最后一层弹到栈底（0）
    会被当成"缩进不合法"报出来 —— 而**两个函数之间那一下必然弹到 0**，于是
    **多函数模块一条都发不出来**（单函数模块全绿）。单函数语料在这里是**看不出来**的。
35. **三引号的引号宽度**：三引号串的内容起点是 `o + 3`（引号占 3 字节），
    写成 `o + 1 + tq` 就差一格 —— **正文的首字符被吃掉**（从 `o+4` 起解）。
36. **`--const` 在两族里的含义不同**：花括号那一族只要"这个名字存在"（只有成员判断），
    Python 那一门要**类型**（`cenv` 的值就是类型）—— 表里得存类型，且**后写的赢**
    （上游 `cenv.update(consts)`）。带不带 `:类型` 的两种写法都要收。

**一处已知的子集外**：一行多条语句（`x = 1; y = 2`）**不收但出声**（退出码 1）——
静默少发一条语句照样编得过，只是少算一步。

第 1/4 步就报 `lomelf: 未定义的标签: `（**空白标签名**）。查下来是 `lomelf.lomt` 的
**全局表**（上限 2048，种子 1801 → 2086）与**回填表**（上限 16384，种子 15686）——
两张都是"单调 bump、没有边界检查"，越界就踩下一张表，所以报出来的错离现场很远。
修法、六条守卫与预算判据写在 `docs/200`。**这一处与 `docs/192` 的输入缓冲是同一种病第二次发作**。

**第二轮做掉的三块**（2026-09-21，覆盖从 19 份示例涨到 24 份）：

41. ⚠ **依赖在单元里的位置是"在前"，不是"在后"** —— 这是这一轮最该先量的一件事。
    `driver.lomt` 里两处注释**互相矛盾**（文件头说"依赖按先序拼进单元"，函数上写
    "顺序=依赖在前"）。实测是**后者**：单元 = `依赖1 依赖2 … 根 预置块?`，
    证据是同一份源喂两个实现，IR 里**被依赖者的函数排在根前面**
    （`lomentc.resolve_deps` 说的"被依赖者在前"是同一件事）。
    ⇒ 于是"根在哪" = **最后一个 `module` 标记**（它是 `__prelude` 时取前一个），
    `unit` 取的是**根**那个名字（不是第 1 个 token —— 那是第一个依赖的名字）。
    **教训**：同一份源上两个不一致的注释，**当判据用的那个数**（这里是 IR 的函数顺序）
    才作数。
42. **`imports` 是"依赖的传递闭包"，顺序也要一样**。`lumtui_demo.lomt` 写 5 条 `use`，
    对象里却是 **6** 个依赖名（`lumtui_font` 是被 `lumtui_layout` 拉进来的）——
    顺序 = 先序。判据里专门留了这一份，因为它同时钉住"名字对"与"顺序对"。
43. ⚠ **检查一个字符串 token 的后缀，别忘了它含闭合引号**。`use "lom/fujr.lom"`
    的判别我第一版从 `off + len - 4` 起比 `.lom` —— 那 4 个字节是 `.lom"`，于是
    **永远不相等**：`demo.lomt` 的 L0 布局没被挡住，两边算出了**两份不同的对象**
    （我这边 `layouts: []`，参考那边 2 条 record）而**判据当时还没覆盖它**。
    修法是从 `off + len - 5` 起比。（与第 33/34 条同一族：**这类函数的边界值要用一个
    真语料反查一遍**，不能靠读代码推。）
44. **impl 方法的 `self` 在对象里是 `__self` + 接受者类型**。`parse_impl` 把第一个形参
    改名成 `__self` 并把类型填成 `for` 后面那个类型（`Small`）——
    而**顶层**函数里的裸 `self`（`fn f(self)`）仍是 `Param("self", "")`。
    两条路长得很像，判据靠 `native_trait.lomt` 把前者钉住。
45. **impl 的方法也算 `functions`，名字是改过名的 `接受者_方法`**（`parse` 在收 impl 时
    就 `f.name = f"{im.type}_{f.name}"`，位置就在 impl 那一处）。所以"哪些 `fn` 算函数"
    是三档：顶层那一层算、**impl 块里那一层算**、`trait` 块里的**不算**（那是签名，
    只进 `traits[].methods`）。

**还缺什么**：单态化（`prepare`）—— 也就是 `instances` 与 `generics` 的 fn/struct 两类
（第 37 条那条"`prepare` 前后是不是同一张表"要在这一轮兑现），以及 L0 布局（`layouts`）。
判据里那 8 份"点名拒绝"就是待办清单。

46. **仓库级 sweep 是这一轮最值的一道工序**：判据的语料是枚举的（`COVERED` +
`EXTRA_COVERED` + 一条"examples 下每份都要有说法"），而**子目录里的语料不在那条 glob 里**
（`loment/examples/addin/main.lomt` 就是）。把它扫出来的那道 sweep 做的是同一件事、
只是语料换成"仓里所有 `.lomt`"：**先量一遍，再决定往判据里钉哪几份**。
它这次抓到的是**参照面自己搭错了**（`_want` 用 `load()` 而不是 `load_unit()`，
于是 `switches` 那一格少了 `addin` 拉进来的定义）—— 判据绿着，因为它没覆盖那份语料。
**两遍的口径必须一致**：`_want` 现在直接调 `lomentc.load_unit`（CLI 唯一入口），
不是自己拼 `load` + `resolve_deps`。

**第三轮（泛型函数的单态化）踩到的五处**：

47. ⚠ **指针不能比相等** —— 参考实现的 codegen 会为 `ptr == ptr` 发出 `icmp == ptr`
    （**非法 IR**：LLVM 的谓词是 `eq`）。它一路活到链接才炸，而**两个链接器反应不一样**：
    Python 链接器抛 `AttributeError`，genesis 那边是别的话。我写 `if sc == 0 as ptr`
    就撞上了 —— 修法是**在 u64 上判**（brk 返回 0 就是失败）。
    值一笔记：**"能过检查"与"IR 合法"是两件事**，这一格在两者之间走钢丝。
48. ⚠ **`u32` 传进 `ptr` 形参不报错，而是变成一个野地址**。我把工作区里的**偏移量**
    （`PT_TMPA` 这种 u32 常量）直接传给了形参是 `ptr` 的函数 —— 编译**过**了，
    运行起来是**访问违例**（`rc=0xC0000005`）。修法是一律 `ptr_add(sc, 偏移)`。
    **本语言在 int→ptr 这一处是宽松的，而且是静默的** —— 形参类型要自己盯住。
49. **实例名按"类型形参"拼，不是按"实参"拼**。`fn max_of<T>(a: T, b: T)` 只有一个形参
    `T`，所以名字是 `max_of_u32` 而**不是** `max_of_u32_u32`；`instances[].args` 同理。
    第一版按调用点实参的个数拼，正好多一个。
50. **同一个形参被推成同一个类型是合法的**（`fn f<T>(a: T, b: T)` 两次都推 `T=u32`）。
    参考实现的 `_infer_targs` 只在**推成两个不同**类型时返回 `None`；我第一版写成
    "第二次见到就跳过"，于是 `all_loment`/`tour` 的实例一个都没建出来
    （症状：`instances: []`，而 `functions` 里也少了那个实例 —— 两份文件全红）。
51. **`fn` 的 `generics` 与 `struct`/`enum` 的拼在一格里**：参考实现是
    `[fn 的] + [struct 的] + [enum 的]`（**按三类分组**，不是按声明先后），最后才接预置块。
    第一版只发了预置块那两条（`Option`/`Result`），`max_of` 落在后面 ✗ ——
    判据第 149 行当场红。
52. **单态化只做了泛型函数那一半**：`struct`/`enum` 的实例化（M7）没做，所以 `native_gen`
    仍拒；泛型**实参**只收"标识符"与 `x as T` —— `p.a` 那种字段访问**点名拒**
    （完整的 `expr_type` 没搬，宁拒勿猜）。
53. ⚠ **链式泛型（泛型函数体里再调泛型函数）会造出"发得出去但错"的实例名** —— 这一轮
    末尾唯一一处**不靠判据、靠推理**发现的洞。参考实现的 `prepare` 是**8 轮迭代**：
    它走的是**实例**的体，那时 `T` 已经被换成 `u32`，于是 `pick` 的实例名叫 **`pick_u32`**。
    自举侧是**一趟**扫单元本体，看到的实参类型还是 `T` —— 会拼出 **`pick_T`**。
    两个对象都"结构完整"、都能解析成 JSON，**逐字节不同**：判据会红，但如果哪天有人拿
    自举侧的对象当输入（而不是当被测物），那就是一个**静默的错**。
    处置与其它三条边界同一条纪律：**点名拒**（新增 `loment/examples/native_chain.lomt`
    当钉子 —— 参考实现能发 `pick_u32`，自举侧必须**说出"链式泛型"四个字**再退出 1）。
    这条也解释了一件事：拒绝码要**分得开**。原先 `pt_mono_body` 只有"1 = 拒"，
    链式泛型会落到"实参形态超出这一节"那句话上 —— **拒对了，但指错了轴**，
    于是钉子钉不住它。现在返回 **2**，`pt_mono_all` 原样上抛，`potato_emit` 那条话点名
    "链式泛型"。**"点名拒绝"的"名"必须是真名**，否则拒了也等于没拒。
    **半个后续（同一天）**：这份钉子一进 `loment/examples/`，就撞上了**同一个洞的另一侧**
    —— 自举侧的 **IR 路径**（`loment_p8_test` 的 M85 语料）也过不了链式泛型（驱动 565B
    vs 参考 776B）。那一侧**不能**拒（它要对整份语料发 IR），所以处置不同：在
    `loment_p8_test` 里给了一条 **`M85_KNOWN_GAPS` 棘轮**（与 `PARSE_KNOWN_GAPS` 同一个
    形状：条目在, 判据断言它**仍然**不一致 —— 哪天修好了那条断言会红, 逼着删条目）。
    一句话：**同一个能力缺口, 在"只发一个对象"的那侧可以拒, 在"要发整份语料"的那侧
    只能登记** —— 两处都不许静默。

**第四轮（M7）踩到的五处** —— 这一轮的五处里**四处是"发得出去但是错的"**（这一格最怕的
那一类），只有一处是直接红：

54. ⚠ **一个既有的洞，被 M7 的语料照出来了**：`max(p.a, p.b)` 里 `p.a` 被 M6 的实参推断
    解析成 `p` 的**声明类型** `Pair<u32>`（因为 `pt_arg_ty` 只看"下一个 token 是不是
    标识符"，`. ` 不是），于是实例名成了 **`max_Pair<u32>`** —— 参考实现按**字段**类型推成
    `u32`，叫 `max_u32`。**之前没有语料触发它**：用 `p.a` 的那两份正好都挂在别的拒绝轴上
    （一份挂泛型类型、一份挂链式泛型）。处置与其它轴一致：**点名拒**（`pt_arg_ty` 只在
    标识符**后面就是分隔符**时才认；`.` / `[` / `(` 一律"定不出来"）。**不能**拿声明类型
    顶替 —— 那正是这一格最怕的形状。
55. ⚠ **名字槽少了个 `+4`，而症状是"键的长度对、尾巴变成一小段二进制"**。池子的条目是
    `[键长 4][键…][名长 4][名…]`，我把名字写成 `+ 键长`（该是 `+ 4 + 键长`）—— 于是
    **名长那 4 个字节正好落在键的最后 4 字节上**。看出来的东西是
    `Result<u32, \x0e\x00\x00\x00`，而那个 `\x0e`（14）**正好是** `len("Result_u32_u32")`。
    同一处偏移在映射表里又错了一次（名字起点写成 `+键长+4`，该是 `+8+键长`），症状变成
    名字前面多 4 个字节、少 4 个字符。**教训**：在这种"一条记录里塞两段变长串"的布局上，
    **长度前缀的位置要当场算一遍**，别凭记忆写。
56. ⚠ **查表那一步必须只认"配了名字"的条目**。池子里收的是**所有**类型位置上的串
    （`u64` 这种也在），而只有泛型实例才在建表时拿到名字 —— 少了这一判，`u64` 会被
    "映射"成**空串**，发出去就是 `"type": ""`（`bootprobe.lomt` 第一行就红）。
    这是"表里有什么"与"表里**有效**的有什么"被混成一件事。
57. ⚠ **`potato_emit` 自己 alloc 工作区，新加的游标得在那儿归零**。`pt_sc_new` 只被
    别的路径用，`potato_emit` 是手写的 `store32(sc, PT_N, 0)` 那几行 —— 我给 M7 加的两个
    游标漏在那儿，于是收集器拿一个垃圾条数去查重、当场"命中"、**一条类型串都没收进来**。
    症状很隐蔽：`enums` / `types` 静静地少掉实例（`"ret": "Result<u32, u32>"`），
    **不报错**。**加状态块就要问一句"谁负责把它清零"**。
58. ⚠ **`functions` 与 `instances` 是两张表，计数与序号各算各的**。类型实例属于
    `instances`，**不属于** `functions`；而 `functions` 的条数是 `nfn + fn 实例`，
    `instances` 的条数是三块之和，且类型那两块的**起始序号**是 `fn 实例数`（不是

#### 同族的两处（**能过翻译器、过不了后面的层**）

这一格与第 18 格后来各关掉了一个**同一个形状**的洞 —— 两个都是"翻译器放过去、后面必炸"，
而且都是**另一个会话上报的**（`docs/198`）：前面那个是"运行期算错"，这两个是"干脆编不过"：

| 处 | 原先发出什么 | 为什么编不过 | 现在 |
|---|---|---|---|
| `~a`（Python 那门） | `( ~a )` | 本语言的**词法器没有 `~`** | 点名拒（按宽度写 `^ -1` / `^ 255`） |
| 裸 `return`（**两族都有**） | `return;` | 本语言的 `()` 函数**没有提前退出** | 点名拒（改写成 `if`/`else`，或改成有返回值） |

两处的修法都**不是**"想办法表达出来"，而是**点名拒** —— 与 `**` / `/` / `>>>` 同一条纪律
（`docs/188` §0）。`~` 本可以按宽度展开，但那一族**不做整数宽度跟踪**，替不了作者选；
裸 `return` 则是**本语言根本没有那个构造**（实测参考实现报 `E19 期望表达式，得到 ';'`）。

**两处都欠一笔"谁来钉住它不再回来"**：`~` 那处加了拒收语料（`loment/pytrans/unary_invert.py`，
走"前端报错且说得出为什么"那一档）；裸 `return` 那处加在两族的 `_EXTRA` / `_PY_BATTERY` 里
（比退出码，不比文案）。**语料一次都没踩到过它们** —— 这是它们活到今天的原因。

**还没搬的**：`pytrans` 自己（`tools/pytrans.py`）没有孪生 —— 这一格搬的是**翻译器**，
判据拿 `pytrans` 当上游。这与"六门翻译器还没有孪生"是**同一笔欠账**。

再往后：六门翻译器的 Loment 孪生里只剩自举侧的 potato 通路 —— 那根不动，
S2（拆参考实现）就动不了。
