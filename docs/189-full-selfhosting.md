# 189 · 完全自举：0.1.4 正式版之前移除全部非 Loment 代码

> 用户 2026-09-18 定的：**「0.1.4 正式版之前务必移除所有非 Loment 代码，包括全部
> rust/py/c/java 的代码，确保完全自举」**。
>
> 上游：`docs/159`（无 Python 自举 —— 那份把去 Python 推到了"用户侧工具链 + L0 生成器
> + 构建路径 + clang"全部有 Loment 实现）。本文档做的是**剩下的那一块**。

## 0. 这一句关掉了哪条路

`docs/159` §4 那张表最后一格写的是：

> Python（**测试侧**）… **不影响"用户构建/使用 Loment"，只影响开发期判据** …
> 把一致性套件写成 Loment 程序（下一批），**或保持 Python 作为"第三方审计工具"——
> 两条路都合理**

**用户这一句把"保持 Python"那条关掉了。** 两条路只剩一条：判据要变成 Loment 程序。

**这一句也让"移除"有了一个明确的对象**：不是"少依赖"，是**仓里不许有**。

## 2. 按"移除它会破坏什么"分五类 —— 每一类的去路都不同

### A. 判据（Python 86，`tools/` 的大头）—— **必须搬进 Loment**

`ci.py` / `loment_*_test.py` / `lomc_test.py` / `potato_test.py` …

**这是最大的一块，也是唯一一块"没有替代品就动不了"的。** 判据是给别的改动兜底的；
先拆它等于把安全带解了再开车。

**模板已经有了**（`docs/159` §4b）：同一份源码喂**两个实现**、比 stdout **逐字节相同**
—— `lomfmt` / `lomdoc` / `lompkg` / `lomc` / `lomrel` / `lomstatus` 全是这么落的。
判据的迁移照这个来：**Loment 版判据 + 与 Python 版逐字节相同**，直到 Python 版可以拆。

### B. 参考实现（`tools/lomentc.py` / `lomc.py` / `lomelf.py` …）—— **排在 A 之后**

它是"两个实现逐字节一致"（`docs/158` §5）里的**对照面**。

⇒ **移除它 = 那条开发期纪律没有对照物了。** 那**是对的**（自举完成时本来就只有一个
实现），但**时机**必须排在 A 之后：判据先搬进 Loment，再拆参考实现。
**顺序反了的话，回车键前一刻没有任何东西能告诉你搬对了没有。**

### C. `loment/build/` 里那些 Rust / C / LLVM IR（53 个）—— **要用户点头**

**它们不是手写的，是生成物。** 谁生成的决定了去路：

* `.rs` / `.c` / `.py` —— **`lomc` 的后端**（`tools/lomc.py:546/571/613` 与它的 Loment
  孪生 `loment/tools/lomc.lomt`）。**那正是 `lomc` 存在的理由**：L0 契约要交付成
  Rust / C / Python，给 FujoOS 那一侧用（`lom/fuai.lom` → `fuai.h` / `fuai.rs` /
  `spec.json`）。
  **⇒ "移除全部 rust/py/c"与"L0 契约要交付成 rust/c"是同一件事的两面。**
  这条**不能自己定**：要么下游改吃 `.lom`，要么这一条指令对 `lom/build/` 不适用。
* `.ll` —— IR 种子/中间物。`genesis` 落地之后编译用户程序**不需要**它，但它是**链条起点**
  （`docs/159` §3）。属于 F 那一类。

### D. `kernel/` `sdk/`（Rust 8 + C 4）—— **要用户点头**

它们是**从 FujoOS 拿来的只读对照物**（`CLAUDE.md` 第 1 条、`loment_publish.COUNTERPARTS`）。
`lom_audit` / `fuai_contract_check` / `lomc_test` 靠它们做**逐字段对账**。

**⇒ 移除等于"L0 契约在本仓没有对照面"** —— 而 `CLAUDE.md` 明写"少了它们判据会**崩**，
不是静默红"。

这条是**跨线**的，不是语言线自己能定的。

### E. `editors/vscode/src/*.js`（2）—— **要用户点头**

VS Code 扩展**只能**是 JS/TS，没有别的选择。移除 = 放弃编辑器支持
（而 `editors/` 是 `docs/157` 花过力气的地方）。

### F. 启动脚本（`.ps1` 2 + `.sh` 2 + `.ld` 1 + `.ll` 13）—— **链条起点的鸡生蛋**

`loment/bootstrap.sh` / `scripts/lomc.ps1` 是**自举链的第一步**。在"从零重建"这个场景里
总得有一个东西先跑起来 —— `genesis` 把这一步压缩到了一小段，但**压不到零**。

`docs/159` 的"仍待做"里记着 **PE64 / 去 WSL / 构建路径去 Python** —— 属于这一格。

### 3.0 S0 的决定（用户 2026-09-18）—— **两条都定了**

#### C：`lomc` 的 rust / c / py 交付后端 —— **交付物豁免，但不再提交**

用户原话选的是这一条。落地形状：

* `loment/build/` 里那些 `.rs` / `.c` / `.py`，以及 `lom/build/` 的 `fuai.h` / `fuai.rs` /
  `fuai.py` —— **从索引里移除、进 `.gitignore`**。仓库里不再有它们的字节。
* **`lomc` 照旧能生成它们**（能力不动）。判据从"提交的那份逐字节一致"改成
  **"生成出来 == 上一层输入"** —— 即"从 `lom/fuai.lom` 生成出来的那份，与生成器说的一致"，
  而不再与一份**存在仓库里的副本**比。
* **代价（写在这里，别到 FujoOS 侧才发现）**：那边原先直接吃**提交好的**文件，
  改完要在自己的构建里**先跑一次 `lomc`**。这是一条跨线的施工顺序，不是这一侧能单方面改完的。

> **为什么这条最贴"自举"的本意**：那 53 个文件**不是代码，是产物**。产物留在仓库里，
> 读的人分不清"这是别人写给我的 C"还是"这是我自己生成的 C" —— 而后者恰恰是自举的证据。
> 移出索引之后，"仓库里只有 Loment"这句话**字面上成立**，而能力一点没少。

**⚠ 实测出来的耦合 —— 做 S3 之前必须先看这一条**（2026-09-18 数完 `git ls-files` 之后查的）：
那 49 个文件里有几个**不只是"交付产物"，它们被本仓的工具在运行时加载**，
所以"移出索引"**不是删文件那么轻**：

| 谁 | 怎么用 | 移出索引之后 |
|---|---|---|
| `tools/fuic.py:28` | `spec_from_file_location(…, "lom/build/fuc.py")` | **import 期就崩** —— 打包器起不来 |
| `tools/fujopack.py:26` | 同上，`lom/build/fujr.py` | **同上** |
| `lom_audit.py:38-50` | 一张 `(.lom, 目标, 产物路径)` 对账表 | 报"缺失"（`lom_audit` 本就是本机固有红项，但这条会变成**新的**红因，混在里面） |
| `loment_lomc_test.py:204-210` | `--check` 拿**提交的那份**当对账目标 | **对账没有对象了** |

**⇒ S3 的真形状不是"删 49 个文件"，而是"把'产物与源头一致'那条不变式换个说法"**：

    旧：提交的那份副本 == 生成器此刻会生成的
    新：生成是**确定的**（同样输入两次出同样字节）+ 漂移**检得出来**

后半句已经有一半了 —— `loment_lomc_test` 的漂移检出那一半用的是**临时副本**
（`loment/build/lomc_bad_tmp`），不依赖索引 ✓。要改的是前半句。

上面两个**运行时加载器**另有一条交代，**我倾向 (b)**：

* (a) `fuic.py` 发现文件不在就**现场调 `lomc` 生成** —— 方便，但**给打包器装上了编译器依赖**，
  而打包器本来的分工是"吃生成物、不产生成物"；
* (b) 文件不在就**报一句清楚的话**（"先跑 `lomc --emit-python lom/fuc.lom …`"）——
  打包器不依赖编译器，代价是构建顺序**显式**。

**顺带一条好消息**：`loment/build/fuai_syscalls.lomt` 那种**生成物是 Loment 源码**
（`lom_audit.py:324`），所以它**不在**这一格里 —— 它照旧提交。按扩展名一刀切会把它误伤。

#### D：`kernel/` + `sdk/` —— **保留**

它们不是本仓的代码，是 **L0 契约对面那一侧的只读对照物**（`CLAUDE.md` 第 1 条、
`loment_publish.COUNTERPARTS`）。保留的理由是**判据的对照面**：`lom_audit` /
`fuai_contract_check` / `lomc_test` 靠它们做逐字段对账，而 `CLAUDE.md` 明写"少了它们
判据会**崩**，不是静默红"。

⇒ **0.1.4 的清单里明确豁免这一类**：措辞是"移除全部非 Loment 代码"，
而 vendored 对照物**不是本仓的代码** —— 它们是**跨线契约的另一侧**，改它们要去 FujoOS 仓改。
这条豁免不是"网开一面"，是把那句指令的**适用范围**说准。

#### 按这两条重算清单

| | 个数 | 去路 |
|---|---|---|
| C 那一类（`loment/build/` 的 25 Rust + 15 C，加 `lom/build/` 的 3+3+3） | **49** | **移出索引**（能力保留，按需生成） |
| D 那一类（`kernel/` 8 Rust + `sdk/` 4 C） | **12** | **保留**，明确豁免 |
| 其余（A 判据 86 + 语料 + E 编辑器 2 + F 链条起点 18 + Vim 3 …） | **114** | 按 S1–S5 逐步来 |

**仍然开着的一格是 E**（`editors/vscode/src/*.js`，2 个）—— VS Code 扩展**只能**是 JS/TS，
所以它要么豁免、要么放弃编辑器支持。**S5 要你对它表态**（不阻塞 S1）。

**另有一格值得单独提**：`loment/<lang>trans/*.<ext>` 那些**语料**（`.c` / `.py` / `.cs` /
`.cpp` / `.go`）按 `docs/188` §0 **就是 Loment** —— 只是拼法不同。所以它们**不该**算进
"非 Loment 代码"。按扩展名数会数错；这一条留一句话在这里，免得将来有人拿 `grep -v lom`
数出来一个吓人的数字。

## 4. 这条指令对**手上正在做的活**的约束（现在就生效）

### 4.1 六门表层语法的翻译器

`docs/188` §7.1 那份计划里，六门的翻译器是 **Python**（`tools/ctrans.py` /
`pytrans.py` / …）。按本指令，它们**也要有 Loment 孪生**，否则 0.1.4 之前又得拆。

**⇒ 从第一门起就按 `docs/159` §4b 那个模板做**：翻译器写两份、判据比**输出的 Loment
源码逐字节相同**。这比"先写 Python、以后补 Loment"便宜得多，因为**判据的形状是一样的**
（同一份输入喂两个实现、比 stdout）。

**但要如实说一句**：`lomfmt` / `lomdoc` / `lompkg` / `lomc` 那几块能那么便宜地镜像，
是因为它们**只吃词法层或声明层**。**翻译器要建树**（递归下降 + 类型 + 发射），
在自举侧是个**大得多**的活 —— 这一格的代价要认，别按前几块的经验估。

### 4.2 新加的判据

**照旧**：新判据是 Python（判据搬到 Loment 是 S1 的整件事，不要求新判据一上来就是
Loment）。但**别把 Python 判据当永久物**设计 —— S1 会来搬它。
