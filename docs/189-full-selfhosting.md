## 0. 这一句关掉了哪条路

**用户这一句把"保持 Python"那条关掉了。** 两条路只剩一条：判据要变成 Loment 程序。

**这一句也让"移除"有了一个明确的对象**：不是"少依赖"，是**仓里不许有**。

## 2. 按"移除它会破坏什么"分五类 —— 每一类的去路都不同

### A. 判据（Python 86，`tools/` 的大头）—— **必须搬进 Loment**

`ci.py` / `loment_*_test.py` / `lomc_test.py` / `potato_test.py` …

**这是最大的一块，也是唯一一块"没有替代品就动不了"的。** 判据是给别的改动兜底的；
先拆它等于把安全带解了再开车。

**模板已经有了**（`docs/159` §4b）：同一份源码喂**两个实现**、比 stdout **逐字节相同**
—— `lomfmt` / `lomdoc` / `lompkg` / `lomc` / `lomrel` / `lomstatus` 全是这么落的。
判据的迁移照这个来：**Loment 版判据 + 与 Python 版逐字节相同**，直到 Python 版可以拆。

### B. 参考实现（`tools/lomentc.py` / `lomc.py` / `lomelf.py` …）—— **排在 A 之后**

它是"两个实现逐字节一致"（`docs/158` §5）里的**对照面**。

⇒ **移除它 = 那条开发期纪律没有对照物了。** 那**是对的**（自举完成时本来就只有一个
实现），但**时机**必须排在 A 之后：判据先搬进 Loment，再拆参考实现。
**顺序反了的话，回车键前一刻没有任何东西能告诉你搬对了没有。**

### C. `loment/build/` 里那些 Rust / C / LLVM IR（53 个）—— **要用户点头**

**它们不是手写的，是生成物。** 谁生成的决定了去路：

* `.rs` / `.c` / `.py` —— **`lomc` 的后端**（`tools/lomc.py:546/571/613` 与它的 Loment
  孪生 `loment/tools/lomc.lomt`）。**那正是 `lomc` 存在的理由**：L0 契约要交付成
  Rust / C / Python，给 FujoOS 那一侧用（`lom/fuai.lom` → `fuai.h` / `fuai.rs` /
  `spec.json`）。
  **⇒ "移除全部 rust/py/c"与"L0 契约要交付成 rust/c"是同一件事的两面。**
  这条**不能自己定**：要么下游改吃 `.lom`，要么这一条指令对 `lom/build/` 不适用。
* `.ll` —— IR 种子/中间物。`genesis` 落地之后编译用户程序**不需要**它，但它是**链条起点**
  （`docs/159` §3）。属于 F 那一类。

### D. `kernel/` `sdk/`（Rust 8 + C 4）—— **要用户点头**

它们是**从 FujoOS 拿来的只读对照物**（`CLAUDE.md` 第 1 条、`loment_publish.COUNTERPARTS`）。
`lom_audit` / `fuai_contract_check` / `lomc_test` 靠它们做**逐字段对账**。

**⇒ 移除等于"L0 契约在本仓没有对照面"** —— 而 `CLAUDE.md` 明写"少了它们判据会**崩**，
不是静默红"。

这条是**跨线**的，不是语言线自己能定的。

### E. `editors/vscode/src/*.js`（2）—— **要用户点头**

VS Code 扩展**只能**是 JS/TS，没有别的选择。移除 = 放弃编辑器支持
（而 `editors/` 是 `docs/157` 花过力气的地方）。

### F. 启动脚本（`.ps1` 2 + `.sh` 2 + `.ld` 1 + `.ll` 13）—— **链条起点的鸡生蛋**

`loment/bootstrap.sh` / `scripts/lomc.ps1` 是**自举链的第一步**。在"从零重建"这个场景里
总得有一个东西先跑起来 —— `genesis` 把这一步压缩到了一小段，但**压不到零**。

`docs/159` 的"仍待做"里记着 **PE64 / 去 WSL / 构建路径去 Python** —— 属于这一格。

### 3.0 S0 的决定（用户 2026-09-18）—— **两条都定了**

#### C：`lomc` 的 rust / c / py 交付后端 —— **交付物豁免，但不再提交**

用户原话选的是这一条。落地形状：

* `loment/build/` 里那些 `.rs` / `.c` / `.py`，以及 `lom/build/` 的 `fuai.h` / `fuai.rs` /
  `fuai.py` —— **从索引里移除、进 `.gitignore`**。仓库里不再有它们的字节。
* **`lomc` 照旧能生成它们**（能力不动）。判据从"提交的那份逐字节一致"改成
  **"生成出来 == 上一层输入"** —— 即"从 `lom/fuai.lom` 生成出来的那份，与生成器说的一致"，
  而不再与一份**存在仓库里的副本**比。
* **代价（写在这里，别到 FujoOS 侧才发现）**：那边原先直接吃**提交好的**文件，
  改完要在自己的构建里**先跑一次 `lomc`**。这是一条跨线的施工顺序，不是这一侧能单方面改完的。

> **为什么这条最贴"自举"的本意**：那 53 个文件**不是代码，是产物**。产物留在仓库里，
> 读的人分不清"这是别人写给我的 C"还是"这是我自己生成的 C" —— 而后者恰恰是自举的证据。
> 移出索引之后，"仓库里只有 Loment"这句话**字面上成立**，而能力一点没少。

**⚠ 实测出来的耦合 —— 做 S3 之前必须先看这一条**（2026-09-18 数完 `git ls-files` 之后查的）：
那 49 个文件里有几个**不只是"交付产物"，它们被本仓的工具在运行时加载**，
所以"移出索引"**不是删文件那么轻**：

| 谁 | 怎么用 | 移出索引之后 |
|---|---|---|
| `tools/fuic.py:28` | `spec_from_file_location(…, "lom/build/fuc.py")` | **import 期就崩** —— 打包器起不来 |
| `tools/fujopack.py:26` | 同上，`lom/build/fujr.py` | **同上** |
| `lom_audit.py:38-50` | 一张 `(.lom, 目标, 产物路径)` 对账表 | 报"缺失"（`lom_audit` 本就是本机固有红项，但这条会变成**新的**红因，混在里面） |
| `loment_lomc_test.py:204-210` | `--check` 拿**提交的那份**当对账目标 | **对账没有对象了** |

**⇒ S3 的真形状不是"删 49 个文件"，而是"把'产物与源头一致'那条不变式换个说法"**：

    旧：提交的那份副本 == 生成器此刻会生成的
    新：生成是**确定的**（同样输入两次出同样字节）+ 漂移**检得出来**

后半句已经有一半了 —— `loment_lomc_test` 的漂移检出那一半用的是**临时副本**
（`loment/build/lomc_bad_tmp`），不依赖索引 ✓。要改的是前半句。

上面两个**运行时加载器**另有一条交代 —— **已定 (a)**（现场按需生成），理由是**那条依赖本来就在**：

* 先看两条候选：**(a)** 文件不在就现场调 `lomc` 生成；
  **(b)** 文件不在就报一句清楚的话、让构建顺序**显式**。
* **选 (a) 的关键一条**：`lom_audit` 明令「打包器必须引用生成模块、**不能退回手写**」
  （`lom_audit.py:206`）—— 也就是说**打包器拿布局的唯一合法来源就是那个生成物**。
  于是"按需生成"不是**引入**了一条依赖，是把**本来就有的**那条依赖**实现出来**。
* (b) 另有一处说不通：S3 之后「文件不在」是**仓库的默认状态**（新克隆就是这样），
  而**对默认状态报错是错的** —— 那不是异常，是常态。
* 代价记一笔：`fuic.py` / `fujopack.py` 从此要么调生成器（S2 之前 `lomc.py`、
  之后 `lomc.lomt`），要么在文件已在时直接加载。**能省的只做一次**：文件在就不调。

**顺带一条好消息**：`loment/build/fuai_syscalls.lomt` 那种**生成物是 Loment 源码**
（`lom_audit.py:324`），所以它**不在**这一格里 —— 它照旧提交。按扩展名一刀切会把它误伤。

#### D：`kernel/` + `sdk/` —— **保留**

它们不是本仓的代码，是 **L0 契约对面那一侧的只读对照物**（`CLAUDE.md` 第 1 条、
`loment_publish.COUNTERPARTS`）。保留的理由是**判据的对照面**：`lom_audit` /
`fuai_contract_check` / `lomc_test` 靠它们做逐字段对账，而 `CLAUDE.md` 明写"少了它们
判据会**崩**，不是静默红"。

⇒ **0.1.4 的清单里明确豁免这一类**：措辞是"移除全部非 Loment 代码"，

这条豁免不是"网开一面"，是把那句指令的**适用范围**说准。

### ⚠ 但在排格子之前，先问一句：**这件工具活得过 S2 吗？**

把 53 件"参考实现"摊开看，它们不是一类 —— **有的工具的全部用途就是"把两个实现比一比"**
（`loment_probe` 头注自己写着"**门禁里不跑, 是定位工具不是检查项**"、`loment_ir_diff`、
`loment_rule_parity` …）。参考实现一拆，**它们就没有意义了** —— 给它们写 Loment 孪生
是白写 ✗。

| 类 | 特征 | 怎么办 |
|---|---|---|
| **活得下去** | 干的是真活（`loment_eol` 查行尾、`loment_src` 打源码包、`lomfmt`/`lomdoc`…） | **写孪生**（S1 的正题）|
| **随 S2 消失** | 它的输出就是"参考 vs 自举"的对照（`loment_probe` / `loment_ir_diff` / `loment_rule_parity`） | **不写孪生**，跟着参考实现一起拆 |
| **换人** | 要 Loment 没有的能力（`loment_filetype` 写 HKCU；`loment_sign` 走 Authenticode/openssl） | 留给安装器/外部工具，或明确留在 Python 那一侧 |

⇒ **53 这个数不是要给 53 件写孪生**：先把每一件归到上表的一类，再谈工作量。
（这条是 2026-09-18 排第二格时想清楚的 —— 差点给 `loment_probe` 写一个没有意义的孪生。）

**三种判据形态要先分清**（不然 44 格会各写各的）：

* **工具型**（判据在测一个 `tools/` 里的工具）→ Loment 版就是那个工具的孪生，
  比 stdout 天然成立（`lomstatus` / `lomrel` 就是这么落的）。**这一型优先做**：
  不新增 Python（孪生是 Loment ✓），而且 S2 拆参考实现时正好把那件 Python 收走。
* **检查型**（判据自己就是一段检查逻辑，没有对应工具）→ 得**先把它抽成一个程序**
  （Python ✓），再写孪生。注意这一步会**让 Python 多一个文件**（`86 → 87`）——
  是为了让"两条实现逐字节比"成立，不是为了永久留着；
* **对**外部神谕**的**（CPython / clang / javac / dotnet / go 当对照物 —— `docs/188`
  §7.1 那六门的判据全是，`loment_json_test` 也是）→ **神谕不能被搬走，也不该搬**。
  Loment 版是**驱动器**：走进程桥（`loment/lib/proc.lomt`）去调那个外部工具，
  比 stdout。这一型的"逐字节相同"比的是**驱动器自己的报告**，神谕那一侧照旧。

**从哪一格开始**（按"不碰 git / 进程 / 编译器"排序，最便宜的先做）：

#### 第 1 格踩到的两处（后面 43 格都会再撞，先写下来）

1. **入口是 `fn _start()`，不是 `fn main()`。** 写成 `main` 时 lld 找不到入口、把入口留成 0
   —— 现象是**一跑就段错误、一个字都不输出**（不是链接失败，也不是编译错，所以最难猜）。
   照抄同行的写法（`lomstatus.lomt` / `loment_ffi_test` 的腿 2 都是 `_start`）就不会错。
2. **别照抄 `loment_status_test` 的比较器**：那个 `_norm` 把反斜杠归成斜杠，前提是"输出里的
   反斜杠只会来自路径"。而 `loment_eol` 的报告里**有一个字面的 `\n`**
   （`写仓库内工件要用 newline='\n'` 那一句）—— 归一之后**判据自己造出一个假差异**，
   红的是比较器、两边真输出逐字节相同。**这一格的 `_norm` 因此刻意什么都不做**，
   并把这个"为什么不做"写在函数头上。
3. 另外两处小的：`const` 只收整数字面量（命令串不能做 `const`，得内联）；
   语言只有 `load8`/`store8`，32 位读写要自己拼（`ld32`/`st32`）。
   两者陷阱清单里都写着，我各踩了一次 —— **写之前先读 §6 那一节**。

#### 第 2 格（`loment_syscalls`）踩到的一处

**别绕开自己的 `open_ro` 助手去直接 openat 字面量指针。** 驱动里 `argv_at` 是先
`open_ro(str_ptr("/proc/self/cmdline"), str_len(...), scr)` —— 它把路径**拷进 scratch 补
NUL** 再 openat。我图省事写成 `syscall4(257, AT_FDCWD, str_ptr("…"), 0)`，结果 openat
失败、`argc = 0`，两条配对判据一起红，而**报出来的话是"需要 --emit 或 --check"** ——
指的完全不是真正的原因（这正是本仓反复讲的"错要指在错的地方"，我自己造了一次）。
**照抄同行的调用姿势比自己拼参数便宜。**

#### 第 3 格（`loment_editors_test` 第 1 条）: **检查型**怎么落

这一格没有对应工具（检查逻辑就写在判据里），所以按 §3 的"检查型"走 —— 但**不必**
先把检查抽成一个 Python 程序（我原先在表里是那么写的，**错了**）：判据那一侧可以
**直接调那条检查函数**（`contextlib.redirect_stdout` 捕获它打印的那一行），拿它当参考。
**Python 一个文件都不用多**。

另一件要划清楚：Python 那一侧**成功是一行 stdout、失败是 `assert` 抛异常** ——
异常没有 stdout 可比。所以这一格**只比成功那一趟**，失败那一档两边各写各的语气
（孪生自己说缺哪些词并退 1）。这与第 1 格的 `--fix` 是同一种边界：**该划出去的划出去，
并写明白**。

**一处自查没抓住、判据会抓住的**：我把 `"syn keyword loment"` 的长度写成了 20（真的
是 18），编译照样过、跑起来也"像是绿的" —— 抓住它的是那条**独立清点**（孪生报的两个数
必须等于判据自己从 vim 文件里数出来的）。**"两边相同"型判据必须配一条独立期望值**，
这是本仓反复讲的那条。

#### 第 4 格（`lom_spec_emit`）：**动工了又撤回**，把查清的东西留在这儿

写了一半发现它是**这批里最大的一格**（三种块 + 一个 JSON 转义器 + 输出顺序与文件顺序
不同），当时那份已经出现占位函数与死表 —— 那不是能落进本仓的东西，所以**撤掉**，不硬凑。
下次按下面这几条重开：

1. **输出顺序 ≠ 文件顺序。** 文件里是 `meta -> param -> enum`；JSON 是
   `$schema/title/version/authority` → **layers** → **primitives**（来自 enum）→ formats →
   gates → deployment_params。**一趟流式发不出来**，必须"先收表、再按 JSON 顺序发"。
2. **判据只走 `--check`。** 写盘那一趟会把 `LinuxFUAI/spec/spec.json` **建出来** ——
   那是**伪造对岸的对照物**（`CLAUDE.md` 第 1 条明令不许）。所以判据不碰写盘那趟。
3. **它的 stdout 里有绝对路径**（`{t}` 打的是 `Path`），两边平台不同 —— 判据要么成文地
   收敛成仓库相对路径再比，要么只比**写出的 JSON 字节**（那份里没有路径，是干净的）。
4. 格式细节（照 `json.dumps(..., ensure_ascii=False)`）：分隔符 `", "` / `": "`；键一律
   双引号而 `deployment_params` 的数值是**裸的**；缺的键写 `null`；组内最后一项后不加
   逗号、`primitives` 段结尾**总是** `],`、param 里每个键**都**带逗号（`note` 最后不带）；
   结尾一个换行。

**其余还没搬的（同类，都不便宜）**：`potato_assert`（要 JSON 解析 + 目录枚举）、
`loment_src`（要 git + 比写出的包字节）、`loment_audit`、`loment_manual`（要加载每个示例）。
再往后就是两根**大轴**：六门翻译器的 Loment 孪生（§4.1）与自举侧的 potato 通路 ——
那两根不动，S2（拆参考实现）就动不了。

## 4. 这条指令对**手上正在做的活**的约束（现在就生效）

### 4.1 六门表层语法的翻译器

`docs/188` §7.1 那份计划里，六门的翻译器是 **Python**（`tools/ctrans.py` /
`pytrans.py` / …）。按本指令，它们**也要有 Loment 孪生**，否则 0.1.4 之前又得拆。

**⇒ 从第一门起就按 `docs/159` §4b 那个模板做**：翻译器写两份、判据比**输出的 Loment
源码逐字节相同**。这比"先写 Python、以后补 Loment"便宜得多，因为**判据的形状是一样的**
（同一份输入喂两个实现、比 stdout）。

**但要如实说一句**：`lomfmt` / `lomdoc` / `lompkg` / `lomc` 那几块能那么便宜地镜像，
是因为它们**只吃词法层或声明层**。**翻译器要建树**（递归下降 + 类型 + 发射），
在自举侧是个**大得多**的活 —— 这一格的代价要认，别按前几块的经验估。
