# 176 · 降低"改冻结面"的代价：先量，再设计

> 2026-09-17 用户指示：`loment/lib/` 三个文件**转正进 std**，但
> "**我们需要研究出一个全新的系统，减少改冻结面代价**"。
> 上游：`docs/158` §5（四条流程，就是这里说的"代价"）· `docs/175`（0.1.4 方向）
> 本文件是**测量 + 方案**，不是规范。

## 0. 一句话

**真正的"双写税"只有 ~153 行手写；一次语言面改动的 diff 里有 93% 是机械产物。**
所以要降代价，优先级不是消灭双写，而是：**把机械产物移出评审面**、
**把"数据"从"逻辑"里拆出来交给已有的生成管线**、**把硬冻结缩到内核线真正吃的那一层**。

## 1. 量：一次语言面改动到底贵在哪

样本 = `extern fn` 进语言（`docs/173` 阶段 1），两次提交：
`392f88b`（参考实现 + 自举硬拒）、`0dd40a3`（自举镜像）。

| 类别 | 改动行数 | 性质 | 能不能省 |
|---|---|---|---|
| 参考实现 `tools/lomentc.py` | **84** | 手写 | 双写税的一半 |
| 自举实现 `loment/selfhost/*.lomt` | **69** | 手写 | 双写税的另一半 |
| 诊断码 `tools/loment_diag.py` | 10 | 手写 | 数据，可生成 |
| **种子** `loment/build/selfhost_driver.ll` | **553 + 3305 = 3858** | **机械** | **不可省，但占 diff 的 93%** |
| 文档（`docs/143/155/158/168/173`） | 225 | 手写 | 冻结面流程要求，不可省 |
| 判据（`lomentc_test` / `p8_test`） | 170 | 手写 | 不可省，且应该变多 |

种子文件本身 **46,752 行**；一次改动能牵动 **7%** 的行 —— 因为它由 `--emit` 重生成，
且 SSA 编号会整体位移。**它淹没了真正需要看的那 153 行。**

### 1.1 结论一：双写税不是大头

153 行手写 vs 225 行文档 vs 3858 行机械噪声。**想省 153 行而去掉第二个实现，
换来的是丢掉"两份独立实现互相印证"这个审计资产 —— 亏本。** 这一条要写下来，
免得以后又有人提"不如只留一个实现"。

### 1.2 结论二：最大的单块噪声是可消除的

`loment/build/selfhost_driver.ll` 在 `.gitattributes` 里只有 `text eol=lf`，
**没标成生成物**。GitHub 不折叠它，`git diff` 把它整段打出来。

## 2. 量：最贵的那张表长什么样

"内建函数表"是冻结面的一部分，而它**不是单源**：

| 位置 | 内容 |
|---|---|
| `tools/lomentc.py` `BUILTINS` | 唯一的真表（dict） |
| `loment/selfhost/checker.lomt` `is_builtin` | 名字清单（手镜像 ①） |
| 同上 `chk_builtin_arity` | arity（手镜像 ②） |
| 同上 `chk_builtin_ret` | 返回类型（手镜像 ③） |
| 同上 `chk_builtin_arg` | 形参类型（手镜像 ④） |

四处都写着"**镜像 `lomentc.BUILTINS` 的第 N 项**"，源码注释自己还写着
"这张表必须与 `is_builtin` 的名字清单**同增同减**"，并且有一条判据
`test_m81_builtin_table_matches` 专门防它们漂。

**一条判据的存在本身就是成本信号：它在替一个不该存在的同步动作站岗。**
加一个内建函数 = 改 5 个地方 + 1 条判据跟着动。

## 3. 仓里已经有一条"单源"的路（不用发明）

`loment/tools/win_shim_data.lomt` 的文件头第一行就写着：

> `win_shim_data.lomt — 由 tools/lomelf.py --dump-win-shim 生成，别手改。`

形状是：

```
参考实现  --dump-X  -->  loment/tools/X_data.lomt   （纯数据 + 访问器）
                                   |
自举      use X_data  <------------+                n_X() / X_part(k)
```

已经在生产里用的三个实例：`win_shim_data`（PE 垫片机器码 + 导入表）、
`lomrel`（版本真源的镜像）、`bytes`（hex blob）。

连"为什么要分片"都已经踩过并写在注释里：运行时 bump 堆只有 64 KiB，
`str_concat` 拼一个 8 KB 的串就撞顶 → **按片给**（`X_part(k)`），调用方逐片解。

**所以"减少改冻结面代价"的正解不是新造机制，是把该上这条路的东西搬上去。**

## 4. 三条方向（按杠杆/代价排序）

### A. 把机械产物移出评审面（代价≈0，立即做）

1. `.gitattributes` 给 `loment/build/selfhost_driver.ll` 加
   `linguist-generated -diff` 等标记 → GitHub 折叠、`git diff` 不出内容。
   **种子仍然提交**（它是 genesis 的根，`docs/167` §5，不能省），只是不再淹没 review。
2. **语言面改动一律两条提交**：一条手写（源 + 文档 + 判据），一条机械（`--emit` 产物），
   后者的消息里写明"只有生成物"。今天的 `392f88b` / `0dd40a3` 已经是这个形状 ——
   **纪律已经有了，只是没写成规矩。**
3. 加一条判据：**"机械产物单独成一条提交"**（可检查：该提交只改 `build/` 下的文件）。

**收益：把 93% 的噪声从人的注意力里拿掉，一行产品代码都不用改。**

### B. 把"数据"从"逻辑"里拆出来，走已有的生成管线（中代价，收益最大）

判据是**这件事是数据还是逻辑**：

| 是数据（→ 生成） | 是逻辑（→ 仍要双写） |
|---|---|
| 内建表：名字 / arity / 返回类型 / 形参类型 | 内建函数的**发射**（`lomentc.builtin` 与 codegen 的对应分支） |
| 关键字表（`extern`、将来的 `choose`…） | 关键字在**文法里的位置**与解析分支 |
| 诊断码表（E001–E021 + 消息 + 修复建议） | 触发诊断的**条件** |
| `lom/*.lom` 原语清单（**含 freestanding / hosted 的区分**） | 原语的实现 |
| 能力域名字表 | 能力域的语义 |

做法：参考实现加 `--dump-surface`，产出 `loment/tools/surface_data.lomt`，
自举 `use surface_data` 逐片解。**形状照抄 `win_shim_data`。**

**收益**：
- 加一个内建函数 / 一个诊断码 = **改一处**，两个实现**由构造保证一致**，
  `test_m81_builtin_table_matches` 这类"站岗判据"可以**删掉**（判据变少是好事）。
- 逐字节一致那条门禁**不可能**再因为表不一致而红。
- **`docs/158` §5 的第 1、2 步（规范 + 一致性套件）从手写变成生成。**
- `docs/175` §4 那条"L0 必须能区分 freestanding / hosted 原语"**直接落在数据表里** ——
  这可能是 B 最先该做的一件事，因为它同时解掉 std 分层的契约问题。

**不做过头**：B 不减少逻辑部分的双写。全量占比要实测，不要先吹。

### C. 分层冻结（高杠杆，但要 compat 线同意）

今天 `docs/158` §2 把七样东西**平铺在同一级**冻结：
语法/类型规则、诊断、单元装载、发射符号约定、双后端等价、内建表、能力语义。

但它们的**下游依赖强度差别极大**：

| 层 | 谁真的依赖 | 冻结强度 |
|---|---|---|
| `lom/*.lom` 原语 + 能力语义 + 发射符号约定 | **内核线（`FujoOS-compat`）真的依赖**（`CLAUDE.md` 第 1 条） | **硬冻结**：四条流程一步不少 |
| 语法 / 类型规则 / 诊断 / 单元装载 | 只有语言线自己依赖；B 之后大半是数据 | **软冻结**：改 = 改表 + 重生成判据期望值，不需要跨线知会 |

**把"硬冻结"缩到内核线真正吃的那一层。** 这与 B 是乘法关系：
B 把数据生成化之后，"改冻结面"对数据类改动就退化成"改一张表"。

⚠️ C 是**契约口径**的变更，不是实现 —— 属于 `CLAUDE.md` 第 1 条，
要单独提交并知会 compat 线。

## 5. 我不主张的

- **不主张去掉第二个实现。** 见 §1.1：省 153 行手写，换来丢掉两份独立实现的交叉印证
  （`docs/147` 的 Potato 交叉判定就靠这个思路），亏本。
- **不主张把所有东西都生成化。** 只有"数据"能生成；文法位置、解析分支、发射逻辑是逻辑，
  双写税照付。**先把数据那半拿走，再实测剩下多少。**
- **不主张一次做完 A+B+C。** A 今天就能做且零风险；B 先拿**一个**表（建议内建表，
  它已经证明了自己在漂）走通，再谈铺开；C 要等 B 有实测数字。

## 6. 建议的次序

| # | 做什么 | 依赖 | 判据 |
|---|---|---|---|
| 1 | **A**：种子标成生成物 + 两提交纪律 + 一条判据 | 无 | 机械提交只改 `build/`；`git diff` 不再吐 3858 行 |
| 2 | **B0**：`--dump-surface` 产 `surface_data.lomt`，**先只放 L0 原语清单 + freestanding/hosted 标记** | 1 | 自举 `use` 它；`docs/175` §4 那条契约问题被解掉 |
| 3 | **B1**：内建表上同一条管线，删掉 4 处手镜像与 `test_m81_builtin_table_matches` | 2 | 该判据**删掉**后其余全绿；加一个内建只需改一处 |
| 4 | **C**：分层冻结（口径变更，单独提交 + 知会 compat 线） | B 的实测数字 | 硬冻结面只剩内核线真吃的那层 |

**在 1–3 落地之前，不要开始 `choose` / 前端 / std 转正** —— 那三件都会改冻结面，
而它们的代价结构正是本文在量的东西（`docs/175` §7 的三处待拍板也随之推迟）。
