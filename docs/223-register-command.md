> 2026-10-09 用户提的形态 · **形态 B 与形态 A 都已落地（2026-10-10，§10）** · 上游：`docs/169` §3b（今天唯一的注册方式）、

> `docs/146` §5 与 SKILL §5（`guard` 不是授权、`syscall4` / FFI 都是裸的）、

## 0. 一句话

**今天注册一条命令要在 `PATH` 上放一个叫 `loment-<名字>` 的文件（`docs/169` §3b）——
名字与实现是分开的两件事。** 这份设计把它们合成一件事：**名字写在源码里，实现也在源码里**。

```rust
module mycmd

pub fn loment_command() -> str { return "mycmd"; }      // 名字进源码

pub fn command_main(argv: ptr, argc: u32) -> u32 {      // 实现也在源码里
    return 0;
}
```

于是 `loment mycmd ...` 能用。**`lomcli.lomt` 一个字都不用改**（启动器要改一行 —— 见 §1
那条实测纠正）。

> **位置只能写成函数**：`command` **在语言里已经是关键字**（`command <语言>`，外部代码块的
> 语言名声明，`docs/185`），所以标签叫 `loment_command()`。实测：`pub fn command() -> str`
> **连解析都过不去**（`期望 {，得到 ' return "mycmd"; '`）。这条不是审美，是撞名。

## 1. 为什么不能更直接一点

不是不想，是三件已经成文的事实把路堵死了，先把它们写死：

1. **命令面是编译进去的。** `loment help` 那 38 条来自 `loment/tools/lomcli.lomt` 的
   `catalog()`（`docs/169` §2），是一份**编译好的** Loment 程序里的表。用户的单元不是它的
   一部分。
2. **没有运行时装载。** 链接是静态的：ELF 那边 `-nostdlib -static`，PE 那边的导入表是
   **构建期写死**的 11 个 kernel32 函数（`loment/tools/win_shim_data.lomt` 里那两张表），
   而运行时只有 8 个 syscall（`docs/167` §5 / `docs/169` §4）—— 没有 `dlopen`，
   也没有能用 `LoadLibrary` 的入口。所以"把一条命令塞进正在跑的那个 CLI"没有机制。
3. **启动器是唯一看得见 `PATH` 的地方**（`docs/169` §3b 的原话）。官方 CLI 看不见 `PATH`，
   所以分发只能发生在启动器这一层。

⇒ **"在源码里注册"必然在构建那一刻结算成一样东西：一个叫 `loment-<名字>` 的文件。**
这不是妥协，是**与 `docs/162` §2b 同向**（"扩展点落在文件系统上，没有注册表"）：
这条设计**不开第三个口子**，它只是让第一个口子的文件名**由源码决定**，而不是由你手敲。

**判据（这条设计成不成立就看它）**：实现落地后，**`lomcli.lomt` 的 diff 是空的**。

> **实测纠正（2026-10-10）**：这句话原先连**启动器**也算进去了，那是错的。产物文件名
> **就是启动器决定的**（`out="${src%.lomt}"`，Windows 侧还负责加 `.exe`），所以"名字来自
> 源码"必然要启动器**去问一次**（`loment-driver <入口> --print-command`，答一行名字、
> 没声明答空行）。改的是 4 行 shell/cmd，不是运行时机制：**没有注册表、没有新的查找路径、
> 官方那 38 条一个字没动**。
>
> 代价记在这里：**不给 `-o` 的 `build` 会多装载一次**（问名字那一趟）。给了 `-o` 就不问
> —— 名字既然由你说，就不必再问。

## 2. 两种形态：表面是 `register`，先落地的是标签

| | 形态 A（用户要的样子） | 形态 B（先落地的那一半） |
|---|---|---|
| 写法 | `register mycmd { fn command_main(argv: ptr, argc: u32) -> u32 { … } }` | `pub fn loment_command() -> str { return "mycmd"; }` + `pub fn command_main(argv: ptr, argc: u32) -> u32` |
| 是什么 | **一条新语法**（名字在语法里） | **两个标签**（不是关键字） |
| 谁读它 | 词法器扫标签（名字与块的形状）+ 解析器收块里那个函数 | 装载器**按标签扫一遍**（词法器，不套 parser） |
| 代价 | `docs/188` §7.1 那张登记处清单走一遍：lexer / parser / checker / codegen / 诊断码 / 内建表 × **两份实现** × **七门表层语法**，外加种子重生成（`docs/176`：那次是 3858 行生成物） | **不动语法**：只动装载器与构建器 |
| 现状 | **已落地（2026-10-10，§10）** —— 实际代价比这张表估的小得多，见 §10 第 2 条 | **已落地（2026-10-10）** |

**A 编译到 B**：`register mycmd { … }` **语义上**就是那两个标签，与 `docs/188` 里"六门表层语法
编译到同一批语义"是同一种做法 —— 表层多一门，语义面只加一处。

> **实测纠正（2026-10-10）**：这句话原先写的是"脱糖成那两个标签"，读起来像**编译器往 token 流里
> 插一段**。做不到，也不必要 —— 自举侧的 token 记录是 `(kind, start, len)`，`start/len` 指进
> **源文本**，凭空造一个 `loment_command` 函数就得改缓冲区。真正的做法是**两处各读各的**：
> 名字由**词法器从语法里读**（形态 A）或从函数体里扫（形态 B），块里那个函数就是**普通函数**
> （块里**恰好一个函数**，见 §10 第 5 条 —— 那不是审美，是实测逼出来的）。
> 于是产物里**没有** `@loment_command` 那条定义（形态 B 有，而且没人调用）—— 两种写法的 IR
> **不逐字节相同**，行为相同。§10 第 1 条。

**为什么 B 不算"引入新格式"**：仓库里已经有**三份按标签读的 Loment 源码**——
`loment.conf` 的 `source_ext()`（`docs/143` §2.3）、`pkg.lomp` 的 `name()` / `version()`、
`lompi.conf` 的 `registry()`，读法都是**词法器扫标签、不套 parser**，理由写在
`docs/158` 里"2026-09-16 加的又两条"那一段的第 2 条（"两个实现的读法必须逐字节同源"）。
命令声明是**第四份同形状的东西**，
不是新物种。而形态 A 是真新语法，所以它排后面。

## 3. 语义（两形态共用；下面都用 A 的样子写）

### 3.1 名字与落点

- **命令名进源码**；命令行只决定**目录**。`loment build mycmd.lomt --install ~/.local/bin`
  → 写出 `~/.local/bin/loment-mycmd`（Windows 上 `loment-mycmd.exe`）。
- **文件名就是登记**（`docs/169` §3b 那条规矩不变）：装了就生效、卸了就没了，
  没有清单、没有中心目录。
- `-o` **保持今天的含义**（一个名字前缀，写出的就是你给的），不改它；要"名字由源码定、
  只给目录"就走 `--install DIR`。

### 3.2 入口

- 工具链**生成 `_start`**：读 `/proc/self/cmdline`、调 `command_main`、把返回值交给
  `exit`。所以带命令的单元**不许自己写 `_start`**（见 §5 诊断）。
- **`argv` 的切法**：命令名在**启动器**那一步就已经被 `shift` 掉了（`docs/169` §3b：`loment foo
  a b` → `loment-foo a b`，"名字 shift 掉，后面的参数一个不动"），所以

  ```
  $ loment mycmd a b
    启动器 exec:   loment-mycmd a b
    command_main 收到:  argv[0]="…/loment-mycmd"  argv[1]="a"  argv[2]="b"   argc=3
  ```

  —— 与 C 的 `main(argc, argv)` 同形，唯一的差别是 `argv[0]` 是**文件路径**而不是命令名。
  命令真正的参数是 `argv[1..]`。
- **退出码原样带出**（启动器本来就"退出码原样带出"，`docs/169` §3b 的表格）。
- **今天能写的入口形态是裸的** `(argv: ptr, argc: u32)`：语言里**没有元素为 `str` 的切片**
  （`[str]` 不是一种类型）—— 所以"`fn main(args: [str])`"那种读法**现在写不出来**。
  想要它得先补那一格（`docs/143` 的类型表），或者用 `lompi/store/host/0.1.0/argv.lomt`
  那几个辅助（`argv_scan` / `argv_at` / `argv_eq`）。**这一条是前置条件，不是实现细节。**

### 3.3 冲突与条数

| 情形 | 行为 | 为什么 |
|---|---|---|
| 一个单元里**两条**命令 | **构建期报错**（新诊断码） | 一个文件只能有一个名字；要发两条命令就写两个单元 |
| 名字与**官方 38 条**撞车 | **构建期报错** | 官方优先（`docs/169` §3b）——装了也顶不掉，与其让你装完白费，不如编的时候就拦住 |
| 两个项目注册了同名命令 | **不拦**：后放在 `PATH` 前面的那个赢 | `PATH` 的优先级是 `PATH` 的事，跟本设计无关 |
| 既有 `_start` 又声明了命令 | **构建期报错** | 两个入口 |

### 3.4 命令名是平的

`loment foo bar` 里 `bar` 是 `foo` 的**参数**，不是「两级命令」—— 启动器只 `shift` 一个名字
（`docs/169` §3b）。所以 `register` 的名字里不许有空格。

## 4. 与既有两条口子的关系

`docs/162` §2b 写的是"**两个**扩展点"：自己的源码后缀（`loment.conf`）与自己的子命令
（`PATH` 上的 `loment-<名>`）。这条设计**不新增第三个**，它给第二个**补上缺失的那一半**：

| | 名字从哪来 | 落点 | 今天 |
|---|---|---|---|
| 源码后缀 | `loment.conf` 的 `source_ext()` —— **源码里** | `<项目根>/deps/…` 按后缀找 | ✅ |
| 子命令（今天） | **你手敲的文件名** | `PATH` 上 | ✅ |
| 子命令（本设计） | **源码里的声明** | `PATH` 上（不变） | ⛔ |

**没有做进运行时的东西**：不新增读 `PATH` 之外的查找、不新增任何清单文件、不碰
`lomcli.lomt` 的命令目录、不碰两个启动器。

**与 `lompi` 那条边界一致**（`docs/170`）：用户注册的命令**不进 `loment help` 的总览** ——
总览只说 `loment` 自己的 38 条。查得到与敲得动是两件事，判据里钉着这一条。

## 7. 判据（要加哪些）

1. **产物名字来自源码**：拿一个真单元编一次 → 产物的文件名就是 `loment-<名字>`。
2. **真的能被分发**：把它放进一个临时目录、前置到 `PATH`，**两个启动器各跑一遍**
   `loment <名> ...`（`loment_cli_test::test_user_command_on_path_is_run` 就是这套模型：
   真 bash 启动器 + 桩 CLI，断言命中用户命令、名字没被当参数传下去）。
3. **不打扰官方面**：`loment help` / `loment commands` 里**没有**这条命令（`docs/170`
   那条边界同款判据）；`loment <官方名>` 仍然走官方实现。
4. **三条诊断各一条反例**：一条单元两条命令 / 撞官方名 / 有 `_start` 又有 `command_main`。
5. **入口契约**：参数的切法（第一个是命令名之后的第一个）、退出码原样带出 —— 用一条
   真跑的命令把 `argv` 打出来比对。

## 8. 边界（诚实清单）

- **不是沙箱。** 注册一条命令 = 让 `loment <名>` 跑**任意原生代码**，带用户全部权限，
  没有任何声明、没有审计、没有拦截 —— 同一条边界在 `docs/146` §5（"`guard` 不是授权"）、
  SKILL §5（"`syscall4` / `alloc` / FFI 都是裸的"）与 issue #23 里各写了一遍。
  发布别人的命令等于发布别人的程序。
- **不能联网。** PE 那 8 个 syscall 里没有 socket（`docs/217` §1）。真想联网的命令得自己带
  网络那一半 —— `lompicheck` 就是：命令用 Loment 写，拉取交给一个 shell 薄壳。
  形式 B 落地后它**只会少掉"注册"那一半**，拉取那一半仍然是 shell。
  （另一条路：像 `lompi fetch` 那样**只打印出 `git clone` 命令**，于是它变成一个纯二进制、
  零 Python、零 shell —— 代价是每次自己更新缓存。两条路都成立，选哪条是它自己的事。）
- **跨平台按目标编**：PE 上只有那 8 个 syscall，写死的 Linux syscall 在 Windows 上返回 -1。
- **不管分发**：`--install` 只是把文件放对地方；`PATH` 仍然是你的事。
- **名字是平的、大小写敏感**（与 `PATH` 上的文件名同一条规矩）。
- **不解决"命令怎么被找到"之外的任何事**：没有版本、没有依赖、没有卸载
  （卸载 = 删文件，`docs/169` §3b 的口径）。

|---|---|---|

**"一个单元两条命令"没做成新码**：两条 `pub fn loment_command()` 就是**现成的 E013
（重名）** —— 语言早就有这条，再发明一个码只是同一个修法写两遍。

**实现纠正了设计里三处**（都是写文档时看不出来的）：

1. **`command` 是关键字**，标签只能叫 `loment_command()`（§0 那条注）。
2. **启动器必须改**（§1 的纠正框）：产物名是它决定的，所以它得去问驱动器；
   `lomcli.lomt` 则真的一字未动。
3. **入口的 argv 缓冲走 `brk`，不走语言那 64 KiB 堆**。第一版用 `alloc(65536)` 正好把堆吃光，
   产物**编得过、跑起来 SIGILL** —— 这条是端到端跑出来的，不是读代码看出来的。

**验过什么**（`tools/loment_register_test.py` 8/8）：

* 五条规则 + 三条码，外加一条"合法单元必须**零码**"；
* 两份官方名清单**逐条相等**（参考是一张元组，自举是 38 个 `cmd_span_is`）；
* `--print-command` 有声明答名字、没声明答空行；
* **拿桩驱动器真跑一遍 bash 启动器**：有声明 -> `loment-mycmd`，没声明 -> 源文件名，
  给了 `-o` -> 不问；
* **编出来、链出来、跑起来**：`cmd_hello one two` 的 stdout 是命令行开头、退出码是 3。

**`loment/examples/cmd_hello.lomt`** 是这条特性的例子，也是上面最后一条判据的夹具；
它同时进了 p8 的语料（两个实现发的 IR 逐字节相同）。

### 形态 A（`register` 块，2026-10-10）

```rust
module mycmd

register mycmd {
    pub fn command_main(argv: ptr, argc: u32) -> u32 { return 0; }
}
```

| 落在哪 | 参考实现 | 自举 |
|---|---|---|
| 名字（扫标签） | `lomentc.command_label_from_tokens` 的 `register` 分支 | `lexer.lex_cmd_find` 的 `register` 分支 |
| 块的**形状** | 同上一处（`_reg_one_fn` / `_brace_close`） | 同上一处（`lex_reg_one_fn` / `lex_reg_close`） |
| 抄名字 | 直接取 token 的 `val` | `lexer.lex_cmd_label`（按 token **种类**决定剥不剥引号） |
| 收块里的那个函数 | `lomentc.Parser.parse_items`（`nested=True`，条目链**同一份**） | checker / codegen **不用动**（它们不看深度）；`potato` 收函数那**两趟**要跳过壳 |

**实现纠正了设计里五处**（都是动手才看得见的）：

1. **"脱糖成那两个标签"做不到，也不必做**（§2 的纠正框）。自举的 token 是
   `(kind, start, len)`，`start/len` 指进**源文本** —— 凭空造一条
   `pub fn loment_command()` 就得改缓冲区，而缓冲区一改，后面每个 token 的偏移都要跟着动。
   改成"名字由语法给、块里的那个函数就是普通条目"之后，自举侧只剩**词法器**那一处
   （外加 `potato` 两趟跳过壳，见第 5 条）：
   - checker 找 `command_main`、codegen 的顶层 `fn` 扫描、字符串常量的按函数归属，
     本来就**不看括号深度**，所以块里的那个函数与写在顶层的那一份走同一条路。
   - 代价是产物里**没有** `@loment_command` 那条定义（形态 B 有，而且没人调用）——
     两种写法**语义相同、IR 不逐字节相同**（`docs/158` 那条记录里钉着）。
2. **块里那个函数必须叫 `command_main`**。设计里写的是 `fn main(argv, argc)`，落地时发现
   **重命名那一层是纯代价**：名字一改，自举侧的符号表、字符串常量归属、递归调用解析全都
   要多一次映射，而参考实现那边（函数表按名字查）又要多一处规则。**不引入重命名**之后，
   两个实现看到的是**同一个函数**，没有可漂的一层。
3. **E026 原先缺一半**：声明了命令却没有 `command_main` 时，两个实现**都不报** ——
   一路编到**链接**才炸（`/proc/self/cmdline` 那个入口去调一个不存在的符号）。补上之后
   拦在检查这一步，码不变（两半少一半，修法都是把两半凑齐）。
4. **名字允许写成字符串字面量**。合法名字的字符集是 `[A-Za-z0-9_-]`，而 `-` **不是**标识符
   字符 —— 只收标识符的话，`cmd-hello` 这种名字（示例就是）在形态 A 里写不出来。多收一种
   名字形态只多几行（抄名字那一处本来就按 token 种类分流）。
5. **块里钉成"恰好一个函数"**，而且这条**不是设计里定的，是实测逼出来的**。设计里写的是
   "块里的条目就是普通条目"（`const` / `impl` 都能进）。落到自举侧才发现：块那层壳对
   **按深度走**的读者是**可见**的 —— `potato` 收函数那两趟只看 `d == 0`，块里的
   `fn command_main` 因此**一条都没收**（`loment_potato_emit_test` 报
   `register_hello.lomt: 第 14 行不同`，形式对象的 `functions` 那格是空的）。修法是让那两趟
   跳过壳，但**只有函数**那两趟需要：把块钉成"只有一个函数"之后，别的条目根本进不来
   （判形状时就拒了，E024），于是要看穿壳的地方是一个**可数的小集合**，而不是"每一处按
   深度走的读者都要各自学会这件事"。**代价**：块里不能放辅助函数 —— 它们照旧写在顶层。

**验过什么**（`tools/loment_register_test.py` **9/9**）：

* 形态 A 的合法单元**零码**（标识符名与字符串名各一条）；块里放东西不对（套一个
  `register` / 有声明没体）各有码；
* **两种写法跑出同一个结果**：`cmd_hello` 与 `register_hello` 编出来、链出来、各跑一遍，
  stdout 与退出码**逐个字节/逐个数字相同**；
* `--print-command` 对块那种写法答出同一个名字；
* **五条新负例**进 `loment_rule_parity`（撞官方名 / 与 `_start` 并存 / 签名不对 / 有声明没体 /
  有体没声明），`BUDGET` **81 -> 86**，两种写法判成**同一批码**；
* 两份示例进 `loment_potato_emit_test` 的 `COVERED`（形式对象逐字节）与
  `loment_elf_test` 的 `CORPUS`（clang 与原生链接器编出来的 stdout/退出码比）。

**入口那一轴（`docs/182` §1.9）一并过了**：`lomfmt` 两份的顶层关键字表加了 `register`
（不加就会被揉进上一行）；两个语言服务的关键字补全表都加了它（`loment_lsp_test` 里那条
"Python 版的关键字必须是自举版的子集"就是那份保证）；`lomdoc` 与 `lomfmt` 的**语料闸门**
自动收进 `loment/examples/register_hello.lomt`（两份实现输出逐字节比）；语言服务那边另加
一条"编得过的 `register` 源不许报假错"（两个服务各一条）—— **那一条抓到的是一处既有缺口**：
`tools/loment_lsp.py` 的 `_parse` 绕过了 `lomentc.load`，于是**命令声明那一趟从来没跑过**，
一份编得过的命令单元在编辑器里被报成"写了 `command_main` 却没有命令声明"（形态 B 也一样）。

**还没做**：

* **`loment build --install DIR`** —— §6 步骤 2。今天产物落在当前目录，仍要你自己拷进 `PATH`。
* **`--print-command` 那趟多装载一次**（不给 `-o` 时）。真要省，可以让驱动器把名字写进
  一个 `--command-out PATH`，一趟出两样东西 —— 没做，因为多一个开关的代价比省一次装载大。
