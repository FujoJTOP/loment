## 1. 为什么"彻底结束"的核心是**归档 + 重定位**，不是加更多语言

今天的 FFI 只吃**一个自包含的 `.o`**：不许有重定位、不许有未定义符号（`docs/173` §3）。

**真实的 C 库不是这个形状。** 真实库是**多目标文件的归档**（`ar rcs libfoo.a a.o b.o`），
成员之间**互相引用**，每个成员**都有重定位**。所以：

- 现在能调的只是"手工挑出来的单函数玩具"；
- "彻底结束兼容库" = 让**标准形状的静态库**能链 —— 这正是 `docs/173` 的**阶段 2**。

**所以计划的第一块是机制（它同时是 C 真正可用的前提），第二块才是语言广度。**
