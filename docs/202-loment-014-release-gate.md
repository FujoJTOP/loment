### 2.1 "全门禁绿"那 4 条：私有姊妹仓怎么进 CI

`fuai_contract_check` / `lom_audit` / `lomc_test` / `potato_cross` 这 4 条要读
`LinuxFUAI/`（L0 契约的**对面那一侧**，`CLAUDE.md` 第 1 条）。它在 GitHub 上是**私有仓**
（实测 `private: true`，体积 102 KB），所以公开 runner 上**没有东西可读**。

| 选项 | 代价 | 风险 |
|---|---|---|
| **A. CI 用 secret 拉私有仓** | 4 条真的能绿，"全绿"保持字面 | ⚠ `pull_request` + secret 是**已知的 pwn-request 面**：同仓分支的 PR 能改 workflow 把 token 带出去。缓解：**只在 `push` 到 main 与 `workflow_dispatch` 上拉**，PR 上不拉 |
| **B. 4 条在 CI 上按设计"响亮跳过"** | 不动 secret；判据口径改成"**全绿（除 4 条需要私有对照面的）**" | 口径不再字面；但**跳过要响亮**（一条 `SKIP: 缺 LinuxFUAI（私有姊妹仓）` 的行进 summary，**不是**静默绿） |
| **C. 造一个"对照物快照"进本仓** | 4 条在 CI 上能跑 | 把跨线契约的对面那一侧**抄进本仓** = 与 `CLAUDE.md` 第 1 条（只读副本、改要去对面改）直接冲突，判据会拿一份只在本地成立的对照面报绿 —— **不建议** |

**我的建议：B**（先让口径诚实、跳过响亮），把 A 留给"确实要 CI 覆盖 L0 对账"那一天，
并且到那时按"只在 push/dispatch 上拉"的写法做。

**裁决（2026-09-22）：这一项不做。** 用户原话「除了 1 其他全做」—— 也就是**连口径也不改**：
门禁的判据**照旧**是"不新增红"，`CONTRIBUTING.md` 与 `gate.yml` 一个字都不动。
⇒ **第 1 项保持未完成**，这是**有意的**，不是漏做。上面的 A/B/C 三个选项连带我的建议
**原样留在**这里，等哪天真要 CI 覆盖 L0 对账时再翻。

### 2.2 "第三方复核"包不包括**独立 agent**

`docs/145` 的 M100 那行写着"**缺第三方复核本身，无法由作者自证**"；而
`CONTRIBUTING.md` 写的是"**任何补丁都可能被 AI 评审，而且算数**"。两条口径**没有对齐**：

- 若"第三方"要求**另一个人类/组织** → 这条只能等（我做不了）。
- 若"独立 agent 的一次干净复核"算数 → 可以现在就做：**开一个没有本会话上下文的会话**，
  只给它 `docs/160` 审计包（主张 / 不主张 / 复核步骤 / 对抗性尝试）+ 仓，让它**独立**跑
  那 18 条主张、并在**它自己**的判断下接受或反驳；结论与证据落盘。

**这一条我不替用户定** —— 它决定 M100 能不能翻 ✅。

**裁决（2026-09-22）：按第二种口径 —— 独立 agent 的一次干净复核算第三方。**
依据是 `CONTRIBUTING.md` 那句"任何补丁都可能被 AI 评审，**而且算数**"：它对**补丁**
成立，对**审计**也就该成立，否则同一份文档里"agent 的复核算不算"会有两个答案。
于是 M100 的"第三方复核"**现在就能做**，做法照上面那条：

* 开一个**没有本会话上下文**的会话（独立 agent），只给它 `docs/160` 审计包 + 仓；
* 让它**自己**跑那 23 条主张、**自己**判接受或反驳，**并留下它试过的对抗性手法**；
* 结论与证据落盘为一份 `docs/` 复核报告，**署名写清它是谁**（模型、日期、"与本会话无上下文"）。

⚠ **对这条口径要诚实的一点**：独立 agent 与作者**同源**（都可能共享同一类盲点），
它**弱于**一个外部人类/组织。所以这条只声明"**M100 的第三方复核这一步有人做过了**"，
**不**声明"这个语言因此被独立验证过"。等真有外部人类愿意复核时，那份报告**仍然有意义**
（它是独立的一份，可与之对照），不被这一条作废。

### 2.3 第 6/7 项：那 22 份手写件与 `editors/` —— 两份豁免

两格的**共同形状**是：判据里写着"要么移走/改写成 Loment，要么明确豁免"，而**移走那一支
不成立**。2026-09-22 裁定**两格都走豁免**，理由各自不同：

| 项 | 裁定 | 为什么移不走（实测） |
|---|---|---|
| **6 · 22 份手写驱动** | **保留 + 明确豁免** | 它们**不是孤立的手写件**，而是**已提交 `.ll` 工件的宿主**：`loment/build/native*.ll` / `demo.rs` 在索引里、由 `lom_audit.transpile_wants()` 与生成器逐字节对账。删掉驱动 → 工件成孤儿。它们还构成一条**不碰 Python 的验证路径**（新克隆 + clang 即可复核原生后端）—— 这条在 **S2 拆掉参考实现之后更有价值**。重写它们的条件是 **S4**（Loment 能产带 IO 的可执行文件），届时驱动该是 `.lomt` |
| **7 · `editors/`** | **明确保留 JS/TS** | VS Code 扩展**只能**是 JS/TS（平台硬约束，`docs/189` §2 E）—— "Loment 孪生"这条判据**本身不成立**，不是"还没做"。扩展的行为判据在（`loment_editors_test`），S5 **无剩余工程** |

⇒ **第 5 项那句"仓里不许有非 Loment 代码"的适用范围**因此要连着这三类豁免一起读：
**跨线对照物**（`kernel/`/`sdk/`，改要去对面改）、**语料**、**手写验证壳**（等 S4）、
**编辑器宿主**（平台约束）。**四条都不是"网开一面"，是把那句话的边界说准**；
逐条的依据写在 `docs/189` §3.0。

## 4. 这份清单怎么用

- **它是一份账**：每一项都要能被**证伪**（"零红"、"18/18 + 第三方复核"、"仓里没有非 Loment 代码"），
  所以"完成了"不是感觉，是判据。
- **改它要跟判据一起改**：某一条的判据变了（比如 §2.1 选了 B），要在**同一个 PR 里**把那张表
  与 `CONTRIBUTING.md` / `docs/189` 的口径一起改 —— 别让两处说法分家。
- **它不是排期**：依赖顺序是硬的（S2 等 S1、hosted 等 B0），但每一条的工期本文不猜。
