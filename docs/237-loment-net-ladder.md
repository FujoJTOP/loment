# 237 · 联网的准入（一）：`net_ladder` —— 宽度组成成了不读源码可判的数

> 状态：**已落地**（2026-10-13，Potato **v14**）。这是**准入**那一层的第一件实产：
> `docs/218` §7 收口的三个可数对象，第 1、2 件早就落了（`surfaces`、E005 的行为轴），
> 第 3 件 `net_ladder` 一直停在"**待定题**：按哪一维拆"（`docs/227` §4 第 3 行）。
> 用户 2026-10-13 拍板：**按"宽度"拆**，而且**准入这一层要做**。
>
> 一句话：**"这份程序要多少联网宽度"里的「组成」，从今天起是一个不读源码可判的数。**

## 1. 为什么是"宽度"这一维

`docs/218` §7 结尾那句话定了顺序：

> 这三条加起来仍然不是"宽度"（§2），但它是宽度的**前置条件**：没有可数的面，
> 就没有可比的宽度。**顺序是：先让它可见且可判，再谈让它随证据变宽。**

§7 第 3 件要的正是"**可比**"这一半，而 §2 那套（宽度是挣的、判定可复现、对端是字节）
要的是"让它变宽"。两件事之间的桥就是这个维度：**档 = 这条站点在它最宽的那一步上要多少
宽度**。选别的维度（GC 四层、`sealed`/`hosted`）都会做出一份与准入无关的计数 ——
`docs/227` §4 那句"做出来的多半是一个**没人会读的第二份计数**"点名的就是那种形状。

四档直接对齐 §2 那三个刻度与 §11 的"从 0 起"：

| 档 | 是什么 | 号 |
|---|---|---|
| `w0` | 只够**验证对端字节** —— 同机上的一对端点，没有陌生对端可以进来 | `socketpair`(53) |
| `w1` | **一条有界连接** —— 对端是它自己挑的**一个**（客户端与数据面） | `socket`(41) `connect`(42) `sendto`(44) `recvfrom`(45) `sendmsg`(46) `recvmsg`(47) `shutdown`(48) `getsockname`(51) `getpeername`(52) `setsockopt`(54) `getsockopt`(55) |
| `w2` | **多条并发** —— 多路复用本身不搬字节，要的宽度是"同时盯着很多条" | `poll`(7) `select`(23) `epoll_wait`(232) `epoll_ctl`(233) `epoll_create1`(291) |
| `w3` | **接受任意对端** —— 对端**由别人挑**，宽度是"谁都能来" | `bind`(49) `listen`(50) `accept`(43) `accept4`(288) |

21 个联网号**恰好**各有一档（`lomentc.NET_WIDTH_RUNGS`）。

**数的是站点，不是能力**：一个单元写了两处 `connect` 就是 `w1: 2` —— 与 `gc_ladder`
数的是 `alloc` 站点同一条口径。宽度本身（同时能持几条、能传多少字节、能活多久）不在这里。

## 2. 对象里长什么样（v14）

```json
"net_ladder": { "w0": 1, "w1": 2, "w2": 2, "w3": 1, "total_net": 6 }
```

**四档恒在**（哪怕为 0），与 `gc_ladder` 同 —— 键的集合固定，读者与校验器都不用猜。

两条自洽，都由**校验器独立判**（它读不到源码，所以判不了"档分得对不对" —— 那是策略 ——
但判得了"两处自相矛盾"）：

1. `w0 + w1 + w2 + w3 == total_net`（与 `gc_ladder` 那条同形）；
2. **`total_net == surfaces.net`**（新的一层交叉）：每个联网站点落在一档里，而它在
   `surfaces` 里落在 `net` 面里 —— **两处数的是同一批站点**，只是分的粗细不同。
   少一档 = 有的联网站点没归类；多一档 = 给不联网的号配了宽度。**两个方向都红。**

### 与 `surfaces` 的关系：粗细不同，不是同一个数

`total_net` **不等于** `total_sites`：号写成变量的站点落在 `surfaces.other` 里，
**不在梯子上**（`lomentc_test::test_net_ladder_rule` 用那 6 vs 7 钉住这一点）。
拿 `total_net` 去对 `boundary.syscalls` 是错的 —— 那条属于 `surfaces.total_sites`。

## 3. 这张表是**策略**，所以它没有"与运行时判等"那条判据

`SURFACE_NUMBERS` 抄的是 `lomelf.PE_SYSCALLS`（运行时的**事实**），两边逐条判等
（`loment_pe_test::test_surface_table_matches_the_runtime`）。**分档不是事实，是策略** ——
运行时不认"宽度"，所以没得判等。能判的只有**同集**：

* `set(NET_WIDTH_RUNGS) == {SURFACE_NUMBERS 里 face == "net" 的那些号}`；
* 四档**都**有号（免得写成三档、代码里留着第四档）。

判据 `lomentc_test::test_net_width_rung_table_covers_the_net_numbers`。

**表的一致靠孪生**：自举侧那张表是 `loment/selfhost/potato.lomt` 的 `pt_rung_code`，
与参考实现是两份手写的表 —— 它们的一致由**逐字节孪生**判据钉
（`loment_potato_emit_test`）。**这一条之所以真的被验过，是因为摆了一份钉子**：
`loment/examples/net_ladder/main.lomt` 让四档**都非零** —— 树里别处**一处联网站点都没有**
（`docs/218` §1④ 实测 0 处），不摆这一份，"四档到底数没数对"两个实现都数出 `{0,0,0,0}`
也照样逐字节相同。形状抄的是 `gc_ladder` 那份钉子（`examples/gc_ladder`）。

## 4. 两处实现（别漏了第二处）

`docs/210` 的教训在这个仓里是常态：**一份判据要落在两个实现上**，否则"孪生"只是自称。

* **参考实现**：`lomentc.NET_WIDTH_RUNGS` + `_count_net_ladder`（与 `_count_surfaces`
  **共用同一遍遍历** `_machine_call_sites` —— 走两遍就会漂，那正是那条交叉不变量的前提）；
* **自举侧**：`loment/selfhost/potato.lomt` 的 `pt_rung_code` + `pt_rung_total`，
  计数循环与面那一张**共用**（`pt_surf_count` 多了一个 `table` 参数：0 = 面、1 = 宽度档）；
* **两份校验器**：`tools/potato.py`（Python）与 `loment/tools/lompotato.lomt`（自举）——
  `potato_test` 的孪生判据比的**连错误条数都要一致**（160 份对象：54 合法 / 106 非法）。

## 6. 写明的边界（别把这一篇读成"准入做完了"）

* **这不是宽度**。它数的是"这份程序**要求**多少宽度"，而 `docs/218` §2 的宽度是
  "**挣来的、可复现的、按台账变宽的**"。这一篇是那句话的前置条件，不是它本身。
* **`w0` 今天只有一个号**（`socketpair`）。§11 的"零宽阶段"要钉的是"**零宽流量能发什么**"
  这一条**静态规则**（只允许产物字节与它的证明），那还是一条没写的规则 —— 记在下一轮。
* **档名与分档都是我划的**，与面名一样是**用户的**（`docs/224` 那条立场）。
  换一套划法不影响形状：对象里只有"四档 + 总数"这个形状是固定的。
* **判定仍然没有时钟**：`qual_seq` 是序号不是时钟（`docs/218` §9），所以"按时间衰减/
  过期"这一族**做不到**，这一篇没有改变它。
