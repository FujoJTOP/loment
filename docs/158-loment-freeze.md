# 158 · Loment L1 冻结面（M96）

> 版本：`L1 0.1.4-alpha2`（显示名 `Loment 0.1.4 Alpha2`；`loment/build/release-manifest.json`
> 的 `release` 字段由 `tools/loment_release.py:RELEASE` 单一真源给出）；对外 tag `v0.1.4-alpha`
> 判据（docs/145 M96）：**冻结意味着"改动要付代价"** —— 任何触及冻结面的改动都必须
> 同时改规范、改一致性套件、两个实现同一次提交改完，并走 §5 的流程。

## 1. 为什么现在能冻结

冻结的前提不是"功能齐全"，而是**规范有唯一的执行者且可测量**：

- 自举 checker 与参考实现在 **63/63 条规则**上判定等价（`tools/loment_rule_parity.py`，
  棘轮门禁 `eq ≥ BUDGET`、假阳性/漂移必须为 0，已进 `tools/ci.py` 静态门禁）；
- 63 条规则负例**直接喂自举驱动**全部非零退出且无一因信号而死
  （`test_m85_driver_gate_on_probe_cases`）；
- 40/40 语料单元零诊断、40/40 可发射目标**两个后端逐字节一致**、三阶段自举定点成立
  （`tools/loment_p8_test.py`）；
- 错误码口径是**单一真源** `tools/loment_diag.RULES`（E001–E017），
  且参考实现能发出的**全部 81 条消息模板**都被它分类
  （`test_m64_all_reference_messages_are_classified`）。

换句话说：从这一刻起，"语言是什么"由**规范 + 一致性套件**定义，参考实现不再是唯一权威
（它是套件里的一员）。

## 2. 冻结面（改动要付代价）

| 面 | 内容 | 为什么冻结 |
|---|---|---|
| **语法与类型规则** | 词法（含"多字符运算符拆成单字符 token"这一条）、解析形状、类型系统、移动/借用规则 | 它们是用户程序与一致性套件的接口 |
| **诊断口径** | 错误码 E001–E017 及其"码按修法分"的分组原则 | 用户脚本/CI 会按码匹配；码是最稳的 ABI |
| **单元装载规则** | `use "...lomt"` 递归装载、依赖**先序**拼进单元、去重、预置枚举注入点（单元末尾） | 决定同名/顺序/枚举可见性，跨文件程序的语义靠它 |
| **发射符号约定** | **顶层名字在单元内唯一**（平名字空间，不做 mangling）；入口名（`_start`/`timer_isr` 等）由内核线按名查找；内核/驱动按名解析的符号不得私有化 | 这是**跨线 ABI**（docs/155 §3）：内核与 C 夹具按名字找入口，改名就是破坏契约 |
| **两个后端的等价性** | 对同一输入，自举 codegen 与参考实现的 IR 必须**逐字节相同**；三阶段定点必须成立 | 这是"两个实现"能互相验证的前提；它也是回归检测的主要手段 |
| **内建函数表** | 18 个内建的名字、元数、参数/返回类型（`lomentc.BUILTINS` ∪ `{slice_len}`） | 名字与签名被内核线直接调用 |
| **能力域语义** | `capability`/`guard`/`excluded` 的判定，字面量越界在编译期拒 | 它是信任自适应能力域（B25/docs/125）的输入 |

## 3. 明确**不**冻结（可以自由改）

- 实现内部：两张编译器的内部表布局、缓冲尺寸、遍历顺序、临时名；
  自举侧的 arena 分段、类型表述、性能（只要不动 §2 的等价性与容量闸门）。
- 工具链内部：`tools/*.py` 的函数/结构，只要对外命令行的**行为**与 §2 的判据不变。
- 文档结构：`docs/manual/` 的生成物内容随源变化（它由 `loment_manual --emit` 生成）。
- 性能：M86 目前只有护栏（自编译 ≤ 30s，实测基线 12.8s）。优化不受冻结限制 —— 索引化
  符号查找这类改动只要不改变产物字节，随便做。

## 4. 已知的开放项与刻意偏离（冻结时必须写明）

冻结**不等于**"完备"。这些是已知的口子，写在这里是为了让后续使用者与审计者不必自己撞：

| # | 项 | 现状 | 影响 |
|---|---|---|---|
| 1 | 三处**刻意偏离** | 下标/`&` 在"类型未知"时不报；`match` 主体未知时不报；`?` 只在能确定不是 `Result` 时报（详见 docs/150 缺口③） | 自举 checker 在这三种情形下**可能少报**；参考实现会报。方向是保守（不假阳性） |
| 2 | 同名 `let` 双 `alloca` | 参考实现复用槽位（一条 `%x.addr`），自举 codegen 发两条且第二条遮蔽第一条（docs/150 bug ⑬） | 同一函数里重复声明同名变量时两个实现语义不同 |
| 3 | 驱动器**没有 parser** | 驱动是 lex → check → emit；解析期错误（如 `const C: bool = true;`）它看不见，只能靠参考实现兜 | 自举链单独使用时，解析期错误不会被报出来 |
| 4 | `aarch64` 目标 | 后端支持 `elf64-littleaarch64`，但**未在真机/模拟器上执行过**（docs/145 M92） | 只保证发射，不保证运行 |
| 5 | 自举性能 | 自编译 12.8s（参考实现 1.2s），符号查找是线性扫 | 大单元编译偏慢；不影响正确性 |
| 6 | DWARF 变量信息 | 只有语句级行表，没有变量位置信息（docs/145 M59） | 调试器能按行断点，看不到变量值 |
| 7 | 外部审计 | 尚未由第三方复核（M100） | 冻结面内的判据都是**自证**的（自证不全等于正确） |

## 5. 改冻结面的流程（四条，缺一不可）

1. **改规范**：先改 `docs/manual/`（或对应的语言章节），把新规则写成可判定的句子；
   若涉及诊断，先在 `tools/loment_diag.RULES` 里给码（**码只增不改**；新规则加 E018+）。
2. **改一致性套件**：在 `tools/loment_rule_parity.py` 的 `_CASES` 里加**最小负例**，
   并**上调** `BUDGET`。**只调低 BUDGET 是放松门禁，等于隐瞒缺口** —— 门禁会因此变红。
3. **两个实现同一次提交**：`tools/lomentc.py`（参考）与 `loment/selfhost/checker.lomt`
   （自举）必须一起改；`loment_rule_parity`、`loment_p8_test`（含 40/40 逐字节一致与
   三阶段定点）全绿才算完成。
4. **过静态门禁**：`python tools/ci.py --static-only` 里的 L0/L1 门禁全绿；
   若触及内核线按名解析的符号（§2 那一条），必须先走 docs/155 的交接约定。
