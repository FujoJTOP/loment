# 238 · 联网的准入（二）：判定是**一个纯函数**，没有时钟

> 状态：**已落地**（2026-10-13）。接 `docs/237`（`net_ladder`：宽度**组成**可判）。
> 这一篇落的是 `docs/218` §2 的第 2/3/4 条 —— **宽度是挣的**、**收窄即时放宽要窗口**、
> **判定可复现**；而 §2 的第 5 条（对端是字节）落在记录里：台账的分组键就是**对端哈希**。
>
> 一句话：**准入判定是 `(自身, 对端, 台账)` 的函数，两个实现逐字节相同，任何第三方拿着
> 同样的输入都能重算。**

## 1. 判定长什么样

一条记录（**字段顺序与分隔符都是判据的一部分**）：

```
seq=12 self=aaaa… peer=bbbb… asked=w3 earned=w1 granted=w1 conns=1 bytes=65536 life=4096 held=3 why=widen-confirmed
```

* `asked` —— **产物自己要求的上限**（`docs/237` 的 `net_ladder` 里最宽的那一档）；
* `earned` —— 台账**挣到的**档（那份台账是**按对端分组**的：per-duty rolling 64，
  duty 就是对端哈希）；
* `granted` —— 在两者之间取小的那个，再过一遍窗口；
* 三刻度 `conns` / `bytes` / `life` —— §2 第 1 条那三个连续量（宽度不是"能不能"）；
* `why` ∈ `zero` / `hold` / `widen-pending` / `widen-confirmed` / `shrink-immediate`
  —— **它自己被记下来**，于是"这次准入为什么是这个宽度"是可判的，不是读日志猜。

输入是**恰好 7 个字段**：`<seq> <self> <peer> <hits> <asked> <granted_prev> <held>`。

## 2. 三条性质，各挂在哪

| `docs/218` 那条 | 怎么落的 | 判据 |
|---|---|---|
| §2 第 2 条 **宽度是挣的** | `hits`（台账命中数）→ 档；**没有"谁批准了你"** | 语料里同一对端只改 `hits`，`earned` 跟着动 |
| §2 第 3 条 **收窄即时、放宽要窗口** | `widen` 要连续 `WIDEN_WINDOW = 3` 个序号；`shrink` **当号生效**且 `held` 清零 | `test_widen_needs_a_window_and_shrink_is_immediate` 逐号走一遍 |
| §2 第 4 条 **可复现** | 判定只有那七个数；`loment_admit.admit` 的**形参表**就是它的输入集 | `test_the_judgement_is_reproducible_and_its_inputs_are_closed` |
| §2 第 5 条 **对端是字节** | 台账按 `peer` 分组、记录里回显两个哈希 | 语料里换 `peer` 就换台账 |
| §11 **宽度从 0 起** | `hits == 0` ⇒ `w0`，而 `w0` 的三刻度是 `(0, 1, 1)`：**只够一次验证交换** | 语料第 1 条 + 那条 `why=zero` |

### "没有时钟"是**结构化**的，不是一句口号

`docs/218` §8 的生死判据写的是"掺入时钟或随机数的实现必须红"。这条今天的样子很具体：
**输入是闭集** —— 用例恰好 7 个字段，**多一个就是错**（`expected 7 fields, got 8` 那一族
用例），而 `admit()` 的形参表由判据逐字钉住。想掺时间，第一个动作就是多要一个输入；
第二个动作是改两边的签名 —— 而判据比的是**两个实现**，两边都得改，骗不过去。

`qual_seq` 是**序号不是时钟**，所以"按时间衰减 / 过期"这一族仍然**做不到**（§9 点名不做）——
这一篇没有把它变可能，只是把它变成了**结构上不可能**。

## 3. 两个实现，逐字节相同

孪生纪律第一次用在**授权**上（§2 第 4 条），形状照仓里已有的那一对
（`loment/tools/lomsyscalls.lomt` ↔ `tools/loment_syscalls.py`）：

* 参考侧：`tools/loment_admit.py`（判定 + 用例读入 + 报错行）；
* Loment 侧：`loment/tools/lomadmit.lomt`（**自己写一遍判定**，不是调 Python）；
* 判据：`tools/loment_admit_test.py` —— 同一份用例文件，**stdout / stderr / 退出码
  逐字节相同**；Loment 侧那份链成 ELF 在 WSL 里跑。

**Loment 侧踩到的三个坑**（都记在那一对的注释里，因为下一个写工具的人会踩同样的）：

1. `sys_alloc` 返回的是**旧 brk**（块起点），不是新 brk —— 第一版返回了新 brk，
   每个缓冲指针都指到自己区域的**尾巴后面**，读到的是垃圾（实测：读进来的"用例文件"
   是进程自己的 ELF 头）；
2. 从 argv 里取路径要给 `open_ro` 传**偏移过的指针**（`ptr_add(argv, p1o)`）——
   那些文件助手从**偏移 0** 开始拷；
3. **入口函数不能靠 `return 0` 退出**：`_start` 是 lld 定的入口，返回就是跳到栈上的
   垃圾地址（实测：16 条记录全打对了，**收尾**段错误）。照 `lomsyscalls.lomt` 用 `die(0)`。

形参上限那条也在这里生效：判定函数只收 4 个形参 —— 解析出来的一条用例是**摆进一块缓冲
再传指针**，因为 11 个以上自举编译器会无声 SIGILL（`FujoJTOP/loment#265`）。

## 4. Stage 1 × Stage 2 的接缝

`asked` **不是**调用方随便给的：它就是产物自己 `net_ladder` 里最宽的那一档
（`loment_admit.asked_rung`）。判据拿**真产物**验了一遍：`loment/examples/net_ladder/main.lomt`
（四档都非零的那份钉子）报出来的 `asked` 是 `w3`。

于是那句"先让它可见且可判，再谈让它随证据变宽"（`docs/218` §7 结尾）有了具体形状：
**梯子给上限、台账给挣到的，判定在两者之间取小的那个** —— 而两者都是**不读源码可判的数**。

## 6. 写明的边界（这一篇**不是**准入做完了）

* **不是"设闸"**。`docs/218` §12 那条前提（执行者本身可改 ⇒ 任何闸都能被它要拦的人重写）
  没有变 —— 这一篇给的是**可判的事实**：谁、在哪份台账下、拿到多少宽度。**没有拦任何动作。**
* **§11 的静态规则还没写**：零宽阶段"只允许发产物字节与它的证明"是一条**要写死的规则**，
  今天只落在 `w0` 的三刻度 `(0, 1, 1)` 这个**数**上。§11 自己给的证伪方式（如果零宽阶段
  最后能用来传任意字节，这一轮作废）仍然有效 —— 而它现在**可以**被验，因为 `w0` 有数了。
* **台账不在本仓**：喂 `hits` 的是 FUAI 那三个原语（`dom_admit`(33555) / `qual_feed`(33556) /
  `qual_seq`(33557)），它们的**实现**在 compat 线（本仓 `kernel/` 是只读副本）。这一篇判的是
  **判定本身**，不是"台账怎么喂"。
* **L0 那句还是含糊的**。`lom/fuai.lom` 的 `gates` 里写着 *"LinuxFUAI: gate semantics for
  deployment"* —— 把它写实要动 `lom/*.lom`，那条路要过 `lom/` 那道禁区（**要 admin 合**）、
  按 `CLAUDE.md` 第一节还要**单独一次提交 + 在 docs 里留"下游影响" + 知会 compat 线**。
  **先有"要写实成什么"（就是这一篇），再动那句话** —— 顺序反过来会把契约当草稿。
* **阈值与三刻度都是策略**（`HITS_TO_W1/W2/W3`、`WIDEN_WINDOW`、`WIDTH` 那张表）：
  换一组数不改变形状，判据也不用改 —— 这是"形状与数值分开"那条纪律。
