# 219 · 收编 libc：库的码进来，库的运行期留下

> 状态: **激进提案**（2026-10-09）· 输入: `docs/183` V1（静态 libc）· `docs/173`（FFI 四阶段）·
> `docs/175` §4（hosted 层）· `docs/182` §C4（二进制开关）· `docs/210`（GC 四层梯）·
> `docs/205` C1（"不链 libc"那条立身之本）
> 一句话: **不链 libc —— 收编它。** 库保留自己的机器码，交出自己的运行期；
> 而"杂"（impurity）从**一个布尔量**变成**一本逐函数签发的账**。

---

## 0. 为什么这条是核心

`docs/183` §1 把这件事写成一句话：**卖点是在"第一眼"立的，而它在"运行"这一刻塌。**
README 敢写"调十个语言的库"，而真去调，链接器当场拒：

```
xxx.o: 引用了未定义的符号 malloc —— 到链接结束都没人提供它 (第 2 阶段仍不链 libc, docs/173 §3)
```

（参考侧 `tools/lomelf.py:2443-2444`，前缀是对象名；自举侧 `loment/tools/lomelf.lomt:2709-2712`，
前缀是 `lomelf: ` —— 后半句两侧一字不差。判据也是明写的：`docs/177` §1"真实的 C 库不是这个形状"。）

所以 libc 不是"FFI 的下一个阶段"，它是**唯一一条能把"访客会不会用"从否改成是的线** ——
这条判断在仓里是可查的：`docs/183` §1 那张卖点矩阵，每一行的"卡在哪"最终都指到同一个符号拒。
而同时，它又与 `docs/205:44` 那条立身之本正面冲突 —— 那一行把
**"产物无未定义符号、不链 libc"** 写成 C1 的判据。

**一条线同时是"最大机会"与"最硬的冲突"** —— 这就是"核心内容"的意思。

## 1. 死链：为什么"调真库"与"无运行期"看起来不可兼得

把它写成闭合的，别含糊：

- **A.** 要调世界上的真库（zlib / openssl / sqlite3 都是静态 `.a`）⇒ 必须满足它们**引用的符号**。
- **B.** 那些符号需求里必含 `malloc / free / realloc / memcpy / memset` ——
  `docs/183:87` 就是这么描述 zlib 的（"`.a` + 依赖 `malloc/free/memcpy`"）。
- **C.** `malloc` 的语义要求**一个进程级、稳定的堆**：谁分配谁释放，指针在同一次运行里恒定，
  `realloc` 可能原地。**堆不是函数，是状态。**
- **D.** 一个进程级可变状态 = 进程级运行期的第一个组件；跟着来的是 `errno`（glibc 里是 TLS）、
  `atexit`、惰性绑定、locale。⇒ **链 libc = 链运行期**，而运行期是本仓最不肯让的一格
  （`docs/205` §0.1 第二条硬冲突）。

于是得到的判断是：**「能调世界」与「无运行期 / 确定性」二选一。**
这不是偏好之争 —— 它是上面 A→D 那条链的**结论**。世界上的语言都选了 A 那头
（链 glibc、带运行期、放弃确定性）；本仓选了 D 那头（`docs/205` C1 把"不链 libc"钉成判据）。
**两边都没错，因为两边都以为只有这两种。**

## 2. 破解：一条规则 + 一条序

### 2.1 规则

> **libc 的内存不属于 libc，属于 Loment 的分配器。**

而且它**今天就在**，不是要新写的东西：

- `@__loment_alloc` —— `tools/lomentc.py:154`：bump 前沿 + **地址序空闲链表** + 4 字节块头 + 8 字节对齐。
- `@__loment_free` —— `tools/lomentc.py:229`：真的归还（前沿可回退，`docs/210` 记着这一格）。
- 堆本体 `@__loment_heap`（`:276`，今天是静态 64 KiB）、前沿 `@__loment_off`（`:277`）、
  空闲链头 `@__loment_freehead`（`:278`）。

`malloc` 因此不是"要引进来的东西"，是**给一个已经存在的对象换一个名字**。
这条规则直接砍断 **B 与 C**：真库要的符号，由**我们**提供；堆在，但它是**Loment 的、确定的**堆 ——
给定分配序列，地址由序列唯一决定（bump + 地址序空闲链表都是确定性的）。

### 2.2 序

但"换名字"不够，因为 D 里还剩下 `errno`/`time`/`getenv` 那一类**消不掉的**东西。
所以破解的第二步是**把它们从"是否有"改成"有几个"**：

> **先记账，再分档，最后才谈链接。**

1. **记账**：把 libc 调用面**逐函数**归类（§3）。
2. **分档**：能消除的杂（内存）消除；消不掉的（时间 / 随机 / 环境）**逐条具名**记账。
3. **链接**：只有前两步做完，"能链"才是安全的 —— 否则你只是把运行期偷偷放进来，
   而不知道放过来了什么。

### 2.3 断链，逐条

| 断在哪 | 怎么断 |
|---|---|
| **B** | 符号由**收编面**满足，不由系统 libc（§4 那张表） |
| **C** | 堆在，但它是 Loment 的堆，**确定性没丢** —— 丢的是"堆必须是 libc 的"这条**假设** |
| **D** | 剩下的只有"外因"那一类；它们归入账，**逐条裁决**，不是整包吞下 |
| **判据** | `llvm-nm` 无 `U` 那条判据**不删，反而变强**：从"产物**没有**未定义符号"改成"产物**每一个**未定义符号都在收编面上，且**它的类别被记下来了**"（§6 C3） |

**最后一行是这一节最值钱的地方。** `docs/205:44` 那条判据不必被推翻 —— 它被**升级**：
从布尔（有 `U` / 无 `U`）升级成一张集合（有哪些 `U`、各属哪一类）。这也是为什么这条路线
可以"激进"而不"叛教"。

## 3. 新的名词：**杂账**（impurity ledger）

**杂（impurity）= 一个函数的值取决于 Loment 源之外的世界。**

关键判断是：**它不是布尔量，是一个集合。** 世界上的语言把 libc 当成**一整块**吞下去，
于是"要不要运行期"成了二选一；一旦把 libc 拆成**逐函数可裁决的集合**，"要这个杂、不要那个杂"
就成立了。

⚠️ **这一节的"新"字要说得准**：把 libc 拆成**可裁剪的组件**不是新的（musl / dietlibc /
uClibc-ng 都在裁剪），"malloc 由 GC 供应"也不是（**Boehm GC / Crystal 在前**，§8.1）。
新的**只有一处**：**把"杂"做成一本逐原语、进产物的账**（§8.3）。机制是重组，名词是新的。

四类，一个函数只归一类：

| 类 | 定义 | 例 | 处置 |
|---|---|---|---|
| **纯** | 无外部状态，产物里不含可变量 | `memcpy` `memset` `memmove` `memcmp` `strlen` `abs` | 我们实现，**零账** |
| **内存** | 进程级可变状态，但**可确定化** | `malloc` `free` `realloc` `calloc` | **消除** —— 接到 `@__loment_alloc`（§2.1）；账上记"几个分配站点"（与 `gc_ladder` 同形） |
| **杂（外因）** | 值取决于 Loment 之外 | `time` `clock_gettime` `getrandom` `getenv` `locale*` `pthread_*` `stdio` | **记账** —— 逐条具名进 Potato；**不写 `choose` 就不给** |
| **不可收编** | 要求系统 libc 的内部结构 | `__libc_start_main`、`__errno_location`、`dlopen` | **点名拒**，带理由与替代（宁拒勿猜，`docs/188`） |

**"内存"那一类是整条路线的杠杆。** 它是 A→D 死链里唯一一条**可以真的被消除**的杂；
把它消除掉，剩下的"杂"就只是**几个具名函数**，而具名函数是可以计数的。

## 4. 收编面：真库到底要哪些符号

一个链接进来的 `.a`（zlib 那种）对未定义符号的需求，实际分五堆：

1. **编译器 libcalls** —— 编译器自己插的（`memcpy` `memset` `memmove` `memcmp`、
   以及 `__udivdi3` 那一族整数除法辅助）。**这是最常撞的一堆**，而且它**不是库作者写的**，
   是编译器生成的 ⇒ 收编它是**编译器的义务**，不是库的事。
   两份权威清单：**C 标准**（freestanding 也必须给的 `memcpy/memmove/memset/memcmp`，
   C11 §4.6.2.1；C23 又扩了一组 `<string.h>`）与 **LLVM `RuntimeLibcalls.def`**
   （编译器"隐式会发哪些 libcall"的表）。**照表收编，不靠记性。**
2. **分配器** —— `malloc/free/realloc/calloc` ⇒ §2.1。
3. **启动胶水** —— `_start` 之后、`main` 之前那一段（glibc 是 `__libc_start_main`）。
   Loment 已经有自己的 `_start`（`tools/lomelf.py:2412` 那条"原生产物 v0 需要一个用户态入口"），
   ⇒ 收编它 = 让 `_start` 直接进"库的入口"，**不经 libc 的启动器**。
4. **`errno` / TLS** —— 今天 glibc 把它做成 `__errno_location()` 返回 TLS 槽。
   单线程下它可以退化成**一个全局**（这正是 Loment 的模型）⇒ 收编，且**记账**（它是一条进程级状态）。
5. **外因** —— §3 第三类。

**顺序有依赖**：4 依赖 3（要有 `_start` 才能谈 `errno` 的初始化），1 与 2 独立，
2 是 1 的前提（`memcpy` 不需要堆，但分配器要用 `memset` 的确定版本）。

## 5. 与 GC 的交点（这才是"核心"落到地上的地方）

收编 libc 会**改动 GC 的边界**，而 GC 的四层梯刚落地（`docs/210`）。三处硬交点：

### 5.1 堆必须从"静态 arena"变成"问 OS 要页"

今天是 `@__loment_heap = internal global [65536 x i8]`（`tools/lomentc.py:276`）——
**64 KiB 静态数组**。`docs/210` §2.1 记着 `gc_auto` 的明写上限：触发 32 KiB、arena 64 KiB，
所以**活集 ≳ 32 KB 就耗尽**。真库（zlib 压一个大 buffer）**当场撞这条线**。

⇒ 收编的前提之一：分配器前沿要能**向 OS 要页**（`brk` 或 `mmap`；仓里已有 `loment/examples/native_brk.lomt`），
arena 从"静态数组"变成"映射出来的区间"。这正是 `docs/210` 里那句"要 L0 的是**问 OS 要页**"。

### 5.2 **阶跃约束**：`choose hosted` 与 `choose gc_auto_alpha` 互斥

这是最关键的一条。L2（块纪元）的实现是**前沿回卷**（`docs/210` §2.3）——
它**假定栈纪律**：`docs/210` §4.4 明写"纪元是唯一'不扫描'的批量回收 —— 而它买的是**栈纪律**"。
而一个 C 库**把指针放进它自己的结构里**（zlib 的 `z_stream`、next_in/next_out），
这些指针**在 Loment 的栈之外**。前沿一回卷，C 还持有的指针就变成**悬垂**。

⇒ **`choose hosted`（或用二进制的那条开关）与 `choose gc_auto_alpha` 必须互斥，点名拒。**
形状与 `docs/175` §3.4 那条 `no_std`+`gc_auto` 的拒法**完全一样** —— 现成的机制，不是新范式。
`choose hosted` 之下，能用的档是 `gc_manual`（默认，逐字节不动）与 `gc_auto`（标记-清扫，**非移动**，
对 C 安全）。

**这一条把 libc 从"FFI 的事"变成了"GC 的事"** —— 两条线在这里接上，也是"核心内容"的第二个意思。

### 5.3 收集器看得见 C 的指针吗？—— 今天**不主张**

要让收集器回收"C 库分配、C 库忘了 free"的内存，得看见**C 持有的指针**，
而 C 的指针可以藏在任何地方（`stderr` 的 FILE*、库的静态变量）= **保守扫描**。
那是 Boehm 那一类（**前史，§8**），成熟但代价清楚（误留、不能移动、与精确根分叉）。
**这一版不主张它**：收编的收益已经落在"堆是共享的、确定的、可计的"上，
不落在"连 C 的泄漏也回收"上。那是下一格，且要单独一条判据。

## 6. 判据（每一条都能证伪）

| # | 主张 | 判据 |
|---|---|---|
| **C1** | 真库能跑 | `loment run` 调 **zlib** 的 `compress`/`uncompress`，解压回原文（**`docs/183:87` 的原文判据，一字不改**） |
| **C2** | 堆**真是**我们的 | C 里 `malloc` 一块、Loment 里看到它（或反过来 `free`）；**且**产物里 `malloc` 的定义落在收编面那一侧（`llvm-nm` 判它**有定义**，不是 `U`）。反面：把 `@__loment_alloc` 换成"向系统要"的一个桩，C2 必红 |
| **C3** | 杂账是一个**不读源码可判的数** | 同一份程序，`choose` 开 / 关，Potato 里那一组数不同；**每一个 `U` 都对应账上一条**（§2.3 那条升级后的 `U` 判据）。与 `gc_ladder`（`docs/210` §3）同形 |
| **C4** | 判据是**强**不是**弱** | 拿一份**故意**引用 `dlopen` 的程序：默认拒（`docs/205:44` 那条判据照旧绿）；写了开关**仍**拒（`dlopen` 归"不可收编"）。**这条对上一条是证伪对** |
| **C5** | 阶跃约束是真的 | `choose hosted` + `choose gc_auto_alpha` → **点名拒**；对照 `choose hosted` + `gc_manual` → 绿。与 `no_std`+`gc_auto` 那条拒法同形 |

**C2 的反面是这套判据里最重要的那一条**：它把"我们真的把堆接管了"与"我们只是把 libc 偷偷链进来了"
分开 —— 后者会让 C1 也绿，所以 C1 单独**不构成证据**。

## 7. 分阶段（对应 `docs/183` §4 的 V1）

| # | 阶段 | 解开什么 | 判据 |
|---|---|---|---|
| **S0** | **记账面** | libc 调用面**逐函数**归类（§3 四类）+ 一份"提供者"表进产物 | 表是**机器可核**的：每个 `U` 都能查到类别（C3 的前半） |
| **S1** | **分配器成为 malloc** | 前沿能从 64 KiB 静态数组换成"问 OS 要页"；`malloc/free/realloc/calloc` 接到 `@__loment_alloc` | C2（含反面） |
| **S2** | **第一个真库** | 一个只用"纯 + 内存"两面的真库链进来并跑通 | C1（zlib） |
| **S3** | **开关 + 阶跃约束** | `choose` 官方开关（`docs/182` §C4 已经点名要它）；`hosted` × GC 档互斥 | C4 / C5 |

**次序的理由**：S0 是"先记账"（§2.2 那条序），没有它 S2 会**静默**把外因放进来；
S1 是 S2 的前提（真库要 O(100 KB) 堆）；S3 是纪律面，等"二进制真能用"才有意义
（与 `docs/183` §4 把 V5 放最后同一个理由）。

## 8. 前史与新颖面（先点名，再说话）

`docs/207` 的教训：动笔前先检索，命中就把那条**当前提**，新颖面缩到剩下的那几条。
下面是检索结果，按"别把重组说成发明"的纪律写。

### 8.1 已被做过的（**勿宣称新颖**）

| 先行技术 | 做了什么 | 与本文的重叠 |
|---|---|---|
| **Boehm GC**（hboehm.info/gc） | **保守 GC 顶替 `malloc`**（`REDIRECT_MALLOC`）；GCJ / 早期 Mono / Guile 都这么用 | §2.1「malloc 接到分配器」**不是新的** |
| **Crystal** | 公开 `GC.malloc` / `GC.free`，直接喂给 C 库 | **"GC 堆供应 C 库"已有先例** |
| **Cosmopolitan**（jart） | 自带 malloc + 自带 syscall 层，一份 APE 跑 Linux/macOS/Windows/BSD | 「不链系统 libc，自己当 libc」已有先例 |
| **Unikraft**（`unikraft-lib-musl`）· **rump kernels** · **Drawbridge** | 宿主运行时 + 把 libc（musl / NetBSD 栈）**当租户托管** | §3 那句"码进来、运行期留下"**同构** |
| **CHERI / CheriABI · Fuchsia · Genode · WASI · CloudABI · Capsicum** | capability 化的 syscall / fd 层（libc 架在其上） | 「libc 受能力约束」的**系统层版本** |
| **llvm-libc overlay mode** · Bazel/Nix hermetic · GraalVM native-image 闭合世界 | hermetic / 闭合世界的依赖分析 | 「声明式依赖」的**构建层版本** |
| **Rust 默认 `System` 分配器** | 默认时 Rust 与所链 C 库**已共用一个 malloc 堆** | 「语言与 C 共堆」**默认就有**（换 GC 分配器才分家） |

### 8.2 空位（**未见任何系统实现**）

1. **"逐原语计数的不纯清单，写进产物的元数据"** —— 检索未见。最近的三个邻居**各差一步**：
   *graded modal types*（Orchard, ICFP'19：效应**记进类型**，不在**链接边界**）；
   *hermetic / 闭合世界分析*（GraalVM native-image / llvm-libc hermetic / Bazel：算**依赖**，
   不算**杂**）；*WASI / CloudABI*（能力在 **fd / syscall** 层，不是"每个 libc 函数一条声明"）。
2. **"确定性 + 真 C 库链接"这一组合** —— 未见过。

### 8.3 于是本文的窄新颖面（一句话）

> **不是"让 C 库用我们的 GC 堆"**（Boehm / Crystal 在前），
> **而是把"杂"做成一本逐原语、进产物、可裁决的账** ——
> 让"这份二进制带了多少运行期"从一个形容词变成**一个不读源码可判的数**。

这也是为什么 §6 的 C3 是全篇最该守的那条判据：**别的都是重组，只有它是新的。**

### 8.4 一条旁注：这条"死链"在文献里是散的

检索**没有找到**任何正式论证"保留确定性就不可能调用真 C 库"。常见的只是一张**障碍清单**
（malloc 的全局状态、TLS `errno`、`atexit`/`__cxa_atexit`、PLT 惰性绑定需要动态加载器）
—— **障碍清单不是不可能性证明**。

所以 §1 那条 A→D 是**本文自己写闭合的**，不是引来的。这一点要说清：
**死链写成闭环是这篇的贡献之一，而不是某篇论文的结论。**

## 9. 代价 / 不做什么

1. **`realloc` 的原地性是装的，不是保证的。** Loment 的分配器是前沿 + 空闲链，
   "原地扩"只在块正好顶到前沿时成立。真实库（`realloc` 当"肯定原地"用的）会因此变慢，
   **但不会错** —— 这条要写进 `docs/173` §3 那张"不主张"的表。
2. **不主张"连 C 的泄漏也回收"**（§5.3）。
3. **不把 FFI 构建交回 clang/lld**（`docs/183` §6 那条不变）：收编面是**我们的**代码，
   由自举链发出，两个实现逐字节一致（`docs/158` §5）。
4. **不动 `docs/205:44` 那条判据的**意图 —— 只升级它的**形式**（§2.3 E）。
