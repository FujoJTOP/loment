# 230 · 收集器也认那块 arena（B1）：`hosted` 不再只有手动档吃得到宿主的内存

> 状态: **已落地**（2026-10-11）· 上游: `docs/228` §4 的 **B1**、`docs/210` §2/§3、`docs/225`
> 一句话: `docs/228` 让 `hosted` 的**堆**从宿主来，但把 `gc_auto` 那一档留在了静态 64 KiB ——
> 因为**标记表的行数就是 arena/8**。这一篇把那一档补上：**换 arena 就得同时换表**。

行号按 2026-10-11 本检出（`tools/lomentc.py`，`docs/228` 落地之后）。

---

## 0. 这一步补的是 `docs/228` 明写的那一格

`docs/228` 落地时，`hosted` + `gc_auto` 走不进那一段 —— §4 的 B1 把理由写得很直白：
**标记表的行数与它的索引口径里，写着 arena 的大小**。当时的处理是"不让它静默"：那一档
发 `; loment-heap: static 65536`，于是"没吃到"是量得出来的（`docs/228` §3.4）。

代价是**同一个 `choose hosted`，手动档涨了、自动档没涨** —— 这个不对称本身是个洞：
用自动回收的人恰恰是最需要大堆的人。这一篇把它补上。

---

## 1. 要换的是**三件事**，而且它们必须**同一次**换

收集器文本里与 arena 有关系的只有三处（其余每一行都与 arena 无关）：

| 处 | 形状 | 为什么换 |
|---|---|---|
| **基址** | `getelementptr [65536 x i8], ptr @__loment_heap, …`（6 处）、`ptrtoint ptr @__loment_heap to i64`（2 处） | `hosted` 的 `@__loment_heap` 是 `ptr`，不是 `[65536 x i8]` —— 直接寻址编译不过 |
| **标记表的行数** | `[8192 x i32]`（5 处，含声明） | **8192 = 65536 / 8**：这个数本来就是 arena 除以 8。索引口径 `偏移 >> 3` **一个字节没动** |
| **两处根扫边界** | `icmp ult i64 %rdo / %wdo, 65536` | 根扫是在"这个地址落不落在 arena 里"上判的 |

**它们必须一起换**：只换基址，表就只覆盖前 64 KiB —— 写到 64 KiB 之后的块**标记不到**，
收集器会把它当垃圾收掉。那是**静默的数据损坏**，不是崩溃。这正是 `docs/228` §1 那句
"64 KiB 不是配置项，是五处各自写死的假设"在实际代码里的样子。

`%hb` 插在**每个 `entry:` 之后**：收集器里那两个函数的入口块都叫 `entry`，而入口块
**支配**其余每一块 —— 所以 `%hb` 在哪儿都可用。这是 LLVM 的支配关系保证的，不是"觉得够用"。

---

## 2. 换，不是抄

`_IR_GC_HOSTED` 是 `_arena_indirect(_IR_GC_SHARED, 1048576)` —— **机器从那一份换出来的**，
不手抄（`docs/158` §5 那条孪生纪律：抄一份就是两份要一起改的东西）。

判据反过来钉这件事：两份文本**去掉 arena 相关的行之后，其余每一行必须逐字相同**
（`lomentc_test::test_hosted_collector_is_the_same_collector`）。不同就说明两份收集器
已经开始各长各的了 —— 而那是一条会**静默**分开的路。

**触发那一段一个字节都没换**：`_IR_GC_TRIGGER_FIXED` 按**字节数**触发（累计请求量过
`32768`），根本不看 arena 大小，所以两个端口共用它（`_IR_GC_HOSTED = _IR_GC_SHARED_HOSTED
+ _IR_GC_TRIGGER_FIXED`）。**自适应那一支不用管**：它的空间触发里写着 `64512` 与
`[8192 x i32]`，确实与 arena 绑着 —— 但 `hosted` 与 `gc_auto_alpha` 本来就是
**定义上冲突**的（`CORE_CONFLICTS`，`docs/219` §6.1），走不到那儿。

`; loment-heap: static 65536` 那条记号因此**没有再出现的场合**。判据从"它说了"
改成"它涨了"（§3 的 B1-2）—— 留一条永远为假的记号只会让人以为还有别的档没吃到。

---

## 3. 判据（每一条都能证伪）

| # | 主张 | 判据 |
|---|---|---|
| **B1-1** | 两份收集器只是 arena 那三件事不同 | 去掉 arena 行之后**逐字相同**；且"换掉的每一处真的换掉了"（防上一条因为两边都空而恒真） |
| **B1-2** | `hosted` + `gc_auto` **在平台上**，表跟着换 | 产物里有 `ptr null` 的 arena、`[131072 x i32]`（= 1 MiB / 8）、`%hb = call ptr @__loment_arena()`，且**没有** `[8192 x i32]` 与 `static` |
| **B1-3** | **一源两档，两个方向** | 同一份程序：先要一块 **200000 字节**（> 64 KiB）写满 7，再 churn 200 次小分配把触发计数据推过 `32768`（**收集器一定会收**），最后把那 20 万字节逐字节读回 —— `hosted` 返回 **7**；同一份源**去掉 `choose hosted`** 必须死在 `lomentc.py:218` 那条 `boom` 上（rc=132 SIGILL） |
| **B1-4** | 孪生 | 同一份源在两个实现上逐字节一致（`test_m82_hosted_arena_is_byte_identical`，与分配器那一份一起跑） |

**B1-3 是骨架**：B1-2 只量了文本形态，而"文本形态对"与"**收集器在这块 arena 上真的
收得对**"是两件事 —— 表换错行数会静默收掉活块，那只有**跑起来读回数据**才抓得到。
"读回全对"这一句同时钉住了两件：收集器**跑过**（churn 把计数推过阈值），而且它
**认得同一块内存**（只被栈上 `big` 指着的那一块在收集之后原封不动）。

## 4. 仍然没做的（`docs/228` §4 的那张表，B1 划掉，其余照旧）

| # | 没做 | 为什么还不在 |
|---|---|---|
| **B2** | 多段 / 无上限增长 | 偏移是 i32；多段要 `(段, 偏移)` 或裸指针 = **重写**分配器与收集器。这一篇换的是"哪块内存"，不是"能不能换第二块" |
| **B3** | 位图标记表 | 现在是"每 8 字节一个 i32" ⇒ **arena 的一半是 `.bss`**（1 MiB 的 arena 带 512 KiB 的表）。位图是 1/64。它是 B2 的**前置**，也是这一篇留下的唯一难看处 |
| **B4** | arena 大小可调 | 仍是编译期常量 `1048576`。它是**产品化**的活（两个实现的 CLI 要对齐），不是机制的活 |
| **B5** | `sealed` 那侧"向 OS 要页" | 破 `sealed` 的定义 + 要一份每平台的 syscall 代码。**没有需求就不做** |
| **B6/B7** | 收集器看不见的外部指针 / arena 的归还 | `docs/219` 的账；一次要一块、进程结束就没了 |

**B3 是这张表里最该下一个做的**：它既是 B2 的前置，又把这一篇留下的 `.bss` 代价拿掉 ——
而这一篇之所以能只换三件事就落地，正是因为**没动表的口径**。

## 5. 代价

- `loment/selfhost/codegen.lomt` 多了一段 `emit_gc_hosted`（与 `_IR_GC_SHARED_HOSTED`
  **逐字节同源**，脚本生成、不手抄）⇒ 自举种子重生成，一条 `[生成物]` 提交。
- `sealed` 侧**一个字节没动**：闸门仍在 `choose port hosted` 上，`_IR_GC` 一个字没改。
  自举种子逐字符一致、`ir_mem.lomt` 那 9 份孪生目标全绿，是这条的旁证。
