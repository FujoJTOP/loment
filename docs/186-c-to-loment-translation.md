# 186 · C 翻成 Loment（Stage A）

> 用户 2026-09-17 定的方向：**「c/py/java …… 最后被 potato 翻译为 Loment 语法」**，
> 以及实现顺序 **「先做 C 一门，跑通再加」**。
>
> 本文档是 C 这一门的落点。Python / Java 两门**没开工** —— 它们照着这份抄。

## 1. 判据是我说的那句话，不是我以为的那句话

用户给的原话：

> 判据是「翻译出来的 Loment 跑出的结果 == 直接用 clang 编那份 C 跑出的结果」

**比的是数，不是文本。** 比文本（golden file）的话，翻译器把 `a % b` 写成
`a - (a / b) * b` 也算过 —— 那不是判据。所以两边都真编真跑：

```
C  ──clang(-ffreestanding -nostdlib)──> ELF ──┐
                                               ├─> 退出码比一比
C ──potato_from──> Potato ──lomt_from --impl──> Loment ──lomentc/lomelf──> ELF ──┘
```

两边都用 freestanding 的 `_start`（不借 libc），于是"跑出来的数"只由那份 C 决定，
与两边各自的 C 运行时无关。

**还要与一个独立算出来的期望值对一次** —— 少了那一步，"翻译器与 clang 一起错成
同一副样子"会被当成通过。两份语料各配一个推论出来的数（见 §5 那条注释：
`while (b)` 改掉了 `b`，后面还在用，手算第一次就漏了）。

判据落在 `tools/loment_ctrans_test.py`（4 条），语料在 `loment/ctrans/*.c`。

## 2. 这条链长什么样

```
  C 源码                      Potato 形式对象                 L1 (.lomt)
  ─────                       ──────────────                 ──────────
  potato_from.from_c   ->     functions[i].abi = "c"
                              functions[i].body = "<原文>"     lomt_from --impl
                                                         ->    pub fn … { … }
```

三段各归各的：

| 段 | 谁的活 | 为什么 |
|---|---|---|
| 认 C、出签名 | `potato_from` | 源语言的语法属于源语言 |
| **带上正文** | `potato_from` | 见 §3 |
| **翻成 Loment** | `ctrans.py`（`lomt_from --impl` 调它） | 表示层不记"怎么算" |

`ctrans.py` 是**新模块**：C 子集的分词器 + 递归下降 + Loment 发射器。
它不依赖 clang、不依赖任何外部二进制 —— 判据里 clang 只用来编"对照组"。

## 3. 正文**原样**过一手 Potato —— 与 `docs/179` §2 是什么关系

`docs/179` §2 写着"让表示层携带实现"是 Potato 的一次**结构性**扩展，那份文档不做。
这一份**没有推翻它**，因为做的事不同：

- 那一句说的是**别把实现藏进表示层** —— 表示层该记"有什么"，不记"怎么算"；
- 这一步带过去的是**源语言的原文**，原样、**一个比特的解释都没有**。读的人拿到的
  就是那份 C。**谁去翻它是下游的事** —— 同一个对象可以被翻成 Loment，也可以被翻成
  别的，而对象本身不变。

所以字段名是 `body` 而不是 `impl`：它是"这条声明的正文"，与 `functions[i]` 记的
签名（`name` / `params` / `ret` / `abi`）并列，**存的还是源语言**。

### 3.1 它是**可选子字段**，所以不动契约版本

沿 `abi` 的先例（`docs/179` §3.1）：省略合法（**声明单元里一个函数都没有正文，
那是常态**），给了就必须是非空字符串。不认识它的消费者忽略它就是对的 ——
它们本来也只按签名用这份对象（接口单元那条路）。

**存整段函数原文，不是只存 `{…}`**：签名那边 Potato 记的是**映射后的**类型名
（`i32`），从 `i32` 回推 C 的拼法是另一张表，而原文本来就在手边；更要紧的是**保真** ——
`unsigned` 与 `unsigned int` 在 Potato 里都是 `u32`，回推必然丢掉用户写的那个拼法。

### 3.2 顺带修掉的一处：剥离注释会**改变长度**

`from_c` 里原先用 `_C_COMMENT.sub(" ", src)` 剥注释 —— 一整段多行注释被压成**一个
空格**。抓正文要按**下标**回原文里切，而下标只有在两边等长时才有意义；更糟的是行号
也一起失真（多行注释把后面的行整体上移）。现在换成**等长、且保留换行**的替换
（`_blank_keep_off`），`body` 与 `src` 逐字节对齐。

这一处不修的话，切出来的"正文"是**别处的字节** —— 而且它照样能编过。

## 4. 子集边界 —— 以及**不支持的怎么处理**

支持的（Stage A，就这些）：

| | |
|---|---|
| 类型 | `int` → `i32`，`unsigned` / `unsigned int` → `u32`，`long` → `i64`，`void` → `()` |
| 函数 | `<类型> <名>(<类型> <名>, …) { … }` |
| 语句 | `int x = e;`　`int x;`　`x = e;`　`return e;`　`if (e) S [else S]`　`while (e) S`　`for (init; cond; step) S`　`e;` |
| 表达式 | 十/十六进制整数、标识符、调用、一元 `- ! ~`、二元 `\|\| && \| ^ & == != < > <= >= << >> + - * / %` |

**不支持的一律报错退出，不静默丢**（`docs/167` 那条纪律）。这里跳过**不安全**：
`--impl` 发出的是**真实现**，少一个就是"这个程序少算了一步"，而它**照样能编过**。
所以 `switch` / `do … while` / `goto` / `break` / `continue` / 自增自减 / 复合赋值 /
三元 `?:` / 赋值表达式 / 指针 / 数组 / 聚合类型 / 预处理指令 / 全局变量 / 变参
全都**点名拒绝**，并且报得出是哪个函数、第几行。

**报得出是哪个函数**这一点是刻意的：一份文件里往往十几个函数，只说"子集外"
用户不知道该去改哪一个。

## 5. 这一节最要紧的东西：C 的 `int` 与 Loment 的 `bool` 不是一回事

C 里 `&&` `||` `!` `<` `>` `==` 这些**出的是 `int`**（0/1），而且**任何整数都能当条件**
（`if (a)`）；Loment 是 Rust 的严格子集，这些出 **`bool`**，而条件**只收 `bool`**。
于是两个方向都要补：

| 场合 | C | Loment |
|---|---|---|
| `int x = a && b;` | 直接存 | `let x: i32 = ((a != 0 && b != 0)) as i32;` |
| `if (a)`（a 是 int） | 合法 | `if a != 0 {` |
| `!a`（a 是 int） | 按 int 取反 | `(a == 0)` |
| `(a < b) + 1` | 直接加 | `((a < b)) as i32 + 1` |

**这两处转换错了，程序照样编得过 —— 只是结果不对。** 所以 `loment/ctrans/coerce.c`
存在的唯一理由就是把它逼出来：那一份**专挑这条缝**（而 `sample.c` 走的是正常写法）。

所以这个翻译器不是"改几个关键字"，而是**带方向的翻译**：发射时带一个 `want`
（`"int"` 还是 `"bool"`），两个方向各一条转换。

**短路保住了**：C 的 `&&`/`||` 短路，改法是把两侧**各自**转成 bool 再 `&&` ——
`&&` 在 Loment 里也短路，两侧各自是纯表达式求值，没有可见的副作用差异。
这一点是对的，不是碰巧。

## 6. 三条**语义**选择（不是翻译，是决定）

写下来是因为它们改的是行为，不是写法：

1. **`int x;`（只声明不给值）补零值。** C 读未初始化变量是**未定义行为**；Loment 要的是
   确定的程序。零值是最接近"什么都没发生"的确定选择。**不是**想把 C 的 UB 变成 0。
2. **`for (int i = …)` 的循环变量改名外提。** Loment **没有裸块** —— 实测
   `15:5 期望表达式，得到 '{'`，所以 C 的 for 作用域没法用一层 `{ }` 圈起来。
   改名是安全的：C 的 for 作用域本来就在循环结束处结束，外面看不到那个 `i`。
   > 这条是**探出来的**，不是查出来的。原以为"包一层 `{ }` 就完了"。
3. **`static` / `inline` / `const` 收下并丢掉。** 丢掉是**保义**的：`static` 是内部链接、
   `inline` 是内联建议，而这里翻的是**整个单元的全部函数** —— 没有第二个翻译单元能再
   定义同名函数，所以"内部链接"在这个语境里没有可分辨的差别。
   其余说明符（`extern` `volatile` `register` `typedef`）**拒绝**，它们都真的改语义。

   > **`const` 原先在"拒绝"那一列，2026-09-18 做 C++ 那一门时挪了过来。**
   > 原先的理由是"它们都真的改语义"，而**对 `const` 不成立**：在只有标量、没有指针的
   > 子集里，`const int x` / `const int a`（形参）丢掉 `const` 是保义的 ——
   > 源侧本来就保证了它不会被改（而 C++ 里 `const` 形参是**常态**）。
   > 顶层 `const` 全局量仍然收不了，那是下面 §9 那一条，不是这一条。

## 7. `--impl` 为什么**必须**是 opt-in

`lomt_from` 一贯发的是**接口单元**（`pub extern fn`，实现在源语言那一侧，
`docs/179` §2）。默认改成发实现会**当场弄坏** `loment_multilang_test`：
那条链靠 `extern fn` 把实现在编好的 `.o` 里的符号接进来 —— 发了体就变成同一个符号
**定义两遍**，而那是**链接期**的错，离源头很远。

所以：

* `lomt_from` 默认仍是接口单元；`--impl` 才翻正文；
* 判据里有一条专门钉住"默认那条路没被带歪"（`test_interface_unit_is_unchanged`）——
  **正文进了 Potato 之后，"默认那条路会不会被带歪"变成了一个真问题。**

还有一条：带正文的函数**没开 `--impl` 时不算"跳过项"**。它什么都没丢 ——
接口单元本来就是"声明在此、实现在那边"。报成 skip 会让上面那条判据红，而且报的是
**假消息**。

## 9. 下一步

* **自举侧没镜像**。这条链的产物是 Loment 源码，**过了自举那道门**（`lomentc`
  与 `fujoc-s` 都能编它）—— 所以这一格比 S1 便宜：`ctrans` 是**工具**，
  不是语言面，不必两侧各写一遍。
* **Python / Java 两门**：照这一份抄。它们各自的原生解析器（`ast` / 无）与
  C 的不同，但**判据一样** —— 翻译出来的跑出的数 == 直接跑那份源码的数。
* **跨单元调用**：Stage A 只翻一个单元。要调外部函数得走 `pub extern fn`
  那条路（`ctrans.translate` 的 `externs` 参数已经留好了口子）。
* **`float` / 指针 / 结构体 / 数组**：都在子集外，一律响亮拒绝。
  要做得先想清楚它们在 Loment 那一侧对应什么。
* **`int x;` 的零值选择**（§6 ①）：C 的 UB 在这里变成了确定行为。
  真要保 C 语义的话得报"用了未初始化的变量"—— 那是另一件事，没做。
* **全局常量（2026-09-18 撞到的真缺口）**：C 子集**不收全局变量**，于是连
  `const unsigned int MAX = 65535;` 也收不了 —— 而 C 里命名常量是**常态**。
  撞的方法是改 `loment/examples/multilang/01-c/pack.lomt`：它原来用
  `#define FRAME_SENSOR_MAX 65535u`（三样子集外），改成内联字面量才过。
  **内联是可用的绕法，但它把"改一个地方"这个好处丢了**（那个文件当初挑 `#define`
  正是为了这个）。要补的话：C 子集收 `const` 全局量 → Loment 的 `pub const`。
  注意 `docs/188` 之后这份是**表层语法**，所以这里补的其实是"Loment 的常量用 C 怎么写"。

### 9.1 `docs/188` 之后：这份文档有一处要改，**还没改**

`docs/188` 把"用别的写法写的单元"从**外源代码**正名为**表层语法**，于是：

* **`§4 子集` / `§6 语义选择` 的框要换**：C 里 `if (x)`（x 是 int）之所以要补
  `!= 0`，是**语法层**的迁就（C 允许这么写），不是"语义搬运"。结论没变，说法要改。
* **`§1 判据` 里"翻译出来的 == clang 编那份 C"仍然成立** —— 因为 C 与 Loment 在
  这个子集上**语义本来就一致**（都是向零截断的 `%`、都是 32 位 `int`）。
  这正是 `docs/188` §0.2 那条"共同子集上的语义一致"。
* **Python 那门不是这样**（`docs/187`）：它的 `//` `%` 与 Loment 不同，
  所以那份文档里的 `__py_mod` 是**做反了**的，见 `docs/188` §0.1 与 §8。
